# 2026-07-24 — 技能索引重构（三层分工 + 实装模式速查）

> 起因：用户 —— "AI 每次都要全部重新读一次（技能系统），非常累、非常烧 token。做索引：
> ①不同技能怎么配置的 ②不同技能怎么实装的；把设计需求也更新一下。"
> 纯文档批，零代码改动。

## 问题

144 条技能的知识散在：`survivor_data.gd`(2300 行表) + `survivor_player.gd`(900 行 apply match) +
`skill_hooks.gd`(700 行钩子) + 十几个消费点文件 + 两份 spec + 一份过时的图鉴。
回答"技能 X 的效果代码在哪"需要通读或全文搜索——每次都是几万 token 的重复劳动。

## 方案：三层分工 + 按"模式"收敛

144 条技能的实装其实收敛在 **8 种模式**里（85 个 stat：84 专用 + `skill_flag` ×60）。
逐条列会腐烂，按模式讲清 + 每 stat 一行映射，一份文档就能覆盖全部。

| 层 | 文档 | 回答 |
|---|---|---|
| 数值现状 | `reference/skill-table.md`（自动生成） | 某技能数值/稀有度/归属/轴 |
| **代码定位** | **`reference/skill-implementation-index.md`（新建，总入口）** | 怎么配置 / 怎么实装 / 效果代码在哪 |
| 设计需求 | `systems/survivor-skills.md`（重写） | 哲学 / 系统概念 / 未实装 backlog |

（数值**为什么**这样 → specs，分工不变。）

## 新建：skill-implementation-index.md

- **§0 按问题路由**：六类问题各指一处，AI 首读。
- **§1 配置字段全解**：UPGRADES 全部 17 个字段的语义 + 消费函数；账本双层结构（队级总账 vs 逐机生效子集 meta）。
- **§2 生命周期七步**：进池过滤 → 轴卡 → 记账 → 分发 → 生效 → 消费 → 重放，每步锚点。
- **§3 实装八模式**：M1 纯 params / M2 字段置位+高频消费 / M3 skill_flag+钩子 / M4 squad_once 账本与静态位 /
  M5 王牌(ACE_FIELD_STATS+strip) / M6 计数缩放(差量幂等) / M7 一次性 dispatch / M8 武器资源(重放跳过)。
  每模式：识别特征 / 改哪 / 新增步骤 / 成员。
- **§4 全 144 条 stat→消费点速查**：84 专用 stat 按消费管线分组（伤害/物理/锁定/状态/flare/武器）+
  60 条 skill_flag 按消费文件分组。**消费点写"文件+函数名"刻意不写行号**（防腐；与锚点校验器分工）。
- **§5 加新技能决策树**（效果类型 → 模式）。
- **§6 铁律八条**（重放不查门控 / ACE strip / static 三件套 / 深拷契约 / 差量幂等 / 三语同步 /
  FEAR 集中 helper / 机动 buff 双注入点）——每条都是踩过的坑。

映射表底稿由脚本自动扫描生成（对 60 条 skill_flag 逐 id grep 消费文件），再人工归类校对。
