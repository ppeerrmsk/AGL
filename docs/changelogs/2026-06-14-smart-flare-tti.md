# 2026-06-14 玩家方智能放焰（TTI 触发，杜绝浪费）

诊断来源：`logs/combat_log_20260614_131429.txt` + 用户反馈：玩家/僚机经常在导弹还很远、
甚至对"明显速度慢、追不上、不可能命中"的导弹就放焰，很浪费。

## 诊断

旧逻辑（`aircraft_flares.gd:update`）按**距离阈值**放焰：正常 `calm/panic` 距离（F-14 = 250m），
但**躲弹中抬到 `EVADE_FLARE_RELEASE_DIST = 1500px = 3000m`**（12×）。而躲弹进入又**无距离闸门**
（`check_incoming_missile`：任何瞄着自己的导弹都立刻进躲弹）。结果：4km 外一发射 → 立刻进躲弹 →
导弹一进 3km 就放焰（命中前 ~2.4s、约 2.6km，日志实证）。且放焰目标只按"最近"选，不判断该弹
是否真能追上 → 对慢速/被甩开的导弹也放焰浪费。

3km 抬升本是**故意**的（注释）：AI 满加力躲弹会把导弹甩在 250m 外永远不放焰 → 导弹烧到寿命尽头
才解除，僚机平飞脱队十几秒。3km 是为治这个"脱队"老 bug。代价就是"放焰过早 + 浪费"。

## 修复（仅玩家方 team 0，敌方 AI 路径与难度不变）

新增纯几何判定 `player_flare_should_trigger(ac, m)`：只对【会命中(在逼近) 且 即将到达】的导弹放焰。
```
closing = (v_missile − v_self)·LOS        # >0 = 间距在缩小
if closing < 30 m/s:        return false   # 追不上/在远离 → 不会命中 → 不放（根治浪费）
if dist ≤ 300m:             return true    # 终端兜底（慢速逼近 TTI 偏大也要放）
return dist/closing ≤ 1.5s                 # TTI ≤ 阈值 → 即将命中 → 放
```
`update()` 里：team 0 走此判定挑"最近的合格威胁弹"放焰（无合格弹则不放）；**team≠0 保留原
"性格距离 + 躲弹 3km 抬升"逻辑完全不变**。`EVADE_FLARE_RELEASE_DIST` 仅敌方还在用。

不会复活"脱队"老 bug：`find_nearest_incoming_missile` 已会在导弹熄火后"追不上就当威胁解除"
过滤掉它 → 躲弹自然退出归队；玩家方靠 closing 判据天然不对甩开的弹放焰。

## 验证

### 单元（`--bench=flare`，5/5 通过）
```
慢速追不上(浪费案例) 800m closing<0  → 不放 ✓     快弹远距 3km TTI=3.75s → 不放 ✓
快弹逼近 1km TTI=1.25s → 放 ✓          慢弹贴脸 300m 触兜底 → 放 ✓
慢弹逼近仍远 800m TTI=16s → 不放(进 300m 才放) ✓
```

### 实战（`--bench=stress_mixed --duration=35`）
- 编译干净、无 SCRIPT/Parse/Compile Error。
- 友机 F-16[Ultra] 被多枚敌弹瞄准：3 枚 5km+ 远弹**一发焰未放**（旧逻辑会进躲弹甩 3km 焰）；
  23.6s 一枚 **589m 近弹** → 友机进躲弹、**26.1s 未放焰退出、全程 0 伤害**（靠机动让导弹丢 FOV）。
  → 友机这一局**一发焰都没浪费**，导弹全靠机动 + 敌弹自己丢锁化解。
- 敌方 Su-27 仍按原逻辑放焰（27.0s）→ 敌方行为/难度不变。

证实目标达成：玩家方不再对慢速/远距/追不上的导弹浪费诱饵，只在导弹确实即将命中时才放。
