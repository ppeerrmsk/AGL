## 设计原则

1. **RefCounted 静态工具类模式**：所有子模块都是 `class_name X extends RefCounted`，全部方法都是 `static func`，首参 `ac: Aircraft` 或 `ai: AIController`。零实例，零状态。
2. **建议者 vs 提交者**：子模块是"建议者"，只读快照 + 写回 `ac.xxx` / `ai.xxx`；核心状态字段（`_state` / `_current_target` / `_tactic` 等）全部继续住主文件，不被子模块拥有。
3. **按关注点拆，不按状态拆**：避免让某一种状态（如 ENGAGE）的代码散落在多个模块。每个模块对应一组功能（物理 / 武器 / 战术 / 编队 / 规避）。
4. **委托壳保外部兼容**：被其他文件调用的 API 保留为主文件实例方法（一行委托到静态调用），其他文件不需要改动。同层关系密切的文件（`pilot_personality.gd` / `ace_squad.gd` / `aircraft_weapons.gd` 内部互引）直接改调用点。

## 拆分顺序（按"耦合度从低到高"）

Phase A — Aircraft 物理/武器拆分：
1. `aircraft_flares.gd`（最独立，只跟导弹管理器交互）
2. `aircraft_weapons.gd`（gun + ciws + rocket + missile + multi_lock_salvo）
3. `aircraft_physics.gd`（最敏感，物理要对比拆前拆后飞行轨迹）
4. `aircraft_combat_tracking.gd`（跟物理的 target_position 强耦合）

Phase B — AI 拆分：
5. `bfm_tactics.gd`（纯计算，无状态写）
6. `target_selection.gd`（重度依赖 radar_targets 快照）
7. `missile_evasion.gd`（触及状态切换）
8. `squad_coordination.gd`（最复杂，多字段交叉）

每步独立 commit + 压测，FPS 掉 >15 或行为漂移立即回滚。
