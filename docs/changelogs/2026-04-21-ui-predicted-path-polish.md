## 1. 雷达标注 TGT（`survivor_hud.gd` `RadarDisplay`）

**问题**：战术地图上黄色标注的 TGT 任务目标在左下角雷达里没区分度，和普通敌机同样是红点，玩家记不住要打谁。

**改法**：

- 遍历从 `Aircraft` 子节点改成 `CombatUnit.all_units`，覆盖空中 + 地面 TGT（SAM/AA/Radar 站也会有 `is_mission_target = true` 的情况）
- `is_mission_target=true` 的单位**不走扫描线节奏**：跳过 `_blip_ages` 衰减判据，永远可见
- TGT 专用颜色 `Color(1.0, 0.85, 0.2)`，和战术地图上 ADBS 黄色脉冲标记一致
- 标记造型：四角方括号（`bd=5, bl=2`）+ 中心 2 px 小点，和普通敌机圆点形成明显对比
- 和锁定目标（黄色方框）的优先级：TGT > 锁定，避免两层 UI 打架

## 2. 来袭导弹警告标记（同上）

**问题**：原来是 4 px 红色菱形闪烁，和敌机圆点几乎没区别。

**迭代**：

1. 第一版改成三角箭头（v1）→ 用户说"菱形太大，用条状更好辨认"
2. 第二版改成细长矩形条（7 × 1.8 px），长轴沿 "导弹→玩家" 方向对齐
3. 既显示是导弹，又直接读出方位

## 3. 世界空间导弹图标（`missile.gd` `_draw_body`）

**问题**：原来是 5 px 菱形（"size × 0.4" 宽），远看就是红点，和敌机图标混淆。

**改法**：10 × 2.4 px 的细长弹体：

- 弹身：尖头五边形（头锥 + 矩形身）
- 前翼：中段十字短线（`mid_fin=2, w=1.2`）
- 尾翼：后段十字短线（`tail_fin=2.6, w=1.4`，比前翼稍宽）

Heading=0 朝上，拉远也能看出是飞行器不是圆点。发动机火焰 `_draw_motor_flame`（尾焰闪烁）保持不变，强化"导弹 + 尾焰"识别。

## 4. 玩家预测线（核心章节）

玩家点击地图后，会从机头画一条预测弧线到点击点，帮助估算转弯半径。这部分经历了最长的修复过程——先做视觉优化，再发现抽搐问题，然后连续 6 轮迭代才找到根因。

### 4.1 视觉优化（第 1 轮）

修了预测线的**准确性**和**可见度**：

**准确性修复**（`aircraft_renderer.draw_predicted_path` 仿真部分）：

原来的预测用的是"巡航模式" bank 曲线（`< 0.05` 零 / `< 0.4` 30% / 满 bank + proximity 衰减），但真机玩家走的是 `aircraft.gd:956 elif use_tactical_preference` 分支（`< 0.02` 零 / `< 0.15` lerp 50%→100% / 满 bank，**无 proximity 衰减**）。两者阈值和形状都不一样。

结果：玩家点击短距离目标时预测线被错误拉直；长距离转弯时预测线比实际航迹晚回正。

改成和真机 "玩家战术巡航分支" 一致的 bank 曲线 + 加上 `aircraft.gd:867-881` 的 critical-damping anticipation（预读当前坡度回 0 期间还会走多少角度，提前从 hdiff 里扣掉）。

仿真步长从 0.08s → 0.06s，记录间隔 3 → 2，弧线更平滑。

**可见度提升**：

- 原来虚线 + 1.5 px + alpha 0.1-0.4 → 双层连续线（光晕 2.2 px alpha 0.35 + 核心 1.0 px alpha 0.85 + 核心提亮 +0.25）
- 航点标记：从单环 + 十字 → 双环 + 十字（从中心留缝）+ 呼吸脉冲外圈 + 中心 2 px 白点

### 4.2 末端标记的几次迭代

围绕"指令会在某个距离自动取消"的提示做了几轮：

1. **第 1 版**：黄色横截线 + 圆圈 + 虚线到达圆 —— 用户说"线抽动、取消标记抽动、范围线太大"
2. **第 2 版**：删掉到达圆，缩小截止标记 —— 用户说"做成固定箭头更好，不需要实时更新"
3. **第 3 版**：静态人字箭头锚在目标位置 —— 用户说"理解错了，要放在线的末端，像彩带"
4. **第 4 版**：线末端彩带箭头（5 顶点菱形收口） —— 用户说"是菱形不是三角箭头；还会消失"
5. **第 5 版**：改成标准 7 顶点箭头（窄轴 + 翼突 + 尖端） —— 用户说"还是时有时无"
6. **第 6 版**：拆成两个凸多边形（矩形轴 + 三角箭头），加兜底方向 —— 解决 Godot 凹多边形三角化偶发失败问题

### 4.3 箭头消失的二次修复（绕圈路径）

当预测路径绕回自己形成闭合圆时（用户截图：玩家绕目标做圆周运动），**最后一段会闪烁**。

**诊断**：缓存是一串世界坐标点连成圆圈。飞机在圈上一点，此时：
- `cache[0]`（飞机当前位置）距飞机 = 0
- `cache[N-5]`（绕一圈回到飞机附近的点）距飞机 = 几十 px

全局最近点搜索每帧会在"真·起点"和"绕回末尾"之间跳，trim 结果从 `N` 个点 ↔ `5` 个点之间抖。

**修复**：加了 `predicted_path_progress_idx` 状态，每帧只在 `[progress_idx, progress_idx + 30]` 这个**前瞻窗口**里搜最近点。progress_idx **单调递增**，绕一圈回来的点在 index 上远超窗口外，永远不会被误选。

副产品：搜索范围从 O(N≈100) 降到 O(30)，每帧成本减半。

### 4.4 箭头方向脱钩 bug（最终修复）

用户报告：**箭头方向和线脱钩**，箭头看起来"指向玩家和目标的相对方向"。

**诊断**：`_recompute_predicted_path` 命中 `arrival_dist` 圈时会做线性插值：

```gdscript
cache.append(prev_world.lerp(sim_pos, t))   # t ≈ 0 时插值点和 prev 很近
```

这个插值点可能和前一个缓存点只差 < 1 px。于是 arrow 计算里：

- `tip = points[-1]`（插值点），`prev = points[-2]`（真·末尾）→ 两者距离 < 1 px
- `tangent.length() < 0.5` → 触发兜底分支：
  ```gdscript
  fwd = local_target / lt_len   # 飞机→目标方向
  ```
- 结果：箭头指向目标，不沿路径切向 → 用户说"指向玩家相对位置"

**修复**：从末端往回**跳 2 段**取 tangent（用 `points[-3]`），跳过可能的插值尾段。再不行跳回 5 段。彻底干掉"飞机→目标"的兜底，改用本地 `Vector2(0, -1)`（机头朝向）——至少方向合理，不会和路径脱钩。

### 4.5 整体抽动问题的根因追踪

这是 4.x 的核心：为什么每帧重算预测线会抽动？走了 5 轮错路才找到根因：

**错路 1：输出平滑（α=0.15）**
→ 没用。抖动依然 ±10-20 px。

**错路 2：降低刷新率到 1s + 缓存**
→ 抽动没了，但箭头方向和线脱钩（缓存老，末端切向不反映飞机当前状态）。

**错路 3：每帧刷新 + 更强输出平滑（α=0.08）**
→ 还是抖。

**错路 4：输入 + 输出双层平滑（输入 α=0.1, TC 167ms）**
→ 用户："这些改动都是没有用的，它还是一直在前前后后地抽搐。"

**错路 5：承认思路根本不对**

重新审视：抖动不是白噪声，是仿真器本身的**系统性振荡**（Forward Euler 积分 + bank 反馈控制环 + critical-damping 补偿三者叠加出来的振荡模态）。低通滤波压不掉主信号自带的振荡——滤波设计假设信号是"理想 + 噪声"，但这里是"振荡的主信号"。

**真·修复：事件驱动 + 世界坐标锁定**

彻底不每帧重仿。路径一旦算出就**写死在世界坐标里**。每帧只做：

- 一次 O(30) 局部窗口扫描找飞机最近点
- 从最近点往前切片
- 画线 + 画箭头

**三种事件才触发重算**（`aircraft.gd` 新增常量）：

| 事件 | 常量 | 触发条件 |
|------|------|----------|
| 目标变了 | `PREDICTED_PATH_RETARGET_THRESHOLD = 20` | target_position 偏移 > 20 px |
| 飞机偏离路径 | `PREDICTED_PATH_DRIFT_THRESHOLD = 90` | 飞机离最近缓存点 > 90 px（实际物理和预测分道扬镳） |
| 缓存快消耗完 | `PREDICTED_PATH_MIN_REMAINING = 12` | 从最近点到缓存末尾 < 12 个点 |

仿真频率：从 60 Hz 降到约 0.5 Hz（每 1-2 秒飞机飞出 90 px 触发一次）。中间每帧的 CPU 成本从 ~0.5 ms → ~0.02 ms。

更重要的是：**缓存里的世界坐标真的锁死不动**，线和箭头在世界空间完全静止（只随镜头/飞机移动平移）。没有任何仿真被执行 → 没有振荡 → 视觉零抖动。

## 经验教训

1. **性能抖动问题**：先判断抖动来源是白噪声还是系统性振荡。低通只能压白噪声，压不掉主信号自带的振荡。
2. **缓存 vs 实时计算**：UI 可视化（玩家感知层）应该优先走"事件驱动缓存"。实时重算除非有强理由。
3. **迭代顺序**：美术反馈（颜色/形状/位置）先改；稳定性问题要诊断根因，别急着加滤波。
4. **几何兜底**：不要把"主路径失败"兜底到"一个语义完全不同的方向向量"（飞机→目标 vs 路径切向）。兜底应该在同一概念下找降级方案（跳 2 段→跳 5 段→机头朝向）。
5. **凸 vs 凹多边形**：Godot `draw_colored_polygon` 对凹多边形不稳，最好拆成 N 个凸多边形并排。
