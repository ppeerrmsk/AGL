# 2026-09-06 战区目标镜头预加载与生成成本修复

## 症状与根因

普通战区只在选择或入圈后生成，奖励任务再等待六秒广播；可见性门又要求生成区离屏，最终由抵达恢复口强制放行。这会使既有任务目标在玩家面前突然出现。旧回归将地面目标的可见恢复视为成功，未验证远距镜头观察。

另一个相关路径是攻克其他战区后的等级刷新：尚未触发的目标名单会被撤销重建，破坏已观察目标的身份连续性。

## 修改

- 镜头预加载带覆盖生成范围即激活；相机平移、缩放及旋转更新后，在绘制前准备正式目标。完整散布范围包含手画部署多边形；护送目标还覆盖独立航线锚点及陆地吸附范围。
- 观察不再等待六秒广播，也不需要玩家飞机靠近或选中任务。画外选中任务仍保留原广播；空中敌机继续从地图边缘真实飞入。
- 已建立目标名单的战区不随其他战区攻克或等级变化重刷；观察本身不触发任务、伤害或奖励结算。
- 未观察、未选择且未进入的普通远区仍保持零实体；没有新增逐实体 tick。
- 地理索引、水面掩码和静态战区陆地适用性移至场景建立期预热。道路净空查询使用 512px 网格筛选，最终仍按原 180px 精确距离判定；先排除便宜的间距/道路失败候选，再做地面净空判断。原接受条件、目标数量、采样 RNG 顺序和位置保持不变。
- 停止物理处理的专项 ZoneMission 不受绘制前补齐干扰；BOSS、玩家死亡和无任务场景继续走原闸门。

## 验证

| 等级 | 证据 | 结果 |
|---|---|---|
| 先失败的回归 | 原实现运行新增 `offscreen_world` 观察案例 | 8 通过、4 失败，复现远距观察不生成 |
| 聚焦 | `offscreen_world` | 最终 13/13；道路网格与原算法比较 1681 点，含负坐标、长线段、零长段 |
| 聚焦 | `zone_air_support` | 77/77；广播中转镜头、五类任务首帧准备、实体身份和原支援终态 |
| 全量 | `bench/run.cmd all 1 300 Shadow Headless` | 95 项测试通过；真实 SceneTree lifecycle gauntlet 86/86；wrapper 退出 0，无运行时错误门失败 |
| 真实画面 | `zone_observation_visual` | 正式 Survivor 镜头与地面工厂，远距未选中 A 区，9 个真实地面目标；首帧存在、任务不误触发、镜头返回保持同一实例 |
| 首次切镜头性能 | 三轮不抓图样本 | 准备耗时 6.628 / 6.612 / 7.146ms；实际最慢帧 15.243 / 15.005 / 15.055ms；三轮均 below60=0 |
| C1 | 36 名 / 8km，三轮 Shadow Visual | avg FPS 119.20 / 119.91 / 119.71；worst FPS 73.44 / 86.84 / 71.13；全部 below60=0，巡检 8/8，36 名与真实炮弹存在 |
| C2 | 48 名 / 24km，三轮 Shadow Visual | avg FPS 118.22 / 118.64 / 119.00；worst FPS 61.45 / 60.06 / 69.72；全部 below60=0，巡检 8/8，48 名与真实炮弹存在 |

初版修复在同一观察样本出现约 45–49ms 准备成本；拆分计时发现约 30ms 来自采样、约 10ms 来自重复整区陆地判断。道路网格、廉价条件前置和静态地理预热后，最终准备耗时约 6.6–7.1ms。此处不以跨版本稳态 FPS 计算收益比例。

专项性能使用实际墙钟帧间隔，避免引擎修正后的 delta 掩盖首次生成尖峰。10 秒参数保存首帧/次帧 PNG；20 秒参数不抓图并强制 below60=0，GPU 图像回读不混入性能验收。
