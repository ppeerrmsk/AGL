# 2026-04-30 — 收紧"对头"定义到 3km

## 调味原因

骑士精神系列原本只看双向 dot（≈ ±45° 锥）就算对头，结果远距 BVR
导弹击杀（5–8km）也会触发 `skill_head_on_perma_hp` / `skill_head_on_aoe_fear`，
完全偏离"对冲冲锋"的设计本意。`head_on_jam` 同理 —— 雷达锥边缘 10km
外的对头敌机也会被累积干扰。

## 改动

新增常量 [skill_hooks.gd](../../scripts/survivor/skill_hooks.gd)：
```gdscript
const HEAD_ON_RANGE_PX := 1500.0   # 3km，PIXELS_PER_METER=0.5
```

三个玩家技能入口加距离 gate：

1. **`SkillHooks.dispatch_on_kill`** — `is_head_on` 现在要求几何 + 距离 ≤ 3km；
   影响 `skill_head_on_perma_hp`（+5 max_hp）和 `skill_head_on_aoe_fear`（FEAR AOE）
2. **`Aircraft._update_*` 的 head_on_jam 累积** — 双向 dot 通过后再 gate 距离；
   超过 3km 当帧不累积也不清零（`continue`），保留"离开雷达锥才清零"语义
3. **`Aircraft.take_bullet_damage` 的 head_on_gun_dodge** — 加距离 gate，与其它对头机制语义对齐
   （机炮射程本就远小于 3km，此 gate 实际上是冗余）

## 不动的部分

- `tactical_planner.gd` MERGE_PASS 的 `head_on_dot > 0.7` —— AI 战术几何判定，距离已通过 BfmIntent 自然约束
- `bfm_tactics.gd` `s.is_head_on` —— 旧 BFM 路径的内部标识
- `flare_params.head_on_fail_reduction` —— 已在导弹 release 距离内执行
- `_record_kill_attribution` 的 `kill_head_on_dot` meta —— 仍仅记录 raw dot；下游 (skill_hooks) 加 gate

## 验证

近距对冲 ~1km 击杀仍触发 perma_hp/AOE_FEAR；远距 BVR 击杀（5km+）静默。
`head_on_jam` 在 4km 外不再累积，2km 内行为不变。
