## 1. 纠偏结论

用户累计等待五天，却未收到一份可在正式游戏里复查的完整效果汇报。这是交付失败，不应以制作量大、技术复杂或测试多解释为接近完成。

主要失误：

1. 先大量生产、后验证整图成本；分页只拆分资源，不自动减少完整视野里的几何。
2. 将资产保存、目录检查、独立场景截图当成推进中心，正式加载到战斗的链路长期未闭合。
3. 候选不断分叉，局部验证反复推进，却没有冻结一套全图可运行候选。
4. 汇报以工序编号和断言为主，没有固定入口、同位对照、明确缺陷与验收判定。
5. 等待进程、暂停标记和终态记录未及时收拢，容易把过期检查点误认为当前工作。

改为一条主线：**冻结现有成果 → 正式整图可运行 → 全缩放视觉完整 → 实战与生命周期 → 用户验收后交付。** 不再以新增版本数、页数或文档长度作为进度。

## 3. 冻结范围与不再重做的工序

- 东京湾先完成整图交付；沙漠、海洋本轮只做共享改动回归，不顺势重制三张地图。
- 保留已获认可的低层密集区块面概括、铁路场坪概括；不逐栋恢复碎细节，不重开一小片城区的审美试验。
- 保留189栋正式建筑的真实轮廓、高度与玩法权威；普通低层可概括，不能据此合并正式建筑或修改2D碰撞、AI、伤害。
- 复用原256片数据、11档组件、已保存纹理/mip/AO、C/B/E候选及原加载/切面系统。原高面数目录作为来源与对照，不先将其全量实装再重做HLOD。
- 固定16活动页、96MiB、24万面既有约束；过渡驻留也计入共享预算，不另开纹理预算池。性能准入遵守原规范，不通过减少战斗负载达标。
- 默认简单静态阴影/AO，不引入复杂动态阴影系统。研究只服务具体阻塞点，优先官方文档；记录问题、结论、落点，不开展无交付边界的技术调研。
- 不删除旧底图或旧可用路径。候选必须可关闭、失败可回退；回退不是新方案验收通过。

## 4. 分阶段执行与交付物

各阶段串行推进，资源制作按需补缺。计时从恢复执行开始算实际工作时间，长测试/外部等待另列；下面是检查窗口，不是保证完成的承诺。

### M0：冻结基线与接管队列（目标30分钟内）

行动：复核现有收据和资产摘要，登记唯一候选组合；核对旧等待链的输入身份与终态，清理自身已失效的调度职责，不杀未知进程、不碰他人的bench锁。需要暂停时登记原因与恢复条件，禁止另开重复队列。

交付：一份基线清单，列候选路径/摘要、当前正式入口、旧版本回退入口、未完成项和仍保留的作业。明确原canonical来源与新HLOD身份不可互借。

完成门：知道本次运行具体使用哪套资产；每个作业只有一个职责；不再发生相同输入无故重烘。

### M1：正式游戏整图验收版本（从恢复执行起2～4小时检查点）

行动顺序：

1. 复用原Stream预算实现纹理独立租约和物理资源共享，先覆盖加载成功/取消/失败/释放，再接可见绘制。
2. 在正式Loading预载所需切面，准备GPU资源；沿同一实例交接到Survivor，冻结完整来源身份，拒绝漂移。
3. 以实际189栋网格轮廓与高度证明覆盖后才接管旧视觉，不能用来源ID数目代替；未就绪时走原安全回退。
4. 接入现有合格候选尺度，验证整图移动、缩放、旋转和边缘；未支持的近景明确回退，不把缺页、黑屏或放大模糊伪装成简化。

交付必须同时包括：

- 正式主菜单→东京湾→Loading→Survivor的准确复现步骤；若需测试开关，提供单一明确入口和关闭方法，不要求用户手改多份清单。
- 至少6张正式游戏原始截图：总览、密集城区、铁路、港口/岸线、正式高楼、地图边缘；标注坐标、缩放和版本。另附一段连续移动/缩放录屏，若捕获工具确有限制则提供可复现巡航入口及连续帧序列，并明确不是视频。
- 一页阶段报告：实装了什么、哪些仍回退、已知缺陷、下一阶段缺口。制作端截图不得混入正式成果。

完成门：用户能打开并检查整张地图，不是只能看独立预览；切面缺失/交接异常不得标完成。此阶段允许明确标注未完成的近景与性能，不宣称最终验收。

止损：到4小时仍未交付时，停止新增素材和候选，提交正式入口的失败证据、具体阻塞路径及剩余最小改动；不能只说“继续集成”。若必须扩展架构或改变已认可风格，先请求方向，不擅自重做。

### M2：完整缩放和全图视觉（M1后预计2～4小时，近景为主要不确定项）
