# 内容铺量阶段生产工作流

> 状态：2026-08-20 起的当前生产入口。本文决定“下一步做什么、按什么顺序、做到什么程度”。
> 设计数值仍以 [specs/_INDEX.md](../specs/_INDEX.md) 为 SSOT；代码接入点看
> [reference/playbook.md](../reference/playbook.md)。旧 [roadmap.md](roadmap.md)、
> [roadmap-overview.md](roadmap-overview.md) 与 [evolution-vertical-slice.md](evolution-vertical-slice.md)
> 均为历史过程，不再承担排期。

## 0. 阶段裁决

AGL 已离开“继续证明底层能不能成立”的垂直切片阶段，进入**以现有底座持续生产完整内容包**的阶段。

当前基线是正式进化树 **43 架**可驾驶机、自动生成技能表 **158 条**、BOSS 注册表 4 个完整轮换项；
这些数字都是现状，不是内容上限。项目目标是让玩家获得**至少约 20 小时持续展开的内容**：功勋、解锁、
机体、技能与必要的核心机制要循序开放，让玩家在这段时间不断遇到新的功能、组合和战场刺激，而不是
前几局看完全部内容、后面只重复刷数值。当前真正的缺口是：

1. 每张地图是否有自己的敌情、任务、王牌、BOSS、奖励与环境身份；
2. 已落地内容能否从 spec 重建，能否经 Debug、bench、Visual 与完整局稳定验收；
3. 三张地图能否先各自独立成局，再串成一条战役。
4. 约 20 小时的内容线上，何时解锁新机体、技能、功能和战场层级，是否持续有可感知的新体验。
5. 音乐、音效、机体/地图细节、战斗特效和 Build 变强表现能否随铺量一起生产，而不是最后补票。

因此本阶段的生产单位是**地图内容包**，不是零散 feature。任何新内容必须回答它属于哪张地图、
补哪个玩法空位、如何改变机型路线或 Build 决策；答不出来就不进生产队列。

## 1. 扩充门与允许线

### 默认不做无目标扩充

- **玩家机谱**：43 机树是当前生产基线，不是封顶。新机必须填补 20 小时解锁节奏、地图身份或现有谱系
  无法表达的玩法空位；不得只为 roster 数字增长。
- **技能总数**：158 条不是 KPI，也不是封顶。可以为构筑闭环、装备联动、地图机制、核心功能渐进解放或
  中后期新鲜感继续扩充，但不做同义数值卡。
- **BOSS 阵容**：Wraith、CSG/LADON、Mother Goose、Black Star 是当前轮换基线，不是封顶。后续仍需要
  新 BOSS；每个新 BOSS 必须服务地图身份或 20 小时新体验曲线，并同时满足独特机制、高难度与聪明 AI，
  不做普通敌人数值放大的换皮 BOSS。
- **新底层框架**：优先复用 GameEvent、AIDirective、BossEncounter、装备组件、状态系统、战区与演出导演。
  内容暴露真实 seam 时才开窄修，不借铺量重写地基。
- **局外成长大改 / UGC 产品化**：UGC 在三张地图各自可完整通关前不抢主线；功勋与解锁系统则必须
  重新按约 20 小时持续内容目标测算，现有价格和解锁顺序不能默认视为最终答案。
- **三图串联**：三张地图尚未各自成局前，不先实现跨图存档、双队会师或 BOSS 顺延。

### 允许并鼓励

- 复用现有 archetype、任务骨架、武器与演出系统做**可感知的新组合**；
- 为当前生产内容补 reconstruction-grade spec，顺手消灭代码独占事实；
- 把“代码已完成、只差模糊 someday playtest”的旧项合并成一次明确的关闭批；
- 同一地图内按 3～5 个紧密相关条目组成批次，共享一次集成、压力与完整局验收。
- 为前/中/后期补可感知的新机体、技能或功能解锁，并明确它填补 20 小时曲线的哪个时段；
- 把音画、机体/地图细节、特效、提示语言与变强可视化纳入内容批，统一走
  [音画生产工作流](audio-visual-production-workflow.md)。

## 2. 接下来的顺序

### P0 · 收口生产底座

目标：把会反复污染每个内容批次的未决问题一次关掉；不要求所有历史债清零。

1. **状态清账**：逐项审计 `_INDEX` 中的 `in-progress`。只有确实还在改代码或缺必需验收门的条目保留；
   “主体已完成、以后可继续调数值”应收口为 `done`，调参进入批次 playtest 记录，不永久占 WIP。
2. **一轮基础手感关闭局**：集中验 flight-model-realism、squad-cohesion、formation-discipline、
   waypoint-fire-control、XP/进化节奏与 UI transition。一次完整局产出明确结论，不拆成六次零散等待。
3. **地图渲染裁决**：完成 raster-basemap-streaming 的同位 Visual A/B，明确晋升或保留 PNG；
   不让两套生产路径长期同时处于“差最终确认”。
4. **最先补的 SSOT**：Ladon/CSG BOSS 总 spec、基础 gun/missile/rocket/flare 武器族、当前地图实际消费但
   仍只有 `.tres` / enemy-index 的基础敌人。优先补“下个内容包会复用的”，不按文件名机械扫库。
5. **性能基线收口（2026-08-22 已完成）**：C1 36 名/8 km 与 C2 48 名/24 km 混合全可见战场均在
   不减员、不裁剪武器/战场反馈的合同下连续三次 30 秒 `Shadow Visual` 达成 `<60 == 0`；同步门
   80/80、生命周期门 20/20。尖峰上下文、分位数和保守归因已进入正式诊断；实现、A/B 与六轮结果见
   [大规模战斗 60 FPS 计划 §14](large-scale-battle-60fps.md#14-2026-08-22--p0g0-收口)。交付同版
   C1/C2 最差分别为 60.00 / 60.07 FPS，当前属于过线但余量偏窄，后续内容批仍须执行代表性负载回退门。
6. **20 小时节奏骨架**：盘点现有功勋、机体、技能、BOSS、功能和地图解锁，先画出“玩家何时第一次见到什么”
   的小时段曲线。首版窗口、节拍槽与确定缺口见 [20 小时内容首次体验排期骨架](20-hour-content-exposure-plan.md)，
   可复算曲线见 [量化模型工作流](quantitative-content-balance-model.md)。此轮只找断层、过早倾倒和长时间无新刺激，
   不在没有数据时拍死价格与小时数。
7. **音画生产入口**：按 [音画生产工作流](audio-visual-production-workflow.md) 建素材交付清单和第一批样板，
   先覆盖初期冷峻、中期升温、后期暴走的对比，以及击杀、状态和 Build 变强的可感知反馈。

P0 退出条件：基础关闭局没有阻断内容生产的手感/指挥问题；地图生产路径有单一默认；同时最多只留
1 个底层系统项处于主动实现；C1 三次 Visual 稳态满足 60 FPS、p1/worst 与相对回退门，且负载合同没有
通过减员、裁剪或关武器卸载；20 小时解锁曲线有可执行骨架；音画首批素材清单和质量样板可直接开工。

### P1 · 东京湾作为量产母版

目标：不用再证明玩法，只证明生产流水线能稳定复制。

- 把现有东京湾内容整理成第一份**完整地图内容包清单**；
- 补齐 CSG 权威 spec 和会被后两图复用的基础武器/敌人 spec；
- 选一个 3～5 项的小批（例如同一任务家族的敌人 + 事件 + 奖励），完整走一次本文 §4～§6；
- 产出可复制的 Debug 入口、聚焦 bench、压力场和 Visual 机位，不另造东京湾专用框架。
- 把东京湾做成第一套完整音画样板：初期→后期密度变化、地图细节、武器/击杀音效、状态提示与
  至少一批 Build 变强表现一起进入验收。

P1 退出条件：新人只看 spec + playbook 就能复制该批，不需要翻 changelog 猜接入点；东京湾能独立从
起飞打到 BOSS 并结算，完整局无阻断问题；玩家能明确感知战场从专业冷峻走向热闹失控，并能从音画上
说出自己的 Build 变强了什么。

### P2 · 沙漠铁路独立成局

每张地图至少交付下列七件套，沙漠先做第一套：

1. 一个明确环境/空间身份；
2. 三类可重复任务（空、地、地图专属至少各有一类，不要求三个全新框架）；
3. 两组地图专属敌情组合（可复用机型，但编成、使命或武器语言必须不同）；
4. 一支地图王牌或宿敌事件；
5. 一个主 BOSS；
6. 一条能改变 Build 取舍的奖励倾向；
7. 主视野、Tab、天气、出生/撤离、陆地判定与压力门完整通过。

P2 退出条件：沙漠不依赖战役串联也能独立完成一局；连续 3 局能出现可描述的任务/Build 差异，
且没有依靠东京湾地理或硬编码 id 才成立的逻辑。

### P3 · 海洋群岛决战独立成局

沿用同一七件套，但海洋图必须额外覆盖舰队水域、反舰目标、舰载机入场、海陆出生安全与最大海战压力。
Black Star 作为最终 BOSS 的身份可以保留，但“最终”只在战役层生效；单图 Debug 与独立局仍须可达。

P3 退出条件：海洋图连续 3 局完整通关；海战压力场 60 FPS 红线、Boss 登场到 VICTORY、Tab 水域表达
与无陆上误生全部过门。

### P4 · 三图战役串联与发布收口

只有 P1～P3 都独立成局后，才把 [three-map-campaign-continuity](../specs/systems/three-map-campaign-continuity.md)
从 draft 推到 approved，补定双队 build 快照、退出/失败、BOSS 顺延、最终会师与总时长。

P4 退出条件：从新档案开始可以完整跑完三图；跨图数据不丢、不串队、不复制奖励；每张图仍保有独立
节奏；中途退出/失败行为有明确 UI 与测试；发布导出包完成一次真实安装态通关。

## 3. 队列与 WIP 规则

- 同时最多 **1 个底层系统批 + 1 个内容批**。底层批必须由当前内容暴露的具体阻断驱动。
- 内容批固定 **3～5 项**；每项必须共享一个地图主题、任务家族或装备链。避免十几个互不相干的
  `in-progress` 横跨数周。
- `draft` 不是 backlog：有未决设计才用 draft；纯想法放本计划的候选池或专门 planning 文档。
- `approved` 表示下一步可直接执行，不再边写代码边重新发明核心规则。
- `in-progress` 表示有人正在做，或缺少该 spec 明确写为**必需**的验收门；不得只因“以后还能调”常驻。
- 每批结束先关状态、索引和证据，再开下一批。禁止把文档收尾跨批滚债。
- 每个内容批必须标记它服务 20 小时曲线的哪个时段、带来什么首次体验；连续多个批都只服务同一时段
  视为节奏失衡。

## 4. 单项流水线

1. **选槽**：从当前地图包与 20 小时曲线缺口选内容，写一句“玩家会在什么时段首次感知到什么不同”。
2. **查真源**：DESIGN_PHILOSOPHY → 对应 spec / known-seams → script-index / code-index → playbook。
3. **定 spec**：复制模板，填 §1～§5，数值/状态/生成几何/失败与清理全部写完，review 后 `approved`。
4. **派生实现**：按 §6 小步实现；共享层改动必须是可复用 seam，不加地图/模式硬分支。
5. **Debug 可达**：技能/装备/奖励分别经 F4/F6；敌人/事件/BOSS 有正式数据源驱动的直接入口。
6. **聚焦证据**：最窄 bench + 静态审计 + i18n；行为零态与激活态都要覆盖。
7. **批次证据**：集成 bench、代表性混合战场性能门、按成本形状选择的专项压力、Visual QA、至少一局真实流程。
8. **收尾**：§7 锚点、reference 索引、`_INDEX`、变更记录与状态同批关闭。

生成几何必须跟随真实遭遇权威：普通拦截压力默认从玩家前方地图边缘进入；护送/追击从任务航线、
被护送对象实时 heading 与前后关系派生；BOSS/海军按遭遇锚点和水域派生。不得把“前方扇形”硬套到
所有任务，也不得退回贴玩家坐标凭空刷新。

## 5. 证据等级与完成定义

| 等级 | 证明了什么 | 不能冒充什么 |
|---|---|---|
| E0 静态 | 资源、注册、i18n、索引、公式一致 | 运行时行为 |
| E1 聚焦 Shadow | 关键状态机/公式/回归可重复 | 视觉和完整局手感 |
| E2 集成 Shadow | 与相邻系统、CPU/状态/泄漏和专项压力兼容 | draw/GPU 与玩家实际看到的画面 |
| E3 Visual | GL Compatibility 下布局、演出、轨迹、层级、可读性及代表性 draw 负载成立 | 完整局节奏 |
| E4 Live playtest | 真实输入、完整流程、节奏和 Build 取舍成立 | 大样本平衡结论 |

三个“完成”不要混用：

- **单项完成**：spec 契约已实现，Debug 可达，所需 E0～E3 通过，状态可为 `done`；纯数值/不可见项可在
  spec 中说明为何不需要 Visual。
- **批次完成**：同批 3～5 项通过集成回归、最坏压力和至少一条真实流程；没有未登记 seam 或索引债。
- **发布就绪**：地图包通过连续 3 局 Live playtest，胜负/退出/存档/三语/导出包均走通。单个 focused
  bench 或一张截图绝不能称发布就绪。
- **节奏就绪**：功勋、解锁、机体、技能和功能在约 20 小时目标内持续提供新刺激，没有长段空窗，也没有
  把核心循环锁在前数小时之外；最终数值必须由遥测和实玩校准。

## 6. 各类内容最低门

| 类型 | 单项必须过的门 |
|---|---|
| 敌人 | 数据 spec、现实参考与游戏定位、正式池/事件归属、Debug 生成、AI/武器 focused bench、轮廓与标签 Visual、压力实例上限 |
| 技能/武器 | F4/F6 直达、正式门控仍真实触发、零层 baseline、满层/边界 bench、AI 经 effective accessor 感知、玩家可见反馈 |
| 事件/任务 | 开始/成功/失败/撤离/BOSS 闸全生命周期、遭遇几何、奖励隔离、无线电排队、跨边界释放、完整流程 Visual |
| BOSS | Registry、Debug、横幅→镜头→ENGAGED、阶段与胜利门、已释放引用、最坏 Adds 压力、被打赢/打死玩家两条实机路径 |
| 地图 | 主图/Tab 同源、出生与撤离、陆海合法性、战区与任务全路径、天气、BOSS 锚点、最大实体压力、完整局 |
| UI | 继承 UI 规范、三语/长文本/缩放、固定分辨率与极端状态 Visual；普通排版改动不另造 spec |
| 音画/表现 | 素材来源与版本、正式触发链、初/中/后期职责、变体与优先级、Build 可感知变化、混合战场 Visual/听感、性能与回退 |

性能门统一看 [performance-guidelines](../reference/performance-guidelines.md)：C1 为 36 名混合海陆空全可见战场，
涉及全局扫描/LOD 再加 C2 多战线，武器/BOSS/地图/UI 分别追加对应专项。`stress_40` 只算启动/人口冒烟，
Sentinel 只在改动真的消费其光环、护卫或 LOD 豁免时出现；任何 draw 结论必须来自 `Shadow Visual`。

## 7. 铺量阶段最终做到什么程度

本阶段不以“所有想法都实现”结束，而以以下结果结束：

- 东京湾、沙漠铁路、海洋群岛三张地图各自达到发布就绪；
- 每张图都有七件套内容身份，且共享框架里没有地图 id 特判蔓延；
- 43 机树、158 条技能作为当前基线继续做质量与闭环修补；后续扩充必须服务约 20 小时的新体验曲线、
  地图身份或明确玩法空位，不能只为数量扩张；
- 当前 4 组 BOSS 作为基线继续收口，同时为后续地图身份与长线新鲜感生产新 BOSS；新增项必须拥有
  独特机制、高难度与聪明 AI，并完整通过地图归属、演出、胜利门和最坏阶段压力验收；
- 功勋与所有解锁系统围绕约 20 小时持续内容目标完成量化和实玩校准，核心循环首局可见、进阶功能循序开放；
- 音乐、音效、机体/地图细节、战斗特效、提示语言、击杀变化与 Build 变强表现形成可持续生产线；
- 当前生产路径消费的敌人、武器、BOSS、地图与核心系统都有 reconstruction-grade spec；
- 三图串联、跨图 build/BOSS/失败边界全部定稿并验证；
- 全量文档、锚点、玩家引用持有者、i18n、focused/all/stress/Visual/导出包证据形成发布清单。

达到这条线后再评估 UGC、第四张地图或更深局外成长。更多机体、技能和渐进功能不是默认冻结项，
但必须作为 20 小时曲线或地图内容包的显式需求进入，不得成为游离于主线之外的数量工程。
