# AGL 主界面 UI 规范

> 范围：生存模式主界面，以及复用同一视觉语言的入口模式选择界面
> 状态：当前有效规则；后续讨论确认后直接更新对应章节。

## 1. 设计方向与总体布局

- 视觉方向为老式军用信息终端、军用控制台与机场起降调度系统。
- 复古感首先来自表格式信息组织、明确网格和高密度代号，而不是单纯依赖扫描线或噪点。
- 常驻信息放置在屏幕左右外围，为中央飞机操作空间让位。
- 新增信息优先插入左右网格，不得逐步侵占中央操作区域。

```text
[ 左侧表格式信息区 ] [ 中央飞机操作区 ] [ 右侧表格式信息区 ]
```

## 2. 网格单位与尺寸

主界面的功能区域使用 `u` 与 `q` 两种布局单位；仅结构对齐可以使用第 2.3 节定义的装饰半格。

### 2.1 长方形单位 `u`

```text
1u = 40 px × 18 px
```

- 功能区域的横向和纵向尺寸只能使用 `u` 的整数倍。
- 功能区域禁止 `0.5u`、`1.5u` 等小数尺寸；`0.5u` 高装饰行只按第 2.3 节处理。
- 超过单格的区域必须写成“横向 × 纵向”，例如 `1u × 2u` 表示竖向两格。
- `2u × 2u` 与 `1u × 4u` 面积相同但形状不同，不能只用总面积描述。

### 2.2 正方形单位 `q`

`q` 使用 `1u` 的高度作为正方形边长：

```text
1q = 18 px × 18 px
```

- `1q` 永远是完全正方形，不随 `u` 的宽度变化。
- 功能区域中的 `q` 横向和纵向数量只能使用整数；`0.5q` 宽装饰列只按第 2.3 节处理。
- 多格区域使用“横向 × 纵向”描述，例如 `2q × 1q` 表示由两个正方形格组成的横向区域。
- 单一连续区域允许在同一轴上使用整数 `u` 与整数 `q` 的加法组合，例如横向 `3u + 1q + 1u`、纵向 `4u`。
- 组合尺寸必须保留各段顺序，不得只写总面积；功能区域仍然禁止任何小数 `u` 或小数 `q`。

### 2.3 装饰半格

装饰半格只用于对齐和结构填充，不是第三种功能单元。

```text
0.5q 装饰列 = 9 px 宽
0.5u 装饰行 = 9 px 高
```

- `0.5q` 只描述横向装饰列；可以由用户手动添加，也可以在对齐既有面板边缘时由自动排版添加或移除。
- `0.5u` 只描述纵向装饰行；必须由用户明确手动添加，自动排版不得自行产生。
- 装饰半格不得承载功能内容，也不得用于容纳更多数字位数。
- 因最大显示字符串宽度不足而扩宽时，仍只允许使用整数 `1q`；数字扩宽 `1q` 与装饰对齐 `0.5q` 必须在声明和实现中分开计算。

## 3. 网格位置

- UI 区域可以通过固定网格位置和跨格尺寸声明。
- 坐标以所属面板或侧栏的左上角为原点，从 `1` 开始计数。
- 位置描述网格槽位，不直接描述像素坐标。
- 每个区域必须声明起始位置、横向尺寸和纵向尺寸。
- 常驻区域不得互相重叠，也不得跨入中央飞机操作区。
- 贴右侧停靠的 HUD 组必须先固定屏幕侧右边缘；因最大字符串或无法被预留空位吸收的新增按键产生的 `q` 增量一律向左扩展，不得把整组向右推离锚点。
- 同一右侧 HUD 堆栈中的不同行可以拥有不同宽度，但它们的屏幕侧右边缘必须对齐；不要求为了左边缘整齐而压缩高优先级信息。
- 为形成操作键等纵向对齐列，可以使用 `0.5q` 装饰列把较短面板补齐到选定基准行；该补齐不得改变数字占位或字号。

推荐写法：

```text
区域：left
位置：(1, 3)
尺寸：2u × 1u
```

## 4. 面板、框板与字板

| 名称 | 用途 | 描边 | 底色 |
|---|---|---|---|
| 面板 | 一片完整 UI 区域，可容纳内部区域 | 完整 `1 px` 终端绿描边 | 纯黑，`alpha = 0.70` |
| 框板 | 面板内部带边界的内容区域 | 完整 `1 px` 终端绿描边 | 无独立底色，透出面板底色 |
| 字板 | 面板内部无边界的文字区域 | 无 | 无独立底色 |

- 用户输入“面版”“框版”或“字版”时，分别按“面板”“框板”或“字板”处理。
- 描边绘制在声明尺寸内部，不增加区域占用的 `u` 尺寸。
- 字板必须包含文字；框板默认包含文字，但允许在明确声明时创建无字符内容的结构性空框板。
- 无字符的结构性区域统一称为“空框板”，不得称为“空字板”或“空文字面板”。
- 空框板可以声明为动态结构填充区；运行时插入或移除相邻功能格时，只允许它按装饰列规则增减，不得挤压已锁定尺寸的功能面板。
- 框板和字板使用所属面板的内部 `u` 网格定位。

### 共享描边坐标

- 同一条逻辑网格边界只能占用一个固定的 `1 px` 位置。
- 父面板、子面板、相邻 `u` 和相邻 `q` 的重合边界必须复用完全相同的坐标，不得在已有描边内侧或外侧继续增加另一个 `1 px`。
- 面板底色与网格描边分层绘制：内容控件不自行累加边框，统一描边层根据区域的原始网格坐标绘制边界。
- 描边不参与位置或尺寸计算；增加父面板描边不得使任何子面板发生 `1 px` 位移。
- 反色状态只能替换既有边界位置上的颜色，不得创建第二条平行边线或改变线宽。

## 5. 文字排版

### 5.1 默认对齐与裁切

- 默认文字水平居中、垂直居中；只有明确声明为“小标题行”的区域使用左对齐。
- `1u` 高且宽度大于 `1u` 本身不会自动触发左对齐；普通状态格、按钮、单位格和其它框板继续居中。
- 所有文字区域均无内边距和呼吸槽，使用所在面板、框板或字板的完整尺寸。
- 每个框板或字板独立裁切，文字不得越过自身区域或外层面板。
- 动态文字在运行时不换行、不推动边界，也不扩大所属区域；超出已声明排版基准的内容直接裁切。

### 5.2 单格短信息

- `1u × 1u` 与 `1q × 1q` 用于极短代号、单位或按键提示。
- 两者固定使用 `Silkscreen Regular`，字号为 `15 px`，并按真实字形边界居中。
- 同一组可选项属于同一信息层级时，必须使用相同尺寸和相同字号；例如 `KT` 与 `KM/H` 均使用 `1u × 1u` 居中框板。

### 5.3 小标题行

“小标题行”是局部语义类型，不是由长宽自动推导的全局规则。

- 高度固定为 `1u`，横向占满所属子面板或信息组。
- 使用框板：生成完整 `1 px` 描边，不生成独立底色。
- 文字使用 `Silkscreen Regular 15 px`，垂直居中并强制水平居左。
- HP、G、ALT、SPD、FLR 等“标题 + 大小数字”信息组使用小标题行。
- 未明确声明为小标题行的 `1u` 高长条仍遵循默认居中规则。

### 5.4 大小数字信息组

- 主要数字默认使用无描边字板，默认水平、垂直居中，并优先分配 `3u` 高度；具体字段或已命名组合模板可以明确覆写描边、分格方式与水平对齐。
- 分隔符和次级数字默认使用无描边字板；只有已命名组合模板明确声明时，分隔符才可以改用框板。
- 分隔符通常使用 `1q × 1q`；次级数字可使用 `1u × 2u` 等较小区域，以形成明确的主次字号差。
- 信息组的父面板仍保留完整外框；“字板无描边”只表示不增加内部边界，不表示删除父面板边界。
- 动态数字必须按其已知最大显示字符串预先决定字号和占位。例如 G 值按 `11.5` 排版，即使当前只显示 `4.5` 也不得临时放大。
- 未声明字号共享关系时，字号选择仍需同时满足真实可见字形高度与排版基准字符串宽度。
- 声明为同一主要字号层级的字段，先按共同目标高度确定唯一字号，再用各自最大显示字符串计算宽度；宽度不足时以整数 `1q` 向外扩展字板和所属信息组，不得缩小其中某一字段的字号。
- 右侧停靠 HUD 中的上述宽度增量只能向左生长，并保持各行右边缘不变；允许某一行比相邻行多出一个或多个 `1q`。
- 同一字段运行时保持按最大显示字符串解析出的字号；若实际内容仍超过该基准，则直接裁切，不重新排版整行。
- “小标题行 + 主要数字 + 次级数字”的层级高于父面板原有高度。空间不足时优先扩高父面板，再调整低优先级相邻区域。
- 调整后无法合理利用的格位可变为空框板，或保持未填满状态；不得为了填满整行而破坏主次层级。
- FLR 的当前实现基准为：`1u` 小标题行、两个 `1u + 0.5q` 宽且 `3u` 高的当前值数字框、无框分隔符与 `2u` 高次级数字、独立 `2u` 高星号动画区。

当前玩家仪表的最大显示字符串：

| 字段 | 排版基准 | 含义 |
|---|---|---|
| HP 当前 / 最大 | `999` | 均固定为最多三位整数 |
| G | `11.5` | 两位整数与一位小数 |
| SPD | `99999` | 固定五位分格整数；超过五位进入溢出警告 |
| ALT | `99999` | 最多五位整数 |
| FLR 当前 / 最大 | `99` | 均固定为最多两位整数 |

### 5.5 两位整数加一位小数的 4u 信息组

本模板用于 G 值，以及之后出现的“整数部分不超过两位、固定带小数点、小数部分不超过一位”的同类信息。

- 信息组总高度为 `4u`：顶部 `1u` 小标题行，下方 `3u` 为组合数字区。
- 整数部分锁定最多两位数并固定补零为两格，例如 `1` 显示为 `0 1`。每格固定宽 `1u + 0.5q`、高 `3u`，使用与 SPD 单数字格相同的 Chakra Petch Bold 固定字号、共享 `1 px` 描边并水平垂直居中。
- 小数点内容固定为 `.`：使用主要数字字体与主要数字字号；使用 `1q × 1q` 框板；放在组合数字区最底部的 `1u` 行。
- 小数部分锁定最多一位数：使用次要信息字体与次要信息字号；使用无描边 `2u` 高字板；与组合数字区底部对齐。
- 三段从左到右依次为“两个整数数字框板 → 小数点框板 → 小数字板”。整数前置补位零使用 `inactive_digit` 灰色。
- 两个整数数字格的宽度固定，不因内容扩展；小数点或小数字板若因声明的最大字符串需要扩宽，只允许使用整数 `1q`，不得使用装饰半格。
- 本模板是第 5.4 节“主要数字、分隔符默认无框”的明确局部例外，不改变其它大小数字信息组。

### 5.6 操作键

- 可操作按键固定使用独立 `1q × 1q` 框板，内部显示单个键位文字。
- 按键框板放在对应信息行左侧，并与该面板最高的 `1u` 行顶部对齐；标题或说明文字中不得重复写入键位。
- 运行中新增按键时，优先占用相邻的动态空框板并使其缩短 `1q`；已锁定尺寸的功能面板不得移动或缩放。
- 没有预留动态空框板时，才允许受影响的信息行或局部组向左增加一列 `1q`；不得移动其它行，右侧停靠边缘保持不变。
- 新出现的按键框板反色闪烁 `5 s`，相位仍每 `0.5 s` 切换一次；闪烁结束后恢复普通终端配色并常驻。

### 5.7 进度条

- 当前玩家 HUD 的横向进度模块总高度固定为 `2u`。
- 模块最右侧固定为 `2u × 2u` 百分比框板，百分比按次要信息规则并水平居右；其右边缘与所属 HUD 堆栈右边缘对齐。
- 剩余左侧区域的上方 `1u` 是标题框板，文字居左；下方 `1u` 是进度条框板。
- 进度条内部禁止出现任何文字；进度条填充在自身区域内预留透明的向内 `4 px` 边界，不覆盖共享 `1 px` 描边。
- 进度模块可以不填满其它行的宽度，但不得压缩标题、主要数字或次级数字的既定区域。
- 竖向进度条如另行声明，必须占用至少 `1q` 宽的独立区域。

### 5.8 通用字号规范

- 除固定 `15 px` 的单格短信息和小标题行外，字号以完整字符串塑形后的真实可见字形轮廓计算。
- 默认选择同时满足“可见字形高度不超过区域高度”和“排版基准字符串宽度不超过区域宽度”的最大整数字号。
- 声明为共享主要字号的字段改为高度优先：先由目标高度与代表字形确定共同整数字号，再调用 `1q` 步进扩宽规则容纳各字段的最大字符串。SPD、G 整数格与 FLR 当前值格是已命名例外：三者固定共用按单字 `0` 适配 `49 × 54 px` 得到的字号，不再按整串文字重新计算。
- 使用同一轮廓边界校正基线，使最终字形上下视觉居中。
- 超过 `1u` 面积的主要数字默认使用 `Chakra Petch Bold`；次要层级可明确使用 Medium 或 Light。
- `TerminalText` 是“通用字号规范”的唯一代码入口，统一提供水平对齐、最大显示字符串、固定字号、宽高约束和真实字形基线。
- 调用方不得复制另一套 TextServer 字形测量或字号搜索算法；完整字符串必须先经 TextServer 塑形，再读取最终 glyph 的真实轮廓边界。
- `font.get_height()` 与 `font.get_ascent()` 仅作为无法取得可见轮廓时的回退，不作为正常大字的撑高依据。

基线计算：

```text
baseline_y = (区域高度 - ink_height) / 2 - ink_top
```

### 5.9 五位分格速度读数

- SPD 当前值固定由五个从左到右排列的单数字框板组成；运行时不得改变格数或倒序显示。
- 每个数字框板固定宽 `1u + 0.5q = 49 px`、高 `3u = 54 px`，生成完整共享 `1 px` 描边。
- 五格合计显示当前所选单位下的正确整数速度，并使用左侧补零。例如 `500 kt` 固定显示为 `0 0 5 0 0`。
- 每格只容纳一位 Chakra Petch Bold 数字；五格共用同一字号，按最宽数字 `0` 在 `49 × 54 px` 内完整可见的最大整数字号计算，字形水平、垂直居中并尽量顶满高度。
- 首个有效非零数字之前的补位 `0` 是无效数值，使用 `75%` 黑度灰 `#404040`；有效数字之后的 `0` 仍属于真实速度，使用当前 HUD 强调色。
- 数值为 `0` 时，最右一位 `0` 视为有效数字，前四位为灰色补位零。
- 实际整数速度超过五位时，不裁切原值，也不扩宽面板；五格统一显示红色 `9 9 9 9 9`，并按 `0.5 s` 相位在红字与不可见之间持续闪烁。
- 本节是“数字位数不足时只按整数 `1q` 扩宽”规则的命名例外：SPD 的五个固定框板本身包含声明过的 `0.5q` 宽度，不得继续因数值位数扩宽。

## 6. 字体

| 字体 | 用途 | 渲染规则 |
|---|---|---|
| Silkscreen Regular | `1u × 1u`、`1q × 1q` 极短信息，小标题行 | 关闭抗锯齿、次像素定位、MSDF、mipmap；最近邻过滤 |
| Chakra Petch Bold | 多格区域的主要数字 | 按真实字形轮廓自动撑高 |
| Chakra Petch Medium | 中等强调层级 | 按真实字形轮廓自动撑高 |
| Chakra Petch Light | 低强调层级 | 按真实字形轮廓自动撑高 |

字体缺失字符允许回退至系统字体。字体与许可证存放在 `resources/fonts/`。

## 7. 颜色

本节是主界面颜色代码的唯一规范入口。具体控件不得散落近似色硬编码。

| 语义名称 | 用途 | HEX / Alpha | RGBA |
|---|---|---|---|
| `block_background` | 默认面板底色 | `#000000` / `0.70` | `rgba(0, 0, 0, 0.70)` |
| `terminal_green` | 默认描边、文字、激活状态与玩家 HUD 默认强调色 | `#00FF41` / `1.00` | `rgba(0, 255, 65, 1.00)` |
| `terminal_inverse` | 反色文字与描边 | `#000000` / `1.00` | `rgba(0, 0, 0, 1.00)` |
| `inactive_digit` | SPD 前置补位零 | `#404040` / `1.00` | `rgba(64, 64, 64, 1.00)` |

玩家 HUD 在没有保存设置时使用 `terminal_green`；用户选择其它 HUD 色后，由持久化设置覆盖描边、文字、星号和激活状态，但不改变 `block_background`。未来的主题切换应修改这些语义颜色映射，而不是逐个修改控件。

## 8. 反色闪烁

- 面板、框板和字板可用反色闪烁表达警告、选中或高优先级信息。
- 普通相位使用终端绿文字与描边，并保留区域原本底色。
- 反色相位使用终端绿实心底色、纯黑文字和纯黑描边。
- 默认每 `0.5 s` 切换一次相位。
- 闪烁只改变颜色，不改变尺寸、字号、位置或裁切范围。
- 闪烁时钟独立于数据刷新时钟。
- 运行时新出现的操作键使用第 5.6 节规定的 `5 s` 有限闪烁，不改变普通警告与状态的持续闪烁语义。

### 8.1 默认武器模块

- 默认武器模块固定保留 `MSL` 与 `GUN` 两个武器面板，每个面板高 `2u`。
- 武器模块与正上方信息行之间必须手动插入一条 `0.5u = 9 px` 无字符装饰框板；它拥有完整共享 `1 px` 描边，不承载文字或按键。
- 装饰框板下方先放置独立的 `1u` 武器优先标题面板，当前英文显示为 `PRIORITY WEAPON`；标题使用小标题行规则。`T` 键使用独立 `1q` 框板并吸附标题左侧，不得吸附装饰框板。
- `MSL` 与 `GUN` 两个面板之间再插入一条同宽、同样有完整描边的 `0.5u` 无字符装饰框板。
- 每个武器面板左侧是 `2u` 高弹量框板，使用 Chakra Petch Bold 次要数字规则并水平居左；按最大四位整数 `9999` 预留宽度。原弹量上方的 `1u PRIORITY` 子格及其文字已废弃，不得保留空占位或隐形语义。
- 弹量框与右侧功能区之间的剩余宽度使用可伸缩无字符空框板填充。
- 每个武器面板最右侧固定为 `2u × 2u` 名称框板，显示 `MSL` 或 `GUN`；使用 Chakra Petch Bold 次要信息层级、完整字符优先并水平垂直居中。
- 名称框左侧紧贴一条 `1q × 2u` 竖向装填进度框板；再向左紧贴一个 `0.5q × 2u` 无字符空框板。三者共享同一组边界坐标，不允许额外插入九格或其它指示器。
- 竖向装填条与横向进度条共用 `4 px` 透明内缩规则；装填时按实际进度从下向上填充，并以 `2 Hz` 在可见与熄灭之间闪烁。它不反相、不显示文字、百分比或比例色阶。
- 被选为武器优先时，对应弹量框和名称框同时持续反色；该状态表示玩家偏好，不表示当前帧实际开火武器。
- 被选中的武器正在装填时，弹量框和名称框与竖向进度条同步以 `2 Hz` 闪烁：数值框在普通与反色之间切换，进度条在可见与熄灭之间切换。未选中武器不得因自身装填而反相。
- 九格指示灯及其选中常亮、顺时针循环和切换复位语义全部废弃，后续排版不得自动恢复。
- 武器缺失时仍保留该行高度、装饰框、空框板与共享边界，但弹量、名称和装填内容透明。

## 9. HUD 刷新频率

| 层级 | 频率 | 内容 |
|---|---|---|
| 信息读数 | 每 `0.5 s`（`2 Hz`） | HP、时间、击杀、经验、飞机/小队/BOSS/王牌状态 |
| 实时操作 | 逐帧 | 加力反馈、战术按钮、雷达、准星及连续操控信息 |
| 事件 | 事件发生时立即更新 | 击杀信息与按键交互 |
| 动画 | 独立时钟 | 反色闪烁与信息淡出 |

HUD 创建后立即执行第一次信息刷新，随后进入 `0.5 s` 周期。

## 10. UI Dev 定位面板

- 生存模式游戏内按 `F7` 显示或隐藏 UI Dev 定位覆盖层；`F6` 继续专用于战区 Debug 面板。
- Boss Debug 模式原有的玩家无敌切换改为 `Shift+F7`，避免占用普通 `F7`。
- 定位层直接读取当前正式玩家仪表、实际僚机行、三轴计数器和经验条，不复制一套仅供预览的排版。
- `scenes/tests/ui_dev_panel.tscn` 仅作为固定数据截图回归场景，正式调试入口仍是游戏内 `F7`。
- 定位层开启后提供 `DEV + MANUAL FLR [R]` 测试按钮；它只在 Debug 覆盖层中授予手动 FLR 技能，用于验证运行时 `1q` 按键占用动态空框板与 `5 s` 反色闪烁，不属于正式战斗操作 UI。
- 所有诊断标记位于独立覆盖层，不修改正式 HUD 的尺寸、绿色共享边线或输入行为。
- 自动排版区域使用向内绘制的 `2 px` 紫色描边，因此诊断框本身不增加面板占地。
- 编号只表示矩形位置，不表示 HP、SPD、武器等功能。
- 顶层区域按“从上到下、同一高度从左到右”依次使用 `A` 至 `Z`；超过 26 个时继续使用 `AA`。
- 顶层中的所有可编辑子框压成单层稳定序号，例如 `A1`、`A2`，不继续生成过长的功能层级编号。
- 大于 `1u` 的自动排版面板，以及独立声明的 `1u`、`1q` 面板均进入定位覆盖层；重复矩形只生成一个编号。
- 代号使用黑底紫字，放在对应紫框内部右上角；小格会自动缩小字号，但不改变代号。

## 11. 入口模式选择界面

- 入口主菜单复用本规范的 `u/q`、70% 黑底、共享 `1 px` 描边、终端字体和 HUD 强调色；不复制另一套近似绿色或圆角卡片样式。
- 终端内容固定为 `23u × 30u = 920 × 540 px`，置于 `1000 × 576 px` 的 CRT 玻璃内；四周分别保留 `1u` 横向与 `1u` 纵向安全显示边界，凸面畸变不得裁掉功能文字。
- 顶部识别仪表固定为 `23u × 6u`：第一行是全宽识别条；下方左侧 `15u × 5u` 为 Chakra Petch Bold 主标题，中间为 `4u` 宽功勋读数，右侧为 `4u` 宽访问状态反色块。
- 中段固定为 `23u × 21u`：左侧 `15u × 21u` 是模式台，右侧 `8u × 21u` 是航路示意和终端设置；底部 `23u × 3u` 为系统记录。
- 模式台顶部为 `15u × 1u` 小标题，下面五条模式行各占 `15u × 4u`。每行从左到右固定为 `2u × 4u` 两位序号、`11u × 1u` 模式名、`11u × 3u` 模式说明和 `2u × 4u` 状态格。
- 键盘焦点或鼠标悬停只反色当前行的序号格与状态格，不改变任何尺寸、字号或行位置；不可用模式使用 `inactive_digit` 灰色且不能取得焦点。
- 右侧终端按“`1u` 航路标题 / `11u` 静态航路图 / `1u` 设置标题 / 四条 `2u` 控制行”排列；语言、音频、速度单位、HUD 色、删档与沙盒入口都不得悬浮在机壳外。
- Y2K 显示器机壳、屏幕压边、通风槽和紧固件属于静态物理层，只绘制一次；CRT shader 只覆盖内屏，提供凸面畸变、圆角玻璃遮罩、扫描线、荧光晕、暗角、轻噪声和滚动亮带，不扭曲机壳。
- CRT 动画使用 shader `TIME`，不得为主菜单重新加入逐帧 `_process → queue_redraw()`；航路示意也只在 HUD 强调色变化时重绘。
- HUD 色设置保存后，标题、模式板、右侧终端与航路示意在当前界面立即刷新为同一强调色；CRT 只处理亮度和玻璃质感，不强制把自定义强调色改回绿色。
