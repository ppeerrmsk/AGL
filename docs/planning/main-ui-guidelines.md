# AGL 主界面 UI 规范

> 范围：生存模式主界面
> 状态：当前有效规则；后续讨论确认后直接更新对应章节。

## 1. 设计方向与总体布局

- 视觉方向为老式军用信息终端、军用控制台与机场起降调度系统。
- 复古感首先来自表格式信息组织、明确网格和高密度代号，而不是单纯依赖扫描线或噪点。
- 常驻信息放置在屏幕左右外围，为中央飞机操作空间让位。
- 新增信息优先插入左右网格，不得逐步侵占中央操作区域。

```text
[ 左侧表格式信息区 ] [ 中央飞机操作区 ] [ 右侧表格式信息区 ]
```

## 2. 网格单位与尺寸

主界面目前使用 `u` 与 `q` 两种布局单位。

### 2.1 长方形单位 `u`

```text
1u = 40 px × 18 px
```

- 横向和纵向尺寸只能使用 `u` 的整数倍。
- 禁止 `0.5u`、`1.5u` 等小数尺寸。
- 超过单格的区域必须写成“横向 × 纵向”，例如 `1u × 2u` 表示竖向两格。
- `2u × 2u` 与 `1u × 4u` 面积相同但形状不同，不能只用总面积描述。

### 2.2 正方形单位 `q`

`q` 使用 `1u` 的高度作为正方形边长：

```text
1q = 18 px × 18 px
```

- `1q` 永远是完全正方形，不随 `u` 的宽度变化。
- `q` 的横向和纵向数量只能使用整数，禁止 `0.5q`、`1.5q` 等小数。
- 多格区域使用“横向 × 纵向”描述，例如 `2q × 1q` 表示由两个正方形格组成的横向区域。
- 单一连续区域允许在同一轴上使用整数 `u` 与整数 `q` 的加法组合，例如横向 `3u + 1q + 1u`、纵向 `4u`。
- 组合尺寸必须保留各段顺序，不得只写总面积；仍然禁止任何小数 `u` 或小数 `q`。

## 3. 网格位置

- UI 区域可以通过固定网格位置和跨格尺寸声明。
- 坐标以所属面板或侧栏的左上角为原点，从 `1` 开始计数。
- 位置描述网格槽位，不直接描述像素坐标。
- 每个区域必须声明起始位置、横向尺寸和纵向尺寸。
- 常驻区域不得互相重叠，也不得跨入中央飞机操作区。
- 贴右侧停靠的 HUD 组必须先固定屏幕侧右边缘；因最大字符串或新增按键产生的 `q` 增量一律向左扩展，不得把整组向右推离锚点。
- 同一右侧 HUD 堆栈中的不同行可以拥有不同宽度，但它们的屏幕侧右边缘必须对齐；不要求为了左边缘整齐而压缩高优先级信息。

推荐写法：

```text
区域：left
位置：(1, 3)
尺寸：2u × 1u
```

## 4. 面板、框板与字板

| 名称 | 用途 | 描边 | 底色 |
|---|---|---|---|
| 面板 | 一片完整 UI 区域，可容纳内部区域 | 完整 `1 px` 终端绿描边 | 纯黑，`alpha = 0.70` |
| 框板 | 面板内部带边界的内容区域 | 完整 `1 px` 终端绿描边 | 无独立底色，透出面板底色 |
| 字板 | 面板内部无边界的文字区域 | 无 | 无独立底色 |

- 用户输入“面版”“框版”或“字版”时，分别按“面板”“框板”或“字板”处理。
- 描边绘制在声明尺寸内部，不增加区域占用的 `u` 尺寸。
- 字板必须包含文字；框板默认包含文字，但允许在明确声明时创建无字符内容的结构性空框板。
- 无字符的结构性区域统一称为“空框板”，不得称为“空字板”或“空文字面板”。
- 框板和字板使用所属面板的内部 `u` 网格定位。

### 共享描边坐标

- 同一条逻辑网格边界只能占用一个固定的 `1 px` 位置。
- 父面板、子面板、相邻 `u` 和相邻 `q` 的重合边界必须复用完全相同的坐标，不得在已有描边内侧或外侧继续增加另一个 `1 px`。
- 面板底色与网格描边分层绘制：内容控件不自行累加边框，统一描边层根据区域的原始网格坐标绘制边界。
- 描边不参与位置或尺寸计算；增加父面板描边不得使任何子面板发生 `1 px` 位移。
- 反色状态只能替换既有边界位置上的颜色，不得创建第二条平行边线或改变线宽。

## 5. 文字排版

### 5.1 默认对齐与裁切

- 默认文字水平居中、垂直居中；只有明确声明为“小标题行”的区域使用左对齐。
- `1u` 高且宽度大于 `1u` 本身不会自动触发左对齐；普通状态格、按钮、单位格和其它框板继续居中。
- 所有文字区域均无内边距和呼吸槽，使用所在面板、框板或字板的完整尺寸。
- 每个框板或字板独立裁切，文字不得越过自身区域或外层面板。
- 动态文字在运行时不换行、不推动边界，也不扩大所属区域；超出已声明排版基准的内容直接裁切。

### 5.2 单格短信息

- `1u × 1u` 与 `1q × 1q` 用于极短代号、单位或按键提示。
- 两者固定使用 `Silkscreen Regular`，字号为 `15 px`，并按真实字形边界居中。
- 同一组可选项属于同一信息层级时，必须使用相同尺寸和相同字号；例如 `KT` 与 `KM/H` 均使用 `1u × 1u` 居中框板。

### 5.3 小标题行

“小标题行”是局部语义类型，不是由长宽自动推导的全局规则。

- 高度固定为 `1u`，横向占满所属子面板或信息组。
- 使用框板：生成完整 `1 px` 描边，不生成独立底色。
- 文字使用 `Silkscreen Regular 15 px`，垂直居中并强制水平居左。
- HP、G、ALT、SPD、FLR 等“标题 + 大小数字”信息组使用小标题行。
- 未明确声明为小标题行的 `1u` 高长条仍遵循默认居中规则。

### 5.4 大小数字信息组

- 主要数字使用无描边字板，默认水平、垂直居中，并优先分配 `3u` 高度；具体字段可以明确覆写水平对齐，例如当前玩家 HUD 的 SPD 主数字使用左对齐。
- 分隔符和次级数字均使用无描边字板，不得为它们单独生成框线。
- 分隔符通常使用 `1q × 1q`；次级数字可使用 `1u × 2u` 等较小区域，以形成明确的主次字号差。
- 信息组的父面板仍保留完整外框；“字板无描边”只表示不增加内部边界，不表示删除父面板边界。
- 动态数字必须按其已知最大显示字符串预先决定字号和占位。例如 G 值按 `11.5` 排版，即使当前只显示 `4.5` 也不得临时放大。
- 未声明字号共享关系时，字号选择仍需同时满足真实可见字形高度与排版基准字符串宽度。
- 声明为同一主要字号层级的字段，先按共同目标高度确定唯一字号，再用各自最大显示字符串计算宽度；宽度不足时以整数 `1q` 向外扩展字板和所属信息组，不得缩小其中某一字段的字号。
- 右侧停靠 HUD 中的上述宽度增量只能向左生长，并保持各行右边缘不变；允许某一行比相邻行多出一个或多个 `1q`。
- 同一字段运行时保持按最大显示字符串解析出的字号；若实际内容仍超过该基准，则直接裁切，不重新排版整行。
- “小标题行 + 主要数字 + 次级数字”的层级高于父面板原有高度。空间不足时优先扩高父面板，再调整低优先级相邻区域。
- 调整后无法合理利用的格位可变为空框板，或保持未填满状态；不得为了填满整行而破坏主次层级。
- FLR 的当前实现基准为：`1u` 小标题行、`3u` 高主要数字区、无框分隔符与 `2u` 高次级数字、独立 `2u` 高星号动画区。

当前玩家仪表的最大显示字符串：

| 字段 | 排版基准 | 含义 |
|---|---|---|
| HP 当前 / 最大 | `999` | 均固定为最多三位整数 |
| G | `11.5` | 两位整数与一位小数 |
| SPD | `9999` | 最多四位整数 |
| ALT | `99999` | 最多五位整数 |
| FLR 当前 / 最大 | `99` | 均固定为最多两位整数 |

### 5.5 操作键

- 可操作按键固定使用独立 `1q × 1q` 框板，内部显示单个键位文字。
- 按键框板放在对应信息行左侧，并与该面板最高的 `1u` 行顶部对齐；标题或说明文字中不得重复写入键位。
- 运行中新增按键时，只为受影响的信息行或局部组向左挤开一列 `1q`，不得移动其它行；右侧停靠边缘保持不变。
- 新出现的按键框板反色闪烁 `5 s`，相位仍每 `0.5 s` 切换一次；闪烁结束后恢复普通终端配色并常驻。

### 5.6 进度条

- 当前玩家 HUD 的横向进度模块总高度固定为 `2u`。
- 模块最右侧固定为 `2u × 2u` 百分比框板，百分比按次要信息规则并水平居右；其右边缘与所属 HUD 堆栈右边缘对齐。
- 剩余左侧区域的上方 `1u` 是标题框板，文字居左；下方 `1u` 是进度条框板。
- 进度条内部禁止出现任何文字；进度条填充在自身区域内预留透明的向内 `1 px` 边界，不覆盖共享描边。
- 进度模块可以不填满其它行的宽度，但不得压缩标题、主要数字或次级数字的既定区域。
- 竖向进度条如另行声明，必须占用至少 `1q` 宽的独立区域。

### 5.7 通用字号规范

- 除固定 `15 px` 的单格短信息和小标题行外，字号以完整字符串塑形后的真实可见字形轮廓计算。
- 默认选择同时满足“可见字形高度不超过区域高度”和“排版基准字符串宽度不超过区域宽度”的最大整数字号。
- 声明为共享主要字号的字段改为高度优先：先由目标高度与代表字形确定共同整数字号，再调用 `1q` 步进扩宽规则容纳各字段的最大字符串。
- 使用同一轮廓边界校正基线，使最终字形上下视觉居中。
- 超过 `1u` 面积的主要数字默认使用 `Chakra Petch Bold`；次要层级可明确使用 Medium 或 Light。
- `TerminalText` 是“通用字号规范”的唯一代码入口，统一提供水平对齐、最大显示字符串、固定字号、宽高约束和真实字形基线。
- 调用方不得复制另一套 TextServer 字形测量或字号搜索算法；完整字符串必须先经 TextServer 塑形，再读取最终 glyph 的真实轮廓边界。
- `font.get_height()` 与 `font.get_ascent()` 仅作为无法取得可见轮廓时的回退，不作为正常大字的撑高依据。

基线计算：

```text
baseline_y = (区域高度 - ink_height) / 2 - ink_top
```

## 6. 字体

| 字体 | 用途 | 渲染规则 |
|---|---|---|
| Silkscreen Regular | `1u × 1u`、`1q × 1q` 极短信息，小标题行 | 关闭抗锯齿、次像素定位、MSDF、mipmap；最近邻过滤 |
| Chakra Petch Bold | 多格区域的主要数字 | 按真实字形轮廓自动撑高 |
| Chakra Petch Medium | 中等强调层级 | 按真实字形轮廓自动撑高 |
| Chakra Petch Light | 低强调层级 | 按真实字形轮廓自动撑高 |

字体缺失字符允许回退至系统字体。字体与许可证存放在 `resources/fonts/`。

## 7. 颜色

本节是主界面颜色代码的唯一规范入口。具体控件不得散落近似色硬编码。

| 语义名称 | 用途 | HEX / Alpha | RGBA |
|---|---|---|---|
| `block_background` | 默认面板底色 | `#000000` / `0.70` | `rgba(0, 0, 0, 0.70)` |
| `terminal_green` | 默认描边、文字、激活状态与玩家 HUD 默认强调色 | `#00FF41` / `1.00` | `rgba(0, 255, 65, 1.00)` |
| `terminal_inverse` | 反色文字与描边 | `#000000` / `1.00` | `rgba(0, 0, 0, 1.00)` |

玩家 HUD 在没有保存设置时使用 `terminal_green`；用户选择其它 HUD 色后，由持久化设置覆盖描边、文字、星号和激活状态，但不改变 `block_background`。未来的主题切换应修改这些语义颜色映射，而不是逐个修改控件。

## 8. 反色闪烁

- 面板、框板和字板可用反色闪烁表达警告、选中或高优先级信息。
- 普通相位使用终端绿文字与描边，并保留区域原本底色。
- 反色相位使用终端绿实心底色、纯黑文字和纯黑描边。
- 默认每 `0.5 s` 切换一次相位。
- 闪烁只改变颜色，不改变尺寸、字号、位置或裁切范围。
- 闪烁时钟独立于数据刷新时钟。
- 运行时新出现的操作键使用第 5.5 节规定的 `5 s` 有限闪烁，不改变普通警告与状态的持续闪烁语义。

## 9. HUD 刷新频率

| 层级 | 频率 | 内容 |
|---|---|---|
| 信息读数 | 每 `0.5 s`（`2 Hz`） | HP、时间、击杀、经验、飞机/小队/BOSS/王牌状态 |
| 实时操作 | 逐帧 | 加力反馈、战术按钮、雷达、准星及连续操控信息 |
| 事件 | 事件发生时立即更新 | 击杀信息与按键交互 |
| 动画 | 独立时钟 | 反色闪烁与信息淡出 |

HUD 创建后立即执行第一次信息刷新，随后进入 `0.5 s` 周期。

## 10. UI Dev 定位面板

- 生存模式游戏内按 `F7` 显示或隐藏 UI Dev 定位覆盖层；`F6` 继续专用于战区 Debug 面板。
- Boss Debug 模式原有的玩家无敌切换改为 `Shift+F7`，避免占用普通 `F7`。
- 定位层直接读取当前正式玩家仪表、实际僚机行、三轴计数器和经验条，不复制一套仅供预览的排版。
- `scenes/tests/ui_dev_panel.tscn` 仅作为固定数据截图回归场景，正式调试入口仍是游戏内 `F7`。
- 定位层开启后提供 `DEV + MANUAL FLR [R]` 测试按钮；它只在 Debug 覆盖层中授予手动 FLR 技能，用于验证运行时 `1q` 按键插列与 `5 s` 反色闪烁，不属于正式战斗操作 UI。
- 所有诊断标记位于独立覆盖层，不修改正式 HUD 的尺寸、绿色共享边线或输入行为。
- 自动排版区域使用向内绘制的 `2 px` 紫色描边，因此诊断框本身不增加面板占地。
- 编号只表示矩形位置，不表示 HP、SPD、武器等功能。
- 顶层区域按“从上到下、同一高度从左到右”依次使用 `A` 至 `Z`；超过 26 个时继续使用 `AA`。
- 顶层中的所有可编辑子框压成单层稳定序号，例如 `A1`、`A2`，不继续生成过长的功能层级编号。
- 大于 `1u` 的自动排版面板，以及独立声明的 `1u`、`1q` 面板均进入定位覆盖层；重复矩形只生成一个编号。
- 代号使用黑底紫字，放在对应紫框内部右上角；小格会自动缩小字号，但不改变代号。

## 维护原则

- 本文档只保留当前有效规则，不记录已经废弃的实验参数和逐次调整历史。
- 新规则确认后直接修改对应章节；历史变化由版本控制记录。
