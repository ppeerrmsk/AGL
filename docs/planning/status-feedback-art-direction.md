# 状态与强化反馈：仪表式 Y2K 方向提案

日期：2026-09-27。状态：**设计草案，待选择；没有实施新特效**。
沿用 [UI 设计规范](../specs/systems/ui-design-guidelines.md) 与
[设计哲学](../DESIGN_PHILOSOPHY.md)，本文是本次美术方案比较，不建立第二套 UI 通用规范。

## 目标与参考解读

让玩家不盯小字也能察觉“刚触发、仍有效、已经结束”，再通过短标签确认具体状态。
参考来自本次用户提供的三张图：球形坐标仪、气象探空分析屏、航管雷达屏。
取它们的黑底、稀疏高亮信号、细线刻度、短代号、连接关系与局部数据密度；
不复制整屏图表密度、细小难读文字或与战斗无关的坐标装饰。

这里的 Y2K 偏向世纪之交的技术终端：有明确用途的几何标记、硬边色块与信号读数。
保持飞机剪影、弹道和选中/锁定符号的优先级。避免彩色烟雾、魔法环、粒子喷泉、
全机发光、厚重辉光、持续色罩及全屏故障抖动；复古感不依赖扫描线与噪点。

## 三种方案

下列尺寸/时长是用于首轮试样的候选值，尚未批准为正式表现合同。

| 方案 | 激活瞬间 | 持续期间与结束 | 适用性与代价 |
|---|---|---|---|
| A：状态栏信号行 | 对应状态行局部反色两次，每相位 0.15 秒 | 保持一小段实色前缀与英文短名、现有剩余百分比；结束后移除，不留空槽 | 最稳妥；可清楚识别多状态，远离视线时察觉较弱 |
| B：机体仪表标记 | 机体外侧的短平行刻线快速点亮，0.2 秒完成 | 机体外侧保留最多两组短线，不闭合为光环；结束直接熄灭 | 视线留在飞机也能识别；要验证与选中、雷达锁定、弹道的辨识度 |
| C：屏幕边缘信号 | 左右外围各一段细色线向内推进 8 px 后退回，整个动作 0.35 秒 | 不维持全屏遮罩；持续状态交给 A/B；结束只撤去 A/B | 激活最显著，适合关键模式；高频触发必须合并，避免屏幕一直闪 |

**推荐 A + B；C 只给关键强化首次激活。** 常驻效果只改变局部区域，
启动时用短促变化吸引注意，之后静止或缓慢变化，给实战弹道留出视觉带宽。
不建议让整个状态栏随 buff 换色：蓝白阵营识别与受伤反相已有稳定含义。
方案 A 仅作用于状态行，身份、HP 和基础数据区保持当前语义。

## 词条映射试样

颜色首先复用当前 `StatusEffects.icon_color`，不在本提案里另定一套 RGB。
每个状态同时提供代号与几何形状，颜色辨认困难时仍可读。

| 当前状态/增强 | 状态行 | 飞机周围候选表现 | 屏幕边缘候选 |
|---|---|---|---|
| OVERLOAD | 橙色 `OVRLD` | 机体两侧各三根短刻线，如仪表进入高输出档 | 首次进入时一次橙色边线 |
| BLOODLUST | 现有红色 `FRENZY` | 两侧各两根向前错位的斜短线，强调攻击状态；不染红机身 | 默认关闭，避免与受击警报冲突 |
| INVINCIBLE | 金色 `INVUL` | 左右各一条端部封口的短直线，表现防护有效；不使用泡泡盾 | 一次金色边线，可作为 C 的对照样张 |
| STEALTH | 浅蓝 `STLTH` | 延续现有透明机体；两侧虚线短刻度，避免在敌方不可见时泄露轮廓 | 默认关闭 |
| 加力 | 青色 `AB` | 优先沿用真实尾焰/尾迹增强；不重复叠新环 | 默认关闭 |
| FEAR / JAM / SLOW | 保留 `FEAR` / `JAM` / `SLOW` 及当前颜色 | 玩家受影响时分别试缺口刻线、断续短线、后置刻线；不让整屏抖动 | 默认关闭；异常与强化分开验收 |
| 永久强化 | 不把所有已学技能都常驻塞进状态栏 | 优先通过挂载、真实武器弹道、机动与命中反馈体现；只有触发条件成立才显示状态标记 | 获得强化时由升级界面反馈，持续期间关闭 |

几何只标识状态，不表示真实射程或方向，不得使用会被误认成锁定框的四角括号、
瞄准十字或闭合扫描圆。所有效果为显示，不影响 AI、伤害、机动或状态持续时间。

## 同时生效、刷新与切控

- 状态行保留所有真实有效状态，顺序复用现有 DISPLAY_ORDER；不是只显示最后一个 buff。
- 机体几何最多同时两组。候选优先级：失控/干扰等负面状态 → 无敌 → 超载 → 嗜血 → 隐身；
  其它状态仍能从状态行读取。AB 的已有尾焰不参与此槽位竞争。
- 屏幕边缘只属于当前操控机。同一时间只播一条，候选优先级为 INVUL 高于 OVRLD。
  1 秒内重复进入/刷新合并；延长状态不重播激活动画，避免云内超载等刷新源持续闪屏。
- 切控直接显示新机的当前状态，不伪造一次“新触发”；旧机屏幕边缘动画立即撤销。
- 暂停冻结动画；状态移除、死亡、场景退出清理标记。拒绝、免疫与零效果不播放。
- 保留现有伤害反相的更高优先级：受伤时状态行跟随受伤相位，结束后恢复状态色。
- 持续时间只来自真实状态源；无固定时长的模式显示代号，不伪造百分比。
- 低动态选项候选：关闭 C、把 A 激活闪烁改为一次固定高亮、B 保留静态形状。

## 实施与验收建议

1. 先在同一真实战斗帧制作 A、A+B、A+B+C 对照，覆盖默认白色 HUD、其它主题、三张地图及近远镜头。
2. 先选 OVERLOAD 与 INVINCIBLE 做最小试样，再测 FRENZY 与受伤重叠；不一次铺开所有词条。
3. 激活 1 秒内能察觉；移开视线后仍可认出持续状态；结束后无残影。
   测两种强化叠加、负面与强化叠加、快速刷新、免疫、切控、死亡及暂停。
4. 世界状态栏沿用唯一屏幕空间覆盖层。动画时钟不提高普通信息轮询频率；
   机体周围标记按变化刷新，不为每架飞机添加常驻处理节点；边缘效果全局单实例。
5. 先 focused，再默认 all；运行真实 GL Compatibility 混合海陆空 36 单位 Visual，
   必须包括同时激活的状态、真实战斗与镜头巡检，分别报告平均 FPS、最差帧、frames_below_60。
   Headless 不能代表画面或性能通过。未达 60 FPS 硬线不能通过移除战斗内容掩盖。

## 本次遗留显示修复（独立于提案）

旧 `draw_status_icons` 仍被普通地面、AA、SAM、空爆 AA、战略目标与舰船调用，
为所有定时状态绘制本地化文字和彩色填充进度条；雷达站则没有相同调用。
统一在共享信息牌提交入口为非飞机 CombatUnit 追加英文状态行与百分比，
复用飞机的显示顺序、颜色与定时数据；完整/折叠档都保留状态。
旧入口仅保留既有 DEADAIR 暴露环。没有新增常驻 tick、单位子节点或独立状态条。
本修复不把“状态被记录”扩展为新的地面 buff 机制。

修复验证（2026-09-27）：`presentation 1 180 Shadow Headless` 400/400；
`all 1 300 Shadow Headless` 101 组通过，LifecycleGauntlet 90/90；
`unit_status_label_visual 1 120 Shadow Visual` 退出 0，已人工查看完整与 0.30× 折叠截图。
AA/SAM/Radar 的 FEAR/JAM/SLOW 与舰船允许的 JAM 均进入正式信息牌，无旧填充条。
截图在 `bench/results/unit_status_label_visual.png` 与
`bench/results/unit_status_label_visual_compact.png`，本地日志在 `tmp/status-*.log`。
本次以文字行替代旧条绘制，没有新增常驻 tick/draw/实体；按性能守则 R7 的替换范围
执行静态、focused、all 与 Visual，不据此声明整局性能或新特效已验收。
