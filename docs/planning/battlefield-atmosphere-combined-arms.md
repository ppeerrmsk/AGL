# 战区战场气氛强化：多兵种自主交战调查

> 状态：**历史设计调查 / 非 SSOT**；当前实现以 [`docs/specs/systems/battlefield-atmosphere-experiment.md`](../specs/systems/battlefield-atmosphere-experiment.md) v4 为准，跨电脑续作见 [`battlefield-atmosphere-handoff.md`](battlefield-atmosphere-handoff.md)。
> 日期：2026-08-08
> 目的：调查轰炸机、旋翼机、地面火炮与舰船如何沿任务轨道移动并发生可读的自主交战，形成“战场在玩家之外也运转”的氛围。
> 权威边界：本文只保留早期调查、推荐方向、风险和拆分顺序；其中鱼雷、低命中率舰炮等旧提案均已被 v4 spec 取代。

## 0. 先给结论

这批需求不应该做成四套彼此独立的 AI，也不应该把所有单位放进全场自由混战。推荐建立一层轻量的**战场交战编排**：

1. 生存模式事件层创建一对有明确交战关系的编组；
2. 复用 `AIDirective` 的 `FOLLOW_PATH / PATROL_RING / HOLD_POSITION` 作为跨平台轨道语言；
3. 用一个编组级控制器低频分配目标，单位本身只消费目标并执行平台专属武器；
4. 交战默认只发生在同一个 `engagement_id` 内，不得越过地图牵动其它战区；
5. 轰炸机保留一次攻击跑，直升机保留平移/环绕，火炮保留间接弹道，舰船保留炮战/鱼雷各自的视觉语言；
6. 氛围战不自动完成正式战区任务、不向玩家发 XP/功勋、不吃敌人 token；玩家主动介入时再按专门 spec 决定收益；
7. 同时最多存在 **2 个**氛围交战编组，每个编组的选敌由控制器 **2Hz** 更新；位置、航向和弹体仍按需要 60Hz 更新。
8. 地堡、仓库、导弹井继续使用既有 `StrategicTarget`：**只有敌对轰炸机的 `bomber_bomb` 才能摧毁**；其它重要 TGT 则使用“玩家真实 HP + AI 战损值”双账本，避免玩家到场前被后台战斗清掉。

核心取舍是：**共享“任务、轨道、目标权限和生命周期”，不共享“物理与武器手感”。**

## 1. 本次问题的范围

### 1.1 要解决

- 轰炸机
  - 基础任务行为与对地攻击行为；
  - 沿指定轨道进入、转场、攻击、离场；
- 直升机
  - 对地攻击、平移、环绕、悬停；
  - 小队以长机轨道 + 固定槽位移动；
- 地面单位
  - 敌我火炮互相攻击；
  - 单车或炮兵纵队沿轨道移动；
- 舰船
  - 敌我舰船以舰炮互相攻击；
  - 敌我舰船发射水面鱼雷互相攻击；
- 把以上活动接成一个可控、可回收、可压测的战场氛围层。

### 1.2 暂不解决

- 不把这些单位变成玩家可直接 RTS 指挥的第二支军队；
- 不新增占点、补给线、战略地图或阵营大战模拟；
- 不让屏幕外战斗替玩家清掉正式 `TGT`；
- 不做真实火控链、声呐、反潜、装甲穿深或现实弹种分类；
- 不在本调查阶段改任何代码、资源、事件池权重或奖励。

## 2. 现状调查：不是从零开始

| 方向 | 已有能力 | 主要缺口 | 复用判断 |
|---|---|---|---|
| 轰炸机 | `BomberMission` 已有 `INGRESS → LINE_UP → RELEASE → EGRESS`、指定航路、5 枚炸弹、阵营过滤和集中 10Hz 控制 | 未接正式随机事件池；缺少“普通沿轨道活动”和氛围战生命周期；仍欠生存实机/压力 QA | **高复用**，不重写投弹闭环 |
| 直升机 | AH-64 已有独立旋翼运动、对地选敌、500m 环绕、悬停和短点射；CH-47 可按航点平移 | 每机各自走路线/选目标；没有编组级轨道、槽位和集中目标分配；仍欠实机 QA | **高复用**，新增小队层而非重写单机 |
| 地面移动 | `GroundUnit` 已有循环 waypoints；`GroundConvoy` 已有头车路线与逐车跟随 | 没有 directive 执行、没有路线结束/撤离语义、无编组生命周期 | **中高复用** |
| 地面战斗 | `GroundUnit` 有直射机炮；SAM/AA 都偏对空 | 没有火炮单位、间接弹道、炮兵互相选敌、炮击演出 | **需新增垂直切片** |
| 战略硬目标 | `StrategicTarget` 已实现地堡/仓库/导弹井三外观、150 HP、永久不可锁定，只接受敌对 `bomber_bomb` | 尚未纳入本氛围层的目标权限表与沙盒演示 | **直接复用，禁止普通 AI 火力绕过伤害门** |
| 舰船移动 | `NavalUnit` 已有 waypoints、同心圆巡航、刚体编队、全水轨道校验和远距 LOD | directive 目前只实际影响停火/HOLD；没有交战编组轨道切换 | **高复用** |
| 舰船战斗 | `NavalWeapons` 已有 CIWS、SAM、VLS、舰载 AA、Flak | 全部是对空/反导；没有 `NavalUnit → NavalUnit` 的选敌、舰炮或鱼雷 | **需新增武器路径** |
| “鱼雷”命名 | 现有 `TorpedoParams` / `_torpedoes` 是 A-10 的空中漂浮雷 | 语义、目标和视觉都不是海战鱼雷 | **禁止直接复用名称/数据类** |
| 轨道指令 | `AIDirective` 已定义 `FOLLOW_PATH / PATROL_RING / HOLD_POSITION` | 完整执行器只在 `AIController`；Ground/Naval/Bomber 各有自己的游标逻辑 | **应收口为共享语义** |

结论：当前完成度最高的是轰炸机和单架直升机；真正的新地基是**编组级交战权限 + 跨平台轨道执行**，真正的新武器是**火炮、舰炮、海战鱼雷**。

## 3. 推荐的体验规则

### 3.1 氛围战必须可读

沿用第三方事件的既有教训：每个氛围交战至少占“看得见 / 听得见 / 局内有理由”三项中的两项。

- 看得见：单位正常进入画面、弹道/炮口焰/烟迹清楚；Tab 图显示交战双方和交战区，不新增常驻 HUD。
- 听得见：首次进入玩家兴趣范围时播放一次短无线电；不为每次开火刷屏。
- 局内有理由：敌方火炮、攻击直升机或舰船会形成真实威胁；玩家介入可以解除该方向压力。首版不额外发永久货币。

单纯在地图另一端低频扣血、玩家既看不到也听不到的“后台战争”不做。

### 3.2 氛围战与正式任务隔离

- 氛围单位统一标记 `ambient_actor=true`、`engagement_id=<id>`、`token_cost=0`。
- 编组级目标分配默认只在相同 `engagement_id` 的敌对演员之间进行。
- 氛围单位不得主动选择正式 `is_mission_target`，除非创建它的事件明确把该目标加入本次编组。
- 即使显式加入编组，目标自身的伤害权限仍是最终裁决：`StrategicTarget` 只接受敌对轰炸炸弹，普通火炮、舰炮、鱼雷、导弹与机炮全部无效。
- 氛围击杀不向玩家发 XP、功勋或生涯击杀；是否给玩家主动击毁的氛围敌人奖励，留给正式 spec 拍板。
- 玩家主动攻击氛围敌军后，对方允许按既有 ROE 反击玩家；不得因此把整个地图所有氛围单位吸过来。
- BOSS 阶段开始后停止新建氛围战；存量单位收到撤离/停火指令，出画后回收，画面内不得瞬间消失。

### 3.3 重要目标保护：真实 HP 与 AI 战损双账本

用户提出的“AI 之间使用专门血量计量单位”是合理的最坏情况保护，但不建议把整个 `CombatUnit.hp` 拆成两套通用血量。更稳妥的是在目标层定义伤害权限，并只给重要目标增加一个**AI 战损账本**：

| 策略 | 玩家/玩家小队伤害 | 氛围 AI 伤害 | 归零结果 | 适用对象 |
|---|---|---|---|---|
| `NORMAL` | 扣真实 HP | 扣真实 HP | 正常摧毁 | 普通炮兵、护卫舰、直升机等氛围演员 |
| `PLAYER_FINISH` | 扣真实 HP，可摧毁 | 只扣 `ai_integrity` | AI 战损归零只进入 `SUPPRESSED`，不销毁节点 | 正式任务重要 TGT、指挥车、关键舰 |
| `BOMBER_ONLY` | 常规攻击无效 | 常规攻击无效；敌对 `bomber_bomb` 扣真实 HP | 只有轰炸覆盖可摧毁 | 既有 `StrategicTarget` 地堡/仓库/导弹井 |
| `IMMUNE` | 无效 | 无效 | 永不因战斗摧毁 | 纯演出锚点、尚未激活的任务设施 |

推荐字段/语义：

- `damage_authority_policy`：上述四种策略；
- `real_hp`：继续使用现有 `hp`，玩家与被授权武器的权威击毁账本；
- `ai_integrity`：只给 `PLAYER_FINISH` 目标启用，debug 可见、正式 HUD 默认不显示；
- `AI integrity == 0`：目标进入 6–10 秒 `SUPPRESSED`，停火/停雷达/停止给友军 buff，之后恢复一部分 AI integrity；
- AI 战损**永不折算成真实 HP**。玩家到场时看到的是一座被压制但仍可亲手摧毁/完成任务的目标；
- 伤害入口携带 `damage_authority = PLAYER_SQUAD / AMBIENT_AI / MISSION_SCRIPT`，不能仅靠 `team` 推断，因为 ALLY 与 HOSTILE 都可能是氛围演员；
- `bomber_bomb` 是武器权限，不等同于“AI 伤害”。敌对 AI 轰炸机仍可按 `BOMBER_ONLY` 规则真实摧毁战略硬目标；
- 普通氛围演员保持 `NORMAL`，否则双方永远打不完，只剩没有结果的烟花。

这套双账本解决的是**正式任务所有权**，不是给所有 AI 做第二套 RPG 血条。它应是目标 opt-in，不能扩散成每个 CombatUnit 的常态成本。

### 3.4 首轮容量与频率种子值

以下是为了写 bench 和估算性能的**建议起点，不是批准数值**：

| 项目 | 建议起点 | 理由 |
|---|---:|---|
| 同时活跃氛围交战 | 最多 2 组 | 足够形成多线，避免地图变成自走棋 |
| 单组双方总实体 | 4–12 | 直升机小队到 3v3 炮兵/舰队都能覆盖 |
| 编组目标重选 | 0.5s（2Hz） | 慢目标无需逐帧扫描 |
| 轨道/状态决策 | 0.1–0.5s | 轰炸门可 10Hz，其余从 2–5Hz 起步 |
| 投射物运动 | 60Hz | 弹道和近炸视觉需要连续 |
| 弹头邻域结算 | `UnitGrid` | 禁止每枚弹全场扫描 |
| 远距降级 | 复用现有单位 LOD/冻结规则 | 不再建第二套距离阈值 |

## 4. 推荐结构

### 4.1 事件层：`BattlefieldEngagement`

建议每一场氛围战由一个生存模式事件对象持有：

- `engagement_id`；
- `kind`：bomber / rotorcraft / artillery / naval_gun / naval_torpedo；
- 双方成员弱引用列表；
- 双方路线或轨道；
- 当前目标分配；
- `INGRESS / ACTIVE / EGRESS / ENDED` 生命周期；
- 一次性无线电与 Tab 呈现信息；
- BOSS、场景退出、全灭和越界清理。

事件层只编排，不执行单架飞机物理，也不直接在每帧扫描全场。

### 4.2 导航层：扩展现有 `AIDirective`

不再新增第四套“路线对象”。继续使用：

- `FOLLOW_PATH`：一次通过或循环航路；
- `PATROL_RING`：绕中心的圆形轨道；
- `HOLD_POSITION`：停留/悬停/驻泊；
- `FLY_TO_POINT`：进场或离场。

但要把航点游标与到达判定提取成一个无节点的共享 helper，由 Aircraft、GroundUnit、NavalUnit 和任务控制器消费。平台只负责把 helper 的“下一目标点”翻译成自身运动：

| 平台 | 如何消费目标点 |
|---|---|
| 固定翼/轰炸机 | 目标航向 + 速度 + 高度；攻击跑仍由 `BomberMission` 管投弹门 |
| 旋翼机 | 平移速度向量 + 独立机头；小队只让长机消费航路 |
| 地面单位 | 底盘转向 + 地速；炮击时可暂时 HOLD |
| 舰船 | 航向 + 海速；旗舰消费航路，僚舰继续刚体跟随 |

共享 helper 必须是 `RefCounted`/静态纯逻辑，不给每个单位新增 Node 或 `_process`。

### 4.3 目标层：编组分配，武器二次验证

控制器 2Hz 做一次目标分配：

1. 清除已释放、已摧毁、阵营不再敌对或离开交战范围的目标；
2. 从本 `engagement_id` 的敌方存活表中选目标；
3. 优先减少超杀：未分配目标优先，其次最低“已承诺伤害”；
4. 写入平台的任务目标槽，不覆盖玩家 `commanded_target` 或 FOCUS；
5. 武器发射当帧再次验证实例、敌我、目标类型和射界。

这样避免每门炮、每艘船、每架直升机各自扫 `CombatUnit.all_units`，也避免氛围单位跨战区乱咬。

### 4.4 伤害层：权限先于数值

推荐新增一个轻量伤害上下文，而不是让各武器散点判断“是不是 AI”：

```text
DamageContext
  authority: PLAYER_SQUAD | AMBIENT_AI | MISSION_SCRIPT
  kind: gun | artillery_shell | naval_shell | naval_torpedo | bomber_bomb | ...
  source_team: int snapshot
  attacker: safe optional reference
```

目标先按 `damage_authority_policy` 和 `kind` 决定写入 `hp`、写入 `ai_integrity` 或拒绝，再执行具体数值。`StrategicTarget.take_bomber_damage()` 继续是最终硬门，不为了统一接口而削弱它。

## 5. 分项设计建议

### 5.1 轰炸机：保留攻击跑，补任务轨道模式

推荐只支持两种清晰身份：

| 模式 | 行为 |
|---|---|
| `STRIKE_ROUTE` | 指定航路进入 → 对准 → 一次投弹 → 保持航向离场；继续复用 `BomberMission` |
| `TRANSIT_ROUTE` | 沿一次性或循环航路通过战区，不选敌、不进 BFM；用于远处编队活动和后续事件铺垫 |

原则：

- 不增加“绕目标盘旋反复投弹”；轰炸机的可读性来自一次明确攻击跑。
- `BomberMission` 的投弹数、提前量、散布和伤害首轮保持现状，不在气氛项目里顺手再平衡。
- 轨道由事件调用方提供；地图只保存路线点，不把攻击目标硬编码进机体资源。
- 同编队共享一条中心航线，各机只加固定横向/纵向偏移；禁止每机独立找路导致编队散掉。
- 氛围轰炸默认攻击本事件创建的地面目标，不碰正式战区 TGT。
- 唯一例外是事件显式创建/登记的 `StrategicTarget`：地堡、仓库、导弹井保持 150 HP，永久不可锁定，普通武器完全无效；两枚 75 伤害敌对轰炸炸弹可摧毁。

### 5.2 直升机：长机轨道 + 小队槽位 + 集中选敌

保留现有 AH-64 单机 `TRANSIT / REPOSITION / ORBIT / BRAKE / HOVER / EGRESS`，在上面加一层 `RotorcraftFlight`：

- 2–4 架为一组；
- 长机消费 `FOLLOW_PATH` 或 `PATROL_RING`；
- 僚机消费长机本地坐标系中的固定槽位，不独立推进航点；
- 长机失效时按成员顺序选新长机，路线游标不重置；
- 编组控制器 2Hz 选择地面目标，再按最少超杀分给攻击型成员；运输型永远不领攻击目标；
- 进入攻击时允许分成两个视觉组：攻击对 500m 环绕，掩护对沿外圈或 HOLD；目标失效后全员回长机轨道；
- 旋翼运动和开火的 60Hz/20Hz 现有分工不变。

首轮只验证**纵队/梯队一种队形**，不做玩家编队编辑器。

### 5.3 地面火炮：新建间接火力，不改造成“大号机炮”

建议新增 `ArtilleryUnit extends GroundUnit`，但武器走独立炮弹路径：

| 参数 | 首轮种子值 | 说明 |
|---|---:|---|
| 目标类型 | 敌对 `GroundUnit` | 首版不打飞机/舰船 |
| 最小/最大射程 | 800m / 5000m | 留出近距死区，形成火炮身份 |
| 炮弹飞行时间 | 2.5–4.5s | 延迟可见，不照抄真实弹道 |
| 每轮齐射 | 3 发 | 有清楚的炮击节奏 |
| 发间隔 | 0.7s | 可读弹列 |
| 齐射冷却 | 8s | 不形成持续 DPS 墙 |
| 爆炸半径 | 90m | 45px |
| 单次伤害 | 75 | 普通地面敌人一发解决，符合 30–100 区间 |

行为：

- 炮兵连沿 `FOLLOW_PATH` 移动；抵达火力点后 HOLD、展开、齐射，随后按事件决定继续射击或转移。
- 首轮目标由交战控制器预分配，不给火炮自己做全图雷达搜索。
- 炮弹使用可见抛物线高度和落点预告；落地才结算一次 AOE。
- 发射者被摧毁后，已出膛炮弹继续飞；归因使用 `source_team` 快照与安全实例引用。
- 炮弹只伤敌对地面单位；玩家是否可被敌炮伤害需在正式 spec 单独拍板，不能默认为“气氛炮弹无害”。
- 车队移动直接复用 `GroundConvoy`，但长机/头车死亡后必须把路线游标交给新头车。

### 5.4 舰炮互射：新增水面武器类型，不借用对空 VLS

在 `WeaponMountParams.WeaponType` 末尾追加 `NAVAL_GUN`，不得插入旧枚举中间。推荐行为：

- 只选择敌对 `NavalUnit`；不把挂点代理当舰船目标；
- 命中点走 `NavalUnit.take_damage_at()`，保留挂点/弱点/船体路由；
- 按挂点 `facing + arc` 验证射界，舰体转向能真实改变可开火侧；
- 目标获取 2Hz，齐射进行中只复用已锁目标，不再扫描；
- 炮弹独立于普通机炮热路径，保存目标位置/速度快照，按固定飞行时间落点；
- 单发伤害仍在 30–100 内，舰船耐久依靠已有船体/挂点结构表达“装甲单位例外”，不把单发伤害抬到几百。

首轮建议从 **2v2 FFG 炮战**做垂直切片，不直接上 6v6 航母群。

### 5.5 舰船鱼雷：与 A-10 漂浮雷彻底分开

建议使用明确命名：

- `NavalTorpedoParams`；
- `BulletManager._naval_torpedoes`；
- `spawn_naval_torpedo()`；
- `NAVAL_TORPEDO` 挂点类型。

首轮种子值：

| 参数 | 建议起点 |
|---|---:|
| 目标 | 敌对 `NavalUnit` |
| 最小/最大射程 | 500m / 3500m |
| 速度 | 90m/s（游戏抽象） |
| 最大转向 | 20°/s |
| 发射冷却 | 12s |
| 单挂点在水鱼雷上限 | 2 |
| 近炸半径 | 35m |
| 伤害 | 100 |

规则：

- 发射时锁定一个 NavalUnit，航行中只验证该 `instance_id`；目标失效后鱼雷直行并超时回收，不重新全场找目标。
- 每帧检查前进段是否进入陆地；触岸即产生水花并失效，不穿岛。
- 只伤敌对舰船，不伤飞机、地面单位和同阵营舰船。
- 首版不允许 CIWS 拦鱼雷，也不做诱饵/反鱼雷；这些是以后独立机制。
- 视觉必须有持续水面航迹、明确入水/命中爆炸，不能只是把导弹颜色改蓝。

## 6. 建议实施顺序

### 里程碑 0 — 正式 spec 拆分与拍板

1. `systems/battlefield-ambient-engagements`：生命周期、目标隔离、容量、奖励与 BOSS 清理；
2. 修订 `systems/bomber-strike-missions`：增加任务轨道接入，不改投弹数值；
3. 修订 `systems/rotorcraft-combat`：增加小队轨道与集中选敌；
4. 新建 `systems/mobile-artillery-duels`；
5. 新建 `systems/naval-surface-combat`；
6. 新建 `weapons/naval-torpedo`。
7. 修订既有 `systems/strategic-hardened-targets` 的依赖说明，但不改变“只接受 bomber_bomb”的已实现契约；
8. 在总规则 spec 内批准 `NORMAL / PLAYER_FINISH / BOMBER_ONLY / IMMUNE` 四级目标权限与 AI integrity 语义。

只有第 1 份总规则和对应分项 spec 均 approved，才进入该分项实现。

### 里程碑 1 — 共享轨道与交战壳

- 提取无 Node 的 directive 路线 helper；
- GroundUnit/NavalUnit 接 `FOLLOW_PATH / PATROL_RING / HOLD_POSITION / FLY_TO_POINT`；
- 建 `BattlefieldEngagement` 生命周期与 `engagement_id` 目标隔离；
- 先用无武装 dummy 编组验证进场、循环、撤离和 leader 继任。
- 同批建立独立可视沙盒：轰炸、直升机、火炮、舰炮/鱼雷四场景，可切换阵型与伤害策略；沙盒不进入正式事件池。

### 里程碑 2 — 先收已有能力

- 轰炸机接氛围事件，但不改攻击跑；
- 直升机加小队轨道与集中目标分配；
- 补齐现有 bomber/rotorcraft 生存实机 QA。

### 里程碑 3 — 火炮互射垂直切片

- 2v2 或 3v3 炮兵；
- 轨道进场 → HOLD 展开 → 三发齐射 → 目标全灭/撤离；
- 证明间接弹道、阵营过滤、发射者失效和玩家介入边界。

### 里程碑 4 — 舰炮互射

- 2v2 FFG；
- 复用全水路线、舰队刚体跟随、挂点伤害与沉没演出；
- 证明表面目标分配和射界，不动现有对空武器。

### 里程碑 5 — 舰船鱼雷

- 在 2v2 炮战上增加单侧鱼雷挂点；
- 验证入水、转向、触岸、目标失效、伤害与同屏上限；
- 最后再扩成双方鱼雷互射。

### 里程碑 6 — 氛围接入与调频

- 接入正式生存模式调度；
- Tab/无线电只做最低可读度；
- 调整同时事件数和生成位置；
- 跑完整压力场景，未通过 60 FPS 红线则先砍密度或降频。

## 7. 验收与回归框架

### 7.1 共享轨道

- 一次性路线抵达末点后不会从头循环；循环路线按顺序稳定循环；
- 圆轨道不会在端点做 180°掉头；
- 长机死亡后新长机继承路线游标，不把编组拉回出生点；
- BOSS 阶段下达撤离后，存量单位不再选新目标；
- 已释放引用全程经过 `is_instance_valid` 后再转型/访问。

### 7.2 武器

- 火炮只伤敌对 GroundUnit；舰炮/海战鱼雷只伤敌对 NavalUnit；
- 武器发射当帧再次验证敌我与目标类型；
- 已出膛弹体在发射者死亡后继续结算，且无 freed-instance；
- 同一弹头对同一单位只结算一次；
- 爆炸用 `UnitGrid` 或固定目标引用，不做每弹每帧全场扫描；
- 海战鱼雷触岸失效，不跨陆地命中。
- StrategicTarget 对普通火炮、舰炮、鱼雷、导弹与机炮始终不掉血；只有敌对 bomber_bomb 写入真实 HP。

### 7.3 任务隔离

- 氛围双方互相击毁不会完成附近正式战区任务；
- 氛围友军击杀不给玩家 XP/功勋/生涯击杀；
- 玩家命令目标、FOCUS 和 `commanded_target` 不被氛围控制器覆盖；
- 不同 `engagement_id` 的单位不会自动串场；
- 场景退出、全灭、BOSS 切换后无静态引用残留。
- `PLAYER_FINISH` 目标被 AI 火力打满只进入 SUPPRESSED，真实 HP 不变；玩家攻击仍能扣真实 HP 并完成击毁。
- `ai_integrity` 恢复、重置或跨场景清理不得改写真实 HP，也不得进入存档。

### 7.4 表现与性能

- 三档 zoom 下能区分轰炸、直升机横移、炮弹抛物线、舰炮和鱼雷航迹；
- 每个事件至少满足“看得见 / 听得见 / 局内有理由”两项；
- 专项 bench 建议统一为 `battlefield_atmosphere`，并保留各分项纯行为测试；
- 压力样本至少包含 2 轰炸机、4 直升机、6 地面单位、6 舰船和在飞特殊弹体；
- 生存模式 + Sentinel + Lv5+ 全程不得低于 60 FPS；新增决策必须有降频或集中控制路径。

## 8. 主要风险

| 风险 | 处理原则 |
|---|---|
| 全场自由选敌导致战区串场 | `engagement_id` 是首要过滤，受击反击也只局部升级 |
| 氛围单位替玩家做任务 | 默认不选正式 TGT、不发玩家收益；专用事件显式 opt-in |
| 四套 waypoint 继续漂移 | 共享 directive 游标/几何，平台只保留运动执行 |
| 直升机小队每机扫全场 | 编组 2Hz 选敌，成员只消费分配 |
| 舰船武器枚举存档/资源错位 | 新类型只追加到枚举末尾 |
| “torpedo” 名称撞现有漂浮雷 | 全链路使用 `naval_torpedo`，绝不悄悄改旧资源语义 |
| 舰炮/火炮弹体塞进普通子弹热路径 | 各自独立数组与低数量上限，爆炸统一邻域查询 |
| 单位很多但玩家看不到 | 事件只在玩家兴趣范围周边建立；远距按既有 LOD/冻结退化 |
| BOSS 开始后舞台不干净 | 停止生成、存量停火撤离、出画回收 |
| 只有代码行为没有战场叙事 | 最低保证可见轨迹 + 一次无线电或 Tab 呈现 |

## 9. 本轮新增的可视沙盒

沙盒先验证“看起来像不像战争”，不作为正式玩法实现证明。它需要同时展示：

- 场景切换：轰炸战略硬目标 / 直升机小队突击 / 炮兵互射 / 舰炮与鱼雷互射；
- 阵型切换：横列、楔形、纵队、环形；
- 伤害切换：共享真实 HP / 重要 TGT 的 AI integrity 隔离；
- StrategicTarget 的普通攻击无效与 bomber_bomb 专属摧毁；
- 玩家模拟打击：验证 `PLAYER_FINISH` 目标的真实 HP 与 AI 战损完全独立；
- 暂停、重置和速度控制，便于逐段观察轨道、齐射和目标保护。

只有沙盒观感得到确认，才把相应阵型、开火节奏和弹体表现写进正式 specs；沙盒参数不能反向成为生产 SSOT。

## 10. 待用户拍板的四个方向

1. **“轨道”语义**：本文按“可循环 waypoint / 圆轨道 / 一次性航路”统一理解，而不是必须使用 Godot `Path2D`。
2. **氛围战是否影响正式任务**：本文推荐默认完全隔离，只有专用事件显式接入 TGT。
3. **玩家介入收益**：本文推荐首版不发额外功勋；介入的即时收益是解除局部威胁，后续再决定是否给时间/XP。
4. **首个垂直切片**：本文推荐先收口轨道地基，再做“2v2/3v3 火炮互射”；它同时验证地面移动、目标隔离、间接弹道和氛围可读性，风险低于鱼雷。
