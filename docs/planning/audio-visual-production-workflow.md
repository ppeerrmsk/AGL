# 音画与战斗表现生产工作流

> 状态：2026-08-20 起的铺量阶段生产入口。本文管理素材清单、接入批次、表现目标与验收证据；
> 音频运行时架构仍以 [audio.md](../systems/audio.md) 为准，UI 稳定通用规则仍以
> [ui-design-guidelines.md](../specs/systems/ui-design-guidelines.md) 为准。具体技能、敌人、地图与数值行为必须回到对应 spec。

## 0. 制作目标

音效、音乐、机体模型、地图细节、战斗特效、提示语言与击杀反馈不是发布前才补的“抛光层”，而是
内容生产的一部分。AGL 的目标反差是：

- **游戏初期**：专业、冷峻、精确，战场事件较少但每次命中都清楚；
- **游戏中期**：多线任务和构筑开始互相叠加，视听层逐步增密；
- **游戏后期**：大规模混战、暴走和高密度冲突，但玩家仍能读懂自己的小队、Build、威胁与击杀。

玩家变强必须能从画面和声音上直接感知。一个重要升级若只改变后台数值、没有任何可辨认的武器、
尾迹、弹道、爆炸、机体、HUD 或音效变化，就没有完成表现层交付。

## 1. 分工与素材入口

制作人提供原始素材或方向参考；项目侧负责整理、转码、命名、注册、混音、接入、变体、性能和验收。

每批素材交付附一份清单，至少包含：

| 字段 | 要求 |
|---|---|
| 素材 id / 临时名 | 同一批内唯一，后续可映射为正式资源 id |
| 类型 | music / world_sfx / ui_sfx / radio / aircraft / map / vfx / reference |
| 使用场景 | 何时出现、由谁触发、初期/中期/后期/BOSS 哪一层 |
| 玩家应感知的差异 | 例如“导弹命中比机炮更重”“取得超载后弹道进入高能态” |
| 原始文件与版本 | 保留无损母版；派生文件不得覆盖源文件 |
| 来源与授权 | 自制、购买、委托或许可范围；无法确认授权的不进入正式包 |
| 变体需求 | 是否需要近/远、轻/重、友/敌、普通/强化、A/B/C 随机变体 |
| 循环与剪辑点 | 音乐是否循环、音效尾音能否裁切、动画是否需要无缝循环 |
| 优先级 | 当前地图批 / 共用基础 / 候选，不用“都很急” |

格式与总线约束不在本页重复冻结；音频导入以 [audio.md](../systems/audio.md) 的现行要求为准。

## 2. 六条生产线

### A. 音乐状态覆盖

第一轮不是追求曲目数量，而是补齐功能状态：

1. 主菜单 / 生涯层；
2. 初期出击的冷峻、克制状态；
3. 中期升级与多线交战的升温状态；
4. 后期大规模混战的失控、暴走状态；
5. BOSS arrival 与正式接战；
6. 胜利、失败与结算。

同一首曲可以通过段落、播放列表或交叉淡化承担多个状态；是否需要 stem、BPM 对齐或动态分层，等素材
到位后在专项 spec 定稿，不在 planning 文档预设实现。

### B. 世界与 UI 音效族

按“声音家族”交付，不按零散单文件堆积：

- 机炮、导弹、火箭、电磁炮、激光、Flak/CIWS 的发射、飞越、命中；
- 小/中/重型击毁，空中解体、地面爆炸、舰船受击；
- 引擎、加力、失速、掠过、热诱弹、干扰与特殊机动；
- 锁定、危险、升级、奖励、进化、武器获得、BOSS 警告、胜负与结算；
- 无线电进入/退出、噪声、优先级插播与队友协同提示。

同一高频事件必须准备可轮换变体或用程序化轻微随机避免疲劳；数量与随机范围在听感 A/B 后定稿。

### C. 飞机与单位视觉

- 以当前 43 机树和常见敌方家族做一次全量质量审计，不要求一批全部重做；
- 先定一组“合格 / 不合格”基准样本，再按机体家族和地图批处理；
- 同时检查顶视轮廓、滚转体积、阵营/王牌涂装、挂载物、受损和击毁状态；
- 机体细节不能牺牲远距识别，模型升级必须在常用 zoom 下仍有可见收益。

### D. 地图细节

- 东京湾先建立道路、机场、港区、建筑、海岸与气候的成品质量门；
- 沙漠铁路和海洋群岛只复用质量规则，不复制东京湾的地理语言；
- 主视野与 Tab 必须同源且都可读；细节增加需跑地图/天气/UI 专项性能门；
- 所有母版、派生层、裁剪和回滚路径有清单，不让临时导出成为唯一源文件。

### E. 战斗特效与提示语言

建立统一语义字典，至少覆盖：普通命中、致命击杀、玩家受击、危险锁定、控制状态、强化状态、任务事件、
BOSS 阶段和奖励获得。颜色、运动方向、持续时间、层级和音效职责必须一致；不能每个系统各自发明一套
闪烁和爆炸语言。

统一不等于只有一种表现。普通、精英、王牌、BOSS 和不同武器可以在同一语义骨架上使用不同强度、
轮廓、碎片、烟迹、镜头和声音变体。

### F. Build 变强的可见化

每个重要技能、武器或里程碑在 spec 中选择至少一个玩家可见通道：

- 机体外形、挂载或涂装；
- 尾迹、弹道、枪口、命中或爆炸；
- 编队形态、协同动作或战场召唤物；
- HUD 状态、获得动画、升级后的持续反馈；
- 发射、命中、循环或完成音效。

表现必须对应真实运行状态，不能常亮伪造；多技能叠加时仍要保持主威胁、玩家机和目标可读。

## 3. 单批流水线

1. **写 brief**：场景、情绪、触发、玩家应感知的差异、初/中/后期位置。
2. **收素材**：登记源文件、授权、版本、变体和缺口；不合格式的先保母版再派生。
3. **做最小样板**：一个正式触发点接一组素材，先验风格和信息层级。
4. **扩成家族**：通过样板后再处理同类武器、机体、地图区块或状态。
5. **集成验证**：真实 Survivor 链路验证混音、遮挡、层级、三语、常用 zoom 和极端状态。
6. **压力与回退**：涉及 draw、粒子、贴图、音源池或动态图层时跑匹配专项；保留可比较的前后证据。
7. **收尾**：资源目录、id 注册、授权清单、关联 spec、Debug 入口和验收记录同批关闭。

## 4. 首轮清单

首轮只建立可复用标准，不同时翻修全库：

- [ ] 选定“初期冷峻 / 中期升温 / 后期暴走 / BOSS”四段音乐参考和现有素材缺口；
- [ ] 建立武器、命中、击毁、引擎、UI/奖励五组音效家族清单；
- [ ] 选 3 架玩家机、3 类敌人和 1 个 BOSS 作为机体/涂装质量样板；
- [ ] 以东京湾一个空域、一个机场和一个港区作为地图细节样板；
- [ ] 统一普通击杀、王牌击杀、BOSS 阶段、玩家受击和强化获得五类表现语义；
- [ ] 选择 5–8 个高频或高价值技能做第一批“变强可视化”，优先覆盖不同表现通道；
- [ ] 为敌人击毁建立至少三种身份：普通快速解体、重型/装甲击毁、王牌/BOSS 特殊终结；
- [ ] 为状态栏建立进入、刷新、叠层、即将结束、结束五种可辨认变化，不增加新的后台状态语义。

## 5. 完成线

- **素材可用**：源文件、授权、格式、id、使用场景和版本齐全，但还不等于游戏内完成。
- **单项完成**：真实触发链可达，视觉/听觉意图成立，资源释放正常，适用的 focused 与 Visual 证据通过。
- **家族完成**：同类事件音量/颜色/强度有层级，连续触发不疲劳、不盖住更高优先级信息。
- **地图表现完成**：该地图的初期→后期密度变化、任务、BOSS、胜负和常用 Build 都有完整音画覆盖。
- **发布完成**：三语、设置、静音/低音量、常用分辨率与 zoom、长局、最大混战和导出包都验证；
  不能靠关闭大规模战斗或削掉关键反馈来守性能。

## 6. 尚未定稿

- 20 小时内容线各小时段具体解锁什么；
- 每个音乐状态需要几首曲、是否做动态 stem；
- 43 机与敌方家族的重制优先级；
- 哪些技能进入首批表现增强及其具体表现；
- 击毁动画、状态栏变体的精确数量与资源预算。

这些问题要由素材现状、玩家节奏数据和第一批样板共同决定；在对应 spec approved 前不得把本页候选
当成已经承诺的运行时机制。
