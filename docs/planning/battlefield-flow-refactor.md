# 战场任务流程重构

> 状态：已完成（2026-08-28）
> 范围：只重构现有生存模式规则所有权，不调整战区数值、王牌时间槽或 BOSS 胜负规则。

## 问题

`survivor_mode.gd` 原先同时保存并修改 `game_time`、战区超时锁存、BOSS 阶段判定、
王牌无放回顺序/已用账本/时间槽和 ORION 一次性门。新局与退局的 static 清理由多个注释块分别执行。
这些字段共同描述一局战场状态，却没有统一 reset，也让 Debug、补给、事件奖励和物理帧能直接改同一时钟。

## 边界

- `BattlefieldFlow`：局内规则状态。独占净时间轴、战区/BOSS 阶段、关闭战区事务、固定王牌槽、
  无放回账本与 ORION 一次性门。
- `SurvivorMode`：运行时执行。保留 Node 创建、信号、UI、无线电、事件对象启动和玩家输入。
- `ZoneData`：战区战略数据、奖励和任务类型；不接管物理实体。
- `ZoneMission`：已激活战区的实体生成、任务终态与退役；不复制阶段时钟。
- `SurvivorRuntimeReset`：只清跨场景 static/RefCounted 局内状态；新局与退局走同一入口。

## 保持不变的契约

1. 普通 1★/2★ 战区选择或抵达后才从战略态进入 LIVE；取消选择不回滚。
2. 战区到点一次性取消任务、锁区并公开 BOSS；BOSS 解锁即冻结时钟和常规系统。
3. 王牌固定为 3:30 第一槽、BOSS 前 3:00 第二槽；第二槽开放后不因 +60 秒倒拨关闭。
4. 同场最多一支轮换王牌、同局无放回、每局最多两支；ORION 仍走独立一次性轨道。
5. `game_time` 仍是净时间轴：补给 +30 秒，击破/事件奖励向后倒拨，HUD 读同一真源。

## 验证

- `battlefield_flow`：时间、阶段事务、王牌锁存、ORION 和跨场景 reset 的纯规则专项。
- `ace_tier` / `zone_air_support` / `boss_phase`：现有节拍、战区实体生命周期和 BOSS 总闸回归。
- `lifecycle_gauntlet` + `all`：真实 SceneTree 终态与全量运行时错误门。
