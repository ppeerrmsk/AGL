# 卡顿排查 R6：玩家HUD布局重复求解

日期：2026-09-18。承接 [R5](2026-09-18-map-repair-r5.md)。**局部优化已实装；整场严格帧时间仍未达标。**

## 原因与修改

在真实玩家HUD的文字绘制入口增加可选CPU细分：`hud_text.layout`（求字号）、`hud_text.baseline`（当前文本基线）、`hud_text.draw_string`（绘制调用）。只在性能明细采集开启时计时，不更改文字绘制。

优化前60秒FINAL WAR诊断 `final_war_ocean_stress_20260918_124954.txt` 中，多次HUD重绘重复调用 `TerminalText.resolve_font_layout`，基准字符串/矩形/字体/固定字号均未变化，却仍进行字号搜索和字符串宽度检查。慢帧2684、3429、6196分别记录布局975/815/1275µs。

`PlayerInstrumentPanel._cached_text_layout` 现在按字体实例ID、基准文本、精确Vector2尺寸及固定字号复用Vector3结果；仅保存数值/字符串，不持有Font或Aircraft对象。上限256项，布局重建清空；动态数字仍逐次测量真实基线，位置、颜色、刷新频率及排版算法不变。地图、LOD、AO、分辨率、MSAA、AI、碰撞、伤害和战斗负载不变。没有把玩法计算迁移到GPU，也没有变更驱动/VSync。

回归覆盖：100次重复调用结果相同且只求解一次、区域尺寸变化、基准和固定字号变化、重建失效、动态文本容量有界。focused `player_hud` 为255通过/0失败。

## 本轮工序失误及纠正

首次全量驱动错误地把Visual诊断的`AGL_BENCH_FRAME_TRACE_MODE=full`传给Headless单元测试，`perf_trace`期待默认`detail_stride=4`，因此101组中1组失败。保留`all-r6-cache.log`，不改断言、不放宽阈值；修正驱动使全细分仅用于Visual，并用`all_r6_clean.py`清理诊断环境后完整重跑。最终回归通过，不把首次配置失败解释为游戏回归，也不抹去该失败。
