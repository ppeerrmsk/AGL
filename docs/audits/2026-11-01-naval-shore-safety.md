# 舰船驶上岸复核（2026-11-01 至 2026-11-03）

东京正式地图的富津尖端有一块陆地，世界坐标为 (1079.432, 6898.463)。旧玩法把这里识别为海面。友军小舰队还会以超出转向能力的速度追踪巡航圆，导致实际航线偏出预先检查的水域。

## 正式行为

- 东京舰船按正式地表制作源判断水域。完整16×16地块包含1,102,526个陆面三角形，覆盖海岸、绿地、公园、铺装地和铁路场地。8px网格记录到最近陆格的保守距离。距离不足、超出覆盖或数据无效时禁止通行。
- 摆位验证完整船体及相邻采样之间的圆弧。航行时沿预检圆推进，转率不足就降速。航点移动和刚体护卫移动都会检查整船经过的区域。整队缺少空间时沿用缩圈、驻泊、缩编等现有降级规则。
- 烘焙数据616,041字节，已纳入导出预设。运行时加载一次，解压后16,000,000字节。UGC使用当前地图注入的陆地多边形。旧局中已经搁浅的船可通过重新开局使用新的摆位。

## 复现与验证

| 检查 | 结果 |
|---|---|
| 旧运动代码 | 21项中7项失败，覆盖小圈偏航、船头触岸、穿过2px窄堤和旗舰推岸。记录在 `tmp/naval-shore-before.log`。 |
| 旧海陆数据 | 富津真实陆面被误判为水。新增反例后36项通过、1项失败。记录在 `tmp/naval-shore-map-before.log`。 |
| 同源数据核验 | 256份地表文件均通过各自制作状态文件的SHA-256核对。独立检查全部陆面三角形重心，误判为可通行者为0。来源摘要与成品摘要保存在 `resources/maps/tokyo_naval_clearance.json`。 |
| 舰队运动 | `naval_formation` 21/21。120px与240px小圈各推进30分钟，旗舰和护卫均保持预检轨道。 |
| 正式水域 | `naval_zone_water` 43/43。富津尖端拒绝驻泊，相邻外海允许通行。近岸绿色DDG和FFG持续航行30分钟。三档任务舰队在外海均巡航，窄水域的一星舰队缩圈，二星和三星舰队全队驻泊无漂移。 |
| 航母舰队 | 南北锚点均有全水解。20px错相采样复核通过。另直接对正式地表三角形与13艘船的完整同心轨迹及94px净空做相交检查，北侧检查543个三角形，南侧检查12,205个，均为0交叠。 |
| 全量回归 | 默认全量回归退出 124。 同步测试共 105 组，失败 0 组。 生命周期阶段在300秒内未完成。 独立运行生命周期时 93 项通过，0 项失败，退出 0。 记录在 `tmp/naval-shore-all-final.log`。 |
| 36单位混合战场 | 镜头巡检8/8，36名成员，平均119.08 FPS。按实际帧间隔计有17帧低于60 FPS，最长21.808ms，严格60 FPS未通过。末秒舰船物理约17µs/帧。报告为 `bench/results/battlefield_atmosphere_stress_36_20261102_234903.txt`。 |

引擎版本为Godot 4.7.2 Steam，所有引擎测试均经过项目Shadow wrapper。30分钟航行证据来自正式生成器及真实运动函数的同步步进。人工F5同位画面尚待复验。

早期33/37的水域结果中，两条航母检查仍使用旧海陆表，另外两条把合法驻泊视作错误。最终验证使用正式地表并分别检查近岸驻泊和外海持续航行。对应契约见[战区海上安全规格](../specs/systems/zone-air-support-naval-safety.md)。
