日期：2026-10-29。工作目录为 `F:\AGL`，当前分支为 `main`，结果来自共享工作区的未提交候选。本文是时间点证据，不替代[流送规格](../specs/systems/tokyo-prepared-streaming.md)或[性能守则](../reference/performance-guidelines.md)。

## 2. 本轮查实并修复的问题

| 原因 | 修复及边界 |
|---|---|
| 只预测 0.25 秒终点，遗漏途中不同物理身份的父页/子页 | 增加 0.02 / 0.06 / 0.12 秒采样，近期优先；同一工作线程、同一物理账本 |
| 高速 SPACE 的预测中心被“一屏保护带”截断，且超过 160 px 被误认作冷瞬切 | 未来查询中心按实际运动外推；仅姿态匹配时消费控制器连续样本，真正瞬切仍清空历史 |
| 已常驻远景因视口变化重新局部绑定，资源虽齐仍等规划 | 有概括质量合同且全图满足原预算时保持全图同一绑定 |
| 第一次滚轮到 0.4 边界才开始加载下一档 | 静止或放大时提前准备远景出口；预测使用正式选页算法，避免预取目录和实际回退目录不同 |
| 资源已经准备，但完整预测切面被丢弃，仍要往返后台 | 保存最多六份纯值切面，主线程按最新机位、清晰度、资源、显示上限和物理联合重新核验，再走原租约/提交入口 |
| 接管第一步时丢掉后续预取请求，刚加载资源被回收 | 接管时保留后续路径请求；实测失败轮曾从 84 项缓存骤降为 22 项，再次读入造成 81.547 ms 缩放停顿 |
| 自由镜头按 SPACE 突然反向，当前方向预取来不及覆盖起步 | 同池余额内提前准备 0.02 / 0.06 秒返回起步，跟随时按原 FOLLOW_LERP 曲线预测，避免直线外推越过玩家。只发布纯值；目标释放后下一帧撤销 |

上述行为均受显式候选开关控制。没有移除覆盖门、延长旧图清晰度宽限、缩小输入目标或拖慢镜头。真实 SceneTree 用例验证了缺资源、覆盖不足、失格、面数/字节/联合超预算、关闭开关时拒绝提交，以及玩家目标实际释放后的提示清理。

## 3. 三轮同条件操作对照

每轮 60 秒，WASD 持续换向、每两秒突发 32 次滚轮，共 960 次。不开像素回读；以实际绘制结束的微秒墙钟量平移、缩放和整幅呈现，包含恢复的末帧。正式模态关闭输入的时间单列。50 ms 是既有短顿失败门、250 ms 另记冻结；低于门限的实际数值仍全部保留，不等同于绝对无顿。

| 轮次 | 修复前平移最大停住 ms | 修复后平移最大停住 ms | 修复前缩放最大间隔 ms | 修复后缩放最大间隔 ms | 修复后整幅最大间隔 ms |
|---|---:|---:|---:|---:|---:|
| 1 | 94.363 | 0 | 111.049 | 49.536 | 49.536 |
| 2 | 94.766 | 25.650 | 103.139 | 32.495 | 16.803 |
| 3 | 69.210 | 0 | 77.557 | 16.760 | 16.780 |

修复前三轮均失败；修复后三轮均未触发 50 ms 门。第一轮 49.536 ms 必须保留：发生在约 11.658 秒、尺度 1.2525 的普通移动/缩放中；镜头没有处于地图等待，资源 pending 为零。该轮未启用阶段追踪，**不能凭这两点认定是 GPU、驱动或操作系统原因**。

## 4. SPACE 回中

每轮 60 秒，先自由移开五秒，再按 SPACE；近景与远景交替，三轮共 21 次。单看首次响应不能证明中途没有停住，因此另量整个回程的停止推进。

| 轮次 | 最长回程镜头停住 ms | 整幅画面最大间隔 ms | 7 次返回 |
|---|---:|---:|---|
| 1 | 24.996 | 17.221 | 全部完成 |
| 2 | 21.299 | 20.009 | 全部完成 |
| 3 | 25.710 | 18.102 | 全部完成 |

21 次首次响应 7–9 ms，回到既有跟随误差范围 401–950 ms。正常跟随的移动时间不是卡死时间；没有修改原跟随速率。此前无返回起步预热的同一开发阶段仍测到 43.344 ms 停住，该记录保留在 `acceptance-return-r1`，没有因低于 50 ms 就当作问题已解决。

## 5. 像素、长期重复与阶段追踪

独立三轮像素回读共 **19217 帧 / 2880 次滚轮输入**：隐藏、像素缺失、未覆盖、失格、预算超限、相机/合成错位与旧 PNG 回退均为零。它不是帧时证据，也不能替代人工 F5 对画面风格和手感的判断。保存的截图覆盖入口、远景和近景；仍是同源三维/HLOD 表示，不是旧 PNG 栅格回退。

追加三轮同路线阶段追踪，最长整幅间隔分别为 **17.657 / 17.630 / 27.570 ms**。再做四分钟连续追踪：**28754 帧 / 3840 次滚轮输入**，平移最大停住 **11.446 ms**，整幅最大间隔 **36.310 ms**；显示状态异常均为零，退出释放成功。后续七分钟未复现原 49.536 ms 事件，不能抹掉它或认定其原因已解决。

四分钟追踪的最长引擎迭代约 36.348 ms，其中渲染提交阶段 31.242 ms，物理脚本 2.727 ms、process 脚本 1.014 ms、绘制前刷新 0.162 ms，节点增删为零。这个阶段包含驱动、SwapBuffers 和同步，**异步视口 GPU 时间不是同帧因果证据**。另有一帧约 26.096 ms，process 23.163 ms、纹理费用增约 21 MiB；这些残余事件仍存入原阶段 CSV/JSONL，未伪装成零成本。

## 7. 相比 main 已有优化经验的补充

[已有复盘](2026-10-28-map-streaming-optimization-lessons.md)强调物理联合预算、当前资源优先和显示/输入分门，本轮继续继承。新增的可复用经验是：

1. 预取终点不是路径覆盖；树的父子页物理身份不同，必须验证途中用到的实际切面。
2. 显示保护带的尺寸限制不应顺带限制未来查询中心；快速返回会跨越多屏。
3. 已加载资源、已规划切面和实际显示是三个阶段。丢掉完整切面元数据，资源齐备也会停镜。
4. 提交第一步不能撤销后续预取意图，否则会形成缓存回收—重读的反复。
5. SPACE 返回是已知可发生的反向输入，可在原缓存余额内预备起步；提示必须随目标生命周期失效。
6. 刚好低于失败门的异常仍须保留并追踪。阶段追踪只能说明被观测区间，不能用未复现替代根因证明。
