## 已定位的直接等待原因

1. 出口预取把尺度改为未来值，位置却仍取较早时刻；WASD 同时放大时，世界速度还随缩放下降。统一时间、积分位置和未来速度。
2. SPACE 跟随使用逐帧线性权重，玩家同时移动。预测改为匹配离散跟随与运动目标；目标更换或释放不得继承速度。
3. 资源已驻留但后台尚未返回切面；候选保留最多八份预测切面，并允许每渲染帧一次驻留资源选择。父块未载入时可以使用完整、合格且满足预算的驻留子树。
4. 后台网格已完成，主线程在镜头准入之后才领取。首次准入前领取完成件，与原流送器共享同帧额度，不同步等待在途任务。
5. 4K 的实际输出尺度为逻辑尺度两倍。旧 0.4 概括范围会过早退出；新增独立 0.8 概括候选，并修正近景预测错误钳回 1080p 上限。
6. WASD 起步与松键存在加速曲线，匀速预测不足。增加有界纯值推演，与真实 `_update_wasd` 的按住、松键和同步缩放逐步核对；不更改真实输入更新。
7. 细 HLOD 缩向常驻远景时，终点已就绪使预取跳过边界之前的最后一个细档视野。将原生已有的边缘检查点扩展到显式候选的 HLOD 交接，尺度和位置仍取同一时刻。
8. 普通 HLOD 资源已齐备时，原即时接管仅支持常驻远景和原生模型。补齐普通 HLOD 的驻留查询，最多尝试三个合格目录，仍每帧一次入口、真实覆盖及联合预算核验，避免等待后台返回相同资源的切面。
9. v20 正式重复仍发现同档在扩视野时改选父块/子块，预取资源身份与当前所需不一致。v21 候选在完整叶块集满足原有页数、面数和显示预算时优先固定叶块身份；超限或缺块仍回到完整树求解，不能截断前若干块。该修复须重新验证，不把单轮通过视作结案。
10. v21 仍有偶发预测未命中，包括一次 SPACE 中 9.365 ms 实际停住。v22 使用新的独立 v4 运动概括合同：常驻同源模型可在输出尺度 10.0 以内接管，正常首选仍限 0.8，细资源异步恢复。旧包、非候选及正式默认不获得该资格；新增计数区分概括接管与恢复细节。普通街区近景短暂变粗是明确质量取舍，不宣称像素等价。测试还覆盖放大中不得因概括层的宽资格阻止恢复细档。

生产实现为 v24 的细节稳定修复，v25 另补正常跟飞恢复的回归；全部源码冻结到 `sources-v25.json`。使用 `matrix-v25-*` 唯一证据名，每轮依次执行：3840×2160 普通窗口回程 120 秒的关闭 / 开启对照，再执行 1920×1080 普通窗口 WASD 加快速滚轮 60 秒的关闭 / 开启对照。固定逻辑视野、v4 包、384 MiB 缓存、96 MiB / 240000 面 / 16 页、36 名战斗成员和 VSync；不排除失焦样本。开启组任一验收失败即中止矩阵，不挑选通过轮。

首轮回程关闭组地图限行 230 样本、平移 / 缩放静止 55 / 14 帧、最大整幅间隔 218.792 ms；开启组 15 次返回完成，限行及静止为零，最大整幅间隔 17.710 ms。后续轮次仍在执行，此单轮不构成完成。

v25 带探针矩阵在第二轮滚轮中止：第一轮滚轮最大 17.069 ms、第二轮返回 19.791 ms 均通过，第二轮滚轮虽然限行 / 静止为零，但出现 38.571 ms 整幅间隔（渲染提交 32.637 ms）而失败。源文件、失败记录及原判定完整保留。

## 正常运行路径与探针干扰诊断

FrameProbe 显式开启每个 Viewport 的 GPU 计时。[Godot 4.7.2 的 GL 源码](https://raw.githubusercontent.com/godotengine/godot/4.7.2-stable/drivers/gles3/storage/utilities.cpp)在时间查询回收时读取 `GL_QUERY_RESULT`，没有先检查可用性，存在等待 GPU 的可能。这是可检验机制，尚不能凭源码就认定全部长峰的因果。关闭 FrameProbe、保留选择追踪的同条件滚轮诊断通过：零地图限行 / 静止，最大画面间隔 21.731 ms。

正式运行证据另用 `matrix-live-v25-*`：同一 v25 源码和 v4 包，同样三轮 4K 返回 / 1080p 滚轮前后对照，关闭普通 F5 本来不加载的 FrameProbe 和选择追踪；仍保留每次 `frame_post_draw` 墙钟、相机响应、完整性、预算、焦点和模态样本。原 33.333 ms 整幅门、零限行 / 零静止门及错误门不变，不过滤失焦或失败帧。此批不能与带探针数字混算，也不覆盖带探针的未解释长峰。

正常运行矩阵仍失败：三轮返回最大间隔依次为 17.442 / 16.782 / 18.218 ms，45 次返回全部无地图限制或镜头静止；滚轮前两轮为 28.338 / 16.782 ms，第三轮为 44.605 ms 而失败。三轮滚轮共 2880 次输入，地图限制 / 平移静止 / 缩放静止全部为零。失败帧在 10.846 s、原生细档、当前资源请求为零、窗口聚焦，采样与输入耗时很小且没有进度文件写入。此结果否定“关闭探针即可消除全部长峰”，不得将此矩阵改判成功。

v26 开始研究主动运动概括：旧实现只在资源来不及时使用概括，快速移动仍可能全程显示原生细档并继续换档。现在同一显式 v4 合同在超过既定运动阈值时主动选择完整常驻根模型，后台停止细树预取，正常跟飞扣除玩家速度；停止后原选择器和 150 ms 稳定门恢复细节。所有真实覆盖 / 资源 / 显示 / 联合预算门保持，默认关闭。另为 FrameProbe 增加只计 CPU 阶段、不启用 GPU 时间查询的显式诊断，缺失的视口计时记为 -1，不伪报为零。改进效果仍须重新测量。

v26 的新增测试漏填跟随 `rate`，v28 的新增接纳测试漏填 `status`，两轮均由错误门判 86，不能记作通过。分别补齐正式输入合同后 v27 / v29 聚焦回归通过。v27 真实诊断虽为 19.562 ms，但检查发现后台缺少常驻就绪快照，不能用它证明主动概括生效。v28/v29 为显式候选只传常驻根的实际就绪键；同一已显示根激活运动模式只更新质量状态，不重绑 GPU，并补真实 SceneTree 的快照和稳定期回归。

v29 两分钟 CPU 阶段诊断（GPU 查询关闭）实际 14309 帧全部显示目录 6 的完整常驻概括，激活计数 1，1920 次滚轮输入，36 名战斗成员 / 实际弹道和命中均核验；零地图限制 / 平移静止 / 缩放静止，最大整幅间隔 17.134 ms。持续移动没有恢复细档是预期行为，正常跟飞恢复须在返回测试及像素检查独立验证。源冻结为 `sources-v29.json`。

预定新正式矩阵 `matrix-live-v29-*`：与 v25 相同的三轮 4K 普通窗口 120 秒返回、1080p 普通窗口 60 秒 WASD+滚轮，每项关闭/开启对照；关闭 FrameProbe 和选择追踪，保持 33.333 ms / 零限行 / 零静止 / 完整性 / 原预算硬门。开启组任一失败即中止，不混用 v25 通过轮。

v29 矩阵第一轮回程通过：15 次返回，零限制 / 静止，最大 19.419 ms；9 次概括接管和 9 次细化恢复，近景回中后回到原生细档。第一轮滚轮仍失败并中止：仅完成 28.814 秒可操控时间、448 次输入，随后边界菜单直到墙钟 122.450 秒才被自动取消，缺少后半段操作而判 17 项失败；已有样本最大 16.727 ms，不能用这个数宣称整轮通过。

v30 只修自动复核：菜单处理与可操控时钟移到独立的 `PROCESS_MODE_ALWAYS` 测试节点，仍调用正式选择/调头回调，不能等下一次 `frame_post_draw` 才处理可能停止绘制的模态画面。按实际模态代次标记恢复帧，画面采样仍逐次 `frame_post_draw`，全程失败门和完整输入时长不变；增加无渲染回调的 Headless 暂停恢复及释放消费者回归。此修改不进入普通 F5，生产地图算法仍为 v29。后续必须重新完成整组测试，不能拼用被中断的样本。
