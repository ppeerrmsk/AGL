## 进地图的分阶段处理

1. 单个工作线程在独占、未入树的地图实例上读取并验证目录、准备原生选择数据及资源描述符。
2. 当前与预测选择器共享其私有只读表，仍各自保存查询上下文和缓存。流送物理索引提前生成，主线程接管，避免进场再重建。
3. 主线程沿原预算分帧创建/上传资源；Compatibility 所需的两帧真实材质绘制预热保留。随后按原入口交接战场。
4. 正式三维地图跳过不用的旧矢量研究预热；显式矢量预览保留。分区凭据接合只复制变动行，未改动数据限独占准备过程只读共享，全部校验保留。
5. 加载界面按数据准备、地图绘制、战场准备显示本地化阶段文字；无法量化的纯数据阶段使用活动进度条，不伪造百分比。
6. 取消不等待工作线程，根会话负责收尾并丢弃半成品；下一会话等待旧任务清理，避免并发准备两份地图。引擎强制退出仍须回收任务。

## 成熟方法与本项目取舍

- [Godot 后台加载](https://docs.godotengine.org/en/stable/tutorials/io/background_loading.html)：先请求、轮询状态，完成后再领取；提前调用 get 仍会阻塞。
- [Godot 线程安全](https://docs.godotengine.org/en/stable/tutorials/performance/thread_safe_apis.html)：活动 SceneTree 留在主线程，工作线程独占未入树的数据准备，避免共享可变资源和后台 GPU 操作。
- [Godot 着色器卡顿说明](https://docs.godotengine.org/en/stable/tutorials/performance/pipeline_compilations.html)：Compatibility 需在加载期间实际绘制材质，不能套用现代渲染器的管线预编译承诺。

顺序应为最小启动/菜单 → 选中地图数据 → 首屏与材质预热 → 开始战斗 → 邻区流送。各阶段按依赖及实际成本安排，不应规定一个通用秒数比例，也不能把等待藏到第一段可操控画面。
