# 2026-11-01 东京地图档位交接复核

## 范围与状态

工作目录 `F:\AGL`，共享 main。目标是用户球场截图中的近/中景生硬交接，以及特定倍率的反复跳档。保持原 M20 几何与纹理、1920×1080、36 单位战斗、384 MiB 流送池及 96 MiB / 240000 面 / 16 页显示门。未修改相机移动速度或输入准入标准。

本轮自动验收完成后，LOD_BLEND、DIRECT_RETURN 和 REUSE_TEXTURE 接入已安装 M20 的中央默认配置。普通 F5 不需要参数；显式 0、其他地图覆盖及普通无地图 bench 隔离保持。手动编辑器 F5 仍由用户复核，本记录不能代替人工动态感受。

## 已定位的原因与修复

1. 原 `catalog_index` 的提前细档策略同时影响预取和显示，静止/移动间会在同一倍率选择不同档。候选分开实际显示与提前加载；缩远有 8% 滞回，上端质量期限不延长。后台结果、缓存及主动交接仍经过同一显示资格门。
2. 普通近景偏好与近/中景成对交接相互冲突。中景已经接管后，同倍率高速平移又抢回原生，随后因预算/缓存切回。候选在该共同区保持已接管中景；真正放大到 1.18 才恢复原生偏好。中景无解时的完整原生回退保留。实测固定约 1.188 倍率的多次来回切换消失。
3. 第一版边界预测把所有前探点都截在同一换档入口；旧的缩远截断又采用没有滞回的边界。后续资源直到过界才准备。候选首点覆盖真实入口，后续点从已预测入口继续前探；不伪造资源已加载或显示已提交。
4. 主交接先在共同合法区求两份完整切面，再使用现有互补像素抖动材质。最长 90 ms 按真实时间推进，快速滚轮按剩余合法倍率区间提前完成。两份显示的真实面数、页数和费用一起受原上限约束；任何新镜头需求立即结束旧过渡。共同区不足或联合预算超限时不叠加两份地图，不能把这些情况计为平滑通过。
5. 原生联合切面提前准备最高细档，避免到 1.6 才临时换资源。空间前探保留原多点路线及当前/0.25 秒玩家落点，未采用整条远距离 SPACE 路径加载。
6. C42 修复纹理复用的队列交接：旧 GPU 对象到期时即可交给已明确且规格完全相同的待加载请求，不再等八个共享 I/O 槽空闲才尝试接管。尚未启动请求继承原完整预约；已经启动的请求保留自己的预约并归还旧费用。取消、关闭或关闭复用开关时释放预约；未上传正确新内容前不能从 `texture(path)` 取得该对象。没有扩大池、I/O 槽或上传额度。
7. C43 补齐近景缩远的边界前视野：首个越界预测先备最高 HLOD 上界的 1.001 倍原生视野，接着备上界的 0.999 倍 HLOD 入口，后续点继续到真实可达位置。前一版只准备边界后资源，虽三轮最长画面间隔均低于 25 ms，第三轮仍在 1.2757 倍率出现一次约 4 屏幕像素的未完成平移。保持原准入门，把此样本计作失败；不抬高阈值。
8. C44 将相邻预测的待加载切面传递扩展到原生近景。此前仅 HLOD 传递，原生每个前探点仍从当前显示重新选块，可产生不同父子网格请求。沿用原在途完整性、倍率、预算与下一视野覆盖门；不把预测写入 committed 或 ready 集合。反例在 C43 失败，在 C44 通过。

## 方法依据

- [Godot Visibility ranges](https://docs.godotengine.org/en/stable/tutorials/3d/visibility_ranges.html) 说明滞回用于抑制边界反复跳档，并给出 LOD 过渡及抖动方案。本项目沿用已有不透明材质，不以全屏模糊或截图缩放替代模型。
- [Godot ImageTexture](https://docs.godotengine.org/en/stable/classes/class_imagetexture.html) 建议同尺寸、格式和 mip 配置的频繁更新复用已分配纹理。复用候选只接管已解绑至少两帧、无消费者引用且不在请求/保护集的对象；费用和取消/退出规则仍走同一账本。它不能保证驱动绝无尖峰，必须独立实测。

## 追加：正式滚轮反向与成对交接（C46–C51）

狗斗聊天明确归还时段后，核对 C45 以来仅四个狗斗文件变化，地图源码保留。本轮不撤销这些修改；F:\AGL 仍为共享 main。再次检查发现两个独立缺口，新增修复如下。

1. 正式鼠标入口原为放大乘 1.1、缩小乘 0.9；一进一退得到 0.99，而已有直接调用控制器的部分测试使用 1/1.1，未覆盖实际入口的漂移。正式生存与旧沙盒入口现在共用互逆常量，放大仍为 10%，缩小除以 1.1；上限、下限、相机推进速度和 SPACE 行为不变。两个正式入口的回归在旧实现失败 4 项，修复后显示节拍专项 51/51。断言同时覆盖松键不重复、50 轮反向不漂移、目标不瞬改显示相机及原倍率上下限。
2. 修正步长后，同一位置能够持续穿过原生/最高 HLOD 边界，暴露原成对切面交接后丢失反向后继的时序问题：后台来不及重建时会在 1.25 精度上界直接接管。保留原切面及原反向阈值，每次交接剥离其自身后继，数据深度有界；不保存递归历史或新的 Object 缓存。就绪、覆盖、资格、池余额及显示联合预算门全部保留。新反例在旧实现失败 2 项，修复后 20 次往返通过，快照未被改写、数据不增长，未就绪/缺覆盖/超预算仍拒绝。
