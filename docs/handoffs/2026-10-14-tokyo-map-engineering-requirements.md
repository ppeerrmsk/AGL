# 东京湾地图工程接手需求书

日期：2026-10-14。性质：基于既有批准规格的实施委托与交接清单，不是新设计规范，也不代表任何未验收候选获准上线。

入口：[地图问题研究与接手索引](2026-10-14-map-upload-guide.md)。配套：[当前进度与技术瓶颈报告](../audits/2026-10-14-tokyo-map-technical-status.md)。权威：[东京湾地图规格302](../specs/systems/tokyo-bay-volume-map.md)。冲突时以最新用户授权及该规格为准，不能把历史实验预算当现行预算。

## 1. 委托目标

将东京湾全256块来源制作成可在正式引擎入口验收的地图：正常相机移动、缩放及跨区时完整连续显示，保留楼体高度、侧墙、道路水绿地和重要建筑；与完整战斗共同运行，并通过原有资源、性能和退出门。

当前有可复用的源数据、概括几何、编码库及局部GL成果。不要从零重生产全部数据。优先接手175完整局部楼体基线，同时评估如何合并已有压缩几何分支；不能只交付新的孤立屋顶或接口样件。

## 2. 不可擅自改变的条件

| 条件 | 要求 |
|---|---|
| 范围 | 权威256块；31块旧边缘集合不是全图 |
| 联合面数 | 当前实际显示与必要交接按规格联合核算，240000面；不得只算屋顶 |
| 页预算 | 16逻辑页；另外记录实际surface、draw、材质/纹理对象，三者不能互相代称 |
| 内存 | 192MiB＝201326592字节；保留约定的三份保守费用，不凭释放采样或COW猜测扣除 |
| 显示 | 保持VSync、2×MSAA、认可美术和完整战斗；不通过隐藏战斗负载赢得性能 |
| 相机 | 不限制正常拖拽/缩放，不冻结镜头，不用过期图像或未获准远景遮掩缺块 |
| 保护 | 重要楼、高楼、正式游戏楼、道路、水绿地、受保护孔洞不动；来源身份可追溯 |
| 正式默认 | 候选资格未过，不切换正式M20；实验入口与正式入口明确隔离 |

普通低层住宅强概括已经授权，无需重复请求同一授权。规格中的6米高度带、24世界单位总轮廓距离、4至8角目标、240跨度等是有保护条件的候选规则，不是无条件强制简化。不得伪改 `height_source`、填受保护孔洞或删除未明确归属的源对象。具体资格以302正文为准。

允许复用已有侧墙屏幕阈值规则：仅对身份和资格完整的普通低楼，在 `height_m × 0.5 × sin(38°) × scale < 2像素` 时按规范省略墙；超过阈值或保护对象仍需墙体。不得自行扩大豁免。

## 3. 首先建立可复现基线

接手者应先提交一份小型复现清单，至少包含：

- 当前源码快照及dirty/untracked清单，不能只提供Git HEAD。
- 175请求、所引用的控制与候选资源、输出报告、截图及SHA256；保留源身份账172、候选164与正确绕序依据。
- 若采用压缩屋顶分支，补165/166资源、shader与实际GPU布局；说明它尚未用于175完整楼体。
- 依赖版本、输入路径重绑定办法、环境变量和bench命令；生产脚本与产生该资产的版本绑定。
- 旧失败证据只读保存，新增输出使用新目录；不要覆盖175或重写历史通过记录。

本机入口链为既有 `tokyo_cells_lifecycle` → 显式分区诊断 → `vector_roof_compare/native_joint_patch`。参考代码为 `scripts/tests/tokyo_native_joint_preview.gd`，最新请求位于 `tmp/tokyo-complete-production-02/joint-boundary-175/request.json`。这些是隔离测试，不是正式F5接入。

复现示意命令如下，必须先把请求复制为新输出目录的版本，并更新其中本机路径及摘要；不要直接覆盖原证据：

```powershell
$env:AGL_TOKYO_PARTITION_STREAM='<已重绑定的新请求绝对路径>'
$env:AGL_TOKYO_PARTITION_STREAM_SHA=(Get-FileHash $env:AGL_TOKYO_PARTITION_STREAM -Algorithm SHA256).Hash.ToLower()
& bench/run.cmd tokyo_cells_lifecycle 1 180 Shadow Visual
```

只通过bench启动引擎，使用现有普通TEMP Shadow。测试前查所有工作树锁、全机引擎/同步/生产进程、RAM至少7.5GiB及磁盘安全余量。不得抢锁、并发引擎、建冷副本或在引擎运行时写项目。测试结束清理该次环境变量，再决定后续测试。管道退出码不能代替日志末尾bench退出码。

## 4. 必须交付的工程能力

### 4.1 完整来源与几何替换

为地表、保留原生楼、概括屋顶和侧墙建立同一来源账。每个被替换原始对象必须有明确身份、保护分类、替代表示和高度来源；一个源不能重复计费或重复删除。孔洞墙和外墙绕序、法线均需校验。源身份有歧义时保留原生，不以坐标接近裁定删除。

当前172仅关闭最高密块的源楼匹配：2050组中2049组complete；175进一步阻断共享来源后接受2048组、两组保留原生。将其扩展到其他块时必须保留这个保守语义。提交跨块重复来源、缺失来源、保护对象和高度误差报告。

### 4.2 统一近中远表示与实际成本出口

对同一代表性范围同时包含所有层，在近、中、远和档位过渡分别提交：实际可见/提交面数，surface/draw，逻辑页，GPU打包通道字节、索引宽度、目录和纹理大小。源数组长度不是最终GPU费用。

可以提出空间分段、共享几何、授权住宅概括或不同档位的合法表示，但需要完整实物验证；不能继续用屋顶降幅代表整套收益。若细分减少面数却增加draw，须给出同一负载下的实际权衡。

175当前候选比原生多937面，169远档在未加完整楼体时已超2212面，155全屋顶特定布局三份超88291500字节。这些是必须针对的基线，不要求保留失败架构，也不允许忽略。

### 4.3 真实资源所有权及预算

资源账以物理身份去重，区分逻辑引用和实际分配。至少列出：

- 当前可显示资源、接替资源、共同共享资源与不能共享的副本。
- CPU输入/解码/索引、固定输出、目录和对象元数据。
- GPU顶点、索引、纹理、对齐及分层填充。
- 文件读取、解析、上传工作区、更新暂存、延迟释放的旧资源。
- 各加载阶段的同时存活集合与峰值；说明三份保守费用覆盖哪些项，哪些另计。

不得把整个离线库偷偷计为“无需内存”后又一次读取；不得既计共享又保留第二套未计费对象。驱动不可观察部分必须标明边界，不能用“函数返回后释放”证明峰值。理论账、登记计数和实测分别列出，不混写。

### 4.4 连续覆盖和原子提交

定义每个已就绪状态合法的相机位置、缩放及来源包络。真实输入改变相机时必须有完整合法表示；旧状态超出合法范围不能继续冒充成功。目标三层/多层全部就绪才发布，取消和失败不发布半成品，也不能提前回收当前仍引用的资源。

正式拖拽没有速度上限，不能靠选定慢速轨迹推导必然准备时间。需要说明系统如何覆盖突发跳转、往返、缩放穿档、边角、取消与资源未就绪。若在原约束内无法实现，应给出明确反例、缺口及需用户决策的最小取舍；不要暗改相机规则。

## 5. 验收矩阵

| 门 | 必交证据 | 不接受的替代 |
|---|---|---|
| 来源保护 | 全范围身份覆盖、保护清单、重复/缺失检查；高度、孔洞和侧墙审查 | 同位截图相同就认定来源齐全 |
| 联合预算 | 所有层同视野，当前/接替/在途完整物理账与实际提交量 | 单屋顶、文件压缩率、旧候选薄余量 |
| 连续显示 | 第一轮每显示帧推进姿态、不等稳定；第二独立重放同姿态，等待3帧取参考；逐帧对拍并做来源覆盖核对 | 每姿态停两帧的175式稳定测试 |
| 边界与档位 | 全边缘、角点、往返、近中远、档位端点和非整数缩放、突发合法输入 | 两中心预加载切换或限制镜头范围 |
| 美术 | 同位原生控制与候选实景，非空负对照，审查道路/高度/孔洞/保护楼；记录可接受差异的授权 | 仅像素稳定或通道差统计自动批准 |
| 运行时 | 修改代码先focused，再all：`bench/run.cmd all 1 300 Shadow Headless`；错误门不绕过 | 只看Godot原始退出0或断言摘要 |
| 正式入口 | 正常F5进入、正式地图与战斗使用候选路径，无诊断注入依赖 | 隔离SubViewport显示成功 |
| 完整战斗 | 代表性完整局，含正常任务、战斗、升级、BOSS与结算，记录同期后台负载 | 静止地图或删减战斗对象 |
| 严格60FPS | 按性能守则的Visual墙钟记录，报告平均、最差、p1、低于60帧数；低于60帧数为0 | Headless、平均60、诊断读回性能、理论带宽 |
| 退出 | 清理与退出日志，无未归属对象/资源存活；关闭当前14/7告警 | 某专项weakref为0或all wrapper0 |

性能测试必须与图像读回诊断分离。沿用项目性能守则的代表性混合战场与所需地图专项，不另造更轻的负载。VSync、分辨率、抗锯齿、实际可见战斗对象和后台活动写入证据。

## 6. 推荐执行顺序与停止条件

1. 固定175基线和依赖清单，纠正测试命名与证据等级，建立不会覆盖历史结果的统一入口。
2. 选择一个包含地表、普通住宅完整楼体、重要楼和孔洞的代表性中远档范围，先做完整表示及实际提交。新方案须有明确联合成本出口，而不是另一个孤立小探针。
3. 在同一运行路径接入就绪状态与真实不间断运动测试，解决覆盖和取消/提交；复用已过的接口、编码和绕序证据。
4. 通过后按有界批次扩展全256块，检查全边缘、密集区和过渡；不把最高密单块降幅直接外推。
5. 候选资格完成后接正式F5，执行完整战斗、严格性能和退出门，再决定正式切换。

若两条候选均没有联合成本收益，或一个阶段到了既定审查点仍无目标证据，应停止该路线并提交数值反例、已排除原因、下一结构性方案或所需取舍。不得不断调整微参数、重跑未修改all或用新的短期限掩盖延期。此顺序是工程建议，不预先批准某一架构。

## 7. 交付物和接手问题

最终应交付可复现源码与资源清单、来源/预算报告、自动回归、连续显示记录、Visual性能记录、完整局与退出证据、正式入口接入说明和回退办法。所有产物绑定源版本与摘要，失败记录保留。

希望接手者首先回答四个问题：

1. 完整楼体在中远视野的主要费用来自哪些层，怎样在不损坏保护对象的情况下真正下降？
2. 选择常驻、分层或流送的哪种组合，如何满足无速度上限正常输入的立即合法覆盖？
3. 该组合在最坏当前/接替/上传阶段的面数、页数、draw和物理费用分别是多少，哪些是实物证明、哪些仍是上界假设？
4. 怎样把现有屋顶压缩成果接到完整楼体运行路径，并用规格规定的连续帧测试而不是逐姿态等待证明它？

工作交接前须约定唯一写入与引擎测试窗口。当前聊天存在自动推进检查，不能假设它已暂停；外部开发开始前应由用户协调停止或分配窗口，避免共享工作树和显卡竞争。本需求书不自动关闭该检查，也不授权删除旧成果。
