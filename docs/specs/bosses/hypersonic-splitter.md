# Black Star / Hyper-A（高超音速分裂体）

> 代号 **Black Star**、机体型号 **Hyper-A**。两架根机先后从超高空俯冲轰炸入场；每架都以自身粉身碎骨为代价完成三次火箭分段式二分。它本质上仍是速度极快的战斗机，高超音速只用于有预警的登场、再入和冲刺。

> **v16 已实现并验收。** G0 是全向锁定 / 离轴发射阶段，G1 恢复普通前向规则；G1 HP 为 `200`。初次身份横幅不再把隐藏根机当作固定地点的飞行演员；横幅收尾后，第一根机直接在当前玩家附近进入真实下降，玩家机仅做视觉隐身，状态栏连续显示高度变化。当前四代 HP 为 `400 / 200 / 100 / 70`，每棵树总 HP `1760`，双根总 HP `3520`。

## 1. 设计意图（Why）

- 登场先给信息、后给伤害：身份横幅结束后，BOSS 状态栏先显示 `30,000m`，危险圆与高度同时倒数约 4 秒，随后才结算落点爆炸。
- 常态是遵守飞机物理包线的顶级高速战斗机；高超音速位移是稀有、清晰、有界的特殊行为。
- 单体威胁随代际下降，目标管理压力随 `1 → 2 → 4 → 8` 上升；每一代都改变武器和招式，不只是缩血量。
- G0–G2 每次冲刺后必须主动靠近当前操控机散热，以标准 `SLOW` 给玩家真实攻击窗口。
- 父体死亡必须表现为粉碎与分段；两个子体从父体碎裂点分离，不得像凭空召唤复制品。
- 最坏 16 个 G3 同场时仍以读线、走位、目标管理为核心，禁止全员同时冲刺或制造无界特效。
- 现实视觉只参考 NASA X-43A 的低矮升力体、黑色热防护主体与浅色边缘，不使用 X-43A、Hyper-X 或 NASA 作为游戏内名称 / 商标。

### 2.3 导弹与枪械

| 参数 | 值 |
|---|---:|
| 四代导弹弹匣 / 装填 | `4` 发 / `20s` 自动装填 |
| 单轮冷却 / 伤害 | `1.5s` / `90` |
| 最大速度 / 过载 | `1600 m/s` / `40G` |
| 射程 / 最小射程 | 后向 `20,000m`、前向倍率 `4.5` / `400m` |
| 全场在途总上限 | 不另设 BOSS 专属硬上限；仍遵守一机对同一目标的共享有效弹约束 |

实际齐射数为 `min(代际锁容量, 合法不同目标数, 当前弹匣余量)`。因此 G0 能维护 8 个不同目标锁，但满弹匣一轮最多实际发 4 枚。Hyper-A 标记为饱和攻击者，不受队友预计伤害的全局“够杀了”抑制，但不会在同一轮向同一目标重复分配。

- 四代 Hyper-A 的导弹齐射均为独立火控通道：只要处于允许战斗的常态 / 散热阶段，就会扫描自身合法满锁目标并发射，不受战术规划当前把主武器选为机炮还是导弹影响。下降、爬升、冲刺蓄力 / 冲刺 / 冲刺后靠近阶段仍由 BOSS 状态机统一关闭武器。
- G0 即使正在使用点射激光，也不能因此永久饿死其 8 锁导弹通道；G3 的机炮狗斗同理。G0 是四代中唯一拥有全向齐射许可的阶段：主雷达半锥角为 `180°`，可持续锁定机身任意方向目标；满锁目标仍须位于导弹射程内。
- G0 对合法满锁目标发射时不要求机头先对准，也不受普通飞机的稳定发射姿态 / 前置点质量门阻断；导弹离架航向直接指向目标当前方位。机体本身不瞬转，后续制导仍走共享导弹物理。
- G1 恢复普通前向 `45°` 半锥与正常稳定窗口 / 前置点质量门；G1、G2、G3 均不拥有全向或离轴发射豁免。四代独立通道只绕过“主武器模式”闸门，不绕过各代仍适用的锁定、雷达锥、射程与在途重复约束。

- G0 点射激光复用忠诚僚机脉冲炮：`20` 伤害、`60 rpm`、`1800 m/s`、`1400m` 射程。
- G3 机炮：`13.5` 伤害、`3000 rpm`、`1200 m/s`、`1350m` 射程、`520` 发弹匣，`20s` 装填。

- 第一根机在身份演出完成后立即进入 4 秒倒数；第二根机在第一根机落地后 `18s` 独立开始倒数，不依赖第一棵树 HP / 代际 / 存活。
- 第二根机的战中登场不暂停、不慢放、不强切镜头；危险圆、状态栏高度和音效承担理解成本。
- 两架根机都在各自真实下降开始时自行播报；说话人分别为 `BLACK STAR-01 / 02`，台词分别为“一号机 / 二号机已突破十马赫，正在高速下降中”。不得由敌指挥部、预警机或无身份旁白代为发现 / 解说。
- 根机倒数与 G1 / G2 隐藏再入阶段均不可锁定、不可受伤；模型不可见。
- G0 分裂产生的两个 G1 不在父体碎裂点直接显形：创建当帧即处于 `30,000m` 隐藏下降，状态栏与危险圆先出现；4 秒撞击结算后才揭示 G1 模型并进入常态战斗。
- G1 / G2 每次落地后 `40–50s` 才可再次尝试爬升；新分裂出的 G2 同样至少正常交战 `40s`，不会出生后立刻使用爬升 / 俯冲。全场同时最多 `1` 个爬升、超高空等待或再入倒数；高空序列占用期间其余分裂体暂停再入倒计时，当前序列开始时又把其它候选者推迟到至少 `12s`，避免多架排队连续轰炸。
- G1 / G2 的爬升阶段为 `2.5s`：达到 `15,000m` 前仍可见、可锁定、可受伤；越过阈值时才隐藏并免伤，同时立即解除所有单位对它持有的 `combat_target`、`commanded_target`、副目标、主 / 副雷达锁存与旧追击点，并移除雷达扫描余辉。隐藏阶段不可重新点名或自动选中，不能残留指向空地图的追踪 / 航迹线或雷达红点，也不能表现成仍可追踪的光学隐形。
- 爬升与俯冲不再首尾相接：完成爬升后先在不可见高空独立等待 `7–10s`，状态栏持续显示 `HIGH HOLD 30.0km` 与剩余秒数；等待结束才锁存新的玩家落点并开始 4 秒俯冲预警。G1 首次由 G0 分裂生成时的隐藏下降属于登场契约，不计作循环技能，不取消。
- AOE 圆、倒计时、状态栏高度与伤害半径共用同一份运行时快照。

| 参数 | G0 | G1 | G2 |

| 最短蓄力 / 对线放弃 / 冲刺时间 | `2.4s / 12.0s / 1.2s` | 同左 | 同左 |

| 冲撞伤害 | `55`；同一冲刺对同一单位最多一次 | 同左 | 同左 |
| 急刹冲击波半径 / 全角 / 伤害 | `900m / 110° / 45` | 同左 | 同左 |
| 冲刺后延迟 | `1.2s` | `1.2s` | `1.2s` |
| 散热接近距离 / 最长接近 | `700px / 5s` | 同左 | 同左 |

- 全场同时最多 `2` 条攻击线、`2` 架冲刺；第二根机登场 / 任意高空再入倒数优先，期间不再发起新冲刺。
- 选线以当前操控机或存活僚机位置为机会点，蓄力开始时锁定方向；危险线以机体当前位置为近端，在 `2.4s` 内由近到远生长至完整 `3200px`，不瞬间铺满屏幕。
- 蓄力时禁止直接写航向、位置或 `speed = 0`。机体关闭攻击并以共享飞行物理减速到 `max(1.35 × 失速速度, min(0.45 × 巡航速度, 600km/h))`，持续把航点放在锁存方向远端，靠真实滚转 / 转弯逐步对线。
- 最短蓄力结束且机头与攻击线误差不超过 `6°` 才能冲刺；`12s` 仍未对线则取消本轮并短暂退回常态，绝不瞬间改写航向强行发射。这个上限允许最坏的 180° 背向起步完成一次真实掉头。
- 蓄力、对线和冲刺期间均可锁定、受伤；只有超高空隐藏阶段免伤。
- G0 / G1 每次冲刺在约三分之一进度发射左右各 `5` 枚火箭。每侧优先选择冲刺航向对应侧的玩家 / 僚机位置；该侧无人时，在最近友方附近偏向该侧生成逼位落点。
- 火箭复用共享弹体：`24` 伤害、`420 m/s`、`2400m` 射程、无额外 AOE；10 发只生成一批，有界且不重复补射。
- 冲刺抵达终点并急减速时，以锁存的 `dash_to` 为圆心、`dash_dir` 为扇区中轴，向机头前方释放半径 `900m`、全角 `110°` 的一次性冲击波；扇区内每个敌对单位受到 `45` 伤害且每次冲刺最多结算一次。冲击波不绕过阵营、无敌或既有伤害规则，不附加击退。
- 急刹扇区不能在攻击线刚出现时提前显示：只有由近到远生长的攻击线完整连接到 `dash_to` 后，才显示终点完整扇区。扇区圆心、方向、半径和夹角与伤害判定消费同一份运行时快照；冲刺结束时再用 `0.65s` 的扇形扩散波确认实际结算，表现范围不得大于判定范围。
- 冲刺后主动靠近当前操控机到 `700px` 或最多追 `5s`，随后直接写入标准 `SLOW` 状态账本 `6s`，绕过未来外部减速免疫。
- 标准 `SLOW` 权威效果保持：目标速度上限 `350 km/h`、滚转 ×`0.6`、关闭加力；本 BOSS 的冲刺后持续时间由 `5s` 延长到 `6s`。散热期正常锁定、正常受伤，不额外减伤。

### 2.6 分裂

- G0–G2 归零后等待 `0.65s` 分段演出，再在父体最后位置左右 `160px` 建立两个下一代子体。G0→G1 是显示例外：G1 节点建立后立即转入隐藏下降，撞击前不绘制机体；G1→G2 与 G2→G3 仍在分裂点直接显形。
- 子体继承父体根树与完整路径，朝向在父航向两侧各偏 `18°`；出生后 `0.8s` 免伤，防同一爆炸连锁清空。
- 待生成账本在父体死亡当帧增加，在两个子体均成功创建后原子核销。
- G3 死亡永久结算叶节点，不再生成。

## 3. 行为与公式（How）

### 3.1 Encounter 与单体状态机

```text
ROOT_PENDING → DESCENT_WARNING → IMPACT → ACTIVE_G0

on G0/G1/G2 defeated:
    live.erase(parent)
    pending_split += 1
    0.65s 后 spawn(path.1, path.2)
    pending_split -= 1

G0→G1 spawn:
    create G1 records at 30,000m
    hide model + disable lock/damage/weapon fire
    4s warning → impact → reveal model + enable fighter combat

victory = roots_arrived == 2
       && pending_roots == 0
       && pending_split == 0
       && live_nodes == 0
       && terminal_g3_defeated == 16
```

```text
G0–G2:
FIGHTER_COMBAT → TELEGRAPH(≥2.4s，直至物理对线) → HYPER_DASH(1.2s)
  → BRAKE_SHOCKWAVE(瞬时；前方扇区 900m / 110° / 45伤害)
  → POST_DASH_DELAY(1.2s) → COOLDOWN_POSITIONING(≤5s)
  → COOLDOWN(SLOW 6s) → FIGHTER_COMBAT

G1/G2 另可由 FIGHTER_COMBAT（落地 / 分裂后 40–50s；其它高空序列期间暂停倒数）：
CLIMB(2.5s；15km 前可攻击) → HIGH_ALTITUDE_HOLD(7–10s)
  → HIDDEN_DESCENT(4s；不可攻击)
  → IMPACT → FIGHTER_COMBAT；下一候选者至少再错峰 12s
```

所有 Hyper-A 节点由单个 encounter 编排器更新；不为每架新增 `_process` / `_draw`。AI 的正常 BFM 与武器循环仍由共享 `AIController` / `Aircraft` 执行，特殊状态只在进入 / 退出时切换 AI 战斗许可。

### 3.2 状态栏

- 常规 BOSS 沿用原有 5 卡布局；Black Star 通过 `BossEncounter.get_hud_entries()` 提供紧凑树条目，HUD 自动切换到专用网格文本，不按 boss id 写 UI 分支。
- 每个活节点显示完整 `Hyper-A…` 路径、代际、HP；处于 `DESCENT / CLIMB / HIGH HOLD` 时追加状态、高度与秒数，`DASH / SLOW` 显示状态。机体因爬升跨过 `15,000m` 消失后，条目仍保留到再次俯冲显形或被击毁。
- 每次分裂在父卡片消失、两个子路径出现的同一次数据刷新中原子更新；最多 16 个条目，4 列排布。
- 连续高度倒数由 encounter 快照直读，不提高普通 HUD 全局刷新频率。

### 3.3 演出

- 初次登场仍走统一 `black_star_arrival`，但只承担 `0–1.5s` 的系统入侵身份横幅；隐藏根机不是可供特写的飞行演员，不再切到固定事件锚点展示它“原地飞行”。
- 横幅收尾时解除暂停并释放演员，镜头保持 / 返回当前玩家附近；`sequence_finished` 后进入 ENGAGED，亮状态栏并立即启动第一根机 `30,000m → 5,500m / 4s` 的真实下降。
- 第一根机的下降落点锁存在开始时的当前玩家位置。倒数期间玩家仍可控制、仍可被雷达和武器正常感知，只把机体视觉透明度暂时降为零；撞击结算或事件异常收尾时必须恢复原视觉透明度，不得借演出获得隐形玩法收益。
- 状态栏高度、危险圆、伤害落点与根机实体消费同一份 encounter 运行时快照；演出不另造 K 帧高度或平行倒计时。
- 第二根机与 G1 / G2 再入不重复全局身份横幅、不暂停战局；使用危险圆、下落高度、冲击环和有界爆炸闪光。
- 分裂使用一次碎裂冲击环与两股短分离迹，不为 30 个历史节点保留常驻粒子。

### 3.4 Debug 与验证入口

Boss Debug 的 Black Star 卡提供 `FINAL WAR // OCEAN`、`FULL ENCOUNTER`、`G0 OMNI SALVO`、`G1 REENTRY`、`G1 FORWARD SALVO`、`G2 DASH`、`G2 BRAKE WAVE`、`G3 DOGFIGHT`、`SECOND ROOT`、`COOLDOWN WINDOW`。`G0 OMNI SALVO` 把玩家摆在 G0 后方，`G1 FORWARD SALVO` 把玩家摆在 G1 正前方；两者都不注入锁定进度或伪造发射。`G2 BRAKE WAVE` 只把玩家放到真实冲刺终点扇区内，不直接扣血或跳过冲刺状态机。

`FINAL WAR // OCEAN` 是关底规模校准沙盒：加载海洋群岛正式 MapDocument / 底图 / 天气，把玩家选择的 T4 路线自动推进到一个相连的 T5 终局节点，并生成同型四机队、8 点三轴、3 件三星战区军械和同级正式技能 Build；另一支 AI 控制的友方玩家队使用不同 T5 节点并遵守同一满配规则。战场另有 4 架普通友机、2 艘友舰、6 架先进敌机和 2 艘敌舰。全部单位使用真实阵营、AI、武器、伤害与死亡语义，不锁血；普通友军 / 敌军不伪装成玩家队，Black Star 仍走双根、分裂、再入与唯一胜利条件。F8 完整重开并重抽两支玩家队的正式 Build。

场景选择通过 `boss_debug_scenario` meta 传给 encounter；F8 重开 / 重 roll 保留它。Debug 只改变起始编成和状态，不伪造伤害、锁定、SLOW、分裂或胜利语义。

## 4. 结构与组成（Structure）

- `HyperABoss extends BossEncounter`：双根时间闸、节点账本、分裂、特殊行为、胜利。
- 四份 `AircraftParams` + 一份 Hyper-A 导弹资源：物理、武器与视觉尺寸的 SSOT。
- `HyperAThreatOverlay`：只消费 encounter 锁存的 AOE / 攻击线 / 冲击快照；不拥有伤害。
- `BossEncounterEvent` / `SurvivorSpawner`：类型派发、统一身份演出与 BGM。
- `BossEncounter.get_hud_entries()` / `SurvivorHUD`：通用自定义 BOSS 树 HUD 协议。
- `BossDebugSelect` / `SurvivorMode`：Debug 场景选择与传递。
- `BossRegistry` / `sequences.json` / i18n：正式轮换、横幅、无线电和三语文本。
