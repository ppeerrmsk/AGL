# ORION 完全体 — Crucible 隐藏终局

> 曾经被反复击落的 Cre，以大型前掠翼本体与 FANG 双机重返熔炉；残存王牌把枪口转向它，玩家在饱和齐射与光剑之间决定先拆护卫还是直取核心。

**设计来源**：[用户 Notion 原稿](https://app.notion.com/p/3e0cb899efcd8172be01d332e74fdf01)，读取版本 2026-09-27。2026-09-27 用户明确“开始实装”，批准按当前方案进入制作；基础机动只调机体性能，不追加行动。东京湾独占验证窗口释放后已接入共享运行时。火控/机体规则 42 项与真实 SceneTree 终态 23 项通过；完整回归、视觉、性能和完整局验收记录见 §5.3，不据此标记完成。

## 1. 设计意图（Why）

- 回收宿敌成长伏笔，服务长期新体验；不把已有普通 Cre 放大血量充作 BOSS。
- 保留 Crucible 的真实自由混战与残存 ACE，乱入发生在混战尚未结束时。ORION 首轮清剿必须通过真实导弹与伤害实现，不脚本处决 ACE。
- 威胁分工：本体的多目标齐射逼迫分散与择时规避；FANG 保护接近路线并迫使玩家改变穿线角度；双电磁炮惩罚长时间直飞。
- 用户追加方向（2026-09-27）：ORION 本体是超常无人 BOSS，常态性能显著高于普通战斗机，高 G 与小转弯半径通过本体性能体现；用户最终澄清仅强化机体基础性能，不追加任何行动，也不挂载现有位移滚转技能。
- 玩家能选择“先杀一架 FANG 打开导弹走廊”或“利用 ACE 分担火力快速斩首”。不存在必须先拆两机的免疫门。
- 大型本体 600 HP / FANG 各 250 HP 是用户明确指定的 BOSS 例外；长剑每次 10 伤害是用户指定的持续空间威胁例外。通过独立外形、血条、预警与招式说明身份，不将例外扩散给普通敌机。
- 不新增手动扳机；不改变玩家 2D 物理、既有技能与武器规则。60 FPS、真实伤害和可见反馈同时成立才算交付。

### 2.4 本体基础机动性能

用户要求的是飞机本身滚转迅捷、可承受高 G、转弯半径很小。由既有 AI 在正常飞行、追击和规避中自然使用更强的机体包线；不新增或授予任何特殊机动行动、技能、触发条件、冷却、阶段、无敌帧或专属动画曲线。

初版基础参数提案为 §2.1 的 3000/1600 km/h、18/24G、加减速 90/150、滚转率 6.0 rad/s 与失速基数 180 km/h。数值尚待实飞校准；如果普通转弯仍不够紧，就继续调整机体 G、低速控制/失速、滚转响应及加减速包线，不以追加技能替代。

滚转响应与航迹转弯半径分别验收：前者看改变坡度的速度，后者看实际速度/G 下的世界航迹。高 G、载荷失速和 AI 角点速度必须一起核对，不能只提高纸面 G 却仍被速度/坡度限制卡成大圈。参数统一进入正式物理与 AI 有效 accessor，保持两者认知一致。
## 3. 行为与公式（How）

### 3.1 一场遭遇、两个横幅、一个结算

```text
开局快照 N / Debug 场景
  → 正常 Crucible 横幅 → ACE_RELAY
  → 无资格：原 18 队接力 → ACE 全灭 → 原胜利
  → 有资格：第 16 队激活后 8s → ORION_ARRIVAL
      → 第二次身份横幅 / 暂停 / 三机展示 / 返镜
      → ORION_COMBAT（剩余两队继续原接力）
      → 本体真实死亡 → SUCCESS → 一次胜利与功勋结算
```

- 如果第 16 队和前序成员在 8s 窗内全部死亡，立即启动乱入；不得先判 ACE 胜利。最后两队仍按原 3s 补位规则进入，直到本体死亡。
- ORION 入场不清空 ACE、不复活被击落队、不恢复玩家 HP/flare。暂停由 Presentation 唯一拥有；暂停中双方攻击与冷却都停止。
- 三机在玩家前方的镜头外安全点生成，复用 Crucible 的镜头外、地图边界与编队整体检查；不能在玩家机身上弹出。
- 新横幅以 ORION/FANG 为演员，完成回到玩家后才开火；HUD 同帧隐藏 ACE 多条并显示 ORION 600 HP 主条和两条 FANG 250 HP 状态。ACE 世界标签、目标圈与真实实体保留。
- 入场序列缺失/被 UI 序列覆盖时释放自己拥有的镜头、暂停和指令，退化为立即接战；不得卡死。场景退出/玩家失败时取消未触发攻击，不补发横幅。
- ORION 本体死亡当帧撤销未发射队列、关剑和电磁炮充能，停止 ACE 后续补位；下一事件更新进入胜利。FANG 残存者停止攻击并随场景终态清理，不伪造击落或追加奖励。
- 正式在飞弹的终态按统一战斗结束规则清除；由 encounter 所有权标签精确回收，不销毁其它事件资源。战斗中发射者死亡仍保留已有导弹的常规生命周期，只有整场终态才统一停火。
- ACE/FANG/本体击落不给局内 XP、额外治疗奖励或普通掉落；沿用 Crucible 的 `no_kill_reward` 契约。玩家现有击杀触发技能（包括 BLOODLUST 治疗）仍走共享击杀分派，不为此 BOSS 禁用构筑。THE_CRUCIBLE 的遭遇/击败/地图胜利记录各记一次；增加独立终局 ORION 图鉴发现/击破字段，不增加第二笔通关功勋。

### 3.2 目标分配与反制

1. 对合法目标按“Crucible ACE → 其它敌对非玩家单位 → 玩家及 ALLY”分组，组内按距离再稳定实例顺序排列。隐形/锁定免疫目标不得绕过共享判定。
2. 首轮分配每个目标 1 枚，最多 16 个；存在 ACE 时，最多预留 2 个初始槽给玩家/ALLY，保证玩家仍有压力。剩余初始槽优先 ACE，再其它合法目标，最后玩家/ALLY。
3. 不足 10 枚时，重复槽优先在 ACE 间轮转；无 ACE 时在其余已选目标间轮转。只有玩家一架时分配 10 枚、锁定 6.05s，随后至少间隔 0.75s 发向同机。
4. 每个重复槽都播放一次收缩锁定框；同一目标同时只显示一个动画框与已锁次数，完成次数递增，避免叠十层不透明 UI。
5. 锁定对象在准备期死亡/离开包线/变阵营/进入锁定免疫时，取消它的未发射槽，不在最后一刻转给无预警的另一目标。本轮剩余弹数允许因此低于 10；这是失效取消，不是负载裁剪。
6. 发射后导弹保留自己的合法目标与 flare 状态；0.75s 错峰提供多次威胁，不硬编码“无视 flare”。若现有 flare 有持续范围效果，应尊重该效果；必须用现有实现验证错峰体感，不能声称数学上保证一枚 flare 永不拦多弹。

ORION 开火后机动脱离，在距离当前目标 1800–2600px 的区间重整；即使尚未开火，距离不足 1800px 也进入同一重整意图，不长时间贴脸转圈。重整航路使用自身有效角点速度作为目标/上限，让增强后的 G 和滚转能力实际用于回转；这是既有飞行指令，不是新增机动行动。接近地图边缘时使用现有边界约束；目标死亡或丢失时优先重选活目标，不能依赖过期玩家引用。

ORION 在场时，Crucible 1Hz 目标导演取消专职玩家猎手分配。合法射程内优先 ORION，主机不可锁时选最近可锁 FANG；三机都暂不可锁时继续非玩家队际交战。保留各 ACE 的飞行/武器/规避和真实敌我关系，不能用切换 team 制造临时无伤联盟。ORION 死亡后不恢复混战，直接进入终态。

玩家对策：利用长锁定窗分散小队，错开 flare 与回转；从已毁 FANG 一侧发射；激光熄灭后的 5s 冷却是集中导弹窗口；读电磁炮锁死轨迹后侧向脱离。僚机沿用正式导弹规避；新增长剑危险线应作为有界局部规避输入，不能覆盖玩家点名/手动航路权威。是否需要该扩展由 E1/Visual 僚机穿线次数证据决定，不能先宣布“AI 已理解”。

### 3.3 引用、帧与终态安全

- 跨帧目标、发射者、演员与玩家缓存读取统一 `Variant → TYPE_OBJECT → is_instance_valid → cast`。参数类型检查发生在函数体之前，不能把 freed Object 先传给带类型形参再试图保护。
- 切控/换帅走现有 `BossEncounterEvent._refresh_encounter_player()` → encounter → 子控制器完整传递；ADMM 已提交目标保持该飞机身份，不因玩家换座瞬移目标。
- 暂停恢复、胜利、失败、取消和重复 cleanup 均幂等；释放本 encounter 的信号连接、directive、视觉覆盖和预警快照。
- 终态测试必须继续至少一帧，并跨过最长 1s 消费缓存 tick；断言 signal 次数、权威状态、缓存清空和回调执行到底。

### 3.4 基础性能接入

- 仅通过 ORION 专用 AircraftParams 配置强机体包线，并沿用现有 AI 与飞行求解器；不设置 displacement_roll 能力，不创建独立机动控制器或临时性能模式。
- 普通滚转、转向与加减速由既有控制意图和物理连续产生。机体朝向、世界航迹、受击位置与尾迹保持一致，不用固定横移或指定反转轨迹替代实际飞行。
- ADMM 与双电磁炮维持各自已有攻击节拍；不因这次性能强化增加禁火、取消、重新充能或无敌规则。电磁炮锁死解继续遵守原预警合同。
- FANG 依靠自己的正式飞行追随；ORION 快速转向不直接搬动 FANG 或其激光方向。

### 4.2 机体、美术与音频制作单

- ORION：骨感棱角、大型前掠翼、突出长翼展、双引擎、脊背弹舱、左右对称双电磁炮。长/翼展初版 36m / 44m，FANG 14m / 18m；这是世界几何，不是把碰撞半径同比放大后的无形圆盾。
- FANG：短中央机身、明确机鼻发射口、锐角翼与双尾构造；左右机共用一份几何缓存，使用 FANG-1/2 标识。两个型号均需独立 2D 轮廓与 3D 模型，普通 Cre 外形不变。
- 用户原稿两张参考图作为待逐图核对的造型来源；本轮读取了其文字描述与图片链接，尚未完成图片视觉核对，不声称已按图建模。
- ORION/FANG LOD0 每型 ≤600 三角面，LOD1 ≤320、LOD2 ≤128；屏幕尺寸驱动轮廓分档，BOSS 逻辑不随视觉 LOD 降级。模型必须审计前向、法线、厚度、左右对称、挂点和双通道涂装。
- 原型配色：深灰主体、浅色棱线、红色武器口；常驻 HUD 仍走用户主题和现有危险语义色，不另造全局 UI 规范。
- 发射表现按“脊背垂直弹束 → 扇形散开 → 各自尾迹”三步可读；起飞投影与命中平面分离，不能让装饰尾迹成为判定。
- 激光预警细线 0.8s，活跃线有亮芯；导弹被截点播放现有小爆点，确保玩家看见是剑切断。长度、机头方向、端点均直接读取伤害用 beam 快照。
- 双电磁炮充能声/机鼻光点/锁死线/两次枪声独立可辨；不全屏白闪。
- 机体模型与尾迹呈现正式飞行产生的高速滚转及紧凑转弯，验证机腹/翼面与挂点连续可见；不新增特殊机动演出。
- 音乐初版复用已授权的现有 boss 曲，由 Presentation 在第二横幅切换；新原创曲另列素材工作，未制作前不得写成完成。ORION 沿用无人宿敌静默身份，台词由 HQ/ACE 见证，不给它随意添加驾驶员。
- 玩家文案、横幅和 Debug 名称走三语 i18n；世界首行战术名固定英文 ORION、FANG-1、FANG-2。无线电固定写入 radio.csv。

- 3s 预热后采样 30s；同机同版本、seed、镜头、地图、质量与缓存条件连续三次。分别记录 avg/p1/worst、frames_below_60、实体/弹丸峰值及 CPU/render/GPU 热点，不能将异步均值相加当同帧总耗时。
