# 可选战区任务：轰炸机护送

> `Optional Zone Mission`（可选战区任务）的首个任务：玩家护送友军轰炸机完成一次真实投弹；目标被炸毁才算成功，截止时间到或编队失去投弹能力则任务失败并从战术地图彻底消失。

## 1. 设计意图（Why）

- **体验目标**：让战区不再全部是“迟早都能清掉”的静态清单；玩家必须跟随一支正在移动的友军编队，在有限窗口内保护它完成任务。
- **玩家主角性**：轰炸机负责唯一合法的目标伤害，玩家负责确保它能抵达；任务成功不是靠玩家提前用常规武器拆掉特殊目标。
- **失败可读性**：失败有明确的即时提示，但战术地图不保留红叉、灰圈、墓碑或失败文字；该战区当帧从地图数据源隐藏。
- **Litmus 自检**：投弹与摧毁反馈仍然即时；武器全自动；失败来自可观察的时间和护送对象状态，而不是暗骰。
- **反模式规避**：不把护送写成无奖励的纯背景事件；不把 zone 任务塞进 `GameEvent`；不让常规 AI 或玩家武器绕过战略目标权限。

## 2. 数据定义（What）

### 2.1 首版任务参数

| 字段 | 值 | 说明 |
|---|---:|---|
| 任务类别 | 可选战区任务（`Optional Zone Mission`） | “可失败”是行为属性，不作为类别名称 |
| `mission_type` | `bomber_escort` | ZoneMission 的新任务类型；不经 GameEvent |
| 友军轰炸机 | B-1B ×3 | 玩家护送对象；沿进攻航向排成纵队，前后间距 300 px（600 m） |
| 自带护航 | F-4E ×2 | 以轰炸机长机为移动锚点在两侧伴飞；近敌时可自由脱离迎战，随后归队 |
| 移动战区半径 | 900 px（1.8 km） | 战术地图圆心跟随仍存活轰炸机的平均位置 |
| 任务截止时间 | 150 s | 从任务触发时开始计时；与既有 BomberMission 最大生命周期一致 |
| 特殊地面目标 | StrategicTarget ×1 | 护送任务副本固定 75 HP；永久不可锁定，只接受敌对 `bomber_bomb` |
| 每机投弹 | 1 枚 | 三架各投一次，单枚 75 伤害；任意一架轰炸机成功抵达并命中即可摧毁目标 |
| 目标前航程 | 12500 px（25 km） | 七条航线从长机生成点到目标完全等长；同机型、同速度、同直线航路，因此理论抵达时间一致 |
| 入场点 | 地图边界外至少 1200 px | 在既定航线轴两端中选择能满足固定 12500px 航程且位于边界外的一端；若两端都合资格则优先玩家净距 ≥5000px |
| 航线来源 | 护送航线目录 | 不再从普通 A–G 战区圆内取点；目录逐条定义独立目标锚点与穿越轴线，按同一轴线的两个方向择一入场 |
| 成功 | 特殊目标被轰炸弹摧毁 | 当帧完成战区，只发放特殊经验奖励 |
| 失败 A | 150 s 截止时目标仍存活 | 不发奖励，不计攻克，不增加攻克热度 |
| 失败 B | 全部友军轰炸机被毁且目标仍存活 | 立即失败，不等待倒计时 |
| 失败 C | 全部存活轰炸机已经离场且目标仍存活 | 立即失败；错过释放线不允许掉头补投 |

150 s 是数据默认值，战区定义可以显式覆写；代码不得把截止时间散落到状态机分支。

### 2.2 出现频率与额外候选槽

每局在创建 `ZoneData` 时只掷一次整局配额：

```text
optional_mission_quota = 1 + Bernoulli(0.20)
```

- **每局保底 1 次**；另有 **20%** 概率使本局总配额变为 2，硬上限为 2。
- 第一次从 C / D / F / G 中选一个仅作状态载体；正式局不得在开局帧出现，必须同时满足战斗时间 ≥150 秒、玩家等级 ≥5，且首批 A/B 奖励目标已经开放。它仍是普通战区之外的额外候选，不得吃掉 A/B 的普通任务、普通奖励或武器/次世代保底。
- 第二次即使已在开局决定，也必须等第一次成功或失败结算后，才在下一轮刷新中追加；两次可选任务不得同时在图上激活。
- 出现概率是**整局配额骰**，不是每次刷新都重新掷 20%；不得因玩家反复清区而把低概率累积成必出多次。
- C / D / F / G 只提供生命周期 id；实际地理始终来自独立护送航线目录，所以不会占普通战区圆心。可选任务结算后，该 id 以后仍可按正常规则承载普通战区。

F6 仍可强制把任意战区改为 `bomber_escort`，但 Debug 强制任务不改正式局配额计数。

### 2.3 专属经验奖励

`bomber_escort` 不发航母、僚机、武器、次世代技能或 `ZoneRewardRegistry` 注册奖励；成功后的唯一奖励进入既有 `SurvivorPlayer` 共享经验池：

```text
bomber_escort_xp = 150 × clamp(difficulty_stars, 1, 3)
```

因此 ★ / ★★ / ★★★ 分别固定为 **150 / 300 / 450 XP**。该奖励是任务完成经验，不是击杀经验：不套 `xp_multiplier`、签名机经验乘区、里程碑经验乘区或小队经验分摊，也不触发击杀数、击杀回血、生涯击坠等副作用。战术地图必须在选择前显示准确数值；成功 toast 与经验条浮字显示同一个值。任务失败严格为 0 XP。

任务类型写成 `bomber_escort` 后必须清除该战区已有的普通奖励预告；若任务类型在开战区前已经确定，普通奖励抽取函数应直接跳过，不占用普通奖励、航母 pity 或保底槽。这里的“特殊经验”仍是既有局内 XP，不新增第二种货币或第二条升级系统。

### 2.4 独立航线与地图状态

普通 A–G id 只继续承担任务状态和刷新槽位；可选任务不读取其普通奖励或实际地理。`bomber_escort` 的目标不使用该 id 的 `center`、`radius` 或 `ground_spawn_polygons`，而是从独立航线目录取得：

```text
route_spec = { route_id, target_anchor, corridor_axis }
attack_direction = corridor_axis 或 -corridor_axis
route = [边界外入口, 目标前整队点, 目标, 离场点]
```

目标锚点必须落在“实体陆地”（官方地图同时命中 land mask 与手画陆地轮廓）内；若不合格，只允许在该专用锚点附近做确定性吸附，禁止把桥梁/道路外扩视作陆地，也禁止回退普通战区圆。入口方向必须同时满足固定 12500px 目标前航程与边界外至少 1200px；合资格方向优先满足离玩家至少 5000 px，两端都不满足时取离玩家较远的一端，但不得换到另一条临时生成的航线。三架纵队因 300/600px 槽位间距会依次晚约数秒抵达，但七条航线之间的对应槽位航程完全相同。

任务达到开放门槛后，先由 AWACS 播放 scripted 护送请求；物理目标在广播入队后延迟 6 秒生成，确保玩家先收到任务信息再看到目标出现。

战术地图把该任务画成“航线 + TGT”，不套用普通战区的大面积填充圆。TGT 使用高对比菱形/准星、`TGT` 文本和独立 HP 条；右侧简报同时显示目标 HP、剩余时间、存活轰炸机、存活护航机与当前航段。所有数值由任务层以 10Hz 写入 `ZoneData` 缓存，地图不得扫描世界演员。

世界画面中的 StrategicTarget 从 AVAILABLE 预刷阶段就必须显示黄色 TGT 括号，以及“轰炸目标 / 仅轰炸机攻击有效”的常驻双行提示；不能等玩家进入或选择任务后才标记。提示是静态绘制，不为目标新增 `_process`。

### 2.5 战区终态

`ZoneData.State` 增加 `FAILED`。失败战区：

- 不进入 `cleared_count` / `_ever_cleared`，不影响 BOSS 成功计数；
- 不发奖励、不回血、不加“攻克战区”热度；
- 清除 selected、奖励、难度、任务类型和动态圆心缓存；
- 立即从 TacticalMap 的绘制、hover、点击和信息面板中消失；
- 任务单位撤销 TGT 标记并按“视线外再回收”规则退场，禁止在玩家眼前瞬间删除；
- 正常刷新新的可选战区时，本轮排除刚失败的 id，防止失败圆圈立刻原地重生；以后轮次允许该地理 id 作为一项全新的任务重新出现。

## 3. 行为与公式（How）

### 3.1 状态机

| 状态 | 进入 | 行为 | 离开 |
|---|---|---|---|
| AVAILABLE | 战区被抽取 | 静态预刷特殊目标；战术地图固定显示轰炸目标，并在地图边缘显示尚在场外的轰炸编队 | 玩家选择 → ACTIVE |
| ACTIVE | 玩家在战术地图选择该战区 | 编队从地图边界外真实飞入；截止时间倒计时；移动标记以 10Hz 缓存为存活轰炸机质心；轰炸机按 INGRESS→LINE_UP→RELEASE→EGRESS | 目标毁灭 → SUCCESS；失败 A/B/C → FAILED |
| SUCCESS | StrategicTarget 被 `bomber_bomb` 摧毁 | 发普通 `mission_completed`，只领取 150×星级 XP 并完成战区 | 交给既有 clear/reset 流程 |
| FAILED | 超时或失去任务能力 | 发 `mission_failed(zone_id, reason)`；清动态圆心、撤目标标记、开始安全退场 | ZoneData 保持隐藏终态，等待以后刷新成新任务 |

### 3.2 移动圆心

```text
alive_bombers = members where valid and not destroyed
moving_center = average(alive_bomber.global_position)
if alive_bombers is empty:
    keep last valid center until failure resolves in the same tick
```

`ZoneData` 同时保存两种位置：`objective_center` 固定为 StrategicTarget 实际落点，`dynamic_center` 以 10Hz 跟随轰炸机质心。TacticalMap 用前者绘制/命中高对比 TGT，用后者绘制三机纵队移动标记；场外位置钳到地图面板边缘显示，但不篡改真实世界坐标。导航读取移动中心并钳到地图边界内侧的会合点，不能把玩家自动巡航目标设到边界外。战术地图只消费缓存，不扫描世界节点。

### 3.3 纵队与投弹

```text
lead_spawn = ingress
bomber[i].spawn = ingress - flight_direction * 300px * i
bomber[i].route_point = route_point + formation_offset * blend_to_target
release_count_per_bomber = 1
```

三架轰炸机在进入和排队阶段保持前后间距，接近目标时逐步收束到同一弹带中心，因此按前后顺序各完成一次投弹，而不是并排同时撒弹。两架 F-4E 不计入轰炸机质心、投弹能力或任务成功条件；它们只是降低护送任务的初始压力。

### 3.4 成功与失败权限

```text
SUCCESS iff strategic_target.is_destroyed
FAILED iff deadline <= 0 and not SUCCESS
          or alive_bombers == 0 and not SUCCESS
          or bomber_mission.has_finished_release_and_egress and not SUCCESS
```

判定顺序固定为先 SUCCESS 后 FAILED，保证最后一枚已释放炸弹在截止时刻命中时以目标真实终态裁决。已经离机的炸弹继续按 source team 快照结算。

## 4. 结构与组成（Structure）

- `ZoneData`：整局 1+20% 配额、A/B 外额外候选调度、FAILED 状态、固定目标中心、明确航线、任务状态与动态编队中心缓存、成功/失败后的刷新策略，以及 150×星级的护送 XP 真源。
- `ZoneMission`：持有 `bomber_escort` 运行记录，发 `mission_completed` / `mission_failed`，不混入 GameEvent。
- `BomberMission`：继续负责 10Hz 航路和投弹；增加只读成员/阶段快照与成功/失败信号所需的任务状态。
- `SurvivorSpawner`：继续复用 B-1B、F-4E、BomberMission 和 StrategicTarget 工厂；轰炸任务入口显式接收阵型、每机投弹数和护航数量。
- `TacticalMap`：固定画高对比 TGT、航线、目标 HP 条和任务状态，另画可钳边的三机纵队移动标记；FAILED 永久隐藏，不绘制任何失败残迹。
- `SurvivorMode`：成功绕过普通战区奖励链并把专属 XP 直接加入共享经验池；失败只显示临时提示、记录日志并刷新候选，不发任何成功收益。

## 5. 验收标准（Acceptance / Litmus）

- [ ] 战术地图同时显示固定轰炸目标和轰炸机编队当前位置；编队在场外时标记贴边，不凭空消失。
- [ ] 护送任务使用独立航线目录，不读取普通战区中心/半径取目标；地图表现为航线 + TGT，不占普通战区的大圆面积。
- [ ] TGT 在地图上有高对比标识与独立 HP 条；右侧简报可确认目标 HP、倒计时、轰炸机/护航机存活数和航段。
- [ ] 选择战区后 3×B-1B 与 2×F-4E 均从地图边界外真实入场，生成点离玩家至少 5000 px（无可行候选时取最远点）。
- [ ] 七条目录航线的长机生成点到目标均为 12500px；对应槽位理论抵达时间一致，不因目标位于地图不同方向而改变护送窗口。
- [ ] 三架 B-1B 沿航向排成 300 px 间距纵队，每架只投一枚炸弹；两架 F-4E 可护卫交战但不影响任务成功判定。
- [ ] 任意一架 B-1B 幸存至投弹点并命中时，单枚 75 伤害炸弹即可摧毁护送任务的 75 HP 目标并完成任务。
- [ ] 世界画面从目标预刷起就显示 TGT 括号、轰炸目标名称和“仅轰炸机攻击有效”提示。
- [ ] 目标被实际 `bomber_bomb` 摧毁前，任务绝不完成；常规玩家/AI 武器无法损伤目标。
- [ ] Tab 在选择前显示 ★/★★/★★★ 对应 150/300/450 特殊经验；不显示普通战区奖励。
- [ ] 正式局 150 秒且 Lv5 前不出现护送任务；达到门槛后先播无线电，6 秒后才生成目标。整局仅掷一次 20% 二次配额，最多出现 2 次。
- [ ] 七个目标点全部命中实体陆地；道路/桥梁的海上外扩不能通过目标合法性检查。
- [ ] 抽到第二次时，必须等第一次成功/失败后才在后续刷新出现；两次不得同时激活，且不得消耗普通奖励/pity/保底。
- [ ] 战术地图和任务简报使用“可选战区任务 / Optional Zone Mission”类别名；“可失败”只描述规则。
- [ ] 目标被炸毁当帧完成战区，只发预告的特殊经验；不额外发航母、僚机、武器、次世代技能或注册奖励。
- [ ] 特殊经验直接进入共享 XP，不套击杀经验乘区/小队分摊，也不触发任何击杀副作用。
- [ ] 超时、编队全灭或全员离场但目标仍存活时，任务失败且不发奖励/回血/热度/攻克计数。
- [ ] 失败后 TacticalMap 不绘制、不可 hover、不可点击、信息面板无残留。
- [ ] 最后一枚已释放炸弹在轰炸机毁灭后仍能摧毁目标并优先判成功。
- [ ] 失败单位只在玩家视线外回收，不在画面中 pop-out。
- [ ] 性能：移动中心由既有 10Hz 控制器缓存；TacticalMap 只读；无逐演员新增 process。
- [ ] 已知 seam：玩家 `commanded_target`、战区奖励即时领取、BOSS 时间闸与正式 TGT 权限不被改写。
- [ ] i18n：任务开始、倒计时、成功与失败原因三语齐全。
- [ ] 文档：本 spec 已登记 `_INDEX.md`，状态/重建标记一致。
