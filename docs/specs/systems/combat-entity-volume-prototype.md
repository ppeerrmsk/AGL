# 战斗实体立体质感原型

2026-09-14首次淡出长帧修复：正式prewarm_catalog除缓存网格，还复用既有32×32、两帧独立材质暖绘，在真实MultiMesh颜色/custom_data格式下绘制不透明机身、透明淡出机身及淡出挂载三种实际材质实例；使用正式Environment、2×MSAA继承、关闭无用动态阴影，不显示到主画面。每帧实际draw数至少覆盖三样本才计提交；Headless只报告跳过，退出断开frame_post_draw且释放。此为初始化渲染准备，不更改淡出时序、伤害/单位/挂载权威，不以关闭淡出或战斗来规避长帧。

> 游戏仍是俯视 2D，但飞机、实际挂载和战斗实体看起来有体积；先在真实混战中比较效果与成本，再决定渲染路线和铺量。

## 1. 设计意图（Why）

### 1.1 已确认的产品边界

- 保留现有 2D 模拟、俯视操作、Camera2D 输入、虚拟高度、航空物理、AI、命中与伤害。用户于 2026-09-05 追加批准地图三维显示实验：仅实验路径用 Camera3D 正交投影呈现真实网格，不代表全面迁移获批。
- 希望会动的东西、与玩家战斗有关的东西具有协调的立体质感，不只升级玩家飞机。具体类别见 §2.2。
- 参考用户提供的 Tacview 截图：简洁纯色实体、可辨认的机体结构、明暗和遮挡。参考其表现语言，不复制其相机视角、地形系统或软件资产。
- 挂载必须反映真实装备，允许不完全符合现实的挂架、组合模块和机腹武器。美术适配不能新增装备数量限制，也不能破坏已有装备互斥。
- 大规模混战和 60 FPS 优先于模型细节。允许普通单位按屏幕尺寸简化，但不减真实交战、单位、火力或必要反馈。
- 用户先看正常游戏视角中的实际效果，再决定是否推广。单独模型转台、漂亮截图和 headless 通过都不能代替这个决定。

用户于 2026-09-05 亲自试玩后明确满意，并批准飞机专属三维模型与地图并行制作。本文件的 `approved` 现包括该表现路线的分批内容制作，**不表示长时性能过门或正式默认全量迁移获批**。未完成资产与性能验收仍保持 `reconstruction_complete: false`。

用户随后明确授权把**当前全部飞机专属三维模型制作完成并接入真实可玩版本**，范围包含玩家、敌人、友军、特种航空单位、运行时别名和空中 BOSS。该授权允许在全部验收通过后把选定三维后端切为正式默认；它不把三架批次 A、技术代理或模型画廊提前视为完成，也不授权改写飞行、AI、武器、伤害与虚拟高度玩法。

### 1.2 设计自检与不做事项

继承 [设计哲学](../../DESIGN_PHILOSOPHY.md) 的信息察觉、武器抽象、60 FPS、变强可见性要求：立体结构应让姿态和装备更容易看懂，不能只在极近截图里有区别；不引入现实挂点兼容性作为新玩法门槛；不改变自动开火节奏。

此次不做正式地图全面迁移、正式自由旋转相机、真实高度空间碰撞、新飞行模型、新武器、装备平衡、全局光照、写实涂装、铆钉和面板线生产。隔离模型实验室允许倾斜观察几何体，但不能用它证明正式点击/碰撞或混战性能。拖尾、激光、曳光、爆炸和 HUD 不要求全部换成三维实体。

### 1.3 与现有权威的关系

- [飞机顶视轮廓](aircraft-top-view-silhouettes.md) 继续约束机型辨识、原始轮廓、机体配色与二维安全回退。本文件经用户追加批准后，仅对正式 Survivor 的飞机表现边界作窄覆写：允许一个共享透明 3D 合成层；地图、玩法和其它二维实体不随之迁移，实验场之外仍不得任意新增逐机 3D 节点。
- [战场视觉尺度](battlefield-visual-scale.md) 继续拥有尺寸、世界单位和高度缩放规则；原型不通过放大全体飞机或改变地图尺度制造效果。
- [局内武器库](inrun-weapon-inventory.md) 与各武器 spec 继续拥有装备合法性、归属、弹药和冷却；本文件只增加只读表现契约。
- [UI 设计规范](ui-design-guidelines.md) 继续拥有标签与提示的通用规则，本文件不建立第二份 UI 规范。
- 若后续选型需要改变上述正式边界，先修订对应 spec 并记录用户裁决，不能以原型通过自动替代原有合同。

## 2. 数据定义（What）

### 2.1 固定约束与待测参数

| 项目 | 本原型规定 |
|---|---|
| 默认启用 | 正式 Survivor 当前候选默认启用；Shift+F11 可在同一局回退 PNG，`AGL_AIRCRAFT_VOLUME=off` 启动时完全不创建三维视口。manifest 在最终性能与完整局前仍标待验证，不等于已发布毕业 |
| 玩法参数变化 | 0；不改速度、G、射程、伤害、发射许可、弹药、补弹时间或装备合法性 |
| 世界与高度 | 沿用现有权威；局部模型厚度不等于新增物理高度 |
| 机体配色 | 沿用机型的 `icon_color` / `wing_color`；机翼掩码与每实例副色比值在同一 surface/material/MultiMesh 内恢复双配色，不能因换帅、切控或阵营变化把机身自动重染成 UI 阵营色 |
| 敌我识别 | 沿用现有阵营标记、锁定和状态栏；模型着色不取代战术识别 |
| 稳态性能底线 | `frames_below_60 == 0`，`p1_fps >= 60`，`worst_frame_fps >= 60` |
| 同条件三次中位回退上限 | `avg_fps` 不超过 5%；`p1_fps` 不超过 10%；继承性能守则，不放宽门槛 |
| 所有航空单位视觉档位 | 三级专属机身 LOD 与独立挂载按实际输出跨度裁决：LOD0 完整体积在 `>=22 px` 进入、低于 `18 px` 退出；LOD1 保留机身/翼面/尾翼等主要连通结构；LOD2 极远轮廓仅在 LOD1 `<8 px` 时进入、到 `>=11 px` 才退出。独立挂载仍按 `22/18 px` 迟滞显示；玩家、友军、敌军、BOSS、Sentinel、旋翼机都使用同一画面门，不以运行时身份豁免；PNG 只用于显式关闭、渐隐/隐形或未知 UGC 安全回退 |
| 关键单位 | 玩家、BOSS、王牌、Sentinel 的物理、AI、伤害、武器和世界模拟豁免保持不变；这些属于性能/逻辑 LOD。屏幕很小时机身几何仍可降级，但身份、状态栏、目标线、危险提示、弹道与爆炸等关键反馈不得随模型 LOD 关闭 |
| 资产预算 | 每个规范 LOD0 机体最多 600 三角、LOD1 最多 320 三角、LOD2 最多 128 三角，均为 1 surface / 1 material；当前 71 个完整机体、71 个中档机体、71 个极远机体与 12 个挂载网格首帧前预热为共享只读路由，运行时不逐实体造网格 |
| 实时渲染预算 | 正式飞机层固定 1 个原生输出像素尺寸的透明 SubViewport、2× MSAA，逐显示帧在相机之后同步；批次节点按实际类型惰性创建，每批初始 128 实例并对异常溢出报错 |
| 预估工期 | 资产生产与正式接线已经落地；剩余工期只按最终性能、BOSS 专项与完整局验收记录，不再用批次 A 外推全量模型数 |

待测字段必须在候选方案记录中写出实际取值、测量场景和结果；选型后回填可重建的参数。不能用“低多边形”替代明确的提交、显存和 CPU/GPU 成本记录。

| 旋翼机 / 无人机 | 一架现有直升机与一架无人机 | 旋翼、悬停/平移姿态、很小实体的远景辨识 | 复用实际移动和战斗状态，不能套固定翼假动画 |

### 2.2.1 实时三维候选 A：本次有限实验

- 单个共享 3D 世界和一台正交 Camera3D；无逐机 SubViewport，无新物理服务器、碰撞体或 AI。
- 世界映射为 `(x, visual_height, y)`，1 个 3D 单位 = 1 个现有世界像素。高度仅决定显示层次，不作真实飞行高度；正俯视中不移动点击中心。
- Camera3D 从真实 viewport canvas transform 反算中心、旋转和正交尺寸；逐帧记录投影中心误差，验收最大误差不超过 0.1 屏幕像素。缩放、抖动、旋转保持同源。
- 技术低模由可复建几何代码生成：有分层厚度、机身曲面/折面、薄翼、座舱、尾翼。属于技术代理，不声称逐机型美术完成，也不声称已完成 Blender 生产流水线。
- 静态网格只构建一次；共用顶点色材质与定向光，无 GI、后处理和局部多灯。机翼顶点 alpha 只作不透明着色掩码，`MultiMesh` custom data 传 `wing_color / icon_color`，不拆第二个 surface 或 draw call；阴影单独开关，需记录开关状态。
- 普通机体按结构族共用网格、MultiMesh 批提交；只读一次缓存实体列表，0.1 秒刷新成员，逐帧只同步现有变换；离屏普通机不提交。玩家/BOSS不因拥挤或数量丢失。
- Mother Goose 独立机体；部件位置消费 `WeaponMount.world_position()`，消失消费 `destroyed`。不把老图里装饰发动机数量当成可伤害部件数量，不新增随机伤害或假冷却。
- 光学隐形、传感器渐隐、销毁残骸及未适配特殊机型必须安全回退原显示并计数；不能泄露原本不可见的单位。
- 此次实测的第一切片不冒充已完成所有航空挂载/弹药恢复、地面舰船模型和全 BOSS。上述仍为 §6 后续工作，未覆盖要在报告中明确列出。
- 实验键：`volume_3d_c1/c2/mother_goose` 与 `volume_2d_c1/c2/mother_goose`；后者同地图、光照与相机，但保留二维机体。`volume_3d_lab` 只作静态几何/斜视检查，不计混战通过。

本次可复建参数：5 个共享网格族（固定翼代理、A-10 结构代理、Mother Goose、本体之外的螺旋桨、VLS），合计 1200 个**源网格**三角形；地图静态合并网格 17620 三角形。每批预留 128 实例，溢出显式报错而非丢单位；尚不承诺此预算支持正式全量。材质为顶点 sRGB 色、背面剔除、粗糙度 0.82、无高光、无透明；统一环境光能量 0.35、定向光 0.8，正交阴影。实时显示高度暂固定为 600 世界像素，仅用于层次/投影；真实高度仍只消费原缩放，尚未建立跨高度三维遮挡语义。相机高度 50000、near 0.1、far 100000，阴影距离 80000，机体投影跟随真实 Camera2D；Mother Goose 成对样本固定近景缩放 1.2 并跟随母机。独立 lab 使用近景观察光照，不冒充同条件性能对照。

首批仅替换不透明固定翼代理与 Mother Goose；旋翼、其它专属 BOSS、渐隐/隐身、残骸和离屏普通机回退。多机型代理不是机型美术完成；机翼第二色、特殊机动缩放/俯仰、分层高度、航空挂载与完整损毁资产仍待适配。只允许据实际提交数评价这一有限切片。

#### 批次 A 对初版预算的覆盖（v4）

上段 5 批次/1200 面/17620 面为初版留档。当前实验候选为 7 批次、源机体合计 2180 面，地图 3553 面；F-14/A-10/F-47 分别为 432/412/416 面。仅在预热构建并缓存，`Catalog.key_for` 映射专属机型，其余固定翼保持初版代理；不是所有战斗单位已经专属建模。旧 `volume_3d_baseline_c1/c2/mother_goose` 使用初版三维模型与初版三维地图，是批次对照，不是纯二维正式基线。

地图按文档的 `world_size_m × PIXELS_PER_METER` 生成地表；保留界外列车进场段。仅支持本批 union 地理环，未实现 even-odd 孔洞时拒绝构建。非 land 区域色以地表色向源颜色混合 0.35，作为低对比覆盖；无 DEM 时不虚构山高。道路宽度按 motorway/trunk/primary/secondary/tertiary/residential/service 为 25/20/16/12/9/7/6 px，另加 5 px casing；铁路 18 px 道床、10 px 双轨间距、轨宽 1.6 px，24 px 累计弧长枕木，共享接点斜接长度不超过两倍带宽。机场完整继承源多边形，标线沿其长轴；建筑四边形采用低矮双坡顶，最高处保持源高度，其余保留平顶与窄边。只装饰显示，不生成新碰撞。

观察场新增 `5/6` 三机顶视/斜视、`7` 机场、`8` 全图；导出三机与地图 GLB 及来源许可 JSON。A-10 继承现有参考的 Kaboldy / CC BY-SA 3.0 署名与许可；F-47 明确原创概念。地图最大 12000 面的批次预算不等于性能验收通过。

- 本次主要是一次性入口接线与按键事件，不新增逐实体节点或渲染批次；手动场景复用现有显示循环并允许暂停期运行，另补一个舞台透明度判断。跑 focused、实际 Visual smoke、C1 三维候选复查和默认 all；未改变全场扫描/LOD，豁免重复 C2。用户手动试玩与这次复查不构成性能优化或 60 FPS 毕业，上一轮长测失败保留。

### 2.2.3 全机型专属三维生产合同（v5）

2026-09-05 当前资源快照包含 97 个实际 `AircraftParams.display_name`。按已经批准的同型号复用关系归并后，二维目录提供 51 个现实/已登记规范 key，24 个 legacy 显示名再归并为 20 个原创/特种规范 key，共 **71 个去重三维几何组**。这是可复算快照而非冻结总数；新增玩家机、敌机、友军、航空 Adds、特种单位或 BOSS 航空器时，审计必须自动把新身份加入完成门。

#### 全量运行时候选接线（v6）

- 正式候选在首个渲染帧前建立目录内全部机型的 LOD0/LOD1/LOD2 与挂载共享只读网格路由，当前动态审计为 71 个 LOD0 机体 + 71 个 LOD1 机体 + 71 个 LOD2 机体 + 12 个挂载类型；`MultiMeshInstance3D` 批次节点只在对应类型/档位第一次有真实实例提交时惰性创建，离场后回到 `visible_instance_count=0` 并隐藏。该方案避免首次切档建网格尖峰和空批次常驻 3D 剔除，不生成战斗实体、不改变火力，也不靠隐藏单位通过性能门；数量始终由目录动态重算，不把当前路由数冻结为永久合同。

## 3. 行为与公式（How）

### 3.1 局部立体表现，不迁移战斗空间

1. 单位屏幕中心仍由现有世界位置与 Camera2D 决定。新增机体厚度、机翼/尾翼遮挡和明暗发生在局部表现内；虚拟高度继续消费现有尺度合同，不另加把飞机“抬离点击位置”的偏移。
2. 航向、坡度和已有机动姿态来自正式状态。若候选需要新增俯仰推导，只能由已有运动量生成只读视觉值，并先写清公式及限幅；不能反向驱动物理。
3. 机身、座舱、发动机要有起伏，机翼相对薄，垂尾在大坡度下仍有结构。不能只把整张轮廓挤成等厚饼干。
4. 光照用于交代体积，允许简洁平滑面或少量硬边，不强制做成夸张三角切面。转向和滚转时不能明显变成带着固定高光旋转的贴纸；预渲染候选也要接受此检查。
5. 保留正确机型轮廓与主要比例；主机体不能为塞武器而任意拉宽、变厚。细节在正常视距不可见时先删细节，不扩大整个游戏尺度。
6. 机体、挂载、发射闪光、在飞弹体和尾迹使用一致的锚点约定。原型不改物理发射点；可做短暂纯视觉离架衔接，但不能推迟真实出弹、改弹道或造成重复命中。衔接时长、偏移和恢复函数在候选实现前登记。
7. 阴影不作为第一阶段必要项；机体自遮挡与体积明暗优先。若增加地图投影，必须单列成本与视觉高度语义，不能把数千米高的飞机画成贴地物件。

### 3.2 多装备与稳定挂点

- 装备是否合法，完全继承正式武器库与各武器规则。现有“库中装备自动挂载、不新增总量上限”的语义不变；已有互斥组合仍互斥。
- 为每个装备类型定义稳定的视觉归属。优先使用机翼、机腹和机身附属位置；允许多联挂架、组合吊舱、保形模块、内置武器舱和虚构中央电磁炮。
- 同时存在的装备不能分配到同一个互斥几何空间。ESM 等持续设备独占其展示区域，不能被导弹补弹时覆盖。
- 同型重复部件使用固定顺序及子槽 ID；存量增加使用该装备预留的挂架扩展区域，不挪用其它装备的区域。换装备或换机型才允许整体重新适配。
- 大容量武器可采用有内部储弹语义的组合挂架：外部可见的是实际挂架/就绪弹，不承诺把所有库存逐枚悬挂在机翼上。每个装备的可见数量映射必须显式记录；不能无说明地截断装备清单。HUD 库存仍是数量权威。
- 炮口、吊舱和弹体可有合理局部遮挡，但整件装备不能因布局冲突而完全消失。正常距离看出构筑差别，近景可定位装备；极远景无需辨认每枚弹。
- 布局失败时给出可定位的诊断，保留该装备真实功能，并标为未适配；禁止偷偷卸装、停火或把候选回退伪报为已完成。
- 特殊装备跟随正式归属，不因切控而复制到整支编队；换帅/进化后的外观读取迁移完成的实际装备状态。

### 3.3 发射、空架与补弹

必须区分**两次发射之间的冷却**和**库存补充/整仓装填**。视觉层不拥有“时间到了就再长一枚”的第二套规则。

| 正式状态 / 事件 | 外观行为 | 禁止行为 |
|---|---|---|
| 已装备且有就绪弹 | 在该装备预留位置显示对应就绪弹 | 凭武器类型固定画满，与实际库存无关 |
| 正式成功发射并消耗库存 | 对应弹体离架，库存映射刷新；挂架与槽位归属保留 | 把空槽交给 ESM / 其它武器，或重排整机挂载 |
| 仅发射间隔 CD 结束 | 根据当前真实库存更新就绪表现 | 当成补弹事件，无条件恢复已耗尽的导弹 |
| 库存为零，正在装填 | 保留空架 / 发射器本体；持续设备照常存在 | 把整个吊舱、炮塔或机翼武器模块一起删除 |
| 正式补弹、补给或容量升级提交 | 按提交后的库存映射，在原预留位置恢复 | 自行增加弹药；按旧容量或旧计时恢复 |
| 无耗弹/无限弹药下成功发射 | 保留真实离架反馈，下一就绪外观按仍有效的库存规则恢复 | 以“库存没减”判定没有开火；用外观动画阻止下次真实发射 |
| 暂停、JAM 或其它正式计时影响 | 只反映权威进度，不另启普通墙钟计时 | 游戏暂停或装填被阻止时，外观自行补满 |
| 切换 LOD、离屏回屏、关闭再开原型 | 从当前权威库存重建 | 当成新生成，默认满弹 |

例如容量为 2 且逐发耗弹的普通案例：`2 → 发射 → 1 → 发射 → 0 → 正式装填完成 → 2`。这是状态示例，不是给全部武器设定容量 2，也不是把发射 CD 设为装填时间。

主、副通道分别绑定自己的真实库存与装填状态；正式主弹装填若同时补充副弹，表现同步接受该结果，不能为了动画整齐把两条计时器强行合并。齐射、免费窗口、补给、被动发射和特殊武器入口必须逐条接入/审计，不能假设只有一个发射调用点。

### 3.4 视觉 LOD 与关键反馈

- 所有航空单位按实际屏幕占用尺寸选择完整体积、简化体积或轮廓；阈值以正常开局、总览、近景三种实测尺寸校准，不能只按世界距离，也不能按玩家/BOSS等身份跳过。
- 切档设置迟滞并保持中心、方向、颜色和主要轮廓连续。不得出现跳位、尺寸突变、导弹重新长出、尾迹断头或模型与图标重影。具体混合方法及阈值在候选记录中定稿。
- 玩家、BOSS、王牌、Sentinel 不进入普通拥挤度的逻辑/模拟降级；这项豁免不传播到机身画面几何。对玩家有直接威胁的弹体、被选中/锁定单位的必要 HUD 辨识仍须保留。
- 当前正式候选对所有 71 个航空身份使用三级机身几何：LOD0 在 `>=22 px` 进入、低于 `18 px` 退出；LOD1 覆盖中远景并保留机身、翼面、尾翼/旋翼盘等可辨结构；只有 LOD1 低于 `8 px` 才进入 LOD2，LOD2 到 `>=11 px` 回到 LOD1。独立挂载仍在低于 `18 px` 后省略。阈值读取实际输出像素，包含机型原生尺寸、虚拟高度/视觉缩放、Camera2D canvas 与窗口 stretch，不直接读取裸 `Camera2D.zoom`，也不读取玩家/BOSS/Sentinel 等身份。Mother Goose 本体同样服从机身像素门，真挂点服从挂载像素门。
- 仅简化不可辨认的几何与表现计算；不以模型不可见为由停物理、少发导弹、少刷敌人或删火力反馈。现有世界模拟/激活边界不在本轮改写。
- 机体可能使用低成本远景轮廓，HUD、危险提示、目标线、弹道和爆炸仍按各自正式规则绘制；这些不能随模型 LOD 一起关闭。

### 3.5 终态与缓存

出生、装备变化、进化、切控/换帅、阵营转换、隐形/现形、部件损毁、实体死亡、回收复用与场景退出均有明确刷新/释放路径。销毁先使表现绑定失效，再释放占用；下一帧及下次缓存消费不得访问旧对象。

跨帧 Object 读取遵守 `Variant → TYPE_OBJECT → is_instance_valid → is/as/字段`；不能把已释放对象先传进强类型形参，再指望函数内部守卫。新玩家引用持有者必须加入正式切控重定向入口。共用资产可缓存，单位状态、槽位占用和临时渲染目标不能跨实体串用。

### 3.6 UI 与战斗可读性

世界标签继续由统一屏幕空间覆盖层持有，不挂到会滚转的三维模型或局部贴图下面。缩放、窗口尺寸、镜头旋转和单位滚转不得让文字倾斜。模型只提供实际视觉边界，不复制标签绘制规则。

保留现有锁定、选中、危险区、轨迹和受击反馈。目标线的世界端点不能烘进会随机体转动的旧缓存。机身明暗不能遮蔽敌我识别，隐形也必须同时约束新增模型、挂载和多余通道，不能从遗漏的部件泄露目标。

## 4. 结构与组成（Structure）

### 4.1 共用边界

拟采用“正式状态 → 只读表现快照与挂点布局 → 可替换绘制后端 → 现有世界/HUD 合成”的边界。只实现原型需要的最小接口，不提前建设通用 3D 引擎。

布局按装备事件重建；位置和姿态按可见连续性需要更新；资源离线制作或受控预热。不能逐实体逐帧扫描场景树、创建材质、读取图片、生成网格或重新布局。缓存、批绘和临时目标都有可测的容量及释放策略，视觉随机独立于战斗 RNG。

### 4.2 候选路线

| 候选 | 保留 2D 的方式 | 要用原型回答的问题 |
|---|---|---|
| 实时低模合成 | 正式单位仍为 2D，只把局部 3D 模型输出合成到原位置 | GL Compatibility 下的批处理、渲染目标数、透明边缘、姿态、遮挡与合成成本 |
| 离线模型渲染图集 | Blender 等工具生成多姿态素材，游戏读取图集 | 航向/滚转采样和插值是否足够平滑；光照是否像贴纸；动态挂载如何一致遮挡；图集与显存是否可控 |
| 混合 | 近景/关键对象与普通远景使用不同表示，共享权威快照 | 切换是否连续；是否值得承担两套资源与测试维护成本 |

候选必须至少比较“姿态与挂载最灵活的方案”和“预计运行成本更低的方案”。若其中一路因可复现的兼容性或成本问题提前淘汰，记录取值与证据，不必为了凑数把失败路线全量实现。

允许使用共同低模源资产导出多种表示，减少重复制作。源模型须可再编辑、可重导出并登记使用权；Tacview 截图是审美参考，不视为其模型文件的授权。

遵守 [性能守则](../../reference/performance-guidelines.md)。本改动可能同时增加 draw 提交、GPU fill、图集/显存、透明合成、按实体更新和创建/释放尖峰，不能用单机面数推算整场 FPS。

| 维度 | 规定 |
|---|---|
| 基线 | 当前正式二维绘制，而不是假定“只有一张 PNG”的旧版本；同机、同 Godot、GL Compatibility、地图、seed、build、相机轨迹、时长、窗口/分辨率、UI 与缓存条件 |

| S1 | `naval_zone_stress` 或正式武器专项，必须真正激活多挂载、导弹、火箭/炸弹和对应火力热点 |

| 镜头与采样 | C1/C2 完成标准 `camera_patrol=on segments=8/8`；前三秒预热与稳态分开；旧/新同条件各连续三次 |
| 结果 | 每次 avg/p1/worst/低于 60 帧数、PerfBuckets 热点、CPU/GPU 可用指标、资源/内存峰值及残留；不把不可获得的 GPU 指标伪写成 0 |

性能通过须同时达到 §2.1 底线及相对回退限制；三次中位数只用于比较趋势，不能隐藏某次低于 60 的失败。基线低于 60 是已有性能债，不构成新方案豁免。冷启动/切档低于 60 必须单列，连续三次复现即按守则失败。

混战必须保留真实 AI、伤害、自然交战与反馈；不能用无敌模型展台、静止单位、少刷怪、降低武器频率或提前减员卸掉压力。候选必须实际启用且达到预先登记的覆盖合同，不能绝大多数回退旧模型后宣称新方案过门。自然战斗出现负载分歧时先核实原因和可比性，不直接比较 FPS。

正式推广前另需 E4 / L1 完整局，覆盖高密度战区、装备获得、进化/切控、Tab、任务、BOSS 与结算。短原型通过仅证明该样本，不代替完整局与全品类覆盖。

## 6. 实现计划（Task Pipeline）

### 当前全量交付边界与 BOSS 覆盖计划

本轮从隔离原型进入全机型生产与正式接入，但只有覆盖、身份、视觉、生命周期和性能门全部通过后才切正式默认并把 `reconstruction_complete` 改为 true。任何中间批次都继续保留明确回退与未完成清单，不能因已经具备可玩实验入口而宣称玩家当前正式版本已更新。

### 并行制作批次 A（用户已批准开始制作）

- 飞机线由独立 agent 制作 F-14、A-10、F-47 三种专属低模，替换本批机型的通用代理；逐机型登记轮廓、机身/座舱、发动机与尾翼结构，使用项目已有轮廓作为比例依据，不改参数资源、武器或飞机尺度。其它机型保留现有回退，不能把通用代理称作专属模型完成。
- 首批每种单材质、最多 600 三角形、中心与北向保持原规范，共享缓存与按机型批绘，不新增逐实体节点、视口或 tick。该上限是本批制作预算，不是整场性能已通过的承诺。保留 Mother Goose 本体及真实挂点。
- 地图线先完善当前沙漠三维样区：读取现有 MapDocument 的地表范围/配色、道路、铁路、机场与建筑轮廓/高度；明确屋顶、侧墙、跑道和道床，铁路连续连接且沿同一源路线采样。只生产静态显示几何，不新造平行地理坐标或改变碰撞/战区/列车玩法。
