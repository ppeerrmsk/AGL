# 玩家仪表 HUD

> 把生存模式右侧 TACTICS、玩家信息栏与旧僚机富文本框统一成不可点击、纯键盘驱动的模块化线框仪表；其它游戏内 HUD 的布局、内容与交互保持原样，首次显现效果统一由 `ui-transition` 规格约束。

## 1. 设计意图（Why）

- **体验目标**：在不改变火控、飞行与加力机制的前提下，让生命、速度、G、高度、热诱弹、自动化开关与武器优先具有清晰、可数、可扫读的座舱仪表反馈。
- **Litmus 自检**：符合“信息察觉优先于数值”；所有状态变化均有数字、反色、进度或闪烁反馈。本批只改变 HUD 表现，唯一行为修订是 T 跳过不存在的基础武器。
- **反模式规避**：不新增手动武器扳机；F 仍只控制现有导弹自动发射语义；不改其它 HUD；不把额外装备、技能或状态强塞进本批仪表。

## 2. 数据定义（What —— 全部数值，权威源）

### 2.1 整体布局

| 字段 | 值 | 说明 |
|---|---|---|
| 锚点 | 右下角、经验条上方 | 复用旧 TACTICS + 玩家信息栏占位，可适度加宽 |
| 尺寸 | 高度固定 `24u = 432 px`；基础内容宽 `6u + 1q = 258 px`，最终总宽动态计算 | SPD 五个固定数字格建立当前宽度基准；其它主要数字按整数 `1q` 扩宽，结构对齐按 `0.5q` 补列 |
| 交互 | 无鼠标交互 | 不可点击、无 hover tooltip、鼠标事件穿透 |
| 操作键 | E / G / F / Q / T；取得机动技能后显示 R；C / V | 仪表内按键均为独立 `1q`；Q 恢复可见的高度偏好反馈，C/V 保留小队交战模式与武器偏好 |
| 模块顺序 | HP → SPD → 加力 → ENGAGE/FIRE 与 FLR/R → `0.5u` 装饰框 → 武器优先标题 → MSL → `0.5u` 装饰框 → GUN | 每条信息行拥有独立局部矩形；T 键只吸附武器优先标题 |
| 默认强调色 | 通用终端绿 `#00FF41` | 主菜单可改；作用于本仪表文字、边框、星号与填充 |
| 预设色 | 绿 / 青 / 琥珀 / 白 | 另提供自定义色盘 |
| 反色文字 | 黑色 | 填充底色使用当前 HUD 强调色 |
| 闪烁节奏 | 每 0.5 秒切换一次 | 完整明暗循环 1.0 秒 |

### 2.1.1 僚机信息行

| 字段 | 规则 |
|---|---|
| 位置 | 玩家仪表正上方，右边缘与玩家仪表对齐，间距 6 px |
| 数量 | 每架当前存活僚机严格对应一行；无僚机时整组隐藏 |
| 排序 | 按固定 `squad_slot` 升序；阵亡造成的编号空缺不得压缩 |
| 外框 | 每行总宽 `1q + 7u = 298 px`、主体高 `3u = 54 px`、黑色 70% 底、共享 1 px 当前 HUD 强调色描边；行间距为 0，相邻行复用同一边界 |
| 顶部标签 | `3u × 1u = 120 × 18 px`；左侧独立 `1q × 1q` 键帽，号机数字使用 Silkscreen 15 px；标签用强调色实心底、黑字显示 `★ 代号` |
| 行内信息 | 当前动作、击坠数、`HP 当前/最大`、`MSL 当前/最大`、`GUN 当前`、`FLR 当前` |
| 装填 | MSL/GUN/FLR 装填时把数值替换为整数百分比，并按统一 0.5 秒节奏明暗闪烁 |
| 缺失装备 | 对应字段内容透明，行宽与其它字段位置不塌缩 |
| 交互 | 僚机行纯显示、鼠标穿透；小队交战与武器偏好继续使用 C/V 键 |

对齐契约：先建立整个玩家仪表的屏幕侧共同右边缘，再从右向左建立每一行自己的 `Rect2`。HP/G、ALT/SPD、加力、自动化/FLR、R 机动与武器行的右边缘必须完全一致；最大字符串造成的宽度增量只能以整数 `1q` 向左增长，结构对齐可以按 `0.5q` 补列，两者不得混算。运行时按键优先占用预留的动态空框板；只有没有预留空间时才以整数 `1q` 扩宽受影响行。每行可以拥有不同左边缘，不得为了左侧整齐而缩小高优先级字号。所有标签、重点数字、补充数字、填充和分隔线只使用所属行的局部矩形；相邻边界由统一描边层复用同一坐标。

重点信息契约：每行只允许一个第一视觉焦点。HP 与 ALT 使用“整行 `1u` 小标题框板 + 无框主要数字字板 + 无框分隔符/次级数字字板”；G 使用主 UI 规范定义的“两位整数加一位小数 4u 信息组”；SPD 使用五个固定单数字框板；FLR 当前值也使用两个固定单数字框板。SPD、G 整数位与 FLR 当前值共用按最宽数字 `0` 完整进入 `49 × 54 px` 单格得到的固定 Chakra Petch Bold 字号；HP 继续按三位整串与 `3u` 高度独立计算。

### 2.2 飞行数据模块

| 项目 | 显示规则 |
|---|---|
| HP | `当前/最大`；当前值大字、最大值小字，均取整 |
| G | 只显示实时 G，保留 1 位小数；不显示结构上限；按最大显示字符串 `11.5` 固定字号；独占 HP 右侧补充区 |
| ALT | 只显示实际高度米数，取整；按五位整数 `99999` 固定字号；不显示档位、箭头或 `M` 后缀；占 SPD 左侧独立状态块 |
| STALL | 平时不占视觉内容；失速时显示并按统一节奏闪烁 |
| SPD | 当前单位下的整数速度，固定格式化成五位并从左到右逐格显示；默认 kt，设置为 km/h 时显示 km/h 数值 |
| 单位标签 | `KT` 与 `KM/H` 同时保留，当前单位反色 |
| 换算 | `kt = km/h / 1.852` |
| 高度偏好 | ALT 状态块底部显示当前本地化状态：`爬升优先` 或 `低空优先`；Q 键帽位于面板外框左侧，与 E/G/F/T 键帽同列；按 Q 两态切换 |

- HP 与 SPD 均不伪造连续比例条；生命、速度与高度只使用数字反馈。
- HP、G、ALT、SPD 均使用整行 `1u` 小标题框板，标题文字左对齐；SPD 的五个数字格与 G 的专用小数组合是局部有框例外。
- HP 高 `4u`：标题占顶部 `1u`，当前生命使用基础 `3u × 3u` 无框字板，分隔符占 `1q × 1q` 无框字板，最大生命使用基础 `1u × 2u` 无框字板；当前与最大生命均按三位整数 `999` 预留，宽度不足时分别向左增加整数 `1q`。
- G 高 `4u`：顶部 `1u` 为小标题行；下方从左到右依次为两个 `1u + 0.5q` 宽、`3u` 高的整数数字框，位于底行的 `1q × 1q` 小数点框板，以及最多一位小数的 `2u` 高无框字板。整数固定补零到两位，例如 `4.5` 显示为 `0 4 . 5`；每个整数格与 SPD 数字格共用字号并居中，前置补位零使用 `#404040`。小数点使用相同主要字体和字号；小数位按 `9` 预留并使用次要信息字号。
- SPD 行从左到右分为 ALT 与速度两组。速度组顶部为小标题行；下方固定五个 `1u + 0.5q` 宽、`3u` 高的单数字框板，共用一个按最宽数字 `0` 完整适配单格的 Chakra Petch Bold 字号，并逐格居中。速度以当前单位格式化成五位：`500` 显示为 `0 0 5 0 0`；首个有效非零数字之前的补位零使用 `#404040`，有效数字之后的零使用当前强调色。超过 `99999` 时五格显示闪烁红色 `99999`，不得扩宽。`KT` 与 `KM/H` 使用两个同尺寸、同字号的 `1u × 1u` 居中框板，当前单位反色，剩余格位使用无字符空框板。
- ALT 组的小标题行左对齐；实际高度为无框字板，高度偏好是普通居中状态框板。STALL 只能占速度/单位区，不进入 ALT 块。

### 2.3 加力与机动进度模块

加力与 R 机动充能统一使用以下结构：

| 区域 | 尺寸与规则 |
|---|---|
| 总面板 | 高度固定 `2u`，右边缘与玩家仪表其它行对齐 |
| 标题 | 位于左区顶部，固定 `1u` 高框板，按次要信息字号并水平居左 |
| 进度条 | 位于左区底部，固定 `1u` 高框板；内部禁止文字，填充向内保留透明 `4 px` 边界 |
| 百分比 | 位于最右侧，固定 `2u × 2u` 框板；按次要信息规则并水平居右，基准字符串为 `100%` |

- 加力标题使用本地化 `AFTERBURNER`，百分比与填充均显示当前剩余能量比例；低能量色阶遵循第 2.7 节。
- R 机动标题使用当前唯一技能的本地化名称，百分比与填充均显示 `0% → 100%` 的就绪进度。
- 现有“有能量即可启动、再按 E 提前关闭、耗尽自动结束”机制不变。

### 2.4 自动化与热诱弹模块

| 项目 | 关闭 | 开启 |
|---|---|---|
| G 自动接敌 | 本地化 `ENGAGE` 普通文字 | 强调色底 + 黑字反色 |
| F 自动开火 | 本地化 `FIRE` 普通文字 | 强调色底 + 黑字反色 |

- F 仍绑定现有 `missile_auto_fire`，不扩展成全武器总开关。
- 加力期间继续显示玩家保存的 ENGAGE/FIRE 开关状态，不显示临时有效性。
- FLR 固定占右栏 `6u` 高：顶部 `1u` 是左对齐小标题框板；中部当前值固定拆成两个 `1u + 0.5q` 宽、`3u` 高的数字框，补零到两位并与 SPD/G 整数格共用字号，前置零使用 `#404040`；分隔符和 `2u` 高最大值均为无框字板；底部 `2u` 是独立星号动画框板。
- 数字资源与下面 10 个 `*` 是两个维度：数字表示可用投放次数；星号表示一次投放里的 10 枚视觉热诱弹。
- ENGAGE 与 FIRE 属于同一个 `3u × 6u` AUTOPILOT 父面板；上下两个 `3u` 高子区分别显示 ENGAGE 与 FIRE。父面板宽度锁定为 `3u`，两行不得独立扩宽或位移。
- AUTOPILOT 与 `6u` 高 FLR 面板之间使用无字符动态空框板；其宽度按 `0.5q` 装饰列自动补齐，使 AUTOPILOT 左边缘与 ALT/SPD 基准行对齐。
- 当运行中取得手动 FLR 技能时，在动态空框板最右侧插入独立 `1q × 1q` 的 R 键框板：空框板缩短 `1q`，AUTOPILOT 与 FLR 的位置和尺寸均保持不变。新 R 键以 `0.5 s` 相位反色闪烁 `5 s`，之后常驻；不得影响其它高度行。

ENGAGE 与 FIRE 是两条独立行；关闭时为黑底强调色字，开启时为强调色底黑字。两态始终保留完整边框与文字，不用透明度表达关闭。

### 2.5 十枚视觉热诱弹

| 字段 | 值 |
|---|---|
| 总视觉粒子 | 每次投放严格 10 枚 |
| 波数 | 保留 6 波 |
| 波间隔 | 0.12 秒 |
| 每波数量 | `2, 2, 1, 2, 2, 1` |
| 星号排列 | 两行，每行 5 个 |
| 熄灭 | 某波实际生成 N 枚时，同帧熄灭 N 个星号 |
| 短冷却 | 星号保持全灭；冷却结束后一次性全亮 |
| 资源耗尽长装填 | 数字保持 `0/最大`；10 个星号按装填进度逐个点亮 |
| 装填完成 | 第十个星号点亮后，数字才一次性更新为 `最大/最大` |

### 2.6 R 主动机动冷却行

| 字段 | 规则 |
|---|---|
| 技能数量 | 玩家永远只持有五种互斥 R 技能中的一个；HUD 不提供选择、轮换或多技能并列显示 |
| 出现条件 | 取得任意唯一 R 技能后立即显示内容并常驻；未取得 R 技能时区域保留为空框板 |
| 位置 | 固定在 `6u` 高自动化/FLR 区下方，占整段基础内容宽与 `2u` 高；未取得技能时保留无字符空框板，不压缩其它行 |
| 重点信息 | 采用第 2.3 节的标题、无字进度条与右侧 `2u × 2u` 百分比；整数充能百分比为 `0%…100%` |
| 进度 | `charge_ratio = 1 - remaining / total`；成功发动时回到 `0%`，随后向 `100%` 填充，`100%` 表示可用；进度条内部无文字 |
| 禁止显示 | 不显示剩余秒数、总冷却秒数或 `/总时长`；总冷却只允许作为内部比例分母 |
| 切控 | 冷却属于 Squad；切换操控机后继续显示同一唯一技能与同一剩余时间 |

五种唯一技能名称复用现有技能本地化 key。各技能总冷却仍由技能机制持有，HUD 不向玩家暴露该数值。

### 2.7 统一进度色阶

所有连续比例条统一按其“已填充比例”着色：

| 已填充比例 | 颜色 |
|---|---|
| `> 0.50` | 当前 HUD 强调色 |
| `> 0.20` 且 `≤ 0.50` | 警戒黄 `#F2D34F` |
| `≤ 0.20` | 危险红 `#FF493D` |

- 加力条的填充比例等于剩余资源比例，因此资源降低时依次进入黄、红；HP 不显示比例条。
- R 冷却条的填充比例等于完成比例，因此从红开始，经黄回到强调色；默认武器装填使用独立竖向进度条，不使用此处的红黄绿比例色阶。
- 闪烁只改变填充明暗，不改变其所属色阶。

### 2.8 武器模块

固定保留 MSL 与 GUN 两行；其它武器与额外状态本批不安置。

武器模块前置结构：上方信息行结束后先放置手动声明的 `0.5u = 9 px` 无字符装饰框板，它有完整共享 `1 px` 描边；其下是独立 `1u` 高武器优先标题面板，当前英文显示为 `PRIORITY WEAPON`。T 键为独立 `1q` 框板并吸附标题左侧，不得吸附装饰框。标题下依次放置 MSL、`0.5u` 无字符装饰框板、GUN；两个武器面板各固定高 `2u`。玩家仪表总高为 `24u = 432 px`。

| 区域 | 尺寸与显示 |
|---|---|
| 左侧弹量格 | `2u` 高；Chakra Petch Bold 次要数字层级、水平居左；按 `9999` 预留最多四位显示余量。旧版弹量上方的 `1u PRIORITY` 格及文字完全删除 |
| 中间弹性空框板 | 自动吸收弹量格与右侧固定功能区之间的全部剩余宽度；无字符、无隐含功能 |
| 辅助空框板 | 固定 `0.5q × 2u`；紧贴竖向进度条左侧；无字符、无功能 |
| 竖向装填条 | 固定 `1q × 2u`；紧贴名称格左侧；复用通用进度条的 `4 px` 透明内缩，从下向上按真实装填比例填充；内部无文字 |
| 右侧名称格 | 固定 `2u × 2u`；显示 `MSL` / `GUN`，使用次要信息层级并居中；完整缩写优先 |

九格指示灯及其 `2468` 常亮、`12369874` 循环和切换复位规则已全部废弃；武器行不得保留相关占位、状态或动画。

| 状态 | 弹量格 / 名称格 / 竖向装填条 |
|---|---|
| 优先、未装填 | 弹量格与名称格持续反色；装填条熄灭。该状态显示玩家偏好，不表示瞬时实际使用武器 |
| 未优先、装填 | 弹量格与名称格保持普通相位；装填条按 `2 Hz` 在当前比例填充与完全熄灭之间闪烁 |
| 优先且装填 | 弹量格与名称格按 `2 Hz` 在反色与普通相位之间闪烁；装填条同相位在填充与熄灭之间闪烁 |
| 武器不存在 | 行高、装饰框、空框板和边框保留；该行弹量、名称与装填内容透明度为 0 |

T 切换规则：两种都存在时切换；只存在一种时固定在可用武器且 T 无操作；两种都不存在时 T 无操作。

### 2.9 主菜单设置

| 设置 | 默认 | 持久化 |
|---|---|---|
| 速度单位 | KT | 保存到独立 HUD 设置文件 |
| HUD 色 | 通用终端绿 `#00FF41` | 保存到独立 HUD 设置文件；用户选择其它颜色后覆盖默认值 |

- 速度单位按钮与 HUD 色按钮放在主菜单 AUDIO 旁。
- HUD 色面板提供绿、青、琥珀、白四个预设以及自定义 ColorPicker。
- 只有 `AFTERBURNER / ENGAGE / FIRE / PRIORITY` 走本地化；HP、G、ALT、STALL、SPD、KT、KM/H、FLR、MSL、GUN 固定不翻译。

### 2.10 字体

| 内容 | 字体 |
|---|---|
| 小型信息、字段名、小标题行、单位、键帽、PRIORITY | Silkscreen Regular；1u/1q 使用 15 px |
| 大号数字、AFTERBURNER、ENGAGE、FIRE、FLR、MSL、GUN | Chakra Petch Bold |
| 中文、日文、韩文本地化文本 | 缺失字符回退至项目当前主题默认字体 |

Silkscreen 与 Chakra Petch 字体资源随项目打包，不依赖运行机器已安装字体。紧凑版的可读性下限：单格字段与键帽保持 15 px；多格主要数字使用 Chakra Petch Bold，并统一通过 `TerminalText` 所实现的“通用字号规范”计算。

## 3. 行为与公式（How）

### 3.1 显示刷新

- 复用生存 HUD 既有单次玩家引用净化结果，不扫描场景树。
- 只更新一个固定仪表实例；无每实体节点、无全场遍历。
- 创建仪表后立即刷新一次；普通信息读数随后按主界面规范每 `0.5 s` 刷新。
- 反色闪烁、连续填充和实时操作反馈使用独立动画时钟，不得通过提高普通信息刷新频率实现。
- R 冷却读取是当前玩家与 Squad 的 O(1) 查询，不扫描场景树。

### 3.2 热诱弹状态同步

```
release:
  flare_visual_emitted = 0
  queue 6 waves with counts [2,2,1,2,2,1]

spawn wave(count):
  create exactly count visual particles
  flare_visual_emitted += count

HUD lit stars:
  if long reload: ceil(reload_progress * 10)  # 最后 10% 已满星，正式完成帧才补数字
  elif release queue active or short cooldown active: 10 - flare_visual_emitted
  else: 10
```

长装填完成前数字不得提前补满；数字更新与正式资源补充发生在同一状态转移。

### 3.3 输入

```
E -> AfterburnerCharge.toggle(player)
G -> auto_engage_enabled = !auto_engage_enabled
F -> missile_auto_fire = !missile_auto_fire
T -> available = [MSL if params.missile, GUN if params.gun]
     if available.size == 2: toggle preference
     if available.size <= 1: no-op and keep/normalize preference to the sole available weapon
Q -> altitude_preference = PREFER_CLIMB ↔ PREFER_LOW; ALT/Q block updates in the same HUD refresh
C -> existing squad engage mode cycle
V -> existing squad weapon preference toggle
```

### 3.4 僚机快照与刷新

- 生存 HUD 只遍历当前玩家 `Squad.members` 的存活僚机，不做全场扫描。
- 生存 HUD 把僚机引用转换为只含显示值的字典快照；绘制控件不跨帧持有 Aircraft 引用。
- 僚机普通信息与玩家仪表相同，每 `0.5 s` 刷新；行数变化时立即改尺寸并重新锚定到玩家仪表上方。

### 3.5 首次显现

- 玩家仪表不能作为一个整体登记。HP、G、ALT、SPD、加力、ENGAGE、结构空框、FLR、FIRE、R 机动、
  武器标题/槽/分隔框与可见键帽必须各自成为独立首次显现目标。
- 每架僚机的信息行各自是一个独立目标，以固定 `squad_slot` 作为首次 id；新增/重排僚机不能让已完成行重播。
- 玩家仪表开局登记已有框板；动态 R 键与特殊武器框首次真实出现时才登记。僚机必须等对应真实信息行出现，空行不得提前消费首次机会。
- 复合绘制控件使用与框板矩形一致的源渲染开关表现独立明灭；关闭时背景、文字和全部边线必须共同消失，禁止用黑色 `ColorRect` 覆盖模拟隐藏。不得修改控件整体 `modulate`，也不得改变内部装填、失速、手动 FLR 等既有闪烁时钟。
- 新登记的复合框板源绘制默认关闭，HUD 必须在 `_ready` 内完成零时刻同步；源关闭区域须向逻辑框板外扩 `1px` 以包含描边外溢，进入树到首次 `_process` 之间也不得露出总体 `1px` 外框。
- 节奏与空间排序以 `ui-transition` §2.13 为权威：`0.02s` 错峰并发启动，每块 `0.50s` 内完成两闪。

## 4. 结构与组成（Structure）

- 独立玩家仪表控件：用独立行矩形构建 HP、SPD、加力、ENGAGE、FIRE、固定 FLR/R 区、MSL、GUN；每行只以自己的左上角为坐标原点。生存 HUD 只注入当前 Aircraft 与 AfterburnerCharge。
- 独立僚机仪表控件：消费生存 HUD 生成的显示快照，按存活僚机数绘制独立信息行；复用玩家仪表的语义强调色、Silkscreen 与 Chakra Petch 字体规范。
- 独立 HUD 偏好静态服务：加载/保存速度单位与强调色，不新增 AutoLoad。
- 热诱弹子系统在 Aircraft 上公开本次视觉投放进度，HUD 只读；队列仍由既有粒子更新函数消费。
- Aircraft 公开唯一 R 技能 id、总冷却与共享剩余冷却的 O(1) 只读查询；HUD 只用总冷却计算 0%→100% 充能，不显示时长且不修改技能状态。
- 主菜单只负责修改持久化偏好；其它主菜单结构与游戏内 HUD 不变。
