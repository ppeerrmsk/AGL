# 飞机击毁与方块爆炸演出

> 小型飞行单位只用单个方框表达命中与坠毁终点；大型有人机才允许结构连续爆炸。任何爆炸都不得与机体同帧消失绑定，坠毁运动由真实受击部位与局部随机共同决定。

## 1. 设计意图（Why）

- **体验目标**：同一次击毁既要在第一眼明确成立，也要让受损机体在画面中连续完成旋转、掉高、缩小、终点爆炸后停留与渐隐；普通飞机、无人机和导弹服从全息雷达图的克制语言，命中一次只闪一个方框，飞机坠毁终点再闪一个小方框。只有大型轰炸机、运输机等有人大型机才允许五点结构连续解体。机头、左右翼、发动机/尾段受损必须产生可辨认的不同运动趋势。
- **硬排除**：不存在“空中爆炸后模型直接消失”的合法方案。爆炸造型、爆点路线和失控轨迹可以按体型与受击部位变化，但爆炸触发帧必须仍能看见真实机体；机体至少经过一段明确的不透明停留与连续淡出后才允许释放。
- **Litmus 自检**：遵循即时反馈、可见反馈、活战场和 60 FPS 底线；所有爆点仍使用 AGL 的白色实心几何方块语言，不引入写实火球或贴图粒子。
- **反模式规避**：不做十字分裂、对角扇出或圆环扩散；不把爆炸做成水花式连续喷溅；不靠全局随机数挑路线；不为每架飞机增加常驻扫描、子节点或独立粒子系统。

## 2. 数据定义（What —— 全部数值，权威源）

### 2.1 爆炸公共数值

| 字段 | 值 | 说明 |
|---|---:|---|
| 单个爆点时长 | 0.30 s | 局部方块膨胀、回落并淡出 |
| 基准尺寸 | 22 px | 调用方 `scale=1.0` 时的基准边长 |
| 初始满亮阶段 | 归一化年龄 0.00–0.18 | 之后按剩余寿命线性淡出 |
| 普通命中 / 小型单位终点爆点数 | 1 | 单个假 3D 方框；不排队、不连续播放 |
| 大型机结构爆点数 | 5 | 仅大型有人机；机头、左翼根、机身中心、右翼根、尾段各一次 |
| 爆点间隔 | 0.11 s | 相邻结构点依次触发，形成连续波动；同屏主要保留 2–3 个相邻爆点，避免叠成一团 |
| 传播路线数量 | 4 | 固定轮转，不读取玩法随机数 |
| 路线轮转 | `airframe_wave_serial mod 4` | 显式指定路线时不改变自动轮转结果 |
| 最小调用缩放 | 0.1 | 防止退化几何 |

### 2.2 大型机专用的四种结构解体路线

普通飞机、无人机与导弹禁止调用本节连续路线。大型机判定优先读取 `destruction_class` meta：`large` / `small`；未显式覆盖时，无人机固定为 small，`crash_style=bomber` 或有人机 `max(visual_length_m, visual_span_m) >= 28m` 为 large，其余为 small。C-130、Tu-160、B-1B 等因此进入 large；普通战斗机和无人机进入 small。

| 编号 | 名称 | 结构点顺序 | 动态 |
|---:|---|---|---|
| 0 | 机首左扫 NOSE PORT SWEEP | 机头 → 左翼根 → 中心 → 右翼根 → 尾段 | 从迎弹方向向后扫过机体 |
| 1 | 机首右扫 NOSE STARBOARD SWEEP | 机头 → 右翼根 → 中心 → 左翼根 → 尾段 | 与路线 0 镜像，避免每架飞机同向爆裂 |
| 2 | 尾段回火 TAIL RETURN | 尾段 → 左翼根 → 中心 → 右翼根 → 机头 | 从受损尾段向前连续回烧 |
| 3 | 翼根跳波 WING ZIGZAG | 左翼根 → 机头 → 右翼根 → 尾段 → 中心 | 在机体两侧交替跳动，最后收束到机身 |

五个结构点使用机体局部坐标 `(纵向, 横向)`：机头 `(0.78, 0.00)`、左翼根 `(0.12, -0.72)`、中心 `(0.00, 0.00)`、右翼根 `(-0.12, 0.72)`、尾段 `(-0.78, 0.00)`。纵向和横向分别乘当前机体实际绘制半长、半翼展，再按死亡瞬间 heading 转到世界坐标；因此爆点覆盖可见机首、翼面和尾段，贴着当前转弯姿态与不同机型尺寸，不形成径向飞散。每个结构点只生成一个原地脉冲方块，尺寸包络为 `0.72 + 0.46 × sin(age × PI) + 0.08 × age`，仅轻微旋转、没有离心位移。

| 命中局部反馈 | 单方框 | 导弹、火箭、AOE 等在贴合机体的实际命中点只显示一次普通方框；不得排队或附加机体波 |

### 2.4 受击位置分区

伤害入口把弹体/爆心的世界坐标转换到飞机局部归一化坐标 `(longitudinal, lateral)`。纵向正值为机头，横向负值为左翼；坐标分别按当前机体绘制半长、半翼展归一化并钳到 `[-1, 1]`。近炸位置落在机体中心时，使用弹体入射速度的反方向推导入射面；没有位置与速度的旧入口才退化为 CENTER。

| 分区 | 判定 | 运动身份 |
|---|---|---|
| NOSE | `longitudinal >= 0.35` | 机头控制受损：更陡下坠，偏航较克制 |
| TAIL_ENGINE | `longitudinal <= -0.35` | 发动机/尾段受损：速度衰减最强，偏航不稳定 |
| PORT_WING | 中段且 `lateral <= -0.22` | 左翼受损：强制向左翼一侧持续侧翻/弯坠 |
| STARBOARD_WING | 中段且 `lateral >= 0.22` | 右翼受损：与左翼镜像的持续侧翻/弯坠 |
| CENTER | 其它或无可靠几何 | 使用中性失控响应 |

### 2.5 自然随机与部位响应

每次击毁创建一次局部 `RandomNumberGenerator`，seed 混合实例 ID、最后命中局部坐标与当前微秒；不得消费全局玩法随机数。随机量只在击毁开始时采样一次，后续物理帧只读字段，不增加每帧分配。

| 基础随机量 | 范围 |
|---|---:|
| 坠毁时长倍率 | 0.90–1.12 |
| 偏航倍率 | 0.82–1.18 |
| 下坠倍率 | 0.90–1.15 |
| 减速倍率 | 0.85–1.20 |
| 前移倍率 | 0.92–1.08 |

在基础随机量上追加：NOSE 下坠 `×1.25`、偏航 `×0.80`；TAIL_ENGINE 减速 `×1.65`、偏航 `×1.35`；左右翼侧翻角速度至少 `1.8 rad/s` 且符号严格镜像，偏航也朝受损侧；CENTER 不追加定向偏置。大型机保留较慢的基础运动，但使用同一部位语义。

## 3. 行为与公式（How）

### 3.1 击毁状态机

| 状态 | 时长/触发 | 效果 |
|---|---|---|
| CRASH_WITH_STATUS | 任意伤害致命后的前 0.85 s | 真实机型轮廓继续按机种旋转失控并降低高度；共享屏幕空间状态栏保留，面板不继承模型缩放或透明度 |
| CRASH | 状态栏计时结束至失控时长耗尽，或高度到 0 | 真实机型轮廓继续旋转、前移减速和降低高度，按坠毁进度缩到 0.55，全程保持 alpha 1.0 |
| BREAKUP_SMALL | small 飞机 CRASH 终点，单帧 | 清空尾迹，在机体当前位置播放一个 0.72（无人机 0.50）普通方框；机体保持清晰并进入 LINGER |
| BREAKUP_LARGE | large 飞机 CRASH 终点，单帧 | 清空尾迹，在机体当前位置按最后受击部位排入一次五点结构解体波；机体保持清晰并进入 LINGER |
| LINGER | 任意终点爆炸后的 0.85 s | 真实机体继续沿原失控轨迹运动；前 0.25 s 完全不透明，之后连续缩小、淡出，计时结束才释放 |

不存在直接隐藏分支：任何致命伤害都不能写 `visible=false`、不能把坠毁视觉缩放/透明度同帧归零、不能在爆炸触发帧 `queue_free()`，也不能在死亡位置排入机体殉爆波。small 只在移动后的终点播放一个普通方框；large 才排入一条结构解体波。两者都必须在爆炸后保留真实机体 0.85 s。伤害源已有的单次命中反馈不计作终点爆炸。

### 3.2 坠毁模型进度

所有坠毁记录起始总时长 `duration_total` 与起始高度 `start_altitude`，每帧同时计算时间与高度损失进度：

`p_time = clamp(1 - destroy_timer / duration_total, 0, 1)`

`p_alt = clamp(1 - altitude / max(start_altitude, 1), 0, 1)`

`p = max(p_time, p_alt)`

- 失控模型缩放：`scale = lerp(1.0, 0.55, smoothstep(0.08, 1.0, p))`。
- 失控模型透明度：`alpha = 1.0`，包括终点爆炸触发帧。
- 爆炸后以 `e = 0.85 - linger_timer` 计算经过时间；`q = smoothstep(0.25, 0.85, e)`。
- 爆炸后模型缩放：`scale = lerp(0.55, 0.30, q)`；透明度：`alpha = 1 - q`。
- 缩放与透明度只作用于机体轮廓，不写入 Aircraft 节点 `scale` / `self_modulate`，因此状态栏、战术面板和其它屏幕空间 UI 不会随模型缩放或淡出。
- 机体仍使用当前参数资源对应的正式轮廓和死亡瞬间阵营色；不再替换成固定大小的通用灰色菱形。
- 旋转、速度与高度继续由 fighter / bomber / heli 三种正式坠毁物理推进；“向下坠落”由真实 altitude 快速下降、状态栏高度读数和持续缩小共同表达，不把世界坐标南方伪装成高度方向。
- 时间与高度进度取较大值，保证低空单位提前触地时模型也会抵达 0.55；爆炸后另走 0.85 s 连续停留/淡出，不在空中突然消失。

### 3.3 爆炸绘制与性能

- 每条局部爆点记录只保存位置、剩余寿命、起始延迟、heading、scale、旋转方向与所属路线编号。
- 单个局部爆点只绘制一个方块；统一宿主把当前全场所有可见爆点的面合并成一次直接 triangle-array 提交、棱线合并成一次 multiline 提交，延迟未到的记录不生成几何。
- 只在活动爆炸数组非空时更新并请求重绘；数组为空时不产生持续 redraw。
- 一条机体殉爆波最多写入 5 条轻量记录；没有全场扫描、临时节点或跨帧 Object 引用，飞机节点释放后仍可独立完成播放。

## 4. 结构与组成（Structure）

- `ExplosionVFX` 是唯一对外爆炸入口，仍由场景内 `MissileManager` 作为统一 Canvas 宿主。
- `MissileManager` 负责四种结构路线选择、延迟推进与局部方块几何绘制。
- `AircraftDestruction` 负责命中点归一化/分区、一次性局部随机、体型分级、统一坠毁入口、状态栏时钟、终点爆炸和释放；不得按伤害类型旁路坠毁。
- `AircraftDestruction` 是战斗击毁飞机的唯一释放权威；生存模式、任务、BOSS 控制器不得根据 `_destroy_timer` 或 `is_destroyed` 提前 `queue_free()`。正常撤离、离屏回收和场景 cleanup 不属于战斗击毁，可以继续静默释放。
- `Aircraft` 只持有终态计时、模型缩放/透明度字段，并在既有 `_draw` 中路由坠毁机体/状态栏；状态栏继续复用 `AircraftRenderer` 的共享屏幕空间面板。

## 6. 实现计划（Task Pipeline —— 工作令）

### 阶段 2 — 飞机终态
