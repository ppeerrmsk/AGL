# 阵营对称轰炸任务（Bomber Strike Missions）

> 轰炸机不再只是横穿地图的经验靶：它沿调用方指定的航路进入，自动计算投弹点，对目标区地面单位执行一次可见的地毯式轰炸，然后保持航向飞出地图；同一套行为分别由友军 B-1B 与敌军 Tu-160 使用。

## 1. 设计意图（Why）

- **体验目标**：玩家能从航线、投弹、连续落点和离场四个阶段看懂“这是一项轰炸任务”，而不是一架恰好飞过的慢飞机。
- **阵营对称**：友军版本为 `TEAM_ALLY`、敌军版本为 `TEAM_HOSTILE`；行为、炸弹和敌我过滤共用，只有机体参数、颜色与呼号不同。
- **任务边界**：本 spec 提供可被战区、事件、演出和 debug 调用的任务 API；不擅自把轰炸加入现有随机事件池，也不免费替代已购 A-10 战区支援。
- **Litmus 自检**：
  - 投弹是自动武器触发，玩家只通过任务目标/航路影响结果，符合“全武器自动开火”。
  - 命中当帧有爆炸、伤害与日志；延迟在进场和炸弹下落，爽点在落地。
  - 单枚伤害处于 30–100；轰炸机固定翼速度处于 600–2200 km/h。
  - 一次进入、一次投弹、一次离场，不会退化成绕目标盘旋。
- **反模式规避**：不让轰炸机进入 BFM；不让炸弹伤害空中单位；不在共享层写模式判断；不每枚炸弹全场扫描。

### 1.1 现实参考只决定“灵魂”，不照抄

| 机型 | 现实参考 | AGL 取舍 |
|---|---|---|
| B-1B | 长 44.5m，翼展 41.8m（前掠）/24.1m（后掠），重型高速常规轰炸机 | 友军高速进入、一次投弹、直接离场 |
| Tu-160 | 长 54.1m，翼展 55.7m（展开）/35.6m（后掠），大型高速战略轰炸机 | 敌军更大、更醒目，仍保持一枚导弹可击落 |

参考来源：美国空军 B-1B fact sheet；美国陆军航空识别手册中的 Tu-160 尺寸。数值仅用于定位与视觉比例。

| 字段 | 值 | 说明 |

| 重复结算 | 同一枚炸弹对同一单位至多一次 | 不做持续 DPS 区域 |
| 建筑遮挡 | 不拦截 | 炸弹从高空落下；建筑仍可成为视觉背景 |

### 2.3 任务几何

| 字段 | 值 | 说明 |
|---|---:|---|
| 航路最少点数 | 3 | 进入点、目标点、离场点；可插入任意中间点 |
| 航点到达半径 | 220 px | 重型机避免在单点上来回修正 |
| 最终离场延长 | 5000 px | 从最后一段方向继续延伸到地图外 |
| 投弹航向稳定门 | 机头与“目标点方向”夹角 ≤ 12° | 不侧投 |
| 投弹横向航迹门 | 目标点到当前速度射线的垂距 ≤ 140 px | 先对准再投 |
| 自动投弹提前量 | `speed_px × 下落时间 × 0.85` | 预计第一枚落到目标点附近 |
| 超过目标点未投 | 立即放弃投弹，转 EGRESS | 不掉头补投，不盘旋 |
| 任务生命期 | 150 s | 兜底回收，正常应先出界 |

## 3. 行为与公式（How）

### 3.1 状态机

| 状态 | 进入条件 | 行为 | 退出条件 |
|---|---|---|---|
| `INGRESS` | 任务创建 | 按指定航路逐点飞行；禁用空战、规避和全局 hunter/航点改写 | 到达目标前一航点 → `LINE_UP` |
| `LINE_UP` | 进入最后攻击段 | 保持巡航速度，指向目标点，计算投弹提前门 | 距离 ≤ 自动投弹提前量且满足两个对准门 → `RELEASE` |
| `RELEASE` | 投弹门打开 | 0.22s 间隔投 5 枚；航向/速度不变 | 第 5 枚释放 → `EGRESS` |
| `EGRESS` | 投弹完成或错过投弹点 | 清目标，只沿最后航段继续；不重攻 | 出界或生命期到 → 静默回收 |
| `ABORTED` | 全部轰炸机被击落 | 任务终止，不生成幽灵炸弹 | 立即终态 |

已释放的炸弹在轰炸机被击落后继续下落；伤害归因使用安全化后的发射者引用，发射者失效只丢失击杀归因，不得崩溃。

### 3.2 投弹与落点

```text
release_lead_px = aircraft_speed_mps × PIXELS_PER_METER × fall_time × horizontal_retention
bomb_pos(t+dt) = bomb_pos(t) + horizontal_velocity × dt
bomb_altitude(t+dt) = max(0, start_altitude × (1 - elapsed / fall_time))
elapsed >= fall_time → 在 bomb_pos 生成一次爆炸并结算敌对 GroundUnit
```

投弹点不是用“距目标小于固定半径”硬触发，而是同时满足提前量、航向和横向航迹三门；因此曲线路径或最后一刻大转弯不会把炸弹甩到侧面。

### 3.3 阵营规则

- 伤害一律走 `CombatUnit.teams_hostile(source_team, target.team)`。
- 每枚炸弹以 `kind="bomber_bomb"` 结算；这是战略硬目标唯一接受的伤害通道。玩家机炮、火箭、导弹、激光和友军常规对地火力均无法伤害或锁定战略硬目标。
- 友军 B-1B 不继承 `TEAM_PLAYER` 的技能、经验或 RTS 控制；使用 `TEAM_ALLY`。
- 轰炸机击杀可正常写 EventLogger；第三方友军击杀不给玩家 XP/生涯击杀，沿用既有第三方收益隔离。
- 敌军 Tu-160 可打已解放机场的 ALLY AA/SAM 等地面资产；没有敌对 GroundUnit 时炸弹仍落地演出，但无伤害。

## 4. 结构与组成（Structure）

- `BomberMission`：每个编队共享一个 Node 任务控制器，持有航路、目标点、阵营、成员和状态；控制器 10Hz 更新，不给每架轰炸机单独挂决策节点。
- `SurvivorSpawner`：创建 B-1B/Tu-160 参数副本与 Aircraft；提供 `spawn_bomber_mission(team, route, target_pos, count)`。
- `BulletManager`：独立 `_bombs` 数组，更新下落、爆炸和批量绘制；不把重炸弹分支塞进普通子弹热路径。
- `AircraftRenderer`：B-1B / Tu-160 两个轮廓；仅表现差异，不承载任务状态。
- Debug：友军/敌军各一个“指定当前镜头中心为目标”的生成入口，用于可重复验收；玩家可见任务提示如新增则走 i18n。

## 5. 验收标准（Acceptance / Litmus）

- [ ] 友军 B-1B 沿含一个转折的指定航路进入，在目标前自动投 5 枚，命中敌军 GroundUnit，之后不掉头、飞出地图。
- [ ] 敌军 Tu-160 用同一路径反向执行，炸毁 ALLY GroundUnit，不伤敌军地面单位。
- [ ] 两阵营轰炸机均不选择/攻击任何 Aircraft，玩家从其机头前飞过也不开火。
- [ ] 目标点无地面单位时仍完成投弹演出并离场，不在目标上空盘旋。
- [ ] 地堡、仓库、导弹井无法进入玩家/AI 的雷达目标表与武器候选；常规武器命中伤害为 0，只有敌对轰炸机炸弹 AOE 可扣血并摧毁。
- [ ] 飞机在第 1 枚后被击落：已释放炸弹继续落地；未释放炸弹取消；无 freed-instance 报错。
- [ ] 弯曲进场且未满足 12°/140px 门时不侧投；错过目标后直接 ABORT/EGRESS。
- [ ] 无头测试覆盖状态迁移、提前量、阵营过滤、出图与发射者失效；加入 `--bench=all`。
- [ ] 性能：任务决策 10Hz；炸弹更新 O(炸弹数)，爆炸用共享空间网格邻域查询；Sentinel + Lv5+ 压测不低于 60 FPS。
- [ ] 已知 seam：第三方收益隔离、玩家引用持有者、跨帧攻击者净化均通过现有校验。
- [ ] i18n：新增玩家可见提示三语齐全。
