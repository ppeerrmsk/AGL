# 全图察觉与交战规则（ROE）—— 仇恨 · 热度 · 任务姿态 · 第三方势力

> 玩家视角：地图上的敌人不再是"一锅全知全觉的追踪导弹"——守区的守区、巡逻的巡逻、
> 猎杀队才是真正冲着你来的；你的动静越大，来找你的敌人越密（难度即热度，不上 HUD，
> 用敌人密度本身说话）。同时友军以事件登场：护送任务送功勋、友军机场有防空伞、
> 预警机给你极速锁定 buff——战场从"你 vs 所有人"变成一场你身处其中的战争。

## 1. 设计意图（Why）

### 1.1 现状与要解决的缺口

现状四件事（代码实证，2026-07-12 审计）：

1. **常规敌机的目标选择其实已有感知门**——只从雷达锥累积的 radar_targets 里选目标、按
   可命中性四因子评分，且**没有**"优先玩家"硬编码（敌人打玩家还是僚机本来就是涌现的）。
   底子是好的。
2. 但其上叠着**两个上帝视角 director**：hunter 指派（每 5s 拿玩家真实坐标点名闲置敌机
   强制交战，配额 `max(3, 2 + level/2)`，无视雷达）+ 磁吸航点（每 8s 把闲置敌机的巡逻环
   重锚到玩家周围 800~1500px；增援类已改锚点环豁免，未分类遗留单位仍被磁吸）。
3. **simple_ai（UAV 族）是"距离即察觉"的近全知**（雷达 ×1.2 全向），不走雷达锥。
4. **没有显式"察觉/未察觉"状态，也没有阵营层**——team 是严格二值（0 友 / 1 敌），全部
   敌我判断散写 team 直比，第三方势力无处容身；机体颜色（icon_color）不与阵营挂钩。

于是缺一层全局规则回答：

- 谁**知道**玩家在哪（察觉）？
- 知道了以后**该不该来打**（ROE / 任务姿态）？
- 同时**允许多少人**来打（热度 / 配额）？
- 来打的人**打谁**（玩家本机 / 僚机 / 第三方）？

### 1.2 体验目标

1. **察觉可读**：敌人"发现你"是可观察事件——未发现的中队按自己任务飞（可绕开、可偷袭、
   可观察）；发现你的中队行为立刻可读（转向、加速、扑过来）。
2. **热度即难度**：游戏的"主动压力"轴（多少敌人来找你）全权由战斗热度驱动。热度**不上
   HUD**——玩家的感知途径就是效果本身：来找你的敌人变密了。安静则冷、大杀则热，
   难度随等级通过热度地板自然爬升。
3. **多线战场（事件化）**：第三方友军以事件方式登场——护送任务（功勋奖励）、友军机场
   防空（地面拒止圈）、预警机支援（锁定/导弹 buff 区）。不可操控、不抢奖励、不抢戏，
   给玩家"这场战争里不只有我"的战场感 + 实打实的支援价值。
4. **任务感**：每个敌方中队有明确任务姿态（守区 / 巡逻 / 狩猎 / 转场 / 撤离），行为从
   姿态直接推出，玩家看两眼航迹就能分类。
5. **敌我一眼可辨**：全部友好单位（玩家小队 / 第三方 / 中立设施）统一蓝绿冷色系，全部
   敌对单位统一橙红暖色系。不再出现蓝色敌机。

### 1.3 Litmus 自检（DESIGN_PHILOSOPHY）

- **信息察觉优先于数值**：热度的反馈 = 敌人密度本身（效果即反馈，无 UI 中介）；AWACS
  buff 的反馈 = 锁定进度条肉眼加速；姿态差异 = 航迹差异。全程无"看不见的暗数值 UI"。
- **战场氛围要热闹 + AI 要演戏**：第三方事件战线 + 巡逻/守区任务感直接服务此条；"敌人
  有自己的事要做"比"全员盯玩家"更像战争。
- **安全玩法有成本**：躲起来降热度 → 只降"来找你的人"，480s 战区时钟照走、token 存量
  照涨（增援机制既有语义）、战区任务不会自己完成——挂机不划算。
- **难度可读**：热度单一输出（hunter 配额）、线性公式、静默基线复刻既有配额曲线——
  可回退、可对拍。
- **60 FPS**：全部决策骑既有 tick（hunter 5s / 航点 8s / 热度 1s / ROE 2s 中队级）；
  感知判定 = 中队数 × 阵营数的纯标量距离比较，**零新增每帧全场扫描**。

### 1.4 反模式规避与简化原则

- **能一个杠杆解决就不加第二个**（v2 核心原则）：热度唯一输出 = hunter 配额；感知唯一
  主体 = 中队。v1 草稿的档位/滞回/HUD 指示器/态势泡公式/拥挤惩罚/追击线全部砍除。
- **不加 HUD 常驻新元素**：热度纯内部量（EventLogger 打点供调参，玩家不可见）。
- **不做潜行游戏**：未察觉是节奏调节层，不是玩法验证层。不加"可见度条"，玩家不需要为
  隐蔽做任何操作投入。
- **不做"敌人集体变瞎"**：HUNT 姿态保持全知（设定 = 地面指挥所 GCI 引导），保证任何
  时刻都有"确实冲你来的"压力来源；感知门只约束守区/巡逻等"有自己工作"的敌人。
- **不覆盖玩家命令铁律**：本 spec 只管敌方与第三方 AI；玩家小队 commanded_target /
  轮盘语义一概不动。
- **不做每帧扫描 / 不做传送**：第三方入场离场全程物理飞行；察觉判定事件驱动 + 骑 tick。

## 2. 数据定义（What —— 全部数值，权威源）

### 2.1 阵营与敌我关系

| 阵营 | team 值 | 说明 |
|---|---|---|
| PLAYER（玩家小队） | 0 | 玩家 + 僚机 + 忠诚僚机（**可控友军**） |
| HOSTILE（敌军） | 1 | 全部现有敌人（机 / 地面 / 舰队 / BOSS） |
| ALLY（第三方友军） | 2 | **新增**。一切不可操控的友军：护送直升机 / 机场防空地面单位 / 预警机 / 奖励·停靠航母（存量收编，原 team 0） |
| （预留）NEUTRAL | 3 | 本期不实装。非战斗设施不是 CombatUnit，不进阵营矩阵，只吃色板规范 |

**敌我判定唯一 API**（收口点，全项目禁止再散写 `team != team` 直比）：

```
is_hostile_to(a, b) := (a.team == HOSTILE) != (b.team == HOSTILE)
```

即：HOSTILE 与 PLAYER、ALLY 互为敌对；PLAYER 与 ALLY 互为友好（不可误伤锁定，弹药
命中不结算——沿用现有友军免伤语义）。任何未来阵营扩展只改这一个函数。

**现状收口清单**（2026-07-12 审计，迁移工单四类分治，见 §6 阶段 1）：

- **A 类 · 敌我判断**（`team != team` 直比 → 改走 `is_hostile_to`）：AI 目标选择评分、
  生存模式雷达锁定累积循环、飞机武器模块的机炮/导弹扫描、子弹/导弹管理器的命中结算、
  地面单位 / 海军武器 / 激光 / 电磁炮的目标过滤。⚠ 这类直比在三阵营下会把 ALLY 判成
  玩家的敌人——是必须收口的根本原因。
- **B 类 · 玩家特权**（`team == 0` 硬编码，约 40 处，语义改为"玩家小队"判定
  `is_player_squad()`，**ALLY 不得继承**）：技能/热诱弹/规避/光环 gating、RTS 指挥归属、
  team0 间 datalink 共享、子弹友军减免、锁定警告显示豁免、战术 planner 自动开火门。
  保持行为不变、只换判定入口。⚠ 航母收编 ALLY 后复核停靠/登舰判定不受 team 影响。
- **C 类 · 上帝 director**（用玩家真实坐标的两个全局 tick）：hunter 指派与磁吸航点当前
  以 `team != 0` 捞单位——三阵营下会把 ALLY 拽去"追杀玩家"。阶段 1 先止血
  （改为只捞 HOSTILE），阶段 2 按姿态体系重构（§2.3）。
- **D 类 · 配色二分**：全部 `team == 0 ? 蓝 : 红` 的颜色函数（标签底/雷达锥/尾迹/导弹/
  datalink 线）+ 战术地图自有色板（玩家绿）——统一迁入 FactionPalette（§2.7）。

### 2.2 感知模型（中队级 —— 谁、以谁为目标、在干什么）

**感知主体是中队，不是单机**（单机敌人视作 1 机中队）。每个中队只维护一份状态，
避免逐机感知计算：

| 字段 | 取值 | 说明 |
|---|---|---|
| `posture` | garrison / patrol / hunt / transit / egress | 任务姿态（§2.3） |
| `aware` | 未察觉 / 已察觉 | 中队整体察觉状态 |
| `squad_target` | 敌对阵营的某中队/单位 或 空 | 中队当前打谁；成员在目标内部按既有可命中性评分自选具体对象 |

**察觉来源（三条，任一命中即全队察觉）**：

| 来源 | 判定 | 成本 |
|---|---|---|
| **感知圈** | dist(长机, 敌对方最近单位) ≤ 长机 `radar_range`（**全向**） | 骑 2s ROE tick；中队数 × 敌对单位数的纯标量距离比较 |
| **事件察觉** | 任一成员被伤害 / 被锁定 → 全队立即察觉 | 事件驱动（挂既有伤害/锁定信号） |
| **datalink** | 敌雷达站存活时，所属战区守军共享 20km 感知（收编 60km-density-pass 既有语义） | 既有 |

- **感知圈 = 长机雷达距离、全向、零新常量**：中队多机朝向各异，整体全向感知合理。
  不引入独立的"态势泡"常量与公式（v1 草稿曾设计 per-unit 泡，按 review 简化删除）。
  各机型感知即其雷达梯度：UAV 800m · F-86 2200m · MiG-29 4000m · Su-35 5500m ·
  MiG-31 6000m（数值即各机现有 radar_range，无第二套表）。
- **锁定不变**：单机前向雷达锥仍只管锁定/开火（既有机制不动）——察觉管"知不知道你在"，
  锁定管"能不能打你"。
- **察觉记忆**：`AWARE_MEMORY_S = 15`——察觉后连续 15s 三条来源全空 → 回未察觉、返回
  任务。中队状态随队存（长机阵亡由继任长机承接，不丢）。
- **simple_ai 收编**：UAV 族现行"雷达 ×1.2 全向距离检测"退役，统一走中队感知圈
  （UAV 长机 800m ≈ 现行 960m，体感不变）；低空/云中遮蔽系数保留照乘。
- **地面单位不进感知体系**：SAM/AA/雷达站/舰队"射程即感知"，既有行为一概不动。

### 2.3 任务姿态（Posture —— 敌方中队的"工作"）

姿态与 AI 原型（Gladiator/Lancer/Schemer）**正交**：原型管"怎么打"，姿态管"任务是什么"。
姿态是中队级字段（§2.2 状态表），增援既有 `reinf_phase` 的 transit/egress 并入本枚举，
onstation 归入 patrol。

| 姿态 | 谁 | 目标获取 | 追击约束（leash） | 察觉后行为 |
|---|---|---|---|---|
| **GARRISON 守区** | 战区任务空战中队 / 驻守预算队 / 舰队护卫 | 仅自身感知 + 战区 datalink | 交战对象必须在 `zone.radius + GARRISON_LEASH_M(1500)` 内；目标脱出 → 停追、回盘旋环（语义同命令轮盘"防守此区"：只打圈内、出圈停追不散阵） | 圈内接敌；绝不离区追击 |
| **PATROL 巡逻** | 旅途增援到站后（原 ONSTATION） | 仅自身感知 | 追击距自身锚点/线路 ≤ `PATROL_LEASH_M(6000)`；超出或丢失 → 回巡逻 | 接敌并有限追击 |
| **HUNT 狩猎** | 从 PATROL 池抽调（既有 hunter 制度） | **全知**（GCI 引导，免感知） | 无 leash，全图追击玩家小队 | 常驻察觉态 |
| **TRANSIT 转场** | 增援入场途中（既有） | 仅事件察觉 + 感知圈近距自卫 | 被打回应 / 近距自卫，威胁解除继续赶路 | 自卫式接敌 |
| **EGRESS 撤离** | 增援退场（既有） | 仅事件察觉 | 被打回头应战（既有语义不变） | 自卫式接敌 |
| —（豁免） | Adds / BOSS / 事件敌人 | 事件系统自管 | 不进姿态体系（既有豁免清单不变） | — |
| —（地面） | 敌 SAM / AA / 雷达站 / 舰队 | 射程即感知（既有） | 不移动 | 既有行为不动 |

**PATROL 两个子型**：

- **定点环**（既有增援锚点环，默认 70%）：绕锚点 4 航点环盘旋。
- **线路巡逻**（新增，30%）：到站时 roll 中——把自身锚点与最近的另一活跃锚点连成往返
  线路（走 AIController 既有 waypoints 数组），沿线巡逻。leash 判定取距**线段最近点**的
  距离。两锚点间距不足 `ROUTE_MIN_LEG_M(4000)` 时退化为定点环。

**HUNT 抽调与归还**：hunter tick（5s，既有）从 PATROL 姿态中队抽调转 HUNT。**配额按
单位数计**（数值连续性见 §2.4），抽调**以中队为单位**：配额余量 ≥ 队规模时整队转 HUNT
（成建制猎杀），余量不足时不拆队、改选更小的队或孤狼单机。目标失效 / 自身减员过半 /
配额下调时归还为 PATROL（物理飞回原锚点）。抽调优先距玩家近者（既有）；配额下调不强拆
正在交战的 HUNT，只停新指派。

### 2.4 战斗热度（Heat —— 难度的主动压力杠杆，纯内部量）

一个全局标量 `heat ∈ [0,100]`，**不上 HUD、无档位、无任何新增玩家可见文本**——玩家对
热度的感知途径就是效果本身：**来找你的敌人变密了**。游戏难度的"主动压力"轴由热度全权
驱动（敌机 HP/伤害的等级缩放是另一条既有轴，不动）。

| 事件（仅玩家小队参与才计入） | Δheat |
|---|---|
| 玩家小队击杀敌机 | +5 |
| 玩家小队击毁地面 TGT / 舰船 | +8 |
| 攻克战区 | +15 |
| 玩家小队成员被命中 | +2 |
| 衰减：连续 6s 无玩家小队参与的交战事件 | −2 /s |
| 等级地板（难度随进度爬升的载体） | `heat_floor = min(75, level × 5)` |

第三方势力的交战**不计入**（那是他们自己的战争，热度只度量玩家的动静）。

**唯一输出——hunter 配额**（单杠杆，无其它耦合）：

```
hunter_quota = round(2 + 10 × heat / 100)        # 值域 2~12
```

数值连续性：**静默基线（heat 贴地板）≈ 既有配额曲线**，活跃度在其上加成——

| 等级 | heat_floor | 静默配额（新） | 既有配额（旧 `max(3, 2+L/2)`） | 满热配额 |
|---|---|---|---|---|
| Lv1 | 5 | 3 | 3 | 12 |
| Lv6 | 30 | 5 | 5 | 12 |
| Lv10 | 50 | 7 | 7 | 12 |
| Lv15 | 75 | 10 | 9 | 12 |
| Lv20+ | 75 | 10 | 12 | 12 |

heat 更新骑 1s tick，事件增量走既有击杀/伤害信号；EventLogger 打点 heat / quota
（F9 回放调参用，玩家不可见）。

### 2.5 仇恨分配（打谁 —— 两道闸）

1. **感知门**：GARRISON / PATROL / TRANSIT / EGRESS 中队必须真的察觉（§2.2）才允许获得
   squad_target——承接 engagement-discipline"无意图不开火"，把"意图"的来源也管起来。
2. **配额闸**：全知指派只存在于 HUNT 姿态，数量被热度配额封顶（§2.4）。

中队接敌后，成员打玩家本机还是僚机 = 既有可命中性评分涌现（现状本就无"玩家优先"硬编码，
保持不动）。**不做** per-target 攻击者上限 / 拥挤惩罚（v1 草稿曾设计，按 review 简化删除；
若 playtest 出现"全员叠玩家本尊"再作为调参项补回）。

敌方对第三方（ALLY）：GARRISON / PATROL 按感知正常接敌；HUNT 专职猎杀玩家小队，被 ALLY
伤害时按事件察觉正常还手，威胁解除（击落 / 丢失 15s）后回归猎杀，不设专用常量。

### 2.6 第三方势力（ALLY —— 玩家不可操控的友军，以事件登场）

**通用规则**（全部 ALLY 单位一致）：

| 规则 | 值 |
|---|---|
| 阵营 | team = ALLY(2)；与玩家互不敌对、互不误伤（同友军免伤语义） |
| 操控 | 完全不可操控：不响应点击 / 轮盘 / 数字键，不入玩家编队 UI，不可选中 |
| XP / 功勋 | ALLY 击杀敌人 **0 XP、0 功勋**（按击杀归因判定）；kill feed 照报（友军色） |
| token / 实例 | 不占敌方 token，不计入敌方实例上限；计入全局单位数（性能预算见 §5） |
| 热度 | ALLY 的交战不计入 heat |
| 色板 | 一律 `COL_FRIEND_ALLY`（§2.7） |
| 存量收编 | 战区奖励航母 / 停靠航母（现 team 0）迁入 ALLY——从此语义纯净：**可控 = 玩家小队(0)，不可控友军 = ALLY(2)** |

**登场方式 = 三类事件**（骑既有 GameEvent + EventDirector 剧本系统，不走刷怪 spawner）：

#### (a) 护送任务（Escort）

| 字段 | 值 |

## 3. 行为与公式（How）

### 3.1 中队察觉状态机（每中队一份，骑 2s ROE tick + 事件信号）

| 状态 | 进入 | 行为 | 退出 |
|---|---|---|---|
| **未察觉** | 默认 / 记忆超时 | 按姿态飞行（守区绕环 / 巡逻走线 / 转场赶路）；squad_target 保持空 | 三条感知来源任一命中 → 已察觉 |
| **已察觉** | 感知命中 | 按姿态 ROE 决定接敌与否（§2.3 表）；接敌者走既有交战路由 | 连续 15s 无感知刷新 → 未察觉并返航任务 |

HUNT 姿态常驻已察觉（全知）。察觉是**中队级门**，门后的一切交战行为（BFM / 武器准则 /
攻击跑 / 交战纪律）全部复用既有系统，本 spec 不触碰。

### 3.2 leash 判定（骑既有 8s 航点 tick + AI 决策 tick）

```
GARRISON:  engage_allowed(target) := dist(target, zone.center) ≤ zone.radius + 1500m
           # 目标出圈 → 清 squad_target、回盘旋环（不追、不散阵）
PATROL:    keep_chasing := dist(self, anchor_or_route) ≤ 6000m
           # 超 leash → 清 squad_target、飞回锚点/线路
HUNT:      无约束
```

leash 释放与 engagement-discipline"无 combat_target → 停火"天然衔接：出圈即停火返航，
不会出现"边跑边回头乱扫"。

### 3.3 热度主循环（1s tick）

```
heat += Σ(本秒事件增量)
if 距最近一次玩家小队交战事件 > 6s: heat -= 2
heat = clamp(heat, heat_floor(level), 100)
hunter_quota = round(2 + 10 × heat / 100)     # 唯一输出
```

hunter tick（5s，既有）只在 `当前 HUNT 单位数 < hunter_quota` 时抽调。

### 3.4 第三方事件流程

```
护送:     触发 → 玩家前方侧边缘生成直升机队 → 沿 A→B 直线飞行(~18km)
          → 中段脚本派 2 波拦截 → 到达判定(距终点 ≤800m/架) → 按存活数发功勋 → 出界释放
AWACS:    触发 → 边缘生成 → 飞抵航线端点 → 两点直线往返(既有 AIDirective FOLLOW_PATH)
          → 被击落: buff 圈消失, 冷却 180s 后可再触发
机场防空: 开局部署, 常驻, 无生命周期
```

### 3.5 AWACS buff 注入（两处单点，均非每帧新扫描）

```
锁定注入: 既有锁定累积循环的 lock_rate 处单点乘 3.0
          条件: shooter 是玩家小队 且 AWACS 存活 且 dist(shooter, awacs) ≤ 8000m
          （每帧仅玩家小队 ≤9 个单位各多一次距离比较）
导弹注入: 发射瞬间 shooter 在圈内 → 该弹 turn_rate ×1.25（快照式，弹生命周期内不再查询）
```

## 4. 结构与组成（Structure —— "ROE 系统做在哪"）

三层切分，严格遵守模式隔离（共享层零 `if in_survivor`）：

| 层 | 住哪 | 管什么 |
|---|---|---|
| **IFF 敌我关系** | 共享层 CombatUnit（单一 API `is_hostile_to` + `is_player_squad`） | 阵营矩阵；全部散点 team 直比收口到此 |
| **感知 / 察觉 / leash** | 共享 AI 层（AIController / target_selection），全参数化（中队状态存单位 meta，posture / aware / squad_target） | 中队的"看没看见、许不许打、追多远" |
| **ROE 指挥部（Director）** | 生存层新模块 `RoeDirector`（RefCounted，SurvivorSpawner 持有，骑既有 5s/8s tick + 新增 1s 热度 / 2s 感知 tick） | 热度账本、hunter 配额、姿态指派、中队察觉判定 |
| **第三方事件** | 既有 GameEvent + EventDirector 剧本系统（3 个新事件类：escort / airfield_garrison / awacs_support） | ALLY 单位的生成与生命周期（**不走刷怪 spawner**） |
| **AWACS buff** | 锁定累积循环单点注入 + 导弹发射快照注入 | §3.5 两处 |
| **阵营色板** | 共享层常量表 `FactionPalette`（收编 GameConstants 二分色函数 + 战术地图散点色板） | 全部颜色 Token 单一源 |

- **RoeDirector 取代两个上帝 director**：hunter 指派制度保留但改为"姿态 + 配额"驱动
  （§2.3/§2.4）；磁吸航点（绕玩家 800~1500px 重锚）**退役**——未分类遗留单位落回真
  PATROL 语义（原地绕环或引导至最近锚点），不再跟着玩家漂。
- 姿态权威字段 `roe_posture` 存单位 meta，与增援 `reinf_phase` 合并（transit/egress 直接
  并入枚举，onstation → patrol），避免双字段漂移。
- **姿态执行不新增航线系统**：守区/巡逻/驻泊/预警机航线全部复用既有声明式 AIDirective
  （FLY_TO_POINT / PATROL_RING / FOLLOW_PATH / HOLD_POSITION / ENGAGE_TARGET / PASSIVE）
  与增援锚点环管线；本 spec 只加"姿态 → 指令 + leash 参数"的映射层。
- 第三方生成复用 `SquadFactory.create` / 地面单位既有生成管线，只换 team 与任务参数。
