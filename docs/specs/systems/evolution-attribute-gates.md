# 进化属性门槛 —— 三轴技能点 / 卡片合一 / 属性守门 / 里程碑奖励跟玩家走

> 纯等级门槛下，玩家每局都能复刻同一条进化路线，"进化"退化成解锁清单。
> 本 spec 让每局的卡片选择成为进化的**前置承诺**：想开某架飞机，先活成那个流派；
> 沿途的投入换成**跟着玩家走**的基础属性奖励，换机不丢。

## 1. 设计意图（Why）

- **问题（用户 2026-07-19）**：进化只查等级 → 每局必然能选同一架机 → 进化无意义、局与局无差异。
- **一个事件、一种货币（用户反推定案）**：每 3 级一次**卡片三选一**，三张卡 = 斗士/骑士/策士**各一张**
  （家系内随机抽具体技能）；选卡 = 得该技能 **且** 该轴 +1 技能点。
  点数收入 = `floor(LV ÷ 3)`，满级 LV26 ≈ **8 点** —— 全部门槛按这个总量级设计（§2.3）。
- **Litmus 自检**（DESIGN_PHILOSOPHY）：
  - 单杠杆：一个事件（卡片）同时是随机性来源（抽哪张技能）、build 承诺（加哪个轴）、进化钥匙（门槛）。
  - 效果即反馈：门槛缺口画在进化树卡上；三轴状态常驻 Tab（§3.2），不加新 HUD 页面。
  - 复用既有数值：三轴沿用技能数据的 `affinity`（GUN/MISSILE/EW）；奖励全是既有字段（HP/弹量/雷达/flare）。
  - 中队级粒度：技能点/里程碑是**玩家全局单池**，ACE/僚机进化查同一份。
- **反模式规避**：无 respec；无强制硬保底；4 级金卡只走
  [classified-card-pity](classified-card-pity.md) 的隐性递增权重；三轴就是三个（用户订正）。
- **与既有决策的关系**：不动“停靠结算进化”经济流；“升级不打断”照旧（卡片事件本就是既有三选一节奏）；
  技能卡、里程碑加成与特殊武器都跟玩家局内库存走，机体底线武装仍随机体变化；武器权威见
  [inrun-weapon-inventory](inrun-weapon-inventory.md)。

## 2. 数据定义（What —— 全部数值，权威源）

### 2.1 三轴定义（玩家可见名即此三词；敌机 AI 的 Gladiator/Lancer/Schemer 内部词汇照旧不上 UI）

| 轴 | 覆盖内容（用户定义） | 守门的机种类 | 对齐 affinity（tree §3） |
|---|---|---|---|
| **斗士** | 突击&近战 / 机炮 / 狗斗能力 | **攻击线**（主）+ 偏近战制空机 | GUN |
| **骑士** | 机动力生存 / 雷达导弹 | **远程线**（主）+ 偏远程制空机 | MISSILE |
| **策士** | 心理战 / 电子战 | **电战线**（主） | EW |

### 2.2 事件节奏与收入

- **每升 3 级**（L3/6/9/…/24）触发卡片三选一：斗士卡 / 骑士卡 / 策士卡各一张（家系池内随机抽技能）。
- 选卡 = 技能入手 + 对应轴 **+1 技能点**。不选不补发（错过=错过，无堆积）。
- 收入公式：`points(LV) = min(floor(LV / 3), 8)`。关键刻度：LV4→1 · LV9→3 · LV10→3 · LV16→5 · LV21→7 · LV24+→8（顶）。
- **收入封顶 8（2026-07-28 v9，用户裁决）**：局内**无等级上限**（"满级 LV26"只是设计刻度，实际曲线可继续升），
  不封顶则 LV30=10 点起 §2.5 排他性数学全面失效（骑5+策5 双专精可行、路线承诺被稀释）。
  封顶后：8 点拿满仍触发卡片事件、技能照拿，只是不再加点（卡面不再显示"+1"标签、家系池抽空时不再合成"专注"纯加点卡）；
  **一切加点来源共用同一封顶**（卡片 / 战区奖励卡 / debug 补发）。`milestone_plus` 的里程碑进度加成（cap 2）不受影响
  ——双计数隔离照旧，10 点预留档从此只能靠 8 点 + 进度加成 2 摸到，坐实"稀罕"。
- 卡片池沿用 survivor-skills 全表按 affinity 归三家系；GLOBAL/UNIVERSAL 类可出现在任意家系卡位。
- **升级节奏前提（联动 [survivor-loop](survivor-loop.md) §5，2026-07-28）**：XP 曲线指数 1.15→1.3 +
  Adds 等级计价废除后，10 分钟战区平均局收 LV18~22（≈6~7 点）、LV24+ 才摸到 8 点满额——
  T5 门槛（主轴 5）只有高节奏局 + 专注选卡才凑得齐，**顶级机不保底**。

### 2.3 门槛规则（v15：只检查具体轴，废除合计门）

- 数据层仅允许 `gladiator` / `knight` / `schemer` 与 F/A-18E 专用的 `any`；`sum_gk`、`sum_all` 从 schema、判定、UI 与文案中删除。
- 攻击机使用斗士门；远程机使用骑士门；电战机使用策士门。制空机按实际定位写成斗士、骑士或明确的两轴组合，不再以“斗骑合计”隐藏配比。
- UI 必须逐轴显示 `当前值 / 要求值`，并优先突出下一项不足的具体轴；达到等级但轴不足时不得只给抽象的“合计不足”。
- F/A-18E 的 `斗士≥1 或 骑士≥1` 保留为唯一 `any` 桥接特例。

### 2.5 收支验证（可行性 + 排他性，review 用）

| 节点 | 到手点数 | 最贵门槛消耗 | 余量 |
|---|---|---|---|
| LV4（T2 开门） | 1 | 1 | 0（第一张卡决定 T2 开局口味）|
| LV10（T3 开门） | 3 | 单轴3 | 0 ✓ 首次真承诺 |
| LV16（T4 开门） | 5 | 斗2+骑3 | 0 ✓ 深承诺 |
| LV21（T5 开门） | 7 | 斗3+骑3 / 单轴5 | 1~2 ✓ |
| LV26（AX-00） | 8 | 三轴各2 | 2 ✓ 均衡终点 |

- **排他性**：对向双专精不可同局（骑5 + 策5 = 10 > 8）✓；相邻双线可勉强共存（骑5斗3 → X-21 + X-09），
  但必然放弃第三线的一切（门槛与里程碑全丢）——每局最多"一主一副"。
  **本表数学由收入封顶 8（§2.2 v9）背书**：等级怎么通胀点数都不会超过 8，排他性与"路线承诺"永久成立。
- **专精 vs 均衡张力**：专精 5+ 冲单轴终极机 = 放弃他线里程碑；均衡 3/3/2 可进入 X-09、X-02、X-90 或 AX-00，但到不了单轴 5 点终点。

### 2.6 里程碑成长线（v13 提案：**斗士前置享受 / 骑士后期兑现 / 策士平滑成长**；只做属性修改，无词条无新技能）

| 线 | **2 点** | **3 点** | **4 点** | **6 点** | **8 点** | 10 点（预留，当前 8 点上限不可达） |
|---|---|---|---|---|---|---|
| **斗士** | **机炮射程 +20%** | **HP +25** | **伤害减免 +20%（复合装甲）** | **G 力 +2.0** | **失速速度 −5%** | **机炮备弹 +20%** |
| **骑士** | **雷达距离 +10%** | **高度变化速度 +10%** | **极速 +2%（加速 +1%）** | **导弹挂载 +1** | **导弹锁定目标数 +1** | 导弹挂载 +1 |
| **策士** | 经验值 +10% | 热诱弹 +1 | 锁定耗时 −10% | 热诱弹 CD −8% | 雷达锥角 +2° | 热诱弹 +1 |

- **可用属性池（用户 2026-07-19：能改的很多，不局限于表内）**——后续替换/扩档从这里取，规则不变：
  机炮 伤害/射程/备弹/梭射节奏 · HP · G 力（转弯半径随之收紧）· 失速地板 · 导弹挂载数 ·
  雷达距离/锥角 · 锁定耗时 · 极速/巡航/加速 · **高度变化速度** · 热诱弹 数量/CD。
  每线五档尽量用**五种不同属性**（本表即范本），比同一属性反复叠更有成长叙事。

- **纯属性铁律（用户）**：奖励只允许改既有数值字段（HP/弹量/雷达/伤害%/flare/锁定耗时/速度%）——
  **不带触发词条、不带新技能、不带光环特效**（v3 的 击坠回血/FEAR/不屈/黑障 全部删除）。
- **三轴时间曲线刻意不对称**：
  - 斗士在 2 点即获得可感知的机炮射程，3/4 点补齐 HP 与装甲，6/8/10 点再补 G、失速包络与备弹；选择斗士后立刻扩大有效射击窗口，兑现“机炮早期享受”。
  - 骑士在 2/3/4 点只铺雷达、爬升与速度包络，6 点才增加挂弹，8 点才获得多目标锁定；前期投资、后期形成齐射能力，兑现“导弹大器晚成”。
  - 策士维持现有平滑曲线，作为两种极端时间曲线之间的稳定基准。
- **早厚后薄不再是跨三轴硬模板**：仍禁止同一属性重复堆叠和不可感知的暗数值，但允许轴身份决定收益落点。
  斗士前置射击窗口与硬生存，骑士把大额资源（导弹 +1 / 多目标 +1）压在 6/8 点；均衡流仍能较早吃到三轴基础收益，专精流则换取明确的时间曲线与终局能力。
- **通用机炮伤害退出里程碑**：普通敌机大多已在有效梭射中死亡，继续加伤害主要产生 overkill；对精英/BOSS 的攻坚价值应由重型目标专属机制表达，不用全局炮伤把清杂一起抬高。
- **门槛与里程碑共同表达路线承诺**：进化门槛继续拉专精；里程碑不再一律反向拉平衡，而是让不同轴在不同局段兑现。
- 与门槛的咬合：首档 2 点 ≤ 全部 T2 门槛——开局前两张卡必亮一个里程碑；均衡流 3/3/2 三线各亮首档。
- 机动类属性（G/极速/巡航/失速地板/高度变化速度）一律走永久 params 写入（CLAUDE.md 加机动 buff 规范·类别 1
  ——AI 战术层经 effective_*() 自动可见；换型重放时同样重写新机 params）。
- 斗士 4 点档复用普通技能“复合装甲”的 `armor/(armor+100)` 软上限管线：里程碑写入 `armor +25`，
  因而对无穿甲的机炮是 `25/(25+100)=20%` 减伤；导弹沿用 50% 穿甲，等效减伤约 11.1%，并可与复合装甲技能自然叠加。
- **6 点 G 档必须跨过体感门槛**：`+0.2G` 对典型 7G 机仅约 3% 账面变化，实战几乎不可辨认；
  v14 改为 `+2.0G`，使 7G 机进入 9G 级。固定速度下可用法向加速度约提升 29%、高能盘旋半径约收紧 22%，
  且同步增加结构 G；这是深投斗士轴的明确战斗兑现，不追加伤害或新词条。
- **发放范围 = 全队**（2026-07-28 订正，详见 §2.7）：里程碑加成**跟玩家不跟机体**，
  且**下发给小队每一架存活飞机**（与技能 UPGRADES 的归属分流语义一致）——
  长机吃到的属性成长，僚机同样吃到。
- **按起手机分化（用户 2026-07-19 补充）**：上表是**基准表**；每个初始飞机有**自己的一套三线里程碑**
  （内容/强度可整表覆写）——起手机与某条线亲和时，该线奖励更强，鼓励对应玩法。
  方向示例（非定稿）：F-15→斗士线厚 / F-14→骑士线厚 / A-6E→斗士·突击口味 / 幻影 III→策士线厚。
  **具体四机分表由用户后续平衡时填**（"现在不用担心太多"）；本 spec 只定数据结构：
  里程碑表数据化，起手机 profile 可整表/逐档覆写，未覆写走基准表。每局路线由起手机在选机时即确定。

### 2.7 玩家层持有 / 全队下发 / 换型重放（用户第 4 点，⚠ 底层修改；v10 订正发放范围与记账粒度）

- 技能点、里程碑加成、卡片技能 **全部记在玩家层**（SurvivorData，局内 roguelike 每局清零），
  **不写死在任何一架飞机的 params 里**。
- **换机/进化 = 重放**：`evolve()` 换完新机 params 后，把玩家层的里程碑加成与卡片技能**重新套用**到新机上。
  这根治旧"自然成长"的路径依赖病（成长写进旧 params → 换型即丢，power-curve §0.4/§6 阶段 2 已判退役）。

#### 2.7.1 发放语义：**跟玩家不跟机体，且下发全队**（2026-07-28 订正）

| 维度 | 旧（v9 及以前） | 新（v10） |
|---|---|---|
| 受益者 | **只有当前操控机** | **小队全体存活成员**（长机 + 全部僚机） |
| 记账粒度 | 玩家级**单账本**（"哪些里程碑已发过"记一份） | **逐机记账**（每架飞机自己记"这架身上已挂了哪些里程碑"） |
| 玩家可见的账本 | 同一份 | "当前操控机那本账"的**视图**——Tab 三轴量表的读法与显示**完全不变** |

**为什么改**：里程碑是"跟玩家走的属性成长"，而技能（UPGRADES）早已按归属分流下发到全队；
里程碑只作用于当前操控机，与整个 RTS 小队方向自相矛盾——升满属性的是**玩家这个人**，
不是他此刻坐在哪架座舱里。

**四条派生规则**（全部由逐机记账构造性成立）：

| 场景 | 规则 |
|---|---|
| 达成新里程碑 | 对**当时存活的每一架**小队成员各发一次 |
| **新僚机入队** | 入队时**全量补挂**已达成的全部里程碑（晚入队不吃亏） |
| **换型（进化）** | 对全队**逐机重放**，且**每机恰好一次**——重放的语义是"先清账再全量重挂"，同一架机重复调用会把加成叠两遍 |
| **换帅**（1–9 切控 / 长机阵亡顶替） | 加成**不丢**：新操控机身上本来就挂着自己那份 |

> 🐞 **顺带修掉的 bug（v10 前长期存在）**：玩家级单账本 + 只发当前操控机 ⇒ 换帅后新操控机
> **一条里程碑加成都没有**，且因为玩家级账本"已发过"已经记满，**永远补不上**。
> 逐机记账后此 bug 由构造消解（不是加了个补丁，是这个错误状态不再可表示）。

- 发放范围的**注入方式**：里程碑发放点向外要一份"当前存活小队成员"列表；
  未注入时**退化为只发当前操控机**（老行为，保回归安全）。
- 实现载体对齐 **modifier-pipeline**（refactor/skill-modifier-system 分支的 accessor 收编 + ModifierTrace）：
  加成以修饰层叠在 params 之上而非改写基值，重放=重挂修饰层。
- **局内语义已确认（用户 2026-07-19）**：全部每局清零，无跨局持久。
- **武器同层**：特殊武器（电磁炮/激光/忠诚僚机等）同样记玩家层、换机重挂——独立成 spec
  [inrun-weapon-inventory](inrun-weapon-inventory.md)（"武器绑机型不继承"旧决策作废）。

## 3. 行为（How it feels）

### 3.1 卡片流

每 3 级触发既有三选一 UI：三张卡固定一轴一张、卡面带轴色边框与轴徽记（斗士红/骑士蓝/策士紫，色值实装定）；
卡角标注"该轴当前点数 → +1 后是否触发里程碑"（拿得到什么当场可见）。

### 3.2 Tab 常驻三轴面板（用户第 1 点；视觉 v6 用户 mockup 定稿）

Tab 菜单（战术图/结算坞同屏）常驻一栏：**三轴量表**——每轴一根 10 分格立柱（=点数上限），
加点从底部逐格点亮（轴色：斗士琥珀 / 骑士青绿 / 策士紫）；里程碑档位（2/3/4/6/8/10）在柱侧画刻度圈，
达成=实心亮圈、下一档=大空圈、远档=小空圈；柱顶点数、柱底轴色圆标+轴名。
量表下方**里程碑明细三列**（v7）：每轴逐档写明具体强化（"■2│HP+25"），三态标记
■ 已达成（轴色）/ ▶ 下一档（白高亮）/ □ 远档（暗）——每档给什么一览无余，不只留标题。
面板底部**状态块**（v7，y2k 终端风：⟦ ⟧ 小节头 + ▸ 条目 + ┊ 分栏）：
"当前加成"= 已生效里程碑按 stat 聚合（add 求和 / mult 连乘 → "HP +25 ▸ 雷达距离 +10%"）；
"机体状态"= live params 最终值（HP/极速/巡航/G/雷达 km±锥/锁定/弹量/热诱弹——一切加成落地后的真实数据）。
标题行路线倾向（按最高轴自动标注）保留。
同一控件（AxisBarsPanel）也陈列在结算坞右栏顶部（原强化栏位置）——选进化目标时门槛差多少一目了然。
只读展示，无操作，不加新页面；静态绘制无每帧重绘（性能守则 1）。

#### 3.2.1 主 HUD 抽象三轴计数器（v18 第一版）

- 现有底部经验条正上方新增一条固定 `400 × 18 px` 的只读计数器，与经验条同宽、间隔 `4 px`；现有经验条内的 `LV / XP` 文本保持不变，因此同一紧凑区域同时呈现当前等级与三轴进度。
- 计数器只分为三个等宽固定单元，按 `斗士 → 骑士 → 策士` 排列，文字格式为 `轴名 数值`；数值读取 `get_milestone_progress(axis)`，即门槛点数与 `milestone_plus` 加成之和，与 Tab 里程碑量表口径一致。
- 单元沿用 `SurvivorData.AXIS_COLORS`，但降低文字亮度；背景仅使用低透明黑底和弱分隔线，不使用闪烁、动画、描边、图标或音效。
- 总尺寸、单元宽度和字号均为常量；数值增长只能在单元内部改字，不得扩张控件、推移经验条或改变其它 HUD 锚点。
- 纯显示、鼠标穿透、无 tooltip；输入不变。控件不自带 `_process`，HUD 刷新只在三轴数值变化时触发重绘。

### 3.3 进化界面（v9 视觉强化：路线 color code + 点数 pip 徽记 + 当前机高亮）

  攻击=琥珀 / 远程=青绿 / 电战=紫 / 制空·桥接·母舰=琥珀+青绿双段 / 隐身=青绿+紫双段 / omni·传说=三色三段。

- **点数 pip 徽记**：每张已揭示卡片内下缘画**门槛 pip 行**——每 1 点具体轴门槛一枚对应轴纯色圆点；
  或门（F/A-18E any）= 一枚双色分瓣点。**已满足=实心、缺口=空心描边**——
  每架机要在哪条线砸几点、自己还差几点，扫一眼树就知道，不用逐个点开。
- **当前机高亮**：金色加粗边框 + 外圈光环 + 底色提亮，"当前"字样照旧——树再大也能立刻定位自己。

### 3.4 Debug

主菜单 B 的 boss debug 不经过结算站，因此仍**豁免进化判定**；但参考态必须和正式成长规则同源：

- 选机只列 `evolution_tree.json` 中 **T4（T5 终端机的前一档）**全部节点，不复用四架起手机白名单；
- 每项参考态是**至少四架同型机的正式玩家编队**（1 长机 + 至少 3 僚机），必须复用 `wingman_count`、`SquadFactory` 与起手僚机管线；不得把单机样本包装成编队 UI；
- 等级取该节点自身 `min_level`，技能次数与三轴收入同为 `axis_points_earnable(level)`（当前 T4 为 5~6 次），不得再用旧版 `level - 1`；
- 三轴先满足该节点 gates，剩余点投入机种主轴，以便在对应等级兑现可观察的里程碑；
- 特殊武器从正式三星战区奖励池加权、无放回抽取：5 次升级里程碑配 2 件，6 次配 3 件；尾雷/忠诚僚机继续互斥；武器先走正式奖励入口挂到当前 ACE，再筛技能，使硬件门控技能读取真实装备；
- 技能只从正式普通随机池抽取，并继续尊重机体身份、`max_stacks`、前置与排他；签名第四槽和 evolved 卡不混入；
- 战斗中 Tab 必须显示这份实际武器、技能、三轴与里程碑。Boss Debug 不加载正式战区地理，仅保留只读构筑面板。
