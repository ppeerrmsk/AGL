# 玩家飞机战斗力曲线规范 —— F-14 最弱锚点 / 档位必增 / 角色特色 / 数据解耦

> 玩家视角：每进化一档都**明确感觉到变强**，绝不"换了套武器反而变弱"；每架机特色鲜明
>（MiG-31 = 速度骑士雷达窄，F-16 = 电战眼睛尖，A-10 = 肉炮台）；敌机平衡随便调，不牵连玩家机。

## 0. 诊断（为什么现在乱，2026-07-03 两份 log + 数据审计）

1. **曲线失控的根因 = 倍率乘在异基数上**：进化变体 profile 的 mult 各自乘不同 base
   （mig31×f14_base、su34×a10_base、f22×default_fighter…），而起手 F-15 的雷达被 ×0.333 平衡性砍过
   → F-15(有效雷达 1667) 进化 MiG-31(4900)：**跳 3 倍**（用户感知"翻倍"）。同轴数值在不同机上不可比。
2. **文件层解耦已成立**：敌人 spawner 只用 `enemy_*.tres`；玩家 base 无敌人引用。要根治的是
   **玩家侧自身口径统一**（§3），不是拆共用文件。
3. **X-02 打杂鱼拉胯（log 190108）**：①**无常规机炮**（全体 X-02 机炮命中=0），清 UAV 无低成本手段；
   ②本人导弹已 80% 命中（航电修复生效），**僚机 X-02 仅 30%**——AI 发射窗口/技巧问题，属 AI 层非数值层（§7 backlog）；
   ③激光拦截无感（定位待查，§4）。

## 1. 规则（Why + 硬约束）

1. **锚点**：玩家 **F-14 = 全谱最弱基准（100%）**。所有数值以"有效值"（base × profile mult 之后玩家真实拿到的）为唯一口径。
2. **档位预算**：T1 = 100% / T2 ≈ 115% / T3 ≈ 130%（按签名轴加权，非每轴平推）。
3. **同类进化 = 纯升级**：任何轴不得低于前一形态（体感绝不倒退）。
4. **跨类进化 = 特色重排**：允许轴重排（如 攻击→电战 掉 HP 换雷达），但总预算仍按档位走高，
   且 UI 已显示武器/数值清单（用户知情选择）。
5. **每机最多 1 条 tradeoff 轴**（角色特色的代价，如 MiG-31 雷达锥窄），降幅 ≤ 前代的 -20%。
6. **雷达范围全谱走廊**：2800 ~ 5000（px），相邻档跳变 ≤ +25%——杜绝再翻倍。
7. **基础武器底线**：所有玩家机必带 机炮 + 导弹 + 热诱弹（2026-07-03 用户令；特色装备叠加其上）。

## 3. 数据解耦落地（How）

1. **新目录 `resources/player/`**：每个树节点一份完整 `player_<id>.tres`（AircraftParams，按 §2 有效值直写）。
   玩家专属，**敌机永不引用**；调敌人只动 `enemy_*.tres`，互不牵连（用户核心诉求）。
2. **PlayableAircraft profile 全部 mult 归 1**：base_params 指向对应 player 文件；profile 只留
   身份/卡片/wingman_count/装填开关等。**数值单一权威源 = player params 文件**，消灭"乘异基数"病根。
3. 旧 `default_fighter / playable_*_base` 退役为参考（或迁移后删除）；命名约定写入 playbook：
   **玩家机数值只改 resources/player/，敌机只改 enemy_\*，武器库 default_\* 共享只读**。
4. 武器资源（default_gun/missile/flare）作为共享**只读**库仍可引用；若某机要改武器数值 → 在 player/ 下开专属副本。

## 4. X-02 专项（log 实证）

- **补常规机炮**（default_gun 引用）：解决"打杂鱼没有低成本手段"（全体 X-02 机炮命中=0 的结构洞）。规则 §1.7 底线。
- 激光（x02_laser）**定位待查**：当前拦截无感——先查其实现（反导弹？DPS 束？触发条件），下一轮定改法。
