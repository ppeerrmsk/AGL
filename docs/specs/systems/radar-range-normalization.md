# 雷达距离规范化 —— 玩家三带（电战>骑士>斗士）+ 敌机分带

> 玩家视角：换更高档的飞机，雷达明显变强；电战机是"眼睛"，骑士机看得远打得远，
> 斗士机凑近了才咬人。初始机不再一出门就照半个屏幕。

## 0. 诊断（2026-07-26：为什么"卸掉配件了还是特别远"）

**结论：不是配件残留 bug，是基线 + 高度倍率本来就大。**

1. **配件链路已验证干净**：每局开始 `base_params.duplicate(true)` → profile 倍率 →
   LoadoutLedger 只把**当前已装**的配件乘进这份拷贝。卸载即写盘（user://loadout.cfg），
   下一局不会再乘。卸完还远 ≠ 残留。
2. **基线本身高**：power-curve v7 矩阵给 F-14 的雷达是 3600px = **7.2km**（"远程/团队"签名轴），
   F-15 是 3000px = 6km。T1 全带 2800~3800px（5.6~7.6km），这是感知"太远"的主因。
3. **高度倍率放大**：有效雷达 = 基线 × 高度倍率（连续插值：0m→×0.5 / 2000m→×0.6 /
   5500m→×1.0 / 10000m→×1.4 / 15000m→×1.5）。高空巡航时 F-14 实际显示锥
   3600×1.4 ≈ 5040px ≈ **10km**。
4. **配件曾经的叠乘**（历史体感来源）：三件雷达配件 ×1.15 × ×1.20 × ×1.25 = **×1.725**。
   全装的 F-14 = 6210px（12.4km），再乘高空 1.4 ≈ 17km——之前"照全图"就是它。
5. **局内成长仍会叠**（有意保留，不属于本 spec 整治范围）：骑士轴 4 点里程碑 ×1.10、
   电子战词条联动 category_radar_mult、电子战专家 +距离(cap 1km)、sig_gcap 联合突击
   ×1.05/层(≤4)、data_link 僚机雷达、"唯一的锁定" +500m 等。

## 1. 设计意图（Why）

- **体验目标**：雷达距离 = 机体"主题"的身份轴。**电战 > 骑士 > 斗士** 三带清晰分层；
  同一条进化线内逐档变强（升级=看得更远），初始机显著收窄（开局不再半屏锁定）。
- **Litmus 自检**（DESIGN_PHILOSOPHY）：
  - 单杠杆：只动 `.tres` 出厂基线一个杠杆，不新增任何运行时机制/字段。
  - 效果即反馈：雷达锥（悬停可见）直接变小/变大，无需 HUD 中介。
  - 复用既有数值：三带映射复用进化树三轴词汇（斗士/骑士/策士-电战），不发明新分类。
- **反模式规避**：不做"雷达等级"新系统；不做档位·滞回；敌机雷达顺带一次性对齐，
  不给敌机加独立成长。

### 2.4 敌机分带 + 迁移表

但常规敌机雷达封顶 4600；超过者必须是拦截专精/王牌/BOSS/传感器平台，且带窄锥或其他 tradeoff。

## 3. 行为与公式（How）

运行时公式**不变**（本 spec 零机制改动）：

```
有效雷达(px) = 出厂基线(.tres) × 高度倍率(§2.5) × 局内成长
局内成长 = 骑士里程碑 ×1.10（4点）· 电战词条联动 · sig/技能加成 ·（配件，待废）
锁定/开火距离 = min(导弹射程, 有效雷达)   ← 收基线 = 直接收玩家交战半径（有意）
```

⚠ 玩家侧同一联动：**电磁炮射程动态读本机雷达距离**——装电磁炮的机（战区获取/签名技能）
射程随本次收窄同步变短。电战机（新基线最高）恰好仍是最佳电磁炮平台，方向自洽，但
playtest 要专项确认电磁炮体感。
