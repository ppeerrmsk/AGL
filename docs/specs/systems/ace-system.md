# 王牌系统（ACE）—— 单英雄进化 + 王冠继任，调和"英雄 vs 编队"

> ⚠ **历史草案，禁止继续派生实现。** 当前技能语义中的“王牌”指玩家**当前操控机**并随切控迁移，
> 不再是本稿的固定长机角色。现行权威见 [skills-720-rework](skills-720-rework.md)、
> [squad-control-switching](squad-control-switching.md)、
> [aircraft-evolution-tree](aircraft-evolution-tree.md) 与
> [evolution-attribute-gates](evolution-attribute-gates.md)。下文只保留早期调和方案的历史过程。

> 解决地基矛盾：进化是"单机英雄"逻辑，编队是"RTS 指挥"逻辑。ACE 让**只有一架是英雄（吃进化树）**，
> 僚机走另一套轻成长，王冠在 ACE 阵亡时传给击坠最多者——单英雄进化与编队指挥两立。

## 1. 核心定义（✅ 用户定 2026-06-28）

1. **ACE = 玩家长机当前那架**（开局默认）。全队**唯一**一个 ACE。
2. **进化分对象**：有些进化只给 **ACE**，有些进化 **ACE 以外的僚机**。需明确哪些资源给王牌、哪些给其他人（§2）。
3. **继任 + 不继承**：ACE 被击坠 → **当前击坠数最高的存活僚机**继任为新 ACE。旧 ACE 身上**已生效的加成不转移**给新 ACE（如旧 ACE 换了机型 + 拿了升级，阵亡后这些一律不继承）。

## 2. 团队共享等级 + 人人进化（✅ 用户定 2026-06-28）

### 2.1 团队等级
- 杀敌经验进**团队共享等级池**（全队一个等级）。进化门槛走团队等级 → **ACE 和僚机都会进化**（人人爬树）。

### 2.2 王牌 vs 僚机：差在"额外深度"，不差在"进不进化"
| | 进化（团队等级触发） | 额外资源 |
|---|---|---|
| **ACE（王牌）** | ✅ 走进化树 | **王牌专属深度**：深度玩法机制 + 签名 loadout（具体待定，耦合"局内玩法深度"） |
| **僚机** | ✅ 走进化树（手动/自动 §2.3） | 无额外深度，只进化 |

> 修正前案：旧 §2 写"僚机不进化"是错的。人人都按团队等级进化；ACE 的特殊只在"额外吃一层专属深度"。
> 副作用（好的）：僚机各走不同进化路线 → 小队混编 → "切到不同号机=不同机型手感"**复活**。

### 2.3 进化模式 + 默认跟随（✅ 用户定 2026-06-28）
- **ACE = 强制手动**：每次进化机会，玩家**必须自己选**王牌路线，永不交给 AI。**自动进化只针对僚机**。
- **僚机默认 = 自动跟随王牌**：默认所有僚机**跟着王牌进化走**，最终都**进化成和王牌一样的飞机**（小队 = 王牌的精锐复制群）。
  - 跟随不可达时（环/树限制、起始种类离王牌太远）→ fallback：取当前等级**最强可达**升上去（贪婪升档），逐步往王牌的种类靠拢。
- **僚机可手动覆盖**：想要混编多样性 → 把某几架设成手动、预设不同路线。**默认统一、多样是 opt-in**（注：所以"切号机换手感"的卖点默认弱化，需手动分化才有；用户接受站位不严）。
- 触发见 §2.4（结算点，不在战斗中）。

### 2.4 进化触发与节奏（✅ 用户定 2026-06-28）
- **进化机会 = 战区结算 + 航母**：每**打完一个战区**给一次"升级 + 进化"机会；**航母**（战区奖励变体，见 [aircraft-evolution §2.7](aircraft-evolution.md)）是第二个升级/进化点。
- **战斗中不触发进化**（不打断 RTS）。团队等级只**门控**能进化到哪档；**结算点**才是扳机。
- **节奏**：一局进化次数 ≈ 清掉的战区数（+ 航母）。这把"5 档树 vs 10 分钟"对齐到**战区数**上（缓解 #3）。

## 3. 继任细则

- **触发**：ACE 阵亡。
- **选谁**：存活僚机中**击坠数最高**者（[combat-feed](combat-feed.md) 战况栏已把"谁在狂刷击坠=heir 候选"可视化，天然协同）。
- **不继承**：旧 ACE 的**王牌专属深度加成全丢**；新 ACE 就停在**它自己当时的进化状态**（僚机也会进化，所以它有自己的档位/路线），不补、不拉到旧 ACE 的高度（§4-C 不做保姆）。玩家自己取舍如何分配整体战斗力。
- **玩家接管**：玩家自动接管新 ACE（复用 squad-control-switching 的"击落接管"）。
- **边界（待定）**：① 击坠数**平手** tiebreak（按存活时长/距长机近？）② 继任者档位低（落差大，但 C 已定不缓冲）③ **全员阵亡** = game over。

## 4. 决议（A/B/C/D，✅ 用户定 2026-06-28）

- [x] **A — ACE = 长机角色（非亲驾机）**：✅ 接受。玩家切控到僚机时，ACE 含进化留在原长机由 AI 飞（你在指挥、不一定在当英雄）。
- [x] **B — 不继承，玩家自负盈亏**：✅ ACE 死=王牌深度全丢，玩家要自己权衡如何分配整体战斗力。高惩罚"护驾"张力是**故意的**。
- [x] **C — 先不做保姆**：✅ 继任不补档、不加速重爬。新 ACE 就停在自己当时的水平。
- [x] **D — 团队共享等级，人人进化**：✅ 见 §2。每架僚机手动/自动进化；自动补缺位；可同时分叉各走不同路线。

## 4.1 推敲进度

- [x] **自动进化逻辑**：✅ 定案——**默认僚机跟随王牌**（最终变同款），跟随不可达时 fallback 取最强可达（§2.3）。砍掉"补缺位"。
- [x] **自动 × 环 × 树空格**：✅ **消解**——自动只跟随/贪婪升档，不强求到达特定种类；树只需每节点 ≥1 可达出口。
- [x] **进化触发模型**：✅ 定案——**结算点触发**（战区结算 + 航母），战斗中不触发；等级只门控档位（§2.4）。
- [x] **默认统一 vs 多样**：✅ 用户选**默认统一**（僚机跟王牌变同款）；多样混编是手动 opt-in。"切号机换手感"默认弱化，用户接受。
- [ ] **ACE 的"额外深度"具体是什么（剩余核心）**：人人都进化后，ACE 只多吃"王牌专属深度" = **局内玩法深度**（仍 TBD，meta-progression §5）。整个局内体验的核心未定项，躲不过去。
- 注：继任后新 ACE 从"自动跟随旧王牌的状态"转为**强制手动**（玩家接手后亲自定它后续路线）。
