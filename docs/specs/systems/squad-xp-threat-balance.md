# 编队经验稀释与敌方警戒响应

> 单机以更高的单杀成长效率养成王牌；扩大直属编队则换取火力、容错和战场控制，同时引来更高敌方警戒。

## 1. 设计意图（Why）

- **体验目标**：单机与大编队都能通关，但形成不同玩法；单机每次击杀更值钱、build 更集中，大编队杀得更快但升级效率被稀释，并面对更大规模的敌方响应。
- **问题根因**：直属僚机把导弹齐射、目标覆盖和生存容错近似按机数放大；现有 XP、Token、敌机池和猎手压力只认玩家等级或近期战斗事件，不认直属编队规模，导致“僚机越多 → 杀得越快 → 升级越快 → 更强”的正反馈。
- **Litmus 自检**：遵守“信息察觉优先于数值”——敌方警戒在 Tab 战术图公开显示；遵守“一击毙命”——压力增长靠编成、方向和交战数量，不给普通敌机堆 HP；遵守“战场热闹且 AI 会演戏”——大编队引来多方向、成建制响应。
- **反模式规避**：不镜像玩家每条升级；不因玩家变强就让所有敌机同步加血加伤；不让绿色 Allied 变成被动 XP 机器；不通过瞬间刷出/瞬间删除单位制造橡皮筋感。

## 2. 数据定义（What —— 全部数值，权威源）

### 2.1 直属编队计数

`N` = 当前存活、登记在玩家直属小队中的蓝色 Aircraft 数量，包含当前操控机。

| 单位 | 计入 N | 说明 |
|---|---:|---|
| 当前操控机 | 是 | 切控不改变 N |
| 蓝色忠诚僚机 | 是 | 包含技能、进化或奖励生成的永久直属僚机 |
| 已阵亡直属机 | 否 | 致死归因完成后立即减员 |
| 绿色 Allied | 否 | 第三方，不属于玩家成长经济 |
| 友军航母、机场设施、地面单位 | 否 | 不是直属飞行小队 |
| 敌方或中立单位 | 否 | — |

直属机只要仍存活并登记在小队中就计数；距离玩家多远、是否在镜头内、是否暂时停放都不改变 N，防止通过派远僚机规避稀释与警戒。

### 2.2 编队经验倍率

```text
squad_xp_mult(N) = 2 / (N + 1)
pre_share_xp = 现有经验公式的最终整数结果
final_xp = round(pre_share_xp × squad_xp_mult(N))
```

| N | 经验倍率 |
|---:|---:|
| 1 | 1.000 |
| 2 | 0.667 |
| 3 | 0.500 |
| 4 | 0.400 |
| 5 | 0.333 |
| 6 | 0.286 |
| 7 | 0.250 |
| 8 | 0.222 |
| 9 | 0.200 |

敌机类别基础值、等级线性项、对头击杀、`xp_mult`、签名技、里程碑乘区及其既有取整顺序全部保持现有定义；编队倍率只乘在既有最终整数 `pre_share_xp` 上，确保 N=1 时逐点复刻当前结果。

### 2.3 XP 归属边界

| 致死来源 | 玩家共享 XP | 计击杀/回血/连击 |
|---|---:|---:|
| 任一蓝色直属小队成员 | 是 | 是 |
| 绿色 Allied | 否 | 否 |
| 敌方互相击杀 | 否 | 否 |
| 自然坠毁、出界清理、无有效攻击者 | 否 | 否 |
| `no_kill_reward` | 否 | 维持该目标既有规则 |
| BOSS 阶段 | 否 | 维持现有“只封 XP”规则 |

经验仍进入唯一的 `SurvivorPlayer` 共享经验条，不为每架飞机建立独立等级或经验条，不按尾刀者分配。

### 2.4 敌方警戒热度

```text
level_heat(L) = min(75, 5 × L)
squad_heat(N) = 6 × max(0, N - 1)
heat_floor(L, N) = min(100, level_heat(L) + squad_heat(N))
```

现有活动热度事件保持不变：玩家小队空中击杀 `+5`、地面/舰船击毁 `+8`、攻克战区 `+15`、任一玩家小队成员被命中 `+2`；安静 6 秒后按每秒 2 点衰减，但不得低于动态 `heat_floor`。唯一例外是僚机刚加入后的爬升窗口：热度允许暂时低于新地板，并按 §3.1 追向它。

| 玩家等级 | N=1 | N=3 | N=6 | N=9 |
|---:|---:|---:|---:|---:|
| 1 | 5 | 17 | 35 | 53 |
| 5 | 25 | 37 | 55 | 73 |
| 10 | 50 | 62 | 80 | 98 |
| 15+ | 75 | 87 | 100 | 100 |

### 2.5 编队响应预算

```text
squad_token_bonus(N) = 3 × max(0, N - 1)
base_token_budget(L) = TOKEN_BUDGET_BASE + floor(L × TOKEN_BUDGET_PER_LEVEL)
response_token_budget = min(TOKEN_BUDGET_MAX,
    base_token_budget(player_level) + supply_token_bonus + squad_token_bonus(N))
response_level = max(player_level, ceil(current_heat / 5))
```

- `response_token_budget` 控制同时在场的常规敌方战力；每名僚机约换来 3 Token，接近一架轻型战斗机的成本。
- `response_level` 只用于敌机池解锁、编成质量和响应节奏，不用于普通敌机 HP、机炮伤害或武器 Tier。
- 敌机属性与武器 Tier 继续读真实玩家等级，确保升级仍能让玩家感到变强。
- Token 达到性能上限后，额外警戒转化为更高质量编成、多方向入场、较短补充间隔和更合理的目标分配，不突破实体性能红线。

### 2.6 敌方出击编成倾向

敌方不会逐架镜像玩家，但**未来生成的常规战斗机出击批次**会根据当前直属编队规模 `N`
调整单机、双机和飞行队的抽取权重。以下为第一版待 playtest 权重：

| 玩家直属机数 N | 敌方单机 | 敌方双机 | 敌方飞行队（3–4机） |
|---:|---:|---:|---:|
| 1 | **60%** | 30% | 10% |
| 2–3 | 40% | **35%** | 25% |
| 4–6 | 25% | 35% | **40%** |
| 7–9 | 15% | 25% | **60%** |

- 这是一种倾向而非硬镜像：单机玩家仍有 40% 概率遇到成对/成队敌机；九机玩家仍有 15% 概率遇到敌方独行机。
- 每次生成先把三档基础权重分别乘独立乱数 `randf_range(0.85, 1.15)`，再归一化后抽取；
  乱数只制造局间变化，不能推翻上表的整体趋势。
- 抽到“飞行队”后，在机型允许且 Token 足够时按 `3机 65% / 4机 35%` 再抽实际数量。
- 机型自身的 `spawn_min/max`、Token 余量、实例上限、冷却和实体性能上限始终拥有最终否决权；
  删除无效规模后，对剩余权重重新归一化。只支持单机的特殊单位仍保持单机。
- `N` 在生成当刻读取。僚机随后加入或阵亡不会拆分、增补或删除已经出场的敌方编队，只影响下一次出击。
- 当前热度/`response_level` 继续决定“哪些机型有资格出现”和可用 Token；`N` 的本表只决定“合格机型更倾向几架一起出现”。

### 2.7 表现

Tab 战术图显示：

```text
敌方警戒  62 / 高
编队规模  3 架
经验效率  50%
```

警戒档：`0–24 低`、`25–49 中`、`50–74 高`、`75–99 极高`、`100 最高警戒`。直属机加入或阵亡时显示一次不超过 3 秒的变化提示。

## 3. 行为与公式（How）

### 3.1 僚机加入

1. 重新计算 N、经验倍率、热度下限和响应预算。
2. 热度不瞬移到新下限；以每秒 `6` 点向新下限上升。
3. 既有刷怪计时不重置；后续增援、猎手分配和敌机池选择逐步读取新值。
4. 不在玩家镜头内瞬间生成敌军。

### 3.2 僚机阵亡

1. 致死帧后重新计算 N。
2. 当前热度立即减少 `6`，但不得低于新的 `heat_floor`。
3. 已出现敌人不删除、已发射武器不取消、当前攻击通场不强制中断。
4. 下一次热度 tick、猎手 tick 和刷怪 tick 使用新的较低配额；超出需求的中队完成当前交战后回巡逻或按既有规则撤离。

### 3.3 敌方目标分配

- Hunter/拦截响应的目标集合是全部存活直属飞机，不再固定只指向当前操控机。
- 以敌方中队为单位分配目标；同一敌方中队保持同一主目标。
- 优先选择当前承压较低的直属机，使大编队形成多条战线；不得从玩家输入、BOSS 指令或事件强制目标手中抢写目标。
- 不按玩家装备或某条技能生成硬克制单位。

### 3.4 敌方出击规模抽取

```text
生成常规战斗机批次：
  1. 读取当前 N、heat、response_level、Token 余量。
  2. 按 heat/response_level 过滤合格机型并抽出机型。
  3. 读取该机型允许的 spawn_min/max、实例上限与剩余 Token，得到 valid_sizes。
  4. 读取 §2.6 对应 N 档的 single/pair/flight 权重。
  5. 每档权重独立乘 uniform(0.85, 1.15)，删除无效档并归一化。
  6. 抽规模；flight 档再按 65/35 抽 3/4，若 4 无效则回落 3。
  7. 一次性支付实际架数 Token，生成后不因 N 变化重算。
```

特殊事件、BOSS、Adds、Snowblind 自身等拥有独立编成 spec 的单位不走本表；但 Snowblind 的动态护卫槽
从常规战斗机池取机时，仍读取生成当刻的热度资格与每架 Token/上限。

## 4. 结构与组成（Structure）

- 共享小队计数 helper：唯一判断直属成员，供 XP、热度、Token、UI 共用。
- XP 结算：空中与地面致死统一验证攻击者是否属于直属小队，再应用编队倍率。
- ROE 热度：动态等级/编队地板、加入爬升与减员下降。
- Spawner：响应 Token 预算、`response_level` 和敌机池读取。
- 编成抽取器：以 N 为软权重选择单机/双机/3–4机，机型约束和 Token 作为硬过滤。
- 目标分配：从单一 `player_aircraft` 扩为直属机集合，但保留现有 TargetSource 优先级。
- HUD/Tab：警戒、编队规模和经验效率公开显示。

## 5. 验收标准（Acceptance / Litmus）

- [ ] 相同敌机、相同等级、无其它乘区时，1/3/6/9 机击杀所得 XP 分别为 100%/50%/28.6%/20%（允许最终取整差 1）。
- [ ] 蓝色直属僚机击杀进入共享经验池；绿色 Allied、敌方互杀、自然坠毁均为 0 XP。
- [ ] Lv10 的 1/3/6/9 机最低热度分别为 50/62/80/98。
- [ ] 增加僚机后热度平滑上升；僚机阵亡后热度下降且后续压力变小，画面内敌人不瞬间消失。
- [ ] 九机编队接敌时，敌方目标分散到多个直属成员，不再全部追逐当前操控机。
- [ ] 固定种子各生成 1000 批：N=1 的单机/双机/飞行队比例接近 60/30/10，N=9 接近 15/25/60；
      加入 ±15% 权重乱数后，误差落在统计容差内且趋势不反转。
- [ ] 单机样本仍能偶遇敌方编队，九机样本仍能偶遇敌方独行机；任何 N 都不是确定性镜像。
- [ ] 僚机阵亡后，已出场敌方编队不变，下一批生成规模倾向按新 N 下调。
- [ ] 单机、3 机、6 机、9 机各跑完整 10 分钟：记录最终等级、XP/分钟、击杀/分钟、存活率和警戒时间分布；各规模 XP/分钟目标差异不超过 15%，若偏离优先调 `squad_xp_mult`，不改敌人 HP。
- [ ] Tab 能明确看到警戒值、编队规模和经验效率，玩家能解释为何扩大编队后敌军响应增强。
- [ ] 性能：九机 + 最高警戒 + Sentinel + Lv15 压测，FPS 掉幅 < 15 且不低于 60 FPS。
- [ ] 已知 seam：玩家引用继续由统一 chokepoint 重定向；目标分配不破坏 TargetSource 优先级。
- [ ] i18n：警戒档、经验效率与变化提示三语齐全。
