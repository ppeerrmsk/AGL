# UI 设计规范

> 生存模式主界面与玩家/僚机仪表共用一套军用终端网格、语义颜色、字体、描边、刷新和交互规则；本文只权威规定稳定通用规则，具体玩家仪表布局属于实现快照。

## 1. 设计意图（Why）

- **视觉方向**：老式军用信息终端、军用控制台与机场起降调度系统；复古感来自表格式信息组织、明确网格和高密度代号，而不是依赖扫描线或噪点。
- **空间目标**：常驻信息只进入屏幕左右外围网格，为中央飞机操作区让位；新增信息不得逐步侵占中央操作区域。
- **体验目标**：在不改变火控、飞行与加力机制的前提下，让生命、速度、G、高度、热诱弹、自动化开关与武器优先具有清晰、可数、可扫读的座舱仪表反馈。
- **Litmus 自检**：符合“信息察觉优先于数值”；所有状态变化均有数字、反色、进度或闪烁反馈。玩家仪表改造只改变 HUD 表现，唯一行为修订是 T 跳过不存在的基础武器。
- **反模式规避**：不新增手动武器扳机；F 仍只控制现有导弹自动发射语义；不让仪表规则意外改动其它 HUD；不把额外装备、技能或状态强塞进玩家仪表。

## 2. 稳定规则与实现快照（What）

### 2.0 主界面通用设计系统

#### 2.0.1 规则优先级与冲突裁决

- 第 2.0 节是所有 UI 默认继承的稳定通用规则；用户在具体修改中给出的明确要求优先级更高。
- 第 2.1～5 节仅记录本次审计时的玩家 HUD 实现快照，便于理解与回归，不构成未来 UI 修改必须同步维护的规则；当前实际布局以代码和自动回归为准。
- 普通 UI 实现、视觉和排版调整默认不回写本文，也不要求为差异新增 spec。只有用户明确要求“写入规范 / 设为通用规则”时，才修改第 2.0 节或把具体设计提升为稳定规则。
- 第 6 节实施阶段和第 8 节变更记录只作历史证据，不构成现行尺寸或行为规则；不得用旧阶段覆盖当前代码或用户的新指示。
- `u`、`q` 的功能尺寸原则上只使用整数。独立 `0.5q`/`0.5u` 仍是无内容装饰半格；HP、ALT 与 FLR 当前值所用的 `1u + 0.5q` 是不可拆分的 `3u` 高数字格模板。SPD 与 G 整数位改用 `1u` 宽、`2u` 高的紧凑数字格模板，不意味着任意半格可以承载功能。
- 文中“终端绿”在默认主题下等于 `#00FF41`；当玩家保存其它 HUD 色时，所有强调色文字、描边、星号、填充和反色底统一使用“当前 HUD 强调色”，不得继续写死绿色。
- Silkscreen 与 Chakra Petch 随项目打包。中文、日文、韩文及其它缺失字符先回退至项目当前主题默认字体；具体控件不得直接指定运行机器的系统字体。
- 普通信息读数每 `0.5 s` 刷新；输入事件立即反馈；连续操控与填充可逐帧更新；闪烁使用独立动画时钟。四者不得通过提高同一个刷新循环的频率混为一体。
- 右侧 HUD 先固定屏幕侧右边缘。不同信息行允许宽度不同，数字扩宽和无预留空间的新按键只向左增长，不得移动整组或压缩高优先级字号。

#### 2.0.2 总体布局

```text
[ 左侧表格式信息区 ] [ 中央飞机操作区 ] [ 右侧表格式信息区 ]
```

- UI 区域通过固定网格位置和跨格尺寸声明；坐标以所属面板或侧栏左上角为原点，从 `1` 开始计数。
- 每个区域必须声明起始位置、横向尺寸和纵向尺寸；位置描述网格槽位，不直接描述像素坐标。
- 常驻区域不得互相重叠，也不得跨入中央飞机操作区。
- 同一右侧 HUD 堆栈中的各行共用屏幕侧右边缘，不强求左边缘对齐。
- 操作键纵列等结构对齐可以使用 `0.5q` 装饰列；它不得改变数字占位或字号。

推荐声明：

```text
区域：left
位置：(1, 3)
尺寸：2u × 1u
```

#### 2.0.3 网格单位

```text
1u = 40 px × 18 px
1q = 18 px × 18 px
0.5q 装饰列 = 9 px 宽
0.5u 装饰行 = 9 px 高
```

- `u` 是长方形功能单位；超过单格的区域必须写成“横向 × 纵向”，例如 `1u × 2u`。
- `q` 使用 `1u` 的高度作为正方形边长，永远是 `18 × 18 px`；允许在同一轴上按顺序组合整数 `u` 与整数 `q`，例如 `3u + 1q + 1u`。
- 功能区域禁止任意小数 `u/q`。只有已命名组合模板可以把 `0.5q` 固化在完整功能矩形中；不得据此创造新的小数功能格。
- 独立 `0.5q` 只用于横向装饰对齐，可由用户明确添加，或由自动排版为对齐既有边缘添加/移除。
- 独立 `0.5u` 只用于纵向装饰行，必须由用户明确添加，自动排版不得自行产生。
- 独立装饰半格不承载文字、数字、按键或隐含功能，也不得用于容纳更多数字位数。
- 最大显示字符串宽度不足时只能以整数 `1q` 扩宽；数字扩宽与装饰对齐必须分开声明和计算。

#### 2.0.4 面板、框板、字板与共享描边

| 名称 | 用途 | 描边 | 底色 |
|---|---|---|---|
| 面板 | 完整 UI 区域，可容纳内部区域 | 完整 `1 px` 当前 HUD 强调色描边 | 纯黑，`alpha = 0.70` |
| 框板 | 面板内部带边界的内容区域 | 完整 `1 px` 当前 HUD 强调色描边 | 无独立底色，透出面板底色 |
| 字板 | 面板内部无边界的文字区域 | 无 | 无独立底色 |

- 用户输入“面版”“框版”“字版”时分别按“面板”“框板”“字板”处理。
- 描边绘制在声明尺寸内部，不增加区域占用；框板和字板使用所属面板的内部网格定位。
- 字板必须包含文字；框板默认包含文字，但允许明确声明无字符的结构性空框板。不得使用“空字板”或“空文字面板”称呼无字符区域。
- 同一信息组含有顶部 `1u` 小标题行时，小标题必须横向连续覆盖所属信息组；无字符空框板只能存在于标题下方的其它行，其竖向边界不得进入或切断标题行。
- 动态空框板可吸收相邻运行时功能格，只能按装饰/预留规则增减，不得挤压锁定尺寸的功能面板。
- 同一条逻辑网格边界只能占用一个固定的 `1 px` 坐标。父子面板、相邻网格与重合边界必须复用该坐标。
- 这里的 `1 px` 是最终画面的物理可见下限。玩家仪表缩放时，共享网格层使用 Godot 不随 Canvas 缩放改变粗细的 hairline primitive；其结果等价于按 `logical_line_width = 1 px / scale` 补偿，使变换后的描边仍为 `1` 个物理像素。不得让线宽随仪表缩成亚像素后消失。
- 面板底色与网格描边分层绘制；内容控件不得自行累加边框，描边不参与位置或尺寸计算。
- 反色只替换既有边界的颜色，不得增加平行边线、改变线宽或造成 `1 px` 位移。

#### 2.0.5 文字、字体与裁切

- 默认水平、垂直居中；只有明确声明的“小标题行”强制左对齐。普通长条、状态格、按钮和单位格不因宽度大于 `1u` 自动左对齐。
- 所有文字区域无内边距，独立裁切；动态文本不换行、不推动边界、不扩大区域，超过声明基准时直接裁切。
- `1u × 1u`、`1q × 1q` 极短信息使用 Silkscreen Regular `15 px`，按真实字形边界居中；同层级选项必须使用相同尺寸与字号。
- 小标题行固定高 `1u`，横向占满所属信息组，使用有完整描边的框板、Silkscreen Regular `15 px`，垂直居中并强制左对齐。
- 主要数字默认使用无描边字板，优先分配 `3u` 高度；分隔符和次级数字默认也是无描边字板。已命名数字模板可以明确覆写描边、分格与对齐。
- 父面板始终保留完整外框；字板无描边不等于删除父面板边界。
- 动态数字按已知最大显示字符串预先决定字号和占位，运行时不得因当前值较短临时放大。
- 同一主要字号层级先按共同目标高度确定唯一字号，再按各字段最大字符串以整数 `1q` 向左扩宽；不得缩小其中某一字段的字号来追求左边缘整齐。
- 无法合理利用的格位可以改成空框板或保持未填满，不得为了填满整行破坏信息主次。

当前玩家仪表排版基准：

| 字段 | 最大显示字符串 |
|---|---|
| HP 当前 / 最大 | `999` |
| G | `11.5` |
| SPD | `99999` |
| ALT | `99999` |
| FLR 当前 / 最大 | `99` |

字体规则：

| 字体 | 用途 | 渲染规则 |
|---|---|---|
| Silkscreen Regular | 单格短信息、小标题行、键帽 | 关闭抗锯齿、次像素定位、MSDF、mipmap；最近邻过滤 |
| Chakra Petch Bold | 多格主要数字 | 按真实字形轮廓自动撑高 |
| Chakra Petch Medium | 中等强调层级 | 按真实字形轮廓自动撑高 |
| Chakra Petch Light | 低强调层级 | 按真实字形轮廓自动撑高 |

字体资源与许可证存放在 `resources/fonts/`。

#### 2.0.6 命名数字模板与通用字号

- 除固定 `15 px` 的单格短信息和小标题外，字号以完整字符串塑形后的真实可见轮廓计算，选择同时满足区域高度和基准字符串宽度的最大整数字号。
- 共享主要字号采用高度优先：先由目标高度与代表字形确定共同整数字号，再按整数 `1q` 扩宽容纳不同最大字符串。
- `3u` 高独立数字框固定为 `1u + 0.5q = 49 px` 宽，即 `49 × 54 px`；HP、ALT 与 FLR 当前值格共用按单字 `0` 完整适配该矩形的字号。
- `2u` 高独立数字框固定为 `1u = 40 px` 宽，即 `40 × 36 px`；SPD 与 G 整数格共用按单字 `0` 完整适配该矩形的紧凑字号。两种模板均不按整串重新计算。
- 使用同一真实轮廓边界校正上下视觉基线：`baseline_y = (区域高度 - ink_height) / 2 - ink_top`。
- `TerminalText` 是字号、水平对齐、最大字符串、固定字号、宽高约束与基线的唯一代码入口；调用方不得复制 TextServer 测量或字号搜索算法。
- 完整字符串必须先经 TextServer 塑形并读取最终 glyph 真实轮廓；`font.get_height()` / `font.get_ascent()` 只作为无法取得轮廓时的回退。

两位整数加一位小数的紧凑 `3u` 模板：

- 总高 `3u`：顶部 `1u` 小标题，下方 `2u` 组合数字区。
- 整数固定补零为两格；每格 `1u` 宽、`2u` 高，使用与紧凑 SPD 相同的 Chakra Petch Bold 固定字号和共享描边。
- 小数点固定为 `.`，保留 `1q × 1q` 框板并位于底部 `1u` 行；小数位最多一位，使用底部对齐的无描边 `1u` 字板。
- 三段顺序固定为“两格整数 → 小数点 → 小数字板”；整数前置零使用 `inactive_digit`。
- 本模板中的 `1u + 0.5q` 是完整数字格命名例外，不能拆出半格承载其它内容。

五位紧凑 SPD 模板：

- 固定五个从左到右排列的 `40 × 36 px` 单数字框板，不得改变格数或倒序；ALT 单独保留五个 `49 × 54 px` 的 `3u` 规格格。
- 当前单位整数速度左侧补零；首个有效非零数字之前的零使用 `#404040`，有效数字之后的零使用当前强调色。数值为零时只有最右一位是有效零。
- 超过 `99999` 时固定显示闪烁红色 `99999`，不裁切原值、不扩宽面板。

#### 2.0.7 操作键、进度与状态动画

- 操作键使用独立 `1q × 1q` 框板，显示单个键位，位于所属信息行左侧并与最高的 `1u` 行顶部对齐；标题或说明中不得重复键位。
- 运行时新增按键优先占用相邻动态空框板并使其缩短 `1q`；无预留空间时才允许受影响行向左增加 `1q`，其它行和右锚不得移动。
- 新按键以 `0.5 s` 相位反色闪烁 `5 s`，结束后恢复普通配色并常驻。
- 横向进度模块高 `2u`：右侧固定 `2u × 2u` 居右百分比框板；左侧上方 `1u` 是左对齐标题，下方 `1u` 是无文字进度框板。
- 进度填充向内保留透明 `4 px`，不得覆盖共享描边；竖向进度条至少独占 `1q` 宽。
- 普通相位使用当前强调色文字/描边与原底色；反色相位使用当前强调色实心底、纯黑文字与纯黑描边。
- 默认每 `0.5 s` 切换一次相位。闪烁只改变颜色或填充可见性，不改变尺寸、字号、位置或裁切范围。

#### 2.0.8 语义颜色

本表是主界面颜色代码的唯一规范入口，控件不得散落近似色硬编码。

| 语义名称 | 用途 | HEX / Alpha |
|---|---|---|
| `block_background` | 默认面板底色 | `#000000` / `0.70` |
| `terminal_green` | 无保存设置时的默认强调色 | `#00FF41` / `1.00` |
| `terminal_inverse` | 反色文字与描边 | `#000000` / `1.00` |
| `inactive_digit` | 数字前置补位零 | `#404040` / `1.00` |
| `warning_yellow` | 中段资源/进度警戒 | `#F2D34F` / `1.00` |
| `danger_red` | 低资源、低进度或溢出警告 | `#FF493D` / `1.00` |

- 用户 HUD 色覆盖当前强调色的文字、描边、星号、填充和激活/反色底，不改变 `block_background`、`terminal_inverse`、`inactive_digit` 与警告色。
- 未来主题切换只修改语义颜色映射，不逐个修改控件。

#### 2.0.9 HUD 刷新层级

| 层级 | 频率 | 内容 |
|---|---|---|
| 信息读数 | 每 `0.5 s`（`2 Hz`） | HP、时间、击杀、经验、飞机/小队/BOSS/王牌状态 |
| 实时操作 | 逐帧或专用连续时钟 | 加力、连续进度、雷达、准星与连续操控反馈 |
| 事件 | 事件发生时立即更新 | 按键切换、击杀与结构增减 |
| 动画 | 独立时钟 | 反色闪烁、装填明灭与信息淡出 |

HUD 创建后立即执行第一次信息刷新，随后进入周期；动画时钟不得驱动普通数据轮询。

#### 2.0.10 UI Dev 定位面板

- 生存模式按 `F7` 显示/隐藏 UI Dev 定位覆盖层；`F6` 仍用于战区 Debug，Boss Debug 玩家无敌使用 `Shift+F7`。
- 定位层读取正式玩家仪表、真实僚机行、三轴计数器与经验条，不复制第二套预览布局；测试场景只用于固定数据截图回归。
- `DEV + MANUAL FLR [R]` 只在 Debug 覆盖层授予手动 FLR 技能，用于验证动态空框板和 `5 s` 闪烁，不属于正式战斗 UI。
- F7 控制区提供右侧玩家仪表专用缩放滑条：默认 `0.9×`，最小 `0.5×`，只能在 `0.5×、0.6×、0.7×、0.8×、0.9×、1.0×` 六档间切换；缩放值只在当前战局生效，不写入玩家设置。
- 缩放对象严格限于 `PlayerInstrumentPanel`。僚机行、三轴计数器、经验条、雷达、顶部信息、战术提示、F7 紫色诊断层和 Debug 控件全部保持 `1.0×`；本滑条不得改变这些控件的尺寸或位置。未来其它 UI 的倍率由各自独立滑条管理。
- 缩放不得重算玩家仪表内部布局。`1u = 40 × 18 px`、`1q = 18 × 18 px` 与所有命名模板继续作为 `1.0×` 逻辑几何，玩家仪表最终横纵统一乘同一个倍率，像素比例始终一致。
- 玩家仪表使用物理屏幕右边缘作为缩放轴，右外框与屏幕之间不保留额外 `1q` 空间；底部以第 2.0.11 节规定的 `3u` 常驻栏上沿为边界。缩小时只让玩家仪表自身向右下轴收拢，其它 HUD 继续使用原有 `1.0×` 物理视口布局。
- 诊断标记使用独立覆盖层和向内 `2 px` 紫色描边，不修改正式 HUD 的尺寸、共享边线或输入。
- 顶层区域按“从上到下、同高从左到右”使用 `A…Z、AA…`；顶层内部可编辑框压成稳定单层序号 `A1、A2…`。
- 大于 `1u` 的自动排版面板与独立 `1u`/`1q` 面板进入定位层；重复矩形只编号一次。代号为黑底紫字，放在矩形内部右上角，小格只缩小字号。

#### 2.0.11 主菜单终端模式板

- 内容栅格固定为 `23u × 30u`，四周保留 `1u` 安全边界；左列使用 `5 × 4u` 模式行。
- 终端外壳是静态结构，CRT shader 仅作用于屏幕内容，不得让整张菜单持续 `_process()` 或无变化重绘。
- 线框、标题、选中底色和焦点符号统一使用当前 HUD 强调色；不得重新写死一套菜单绿。
- 模式名、说明、状态和按钮全部走本地化；生存模式文案必须明确“击败 BOSS 即过关”，不得描述为无尽波次。

#### 2.0.12 HUD 首次显现

- 只在每个 HUD 元素第一次拥有真实内容时播放；已经稳定显示的元素不重播。
- 排序按屏幕 `y` 后 `x`；相邻元素启动间隔 `0.02 s`，允许并发。
- 单元素四相各 `0.125 s`：`亮 → 灭 → 亮 → 灭 → 稳定`，总时长 `0.50 s`，恰好两次闪烁。
- 玩家仪表每个格、每条僚机行和坐标轴格分别计为独立元素；动画直接切换源绘制，不叠黑色遮罩。
- 元素在动画中隐藏时取消并等待下次真实出现；稳定后隐藏再显示不得重播。
- `_ready()` 时先以闭合状态初始化，展开闭合误差不得超过 `1 px`。

对齐契约：先建立整个玩家仪表的屏幕侧共同右边缘，再从右向左建立每一行自己的 `Rect2`。HP、SPD+G、ALT、加力、自动化/FLR、R 机动与武器行的右边缘必须完全一致；根控件保持名义总宽，单行内容过宽时允许使用负局部 X 向左突出，不得为单行修改扩宽整个根控件。最大字符串造成的宽度增量只能以整数 `1q` 向左增长，结构对齐可以按 `0.5q` 补列，两者不得混算。运行时按键优先占用预留的动态空框板。每行可以拥有不同左边缘，不得为了左侧整齐而缩小高优先级字号。所有标签、重点数字、补充数字、填充和分隔线只使用所属行的局部矩形；相邻边界由统一描边层复用同一坐标。

重点信息契约：每行只允许一个第一视觉焦点。HP 当前生命、SPD、ALT 与 FLR 当前值使用固定单数字框板；HP 的最大生命和分隔符保持无框补充信息。G 使用缩至 `3u` 的“两位整数加一位小数”信息组。ALT 的五格沿用 `49 × 54 px` 的 `3u` 数字框与字号；SPD 与 G 主数字使用适配 `40 × 36 px` 的 `2u` Chakra Petch Bold 字号；FLR 保留 `49 × 54 px` 字号，不受 SPD 缩小影响。

### 2.2 飞行数据模块

| 项目 | 显示规则 |
|---|---|
| HP | `当前/最大`；当前值取整、补零为三位并逐格显示；最大值取整 |
| G | 只显示实时 G，保留 1 位小数；不显示结构上限；位于 SPD 右侧，共用一条 `3u` 行 |
| ALT | 只显示实际高度米数，取整并补零为五位；独占 `4u` 行，带连续高度指针与 HIGH/LOW 档位 |
| STALL | 平时不占视觉内容；失速时显示并按统一节奏闪烁 |
| SPD | 当前单位下的整数速度，固定格式化成五位并从左到右逐格显示；默认 kt，设置为 km/h 时显示 km/h 数值 |
| 单位标签 | `KT` 与 `KM/H` 同时保留，当前单位反色 |
| 换算 | `kt = km/h / 1.852` |
| 高度偏好 | ALT 行右侧以正式信息字体显示固定英文 `HIGH` / `LOW`；Q 键帽吸附 ALT 外框左侧，允许随突出行独立左移，不强求与 E/G/F/T 同列；按 Q 两态切换 |

- HP 与 SPD 均不伪造连续比例条；高度的半圆仅表达实际高度与档位，不替代五位数值。
- HP、G、ALT、SPD 均使用有框 `1u` 小标题行并左对齐。
- HP 高 `4u`：标题连续占满顶部 `1u`；当前生命使用三个 `49 × 54 px` 独立有框数字格，固定补零到三位并按有效位使用强调色；其右依次保留 `1q × 1q` 无框分隔符和 `2u` 高最大生命，剩余无字符框板只能从标题下方开始，暂不承载状态。
- HP 模块正下方固定增加一条 `0.5u = 9 px` 高无字符装饰框板；它与正下方 SPD+G 模块共用左右边缘和宽度，不承载状态、进度或输入。
- SPD+G 共用一条总高 `3u` 的行：SPD 位于左侧，G 位于右侧。SPD 标题连续覆盖所属组顶部 `1u`，下方五个 `40 × 36 px` 单数字框板；数字规则、补位色、溢出行为不变。数字格右侧的无字符框仅占标题下方 `1q × 2u`，单位列在同一 `2u` 空间内分别显示 KT 与 KM/H，不得以空格切断标题。
- G 总高缩至 `3u`：标题 `1u`；两个主整数格由 `3u` 字高缩至 `2u`，一位次要小数由 `2u` 字高缩至 `1u`，字体家族仍为 Chakra Petch Bold；`1q × 1q` 小数点框和分隔结构不变。整数固定补零到两位，例如 `4.5` 显示为 `0 4 . 5`。
- SPD 模块正下方固定增加一条 `0.5u = 9 px` 高无字符装饰框板；它与 SPD+G 及正下方 ALT 模块共用左右边缘和宽度，不承载状态、进度或输入。
- ALT 独占总高 `4u`：顶部是 `1u` 标题；下方中部为五个与旧 SPD 完全相同的 `49 × 54 px` 有框数字格和旧 `3u` 字号，按五位补零；右侧为 `1u + 1q = 58 px` 宽、`2u` 高的有框正式信息字板，显示 HIGH 或 LOW，余下 `1u` 高度为空框板。
- ALT 标题下方最左侧剩余 `3u` 空间绘制居中的上半圆仪表：圆弧线宽固定 `3 px`，底边中心为轴心，指针线宽固定 `6 px`。把半圆左端定义为 `0°`、右端定义为 `180°`，指针只能在 `20°…160°` 内移动；LOW 使用左半区 `20°…85°`，HIGH 使用右半区 `95°…160°`，实际高度在所选半区内连续映射。高度或档位改变时按角速度平滑追随目标角，不允许只在两个端点瞬切。STALL 只能占 SPD 区，不进入 ALT。

| 区域 | 尺寸与显示 |
|---|---|
| 左侧弹量格 | `3u` 高；Chakra Petch Bold 次要数字层级、水平居左；按 `9999` 预留最多四位显示余量。字号沿用原 `2u` 槽版本，不因行高增加而放大 |
| 中间装填信息格 | 自动吸收弹量格与右侧名称格之间的全部剩余宽度，总高 `3u`；上方 `2u` 放置双读数，底部 `1u` 放置横向装填条 |
| 装填百分比 | 位于中间信息格上方 `2u` 空间的最左侧，固定 `2u × 2u`，水平居左；显示整数 `0%…100%`，基准字符串为 `100%` |
| 装填剩余时间 | 位于同一 `2u` 空间最右侧，与百分比严格同尺寸、同 Chakra Petch Bold 字号及同色阶，水平居右；以向上取整的整数秒显示，格式仅把百分比后缀替换为 `s`，例如 `8s` |
| 横向装填条 | 位于中间信息格最下方，宽度占满信息格、高 `1u`；复用通用进度条 `4 px` 透明内缩，从左向右按真实装填比例填充，内部无文字 |
| 右侧名称格 | 固定 `2u × 3u`；显示 `MSL` / `GUN`，名称字号沿用原 `2u × 2u` 版本并居中；完整缩写优先 |

九格指示灯及其 `2468` 常亮、`12369874` 循环和切换复位规则已全部废弃；武器行不得保留相关占位、状态或动画。

| 状态 | 弹量格 / 名称格 / 中间装填信息格 |
|---|---|
| 优先、未装填 | 弹量格与名称格持续反色；中间信息格不显示数字，装填条熄灭。该状态显示玩家偏好，不表示瞬时实际使用武器 |
| 未优先、装填 | 弹量格与名称格保持普通相位；百分比与剩余秒数持续可读，装填条按 `2 Hz` 在当前比例填充与完全熄灭之间闪烁 |
| 优先且装填 | 弹量格与名称格按 `2 Hz` 在反色与普通相位之间闪烁；百分比与剩余秒数持续可读，装填条同相位在填充与熄灭之间闪烁 |
| 武器不存在 | 行高、装饰框、空框板和边框保留；该行弹量、名称与装填内容透明度为 0 |

T 切换规则：两种都存在时切换；只存在一种时固定在可用武器且 T 无操作；两种都不存在时 T 无操作。

## 3. 行为与公式（How）

### 3.1 显示刷新

- 复用生存 HUD 既有单次玩家引用净化结果，不扫描场景树。
- 只更新一个固定仪表实例；无每实体节点、无全场遍历。
- 创建仪表后立即刷新一次；普通信息读数随后按本规范第 2.0.9 节每 `0.5 s` 刷新。
- 反色闪烁、连续填充和实时操作反馈使用独立动画时钟，不得通过提高普通信息刷新频率实现。
- R 冷却读取是当前玩家与 Squad 的 O(1) 查询，不扫描场景树。

### 3.2 热诱弹状态同步

```
release:
  flare_visual_emitted = 0
  queue 6 waves with counts [2,2,1,2,2,1]

spawn wave(count):
  create exactly count visual particles
  flare_visual_emitted += count

HUD lit stars:
  if long reload: ceil(reload_progress * 10)  # 最后 10% 已满星，正式完成帧才补数字
  elif release queue active or short cooldown active: 10 - flare_visual_emitted
  else: 10
```

长装填完成前数字不得提前补满；数字更新与正式资源补充发生在同一状态转移。

### 3.3 输入

```
E -> AfterburnerCharge.toggle(player)
G -> auto_engage_enabled = !auto_engage_enabled
F -> missile_auto_fire = !missile_auto_fire
T -> available = [MSL if params.missile, GUN if params.gun]
     if available.size == 2: toggle preference
     if available.size <= 1: no-op and keep/normalize preference to the sole available weapon
Q -> altitude_preference = PREFER_CLIMB ↔ PREFER_LOW; ALT/Q block updates in the same HUD refresh
C -> existing squad engage mode cycle
V -> existing squad weapon preference toggle
```

### 3.4 僚机快照与刷新

- 生存 HUD 只遍历当前玩家 `Squad.members` 的存活僚机，不做全场扫描。
- 生存 HUD 把僚机引用转换为只含显示值的字典快照；绘制控件不跨帧持有 Aircraft 引用。
- 僚机普通信息与玩家仪表相同，每 `0.5 s` 刷新；行数变化时立即改尺寸。僚机面板使用独立 `1.0×` 右锚基准，不因玩家仪表缩放而改变尺寸或位置。

### 3.5 右侧玩家仪表独立缩放

缩放档位：

```text
scale ∈ {0.5, 0.6, 0.7, 0.8, 0.9, 1.0}
default_scale = 0.9
displayed_player_size = logical_player_size × scale
displayed_player_right = physical_viewport_width
displayed_player_bottom = physical_viewport_height - 3u
other_ui_scale = 1.0
```

- 正式 HUD 根节点始终保持 `1.0×` 并直接使用物理视口；只有玩家仪表 Control 接受等比变换。禁止逐字段改字号、边距或 `u/q` 常量来模拟缩放。
- 共享网格描边是唯一的线宽补偿例外：玩家仪表矩形坐标和尺寸随倍率变换，线宽使用 scale-invariant hairline（等价于按 `1 / scale` 反向补偿），确保最终始终可见为 `1` 个物理像素。
- 玩家仪表右外框直接落在物理屏幕右边缘，不再保留旧 `1q` 外部留白；底边固定落在 `3u` 常驻栏上沿，不随倍率缩小。
- 僚机、三轴、经验条以及所有其它 HUD 的尺寸和定位公式不读取玩家仪表倍率；滑条变化前后其物理矩形必须完全一致。
- F7 滑条变值后立即重新布局，并让紫色定位层读取缩放后的物理矩形；不得等待普通信息层下一次 `0.5 s` 刷新。

## 4. 结构与组成（Structure）

- 主界面 UI 使用统一语义颜色入口、网格描边控件和精确文字控件；业务控件只声明语义色、网格矩形和文字基准，不复制底层测量或描边算法。
- 生存 HUD 的正式控件统一挂在一个保持 `1.0×` 的根节点下；仅玩家仪表子控件接受独立等比变换。F7 调试控件与诊断层留在该根节点之外，不持有第二套布局数据。
- 生存 HUD 根节点持有横跨视口底部的 `3u` 常驻框板，并把三方向计数与经验条作为其内部内容；玩家与僚机仪表只锚定到该框板上沿。
- `ZoneHint` 持有互相独立的顶部常驻与底部临时通知框板；精英/BOSS 等事件只通过顶部通道发布紧急状态，普通提示、奖励与错误只通过底部通道发布临时反馈。
- 主界面左右侧栏负责常驻表格式信息，中央区域只保留飞机操作、雷达、准星及短时战场反馈。
- 独立玩家仪表控件：用独立行矩形构建 HP、SPD+G、ALT、高度表、加力、ENGAGE、FIRE、固定 FLR/R 区、MSL、GUN；每行只以自己的左上角为坐标原点。生存 HUD 只注入当前 Aircraft 与 AfterburnerCharge。
- 独立僚机仪表控件：消费生存 HUD 生成的显示快照，按存活僚机数绘制独立信息行；复用玩家仪表的语义强调色、Silkscreen 与 Chakra Petch 字体规范。
- 独立 HUD 偏好静态服务：加载/保存速度单位与强调色，不新增 AutoLoad。
- 热诱弹子系统在 Aircraft 上公开本次视觉投放进度，HUD 只读；队列仍由既有粒子更新函数消费。
- Aircraft 公开唯一 R 技能 id、总冷却与共享剩余冷却的 O(1) 只读查询；HUD 只用总冷却计算 0%→100% 充能，不显示时长且不修改技能状态。
- 主菜单只负责修改持久化偏好；其它主菜单结构与游戏内 HUD 不变。
