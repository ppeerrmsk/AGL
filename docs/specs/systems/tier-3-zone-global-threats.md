# 三级战区全局威胁与超级单位

> 1★/2★仍是局部、直接的战区目标；3★会出现一个可被摧毁的战略威胁源，在玩家处理其它战区时也持续影响整片战场。

## 1. 设计意图（Why）

- **体验目标**：让战区等级不再只代表“同类目标更多”。玩家看到 3★时，应理解这里存在一件会改变整个战区、甚至整张地图行动方式的战略兵器；继续执行别处任务意味着主动承受它的远程影响，优先摧毁它则能解除全局压力。
- **等级身份**：1★/2★保持简单、局部、容易理解；只有 3★引入“战略威胁源 + 跨战区投射”结构。难度来自可见的新单位、攻击几何与远程影响，不靠给普通单位统一加血。
- **Litmus 自检**：遵守设计哲学 3「信息察觉优先于数值」、7「战场要热闹」、8「真机制而非堆血」和 11「60 FPS 红线」。全局威胁必须看得见来源、看得懂预警、能通过摧毁来源永久解除。
- **反模式规避**：不做无来源的全局随机扣血；不让画外攻击变成无预警 hitscan；不把 3★退化成普通 AA/SAM/舰船的 HP 放大版；不把正式超级单位塞进 `zone-atmosphere-combat` 的表演演员名单；不在本轮擅自补齐尚未定稿的射程、伤害、冷却、编成或支援机身份。

## 2. 数据定义（What —— 当前设计权威）

### 2.1 三个战区等级的身份

| 战区等级 | 目标结构 | 影响范围 | 当前方向 |
|---|---|---|---|
| 1★ | 简单局部目标 | 所属战区 | 保持现有任务语义，不增加全局效果 |
| 2★ | 更强或更多的局部目标 | 所属战区 | 保持现有任务语义，不增加全局效果 |
| 3★ | 常规目标 + 至少一个战略威胁源/超级单位 | 整个战区，部分类型可覆盖整张地图 | 新增本 spec 的全局投射机制；正式局全图同时最多存在 1 个 |

3★的核心循环固定为：

```text
战略威胁源存活
  → 持续向所属战区外投射可观察影响
  → 玩家决定继续承压或改变航线优先处理
  → 摧毁威胁源
  → 停止产生新的全局影响
```

### 2.2 全图三级战区并发上限

```text
MAX_CONCURRENT_TIER3_ZONES = 1
```

- **全图唯一**：正式局中，所有已经公开且尚未解决的正式战区合计最多只能有 **1 个 3★战区**。这条规则跨任务类型生效，地面、空战、海军、机场与可选任务共用同一个名额。
- **计数范围**：`AVAILABLE`、`SELECTED`及正在执行的战区计入；`LOCKED`、`CLEARED`、`FAILED`与没有星级的 BOSS 战区不计入。
- **分配顺序**：已有且可见的 3★保留身份；新开放、重新激活、按热度定档或 Debug 普通开放的候选，如果发现名额已被占用，则其最高难度强制压为 2★，不得先显示两个 3★再事后降级。
- **批量开放**：同一次刷新若连续开放多个战区，难度必须逐个提交；第一个成功获得 3★后，后续候选在本批次内立即失去 3★资格。
- **名额释放**：现有 3★进入 `CLEARED`、`FAILED`或 `LOCKED` 后，名额才释放；只是在 `AVAILABLE`与 `SELECTED`之间切换不会释放名额。释放后只允许未来新定档的战区获得 3★，不把已经公开的 1★/2★临时抬成 3★。
- **机场冲突**：机场按热度本应进入 3★时，也必须先经过同一全图闸门；若另一个 3★仍存活，则该机场本轮显示并执行为 2★。
- **Debug 边界**：普通 Debug 开放遵守该上限；只有专用压力测试覆盖可以故意生成多个 3★，并必须明确标记为非正式局分布。

现状审计：首批 A/B 的随机上限已经是 2★，不会在开局占用三级名额；但后续普通战区会各自独立抽取 1–3★，机场也会按热度独立定档，目前没有全图三级计数器或统一分配闸门。因此，现有运行时在中后段确实可能同时出现两个或更多 3★战区；本节是后续实装必须补上的硬约束。

除“3★全图最多一个”外，本轮不额外规定全图必须同时拥有几个 1★或 2★；其精确配额与节奏仍待后续战区分布打磨。

### 2.3 三级威胁的共同契约

| 项 | 当前裁定 |
|---|---|
| 所有权 | 威胁源属于一个明确的 3★战区，并登记为正式任务 TGT 或正式 TGT 组的一部分 |
| 作用范围 | 至少覆盖所属战区；标记为全局型时可攻击正在其它战区执行任务的玩家 |
| 玩家反制 | 摧毁对应威胁源；不靠等待隐藏倒计时自然失效 |
| 视觉来源 | 每次全局影响都必须能追溯到地图上的真实单位/舰队/支援机，不生成无主效果 |
| 预警 | 必须存在来源、轨迹/影响区与命中时机的可读提示；具体 UI、声音与预警时长待定 |
| 远距伤害身份 | 属于正式任务攻击，不是气氛炮火；不得因玩家距该战区超过 3.6 km 就自动变成 0 伤害 |
| 终止 | 威胁源毁灭后不再产生新的全局攻击/支援效果；已经在途的效果如何结算待定 |
| 完成条件 | 是否还需清除其它护卫/TGT 后才算战区完成，按各类型后续 spec 定义 |

### 2.4 首批超级单位与任务方向

下表只登记用户已确认的身份；“待定”项不得由实现默认值反向定义设计。

| 任务类型 | 工作名 | 地图范围 | 已确认组成 | 已确认影响 | 仍待设计 |
|---|---|---|---|---|---|
| 3★地面 | **超级巨炮** | 东京湾与沙漠地图 | 一个正式地面战略威胁源 | 射程极远；可攻击正在其它战区执行任务的玩家；造成 AOE 区域攻击 | 机动/固定、射程、炮弹、预警、AOE、伤害、射速、护卫、HP 与弱点 |
| 3★地面 | **沙漠工程坦克** | 沙漠地图专属 | 陆地移动工程坦克；明确安装 **4 门 AA 炮**及其它待定装备 | 对整个地面战区构成高威胁；跨战区/全图投射方式尚未拍板 | 工程能力、对地武器、4 炮是否独立挂点、移动路线、装甲、护卫与完成条件 |
| 3★海上 | **远程重型舰队** | 任何满足全水硬闸的海上任务地图 | 更强的新舰船与更强的舰队；舰队以真实 VLS 舰船/挂点向玩家发射 VLS | VLS 攻击距离非常远，可跨战区追击玩家并长期影响其行动 | 新舰型、旗舰、编成、发射舰、齐射规模、射程、冷却、锁定/预警，以及是否取代或扩充现有 3★舰队 |
| 3★空战 | **特殊支援机** | 地图与任务池待定 | 至少一种有独特支援作用的飞机 | 通过支援机制改变整个 3★空战任务；是否全图投射待定 | 机型、支援效果、护卫、武装、可锁定窗口、撤离/击毁与任务完成条件 |

### 2.5 地图适用范围

| 地图 | 当前允许/确认方向 | 边界 |
|---|---|---|
| 港湾 / 东京湾 | 3★地面超级巨炮；合法水域中的 3★远程舰队；空战支援机待定 | “包含东京湾”是硬要求；所有地面出生点仍须避开港池/河道并满足连续陆地净空 |
| 沙漠铁路 | 超级巨炮与沙漠工程坦克均为 3★地面候选 | 当前地图为连续陆地、无可用海战水域，因此不生成海军任务；两种超级单位如何进入任务池、是否互斥待定 |
| 海洋决战 | 3★远程舰队方向；特殊支援机待定 | 岛上超级地面单位只有在后续明确批准且完整占地通过安全陆地检查时才可加入 |

### 2.6 与现有系统的边界

- [zone-air-support-naval-safety](zone-air-support-naval-safety.md) 当前已实现的 3★海军基线仍是 `1 CG + 2 DDG + 3 FFG`、全舰 TGT。新远程重型舰队在具体舰型与编成定稿前**不替换**这条现役规则；跨战区攻击必须由编成内真实存在的 VLS 发射舰/挂点发起。
- [zone-atmosphere-combat](zone-atmosphere-combat.md) 的 SPG/舰炮只负责远距演出并在玩家 3.6 km 外降为 0 伤害；本 spec 的超级单位是正式威胁，不能复用该“画外零伤害”身份。
- [airburst-aa-gun](../weapons/airburst-aa-gun.md) 是 800–5000m 对空空爆武器。超级巨炮是跨战区对玩家投射 AOE 的新地面火炮，二者不是同一单位，也不自动继承参数。
- 沙漠工程坦克的 4 门 AA 炮仍只允许攻击 Aircraft。它“对地面单位威胁极大”的部分必须由后续明确设计的其它装备/工程机制承担，禁止让 AA 炮越权攻击 GroundUnit。
- 海上超级任务继续继承全舰占地与完整轨道 `land_hits == 0` 的硬闸；宁可缩编或不生成，也不能让更大的新舰船上岸。
- 1★/2★任务、现有奖励概率、气氛组与第三方友军支援不因本 draft 自动改变。

### 2.7 明确保留的待定项

- 三级威胁何时开始投射：地图预生成时、战区揭示时、任务 ACTIVE 时，或其它节点；
- 玩家在 Tab/主视野如何得知“其它战区正在向我开火”，以及来源线、落区、倒计时与声音的表现；
- 超级巨炮在东京湾与沙漠的全部数值、落点算法、是否预测玩家移动、是否可破坏炮管/弹药库等子系统；
- 沙漠工程坦克的“工程”机制、对地武器、4 门 AA 炮挂点与本体的击毁关系；
- 新海军单位、旗舰身份与舰队编成；VLS 由哪些舰船发射、齐射规模、射程、冷却、制导与预警；现有六舰基线是被扩充还是被新的核心舰替换；
- 特殊支援机的具体作用，以及它属于无武装支援、带护卫支援还是可直接交战的任务核心；
- 单个 3★战区内部若有多个炮管、VLS 发射舰或支援来源时的攻击数量上限、错峰规则与优先级；
- AOE 是否影响玩家僚机、第三方友军、其它敌人、地面/舰船及建筑；
- 威胁源毁灭时已经在途的炮弹/导弹/支援效果是否继续完成；
- 当前 BOSS 阶段会保留地面单位与舰船；三级全局威胁在 BOSS 登场前停火、撤离、保留还是继续攻击必须单独拍板；
- 三级任务的奖励、XP、跨三图战役继承及顺延关系。

## 3. 行为与状态流（How）

### 3.1 通用生命周期

| 状态 | 含义 | 转移 |
|---|---|---|
| `CREATED` | 三级任务和威胁源已生成，但全局投射是否立即开启待 §2.7 定稿 | 达到启用条件 → `PROJECTING` |
| `PROJECTING` | 威胁源按自身机制影响所属战区外目标 | 来源毁灭/任务取消/BOSS 阶段裁定 → `NEUTRALIZED` |
| `NEUTRALIZED` | 不再发起新的全局影响；保留死亡/撤离/在途效果收尾 | 任务清理完成 → `ENDED` |
| `ENDED` | 释放引用与预警表现，不再参与调度 | 终态 |

战区任务执行器拥有任务生命周期；全局威胁调度只读取仍存活、仍处于 `PROJECTING` 的正式来源。来源与状态必须一一对应，不能生成“单位已经死了但地图还在随机落炮”的孤儿效果。

### 3.2 超级巨炮攻击骨架

```text
选择合法目标/落区
  → 向玩家显示来源与 AOE 落区预警
  → 发射具有真实飞行/等待时间的炮弹
  → 到达落区后进行一次 AOE 结算
  → 进入长冷却
```

- 合法目标可以是正在另一战区执行任务的玩家，这是超级巨炮的核心身份。
- 攻击必须有足够可读的提前量；禁止屏外无轨迹瞬时扣血。预警时长与弹道速度待定。
- AOE 是一次性结算，不做长期驻留 DPS 云；半径、伤害、衰减与友伤规则待定。
- 巨炮是正式可摧毁目标；护卫是否必须全部击毁、是否存在挂点/弱点与移动能力待定。

### 3.3 沙漠工程坦克骨架

- 作为真实 `GroundUnit` 在安全陆地上移动，不允许跨越海面、港池或地图外框。
- 4 门 AA 炮必须在视觉上可辨认，并遵守只对空语义；是否独立索敌、独立受损和独立冷却待定。
- 对地面单位的高威胁来自其它待定装备或工程行为，不借用 AA 炮伪造。
- 工程坦克是单个超级核心、带护卫车队，还是由多个模块组成的目标组，待后续定稿。

### 3.4 远程重型舰队骨架

- 3★舰队会由真实舰船/挂点向当前玩家操控机发射 VLS；玩家正在其它战区执行任务时仍是合法目标。
- 每枚 VLS 必须是具有发射来源、飞行过程、制导与可读预警的真实弹体；禁止用无来源的画外伤害代替。来源舰/挂点毁灭后停止新的对应发射。
- 这套跨战区 VLS 与舰队的 Flak/CIWS 近程职责必须从弹道、预警和射程上直接区分，不能只把现有武器伤害调高。
- 具体由 CG、DDG、新舰型或多个舰种发射，以及齐射规模、锁定、射程、冷却、拦截窗口与脱锁规则，仍待后续定稿。
- 舰队完整编成、缩编顺序与全部 TGT 身份在新舰型确定后再写；当前六舰基线保持生效。
- 生成前先完成整支舰队的全水方案，随后事务式实例化；不得边搜索边生成半支舰队。

### 3.5 特殊支援机骨架

- 支援机的难度身份来自“支援了什么”，不是普通战斗机加血。
- 其作用对象、作用范围、是否需要护卫、何时可锁定/击毁和效果终止条件必须一起设计。
- 在身份定稿前不指定机型、不复用现有 Snowblind/预警机/轰炸机机制，也不登记进普通敌机池。

### 3.6 全局威胁调度纪律

- 全部三级威胁由集中、低频的战役/战区调度器维护；禁止每个超级单位各自做逐帧全图扫描。
- 单次攻击选定目标与落区后保存快照；在途阶段不每帧重新全场选敌。
- 正式局全图最多只有一个 3★战区；但该战区内部多个炮管、舰船或挂点的攻击仍必须有硬上限和错峰，避免炮击与 VLS 在同一时间形成不可读秒杀；具体火力上限待定。
- 玩家切换操控机后，后续新攻击必须读取当前操控机；已经发射的攻击是否重定向必须按“发射快照”原则显式裁定，默认不得偷偷追踪。

## 4. 结构与组成（Structure）

| 组成 | 职责 | 当前状态 |
|---|---|---|
| `Tier3ThreatProfile` | 声明任务类型、地图允许表、威胁来源、影响范围与生命周期策略 | 设计占位 |
| 全图三级名额闸门 | 在普通随机、批量开放、重开、机场热度定档与普通 Debug 开放前统一保证 `MAX_CONCURRENT_TIER3_ZONES = 1` | 未实装；现状可产生多个 3★ |
| 三级战区任务定义 | 在现有 `ground / air / squadron / naval` 三级编成中登记对应 profile | 未实装 |
| 集中全局威胁调度 | 低频维护存活来源、错峰、目标快照和终止清理 | 未实装 |
| 单位专属控制器 | 超级巨炮、工程坦克、远程舰队与支援机各自的窄机制 | 数值/行为待定 |
| 预警快照 | 向主视野、Tab、HUD、音频提供同一来源/落区/时间数据 | 表现待定 |
| 正式任务结算 | 只由 `ZoneMission` 判断 TGT 与战区完成，不由气氛演员代结算 | 复用既有所有权 |

## 5. 验收标准（Acceptance / Litmus）

- [ ] 1★/2★任务的单位、奖励、完成条件和局部影响完全不变；只有 3★启用战略威胁 profile。
- [ ] 任意正式局帧中，所有 `AVAILABLE` / `SELECTED` / 执行中的正式战区合计最多只有 1 个 3★；普通战区、机场与可选任务不能各自绕过该上限。
- [ ] 已有 3★存在时，新候选最高只会显示并执行为 2★；3★解决后只向未来的新定档释放名额，不临时抬升已经公开的低级战区。
- [ ] 任一 3★全局影响都有存活的正式来源单位，玩家可从预警追溯到其所在战区。
- [ ] 玩家在其它战区时仍会受到三级威胁的真实影响；该影响不经过 `zone-atmosphere-combat` 的画外 0 伤害路径。
- [ ] 摧毁威胁源后不再生成新的全局攻击/支援效果，也不会遗留无主预警或引用。
- [ ] 超级巨炮可在东京湾和沙漠地图的合法地面战区出现，并能用有预警的真实弹道对其它战区产生一次性 AOE；无屏外 hitscan。
