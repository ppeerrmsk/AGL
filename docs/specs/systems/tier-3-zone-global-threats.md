# 三级战区全局威胁与超级单位

> 1★/2★仍是局部、直接的战区目标；3★会出现一个可被摧毁的战略威胁源，在玩家处理其它战区时也持续影响整片战场。

## 1. 设计意图（Why）

- **体验目标**：让战区等级不再只代表“同类目标更多”。玩家看到 3★时，应理解这里存在一件会改变整个战区、甚至整张地图行动方式的战略兵器；继续执行别处任务意味着主动承受它的远程影响，优先摧毁它则能解除全局压力。
- **等级身份**：1★/2★保持简单、局部、容易理解；只有 3★引入“战略威胁源 + 跨战区投射”结构。难度来自可见的新单位、攻击几何与远程影响，不靠给普通单位统一加血。
- **Litmus 自检**：遵守设计哲学 3「信息察觉优先于数值」、7「战场要热闹」、8「真机制而非堆血」和 11「60 FPS 红线」。全局威胁必须看得见来源、看得懂预警、能通过摧毁来源永久解除。
- **反模式规避**：不做无来源的全局随机扣血；不让画外攻击变成无预警 hitscan；不把 3★退化成普通 AA/SAM/舰船的 HP 放大版；不把正式超级单位塞进 `zone-atmosphere-combat` 的表演演员名单。首版运行参数集中在专属单位/任务常量中，后续用 Visual 与实局证据调校，不散落魔法数。

## 2. 数据定义（What —— 当前设计权威）

### 2.1 三个战区等级的身份

| 战区等级 | 目标结构 | 影响范围 | 当前方向 |
|---|---|---|---|
| 1★ | 简单局部目标 | 所属战区 | 保持现有任务语义，不增加全局效果 |
| 2★ | 更强或更多的局部目标 | 所属战区 | 保持现有任务语义，不增加全局效果 |
| 3★ | 常规目标 + 至少一个战略威胁源/超级单位 | 整个战区，部分类型可覆盖整张地图 | 新增本 spec 的全局投射机制；正式局全图同时最多存在 1 个 |

3★的核心循环固定为：

```text
三级战区存在且战略威胁源存活
  → 不等待玩家选择或进入，持续向所属战区外投射可观察影响
  → 玩家决定继续承压或改变航线优先处理
  → 摧毁威胁源
  → 停止产生新的全局影响
```

### 2.2 全图三级战区并发上限

```text
MAX_CONCURRENT_TIER3_ZONES = 1
```

- **全图唯一**：正式局中，所有已经公开且尚未解决的正式战区合计最多只能有 **1 个 3★战区**。这条规则跨任务类型生效，地面、空战、海军、机场与可选任务共用同一个名额。
- **计数范围**：`AVAILABLE`、`SELECTED`及正在执行的战区计入；`LOCKED`、`CLEARED`、`FAILED`与没有星级的 BOSS 战区不计入。
- **分配顺序**：已有且可见的 3★保留身份；新开放、重新激活、按热度定档或 Debug 普通开放的候选，如果发现名额已被占用，则其最高难度强制压为 2★，不得先显示两个 3★再事后降级。
- **批量开放**：同一次刷新若连续开放多个战区，难度必须逐个提交；第一个成功获得 3★后，后续候选在本批次内立即失去 3★资格。
- **名额释放**：现有 3★进入 `CLEARED`、`FAILED`或 `LOCKED` 后，名额才释放；只是在 `AVAILABLE`与 `SELECTED`之间切换不会释放名额。释放后只允许未来新定档的战区获得 3★，不把已经公开的 1★/2★临时抬成 3★。
- **机场冲突**：机场按热度本应进入 3★时，也必须先经过同一全图闸门；若另一个 3★仍存活，则该机场本轮显示并执行为 2★。
- **Debug 边界**：普通 Debug 开放遵守该上限；只有专用压力测试覆盖可以故意生成多个 3★，并必须明确标记为非正式局分布。F6 选择“超级巨炮 / 攻城坦克”时必须把它作为原子预设提交：同拍写入 `ground + 3★ + 对应 profile`，不能保留锁定战区默认的 1★或其它 mission type。若另一个可见战区已占唯一 3★槽，F6 应先把旧区降为 2★并按普通内容重刷，再把唯一名额转移给用户指定区；不得把新请求静默压成 2★，也不得短暂保留两个真实 3★来源。

运行时现状：`ZoneData` 已统一管理普通随机、批量开放、重开、机场定档与 F6 Debug 的三级名额；第二个候选在提交时直接压为 2★。只有专项测试显式传入 `allow_multiple_tier3=true` 才能构造多源保护场。

除“3★全图最多一个”外，本轮不额外规定全图必须同时拥有几个 1★或 2★；其精确配额与节奏仍待后续战区分布打磨。

### 2.3 三级威胁的共同契约

| 项 | 当前裁定 |
|---|---|
| 所有权 | 威胁源属于一个明确的 3★战区，并登记为正式任务 TGT 或正式 TGT 组的一部分 |
| 作用范围 | 至少覆盖所属战区；标记为全局型时可攻击正在其它战区执行任务的玩家 |
| 启用时机 | **三级战区只要存在，威胁就始终启用**；不等待玩家选中、进入战区或把任务切为 ACTIVE |
| 玩家反制 | 摧毁对应威胁源；不靠等待隐藏倒计时自然失效 |
| 视觉来源 | 每次全局影响都必须能追溯到地图上的真实单位/舰队/支援机，不生成无主效果 |
| 预警 | 必须存在来源、轨迹/影响区与命中时机的可读提示；优先复用既有世界空间预警语汇，具体数值与声音后续调校 |
| UI 身份 | 战术地图/战区详情稳定显示 `3★ / 高威胁` 即可；来源激活或解除不得额外弹出 warning banner、横幅、模态弹窗或临时 toast |
| 远距伤害身份 | 属于正式任务攻击，不是气氛炮火；不得因玩家距该战区超过 3.6 km 就自动变成 0 伤害 |
| 来源终止 | 威胁源毁灭后立即停止其投射，并清掉仍由该来源拥有的持续支援、预警与未结算效果；已经结算的伤害/失导等历史结果不回滚 |
| 完成条件 | **与普通战区完全一致：清空全部正式 TGT 才完成**；超级单位只是其中一个高威胁 TGT，摧毁它只解除对应威胁，不代替清除其余目标 |
| BOSS 转场 | 完全沿用普通战区清理：三级来源直接停火并随战区单位一起消失，不把全局威胁带进 BOSS 阶段 |
| 奖励结算 | 完全沿用同等级普通战区的奖励与 XP 结算，不设三级专属奖励、继承账本或顺延规则 |

### 2.6 与现有系统的边界

- [zone-air-support-naval-safety](zone-air-support-naval-safety.md) 当前已实现的 3★海军基线仍是 `1 CG + 2 DDG + 3 FFG`、全舰 TGT。本 spec 不要求新增旗舰或替换舰型；只在真实 VLS 发射舰/挂点上配置更远射程，最终编成仍可随普通海军平衡调校。
- [zone-atmosphere-combat](zone-atmosphere-combat.md) 的 SPG/舰炮只负责远距演出并在玩家 3.6 km 外降为 0 伤害；本 spec 的超级单位是正式威胁，不能复用该“画外零伤害”身份。
- [airburst-aa-gun](../weapons/airburst-aa-gun.md) 是 800–5000m 对空空爆武器。超级巨炮自身不安装它或任何防空武器；巨炮近身防护完全由周围独立 AA/SAM 正式 TGT 承担。
- 沙漠攻城坦克只是更厚、挂点更多的正式 `GroundUnit`，不因“攻城”命名获得工程建造、地形改造或模块化 BOSS 权限。四个防空挂点固定为 `2×CIWS + 1×SAM + 1×空爆`；其中“远”明确指 **SAM 武器射程更远**，不是把 SAM 挂点摆在离坦克本体更远的位置。独立主炮是唯一对地武器，只与敌对的地面气氛演员交火。
- 海上超级任务继续继承全舰占地与完整轨道 `land_hits == 0` 的硬闸；宁可缩编或不生成，也不能让更大的新舰船上岸。
- Sentinel X 只复用普通 Sentinel 的飞行、固定护卫、光环与轮廓语汇，并用集中低频调度放出普通 MQ-109/110；不复制 Mother Goose 的 30 机蜂群、MQ-111/112、指定猎杀波或 BOSS 相位。
- DEADAIR 退回普通随机特殊支援包，不再是三级 profile；它与 Snowblind 不互斥，两者合法抽中且预算满足时可同场存在，各自保持同型上限、冷却、阶段累计和效果所有权。
- 1★/2★任务、现有奖励概率、气氛组与第三方友军支援不因本 draft 自动改变。

### 2.7 后续调校边界

- 当前首版数值已是可重建运行合同；任何 HP、射程、伤害、冷却或编成变化先改本 spec，再改集中常量。
- 世界视图使用来源真实轨迹/场；战术地图与 Tab 只稳定标识 `3★ / 高威胁` 并说明“来源解除不等于任务完成”。禁止再为来源激活/解除显示顶部 warning banner、横幅、模态弹窗或临时 toast。四类 profile 在首次被 Tab 或生成链查询时一次性固化，Tab 任务介绍、普通任务开始提示与实际实体编成必须读取同一结果，不能分别随机；普通开始提示不得再重复播一条“全局威胁”。若地面/海军安全门在生成时改变 `mission_type`，旧 profile 必须失效并按真实类型重新裁决。
- 普通任务介绍同样服从实际 `mission_type`；对舰任务明确要求清空全部舰艇，不能沿用已经失效的“只击毁旗舰”文本。无线电与专属音效仍可后续追加，但不阻塞功能完成。
- AURORA LANCE 的世界状态栏首行固定使用英文，不随 locale 改成“极光长枪”或日文；任务简报与图鉴仍可使用本地化全名。固定基盘与旋转炮架不再拥有独立锁定点或独立 HP；命中任一视觉区域都伤害同一本体，本体摧毁时整座炮塔一起消失。攻城坦克四挂点当前仍不可单独锁定/摧毁。
- 跨三图战役若未来统一改变普通战区继承，三级战区随普通规则变化，不另设三级专属账本。

## 3. 行为与状态流（How）

### 3.1 通用生命周期

| 状态 | 含义 | 转移 |
|---|---|---|
| `CREATED` | 三级战区及正式威胁源已经生成 | 创建同拍直接 → `PROJECTING`，不等待 SELECTED/ACTIVE |
| `PROJECTING` | 只要战区和来源仍存在，就持续影响所属战区外目标 | 高威胁来源被摧毁 → `NEUTRALIZED`；战区普通清理/BOSS 转场 → `ENDED` |
| `NEUTRALIZED` | 高威胁来源已毁，来源拥有的持续支援、预警与未结算效果已清除；其它普通 TGT 继续战斗 | 全部正式 TGT 清空 → `ENDED` |
| `ENDED` | 普通战区结算或清理完成；停火、移除单位并释放全部引用/表现 | 终态 |

战区任务执行器拥有任务生命周期；三级战区创建时立即启用存活来源，不能由玩家是否选中该战区控制开火。来源与状态必须一一对应，不能生成“单位已经死了但地图还在随机落炮”的孤儿效果。摧毁高威胁来源只把该来源转为 `NEUTRALIZED`，战区仍按普通规则等到全部 TGT 清空才结算。

### 3.2 超级巨炮攻击骨架

```text
固定炮台从存活长机/僚机中随机选择一个目标并旋转对准
  → 锁存炮口、方向与弹道终点快照
  → 以 Black Star 攻击线语汇显示直线危险区，末端透明淡出
  → 预警结束的开火瞬间，对整条锁存 AOE 内全部玩家小队飞机结算
  → 沿锁存直线播放高速长条弹迹（只负责表现，不延迟伤害）
  → 进入长冷却
```

- 巨炮固定在合法陆地上，不巡逻、不换位；炮身按正常转速转向满足**远距离射程窗**的存活玩家小队成员。每轮重新从长机与僚机中随机选择一个目标，不固定只打当前操控机。
- 视觉根节点与圆形基盘保持世界朝向不动；只有上层回转座、左右设备舱、桁架炮管和后部支撑架读取 `heading` 旋转。状态栏继续由固定根节点承载，不能随炮架公转。
- 合法目标可以是正在另一战区执行任务的长机或僚机，这是超级巨炮的核心身份。每次开火锁存方向；预警开始后不再每帧追着目标转弯。
- 直线 AOE 只复用 Black Star 的“来源、方向、终点、预警与判定消费同一快照”契约，不照抄其冲刺长度、危险带宽、急刹扇区或伤害数值。
- 伤害是“有来源、有 5.5s 分段预警的瞬时线性结算”，不是无预警画外 hitscan。前 4.0s 以锁存中心线为轴从 4px 细线连续扩宽到最终 180px；随后保持最终命中宽度并闪烁 1.5s，闪烁结束同拍才扫描锁存线段。最终判定半径为 90px（180m 半径 / 360m 全宽），危险带内所有玩家小队飞机同时受伤；随后高速弹迹只表达电磁炮的速度与方向，不能再沿飞行进度重复伤害。
- 渐宽阶段、满宽闪烁阶段和实际判定必须共用同一个最终宽度常量；不允许视觉填满后仍用旧 720m 宽度暗中结算，也不允许闪烁时重新追踪玩家。
- 巨炮只生成一个正式 `GroundUnit` / TGT。底座和炮管是同一图标与同一本体的组成部分，不生成独立底座标签、独立伤害体或独立销毁残留；玩家攻击底座或炮管都伤害同一 HP，本体被毁后整体消失并立即停止投射。
- 巨炮自身没有 CIWS、AA、SAM、机炮或其它防空能力，也不把气氛武装直升机作为目标。其主炮存在最近射程死区：玩家一旦进入近身范围，巨炮无法对该玩家发射或采取其它反击；最近射程具体数值后续调校。
- 近身防护完全来自周围独立生成的 AA 与 SAM。它们是普通正式 TGT，不属于巨炮本体；玩家清掉外围防空并贴近后，巨炮本体就是没有反抗能力的拆解目标。
- `ALLY` 气氛武装直升机可以选择巨炮单体进行对地攻击，但对该正式 TGT 仍走非致死入口，不能替玩家摧毁巨炮或完成任务。

### 3.3 沙漠攻城坦克骨架

- 作为真实 `GroundUnit` 在安全陆地上移动，不允许跨越海面、港池或地图外框。
- 它仍是一个普通任务语义下的单体地面单位，只是本体 HP 比普通地面单位高、炮塔更多；不建立模块化 BOSS、工程建造或地形改造系统。
- 四个防空挂点在视觉上可辨认，固定组成是两个 CIWS、一个 SAM、一个空爆挂点；上一版 `CAWS` 是笔误，全部按项目既有 `CIWS` 术语执行。
- SAM 挂点安装位置服从正常车体布局；它的特殊点是**武器射程比普通 SAM 更远**。具体射程后续调校，不把“距离较远”误写成挂点与车体的物理间距。
- 两个 CIWS 复用项目既有近程防空/拦截语义；SAM 与空爆挂点只攻击 Aircraft。四个防空挂点都不能把 GroundUnit 当作目标。
- 车体另有一门独立主炮，只选择敌对的**地面气氛组友军**，不攻击正式友军地面资产或其它正式 TGT。当前合法目标就是 [正式战区氛围战斗](zone-atmosphere-combat.md) 生成的 `ALLY` 专用 SPG。
- 主炮的每次可信直击都立即摧毁一个合法气氛地面目标；这是一击击毁语义，不依赖玩家进入 3km，也不经过气氛武器在 3.6km 外归零的伤害 LOD。近失弹如何表现、射程、冷却和弹道后续调校。
- 友方气氛 SPG 可以把攻城坦克作为交火目标，但对这个正式 TGT 继续走既有非致死入口，最低保留 1 HP，不能替玩家完成战区。双方气氛交火都不给玩家 XP、击杀数或任务完成进度。
- 主炮与四个防空挂点都随本体一起存亡，不作为独立 TGT；攻城坦克本体和同战区其它普通 TGT 全部清空后才完成任务。

### 3.4 远程 VLS 舰队骨架

- 3★舰队会由真实舰船/挂点向当前玩家操控机发射 VLS；玩家正在其它战区执行任务时仍是合法目标。
- 每枚 VLS 必须是具有发射来源、飞行过程、制导与可读预警的真实弹体；禁止用无来源的画外伤害代替。来源舰/挂点毁灭后停止新的对应发射。
- 这套 3★舰队相对普通舰队的核心差异只有 VLS 射程更远；不以额外旗舰、新舰型、复杂协同或舰体堆血制造身份。
- 当前 `1 CG + 2 DDG + 3 FFG` 六舰基线和全舰 TGT 语义继续有效；实际 VLS 发射舰、射程、冷却与弹体参数在既有舰队结构内调校。
- 生成前先完成整支舰队的全水方案，随后事务式实例化；不得边搜索边生成半支舰队。

### 3.5 Sentinel X 高威胁指挥机骨架

- 直接使用 [Sentinel X](../enemies/sentinel-x.md) 的固定 150 HP、普通 Sentinel 1.50× 飞翼、`5×MQ-109 + 1×Aegis` 固有护卫与集中低频猎手补充合同。
- 三级任务只把 Sentinel X 本体登记为正式高威胁 TGT；固有护卫和持续猎手是非 TGT，普通空战 TGT 继续按正常任务规则结算。
- 本体存活时先在 4s 放出首批，之后每 20s 最多补 2 架普通 MQ-109/110，来源所属猎手同时存活上限 6且不累计欠兵。
- 本体被摧毁后立即停补并清空队列；已放出的猎手解除跨图强制追猎后 EGRESS，不在玩家眼前凭空消失。Sentinel X 死后绝不继续生成。

### 3.6 全局威胁调度纪律

- 全部三级威胁由集中、低频的战役/战区调度器维护；禁止每个超级单位各自做逐帧全图扫描。
- 单次攻击选定目标与落区后保存快照；在途阶段不每帧重新全场选敌。
- 正式局全图最多只有一个 3★战区，因此本轮**不新增跨来源共享火力上限或错峰调度器**；巨炮、VLS 与 Sentinel X 各自服从自身冷却、弹药和实体上限。
- 玩家切换操控机后，后续新攻击必须读取当前操控机；已经发射的攻击是否重定向必须按“发射快照”原则显式裁定，默认不得偷偷追踪。

## 5. 验收标准（Acceptance / Litmus）

- [x] 1★/2★任务的单位、奖励、完成条件和局部影响完全不变；只有 3★启用战略威胁 profile。
