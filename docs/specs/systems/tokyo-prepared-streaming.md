# 东京地图预计算、后台规划与就绪交接

## 1. 设计意图（Why）

跨块、缩放与转向期间保持地图完整和精度合格，同时避免主线程选页、桥接和预测造成的长帧。
依据开放世界成熟流送方法，将静态准备移到构建/Loading，将动态全树规划移到后台，主线程只做小切面验收和资源提交。
本规格覆盖静态资格准备、后台完整规划、实时接纳和物理阶段的显示请求合并；不将短路线性能改善外推为完整游戏已稳定达到 60 FPS。

- 不减少实际可见战斗、物理步频、碰撞精度、地图清晰度、分辨率或抗锯齿。
- 不把未命中、后台尚未完成和已证明无解混为一谈；不以隐藏地图避开长帧。
- 固定物理推进与显示构建分离，合并同一呈现帧内的重复绘制请求；状态变化仍来自原权威逻辑。
- 相关设计哲学：操作反馈及时、信息可见、保留战场氛围。避免以减少内容或改变规则制造性能收益。

## 2. 数据定义（What）

### 2.1 不变的显示合同

| 项 | 本批约束 |
|---|---|
| 正式目标 | 当前 installed M20 包；7 份 HLOD 目录和原生层 |
| 显示预算 | 默认 96 MiB，既有显式候选配置另行透传，不在本批自动扩大 |
| 显示面数 | 不超过 240000 |
| HLOD 页数 | 不超过 16 |
| 原生页数 | 正式 16；既有显式 bench 32 页对照仍显式传入 |
| 物理 | 原固定 60 Hz 与现有时间推进不变 |
| 选择节拍 | 保留 0.05 s 常规节拍；快速缩放及已提交、无全向保护带的原生方向/裸视野切面允许每 1/60 s 重采移动镜头；失去资格、反转和覆盖不足仍可立即请求 |
| 空间保护 | 192 / 96 / 48 像素逐档尝试；各档均可在真实联合预算允许时由半池首选重试显示上限。平移前探为 0.35 s；原生近景在对称带无解后另试仅沿移动方向的 0.35 / 0.175 / 0.0875 s 包络，最后才退裸视野 |
| 缩放资格 | 保留原 PREFETCH_RATIO=0.50 与逐页 max_scale，不量化相机、不修改阈值 |

### 2.2 准备数据和所有权

准备缓存记录 schema、算法版本、来源路径/摘要、原始树拓扑和精确资格区间。
区间为 `(lower, upper]`，与 `scale > max_scale` 失格条件完全一致；没有混合资格的目录不复制多份树。
缓存无效或缺失只能在 Loading 重建；运行中的查询不得构造资格树或隐式读取缓存文件。

来源快照只在配置时建立：HLOD 目录与准备树、原生配置根树、纯费用/依赖描述符、固定层及已解析开关。
不把 Node、Resource、WeakRef、RID、Callable、Signal 或实际网格/图片对象传给后台规划。
无需复制原生组件文件的几何大数组；规划仅消费已验证身份、费用、包络与依赖。

每次请求包含序号、来源代次、状态修订、真实 canvas、逻辑视口、输出尺寸、相机运动、已提交/目标小切面、固定集和就绪键集合。
小切面的 entry 不携带无关后代树；逻辑视口和实际输出尺寸必须分别保存，不能混用。

## 3. 行为与公式（How）

### 3.1 单任务规划

同一 overlay 最多一个后台规划任务；等待任务完成时只保留最新需求，不无限排队。
任务独占求解缓存，以请求序号作为 epoch；后台不读取 Engine 帧号、PerfBuckets 或可变全局预算缓存。
原选择优先级和完整树动态规划保持不变，包括原生偏好、桥接、裁旧页、预算收缩、预期尺度和预测。
任务内 CPU 计时在结果返回后统一并入后台统计，不能计入当帧主线程 CPU 根桶。

| 状态 | 主线程行为 |
|---|---|
| 准备中 / pending | 保留仍合格且覆盖完整的显示；继续资源领取和既有就绪目标提交；不同步补算 |
| 有候选 | 核验代次、实际覆盖、精度、真实联合预算和当前状态，再更新请求 |
| 已证明无解 | 仅当结果对当前视野仍适用时记录无解；不能把过期结果用于清除新画面 |
| 退出 / 换源 | 停止提交需求与接收旧结果，回收任务后释放独占快照 |

### 3.2 就绪交接

顺序为 bytes available → decoded → engine/GPU ready → qualified/covered/budget valid → committed。
主线程每帧领取已完成任务，不因相机停止而遗漏结果；调用 wait 前必须已确认任务完成。
相机移动不自动否决旧请求，保护带内的候选只要通过当前精确验证仍可使用。
资源就绪、原生层掩码、共享组件去重、固定集抵扣、地面租约必须沿用原正确性门。
新目标提交前再次检查实时 ready；旧目标仍被保护至新目标完整绑定。后台快照不能代替实时资源凭据。

`anticipated_scale` 的提交不得再次触发主线程整树选择。后台完成资格准备，提交帧用真实覆盖和逐页资格证明；需要新规划时重新排队。
主线程诊断也不得运行 counterfactual 全树重算；此类比较进入纯规划测试或离线重放。

显示合同必须在该帧所有就绪提交之后再次检查，即使目标等于当前切面也不能跳过。
记录隐藏、预算超限、投影未覆盖、超过原有限缩放宽限的失格，以及处于原宽限内的失格；单纯 `visible=true` 不足以证明完整合格。

裁减旧页时保留当前与 0.25 s 平移前探视口的屏幕矩形包络，并对原完整目录证明覆盖，不能以裁后的子集自身作为完整性证明。
桥接允许在显示与真实联合预算内保留等大或稍大的切面，不要求每次交接都单调减少字节。
每档 HLOD 保护带先求原首选预算与完整显示预算；若完整显示切面可用但与旧图的真实联合费用超池，则在缩窄保护带前尝试共享资源加权求解。该次加权结果必须保持本档或更宽的保护带，不能用较窄结果抢占下一档正常求解；完整显示费用、联合费用、未来清晰度和当前覆盖仍分别核验。
缩远的 HLOD 显示查询与桥接额外考虑未来视野扩大，仍用真实当前尺度判定清晰度；已在未来尺度查询的预测分支不得再次外推。
方向性近景包络包含当前视口和按平移、缩放预测后的视口，没有全向边带，诊断中的 `spatial_guard_px` 必须为 0，另记方向向量及时间范围。
在 192/96/48 px 对称保护带均不可行时，依次尝试 0.35/0.175/0.0875 s 方向包络；未来视口在当前尺度下的尺寸为 `size × exp(clamp(-zoom_rate × horizon, -0.7, 0.7))`，取两视口矩形并集后仍按真实当前尺度选择同一配置。
已在未来尺度查询的原生预测分支只保留原平移保护，不再叠加缩放预测。相机平移速度用 0.10 s 时间常数平滑，权重为 `1 - exp(-delta / 0.10)`，不能按呈现帧固定插值而使 60 Hz 物理采样在高帧率下交替失真。
沿既有 160 px 单帧位移门识别冷进入或镜头瞬切时，同时清零平移速度、缩放预测速度和缩放方向历史。新视野仍走实际覆盖与资源接纳检查；不能把设置初始镜头时的尺度差外推为连续缩远，也不能仅把本帧平移样本归零而留下旧速度。
所有对称与方向包络均不可行时，退裸视野前可保留已提交的原生目标，但必须仍满足请求配置、当前清晰度、精确投影覆盖、页数、面数及本次字节预算。该门只允许实际显示查询复用，不适用于未来预测；保留后仍继续原有提前升档和预取流程，不把“旧图现在完整”当作未来完整的证明。
保留结果必须复制为 `native_retained` 且保护带为零，不能沿用旧查询的正保护带标记去抢占当前完整 HLOD。最终候选与目标资源身份相同时，即使不重绑或只有预取改变，也同步目标与对应已提交切面的阶段及保护带元数据；元数据刷新本身不触发资源请求、revision 或重绑，同时发生的预取身份变化仍走正常接纳、请求与修订流程。
已提交的原生切面若为方向包络、裸视野或仅保留当前覆盖、且显式记录全向保护带为零，则沿用快速缩放的 1/60 s 最小重采间隔。计时触发还要求 canvas 或输出尺寸变化；拒绝、修订或强制重规划仍可在停镜时重试。后台忙时仍只有一个任务和一个待更新标记。该规则不放宽覆盖、revision、页数、面数、字节或清晰度门，也不把预测方向包络当作转弯时的全向保护。

相机缩放方向按逐帧实际尺度判断。若缩远后反转、旧在途目标比完整合格的当前 HLOD 更早失格，则撤销旧降档事务，恢复当前资源保护、递增修订并重采最新需求。
下一呈现帧没有新的物理位移时不能让旧事务恢复提交；再次明确缩远仍可重新规划和交接。
求解前 `_pending_hlod_covers` 快速复用尚未提交 HLOD 目标时，所有目标均须通过既有 0.25 s 缩放预测清晰度门，不能仅检查带桥接标记的切面。后续同目录 retained/finishing 分支保留各自原有条件。该快速入口的限制可避免当前资格复用阻塞正常的提前升档；不延长显示宽限，也不改变当前清晰度阈值。

### 3.3 工作粒度与范围

本批不改磁盘包的网格、纹理和既有上传粒度；首先移除测得的同步选择尖峰，再以探针判断提交/上传是否仍需拆分。
现有 GridNative 动态 subset 注册会写 Stream，不得直接放入纯 worker。当前 installed M20 不含该候选；其旧路径必须显式保留并标明尚未迁移，不将 M20 结论外推到 GridNative。

### 3.4 物理与绘制

同一单位的物理更新保持原顺序和次数。物理阶段的显示失效请求通过弱引用队列合并，在 process_frame 刷新。
跨帧请求读取先检查 Variant 类型、实例有效、树内和退出状态。批次先交换再消费，防止消费期间的新请求丢失。
覆盖 Aircraft/编队、Missile、GroundUnit 及覆写物理的防空/雷达单位、NavalUnit/挂点和相关地面控制路径。
事件改变权威状态的时刻不延后；显示合同通过真实场景逐帧采样验证，不用 Headless 的零绘制记录冒充 Visual 通过。

### 3.5 剩余慢帧的函数与系统归因

继续优化前，必须先区分原 CPU 根桶漏计、脚本具体函数、渲染后端与系统等待。诊断保持相同地图包、镜头路线、演员、物理频率、分辨率及抗锯齿；不得通过减少工作负载制造收益。
仅显式 bench 参数允许连接本机 loopback 远程 profiler；普通游戏与默认 bench 不开启。收集 Godot 原生脚本 profiler 的函数身份、调用数、self/total/internal 时间及引擎帧号，记录函数容量、截断风险和采集开销。脚本墙钟耗时与 OS 实际 CPU 时间分开报告；不能将函数 total 相加，也不能将 GPU 延迟读回冒充同帧执行时间。
独立诊断轮与无 profiler 对照保持同一源码。原始逐帧记录、来源摘要、采样配置及失败日志保存在外部证据目录；优化只针对函数与因果对照已确认的工作，保留现有战斗权威与画面合同。

轻量扩展计时只由 `-DeepTrace -ExtendedCpuTrace` 开启，普通游戏与默认 bench 关闭。补齐独立导弹、防空、轰炸任务、主场景物理剩余、玩家预测准备、尾迹更新、状态栏、天气/气氛绘制和三维机体准备；已有父桶中的重复部分及共享 event/audio 叶计时从新增根扣除。total/covered/shared 与具体绘制函数子桶只作诊断，不能再加入根总量；负差值显式标为无效，不能静默归零。系统 CPU 计数只在共同时间窗比较，函数墙钟包含线程等待，Godot 父类调用 self 重叠与后台线程聚合不能相加冒充主线程 CPU。

高射炮与防空导弹车覆盖基类的独立绘制回调必须单独计根，不能假设已由地面单位桶覆盖。逐帧结算、测试记录与渲染信号的诊断开销也单列；发生在帧首时钟之后的记录工作必须归入新帧，不能在随后清空桶时丢失或倒记上一帧。无法用同次记录或原生符号证明的剩余明确保留为未解析，不以引擎开销名义凑满总数。

热点候选必须保持尾迹位置、bank、宽度、颜色、淡入、完整采样点及抽点步长，预测线全部显示点、三层线宽/抗锯齿、渐变与箭头，以及狂化身份查询的安全引用和队伍/操控语义。任何候选均不得改变物理积分、决策频率、演员数量、相机或渲染质量设置；几何数组/生命周期 focused 通过后仍必须进行无探针对照。正确性通过不等于性能通过，未证实收益或出现退化的候选不得作为已验收优化进入当前实现。

本轮尝试的尾迹拓扑缓存、预测线逆变换复用/移除健康度拷贝、狂化关闭时提前返回，均通过对应等价检查，但六组前后与追加相邻对照未证明整体收益，已撤回生产改动。候选补丁、等价测试及全部成功/失败记录保存在仓库外诊断证据中；当前保留新增诊断和生命周期检查。

## 4. 结构与组成（Structure）

- PreparedCatalog：Loading/离线缓存与精确资格区间查询。
- MapPlanner：独占纯值来源、完整选择策略、候选/无解结果及后台计时。
- MapPlanWorker：一个在途任务，来源代次、序号、生命周期回收。
- HLOD overlay：相机/状态快照、实时 admission、Stream 请求/资源绑定及诊断。
- 原生/目录选择器：同步兼容接口与显式后台 context，共用同一求解算法。
- VisualRedrawQueue：纯显示请求合并，不承担物理权威。
