# 敌机传感器隐形系统

## 1. 设计意图

- 隐形只改变玩家侧的传感器接触，不让敌机从世界、物理或敌方 AI 中消失。
- 玩家必须持续用任一具备锁定能力、未受 JAM 的小队雷达照射隐形敌机，才能维持精确接触；脱离照射后以短暂记忆窗口收束，而不是瞬间闪烁。
- 功能必须带来可验证的渲染与逻辑减负：完全隐形时停止该机尾迹采样/绘制，并跳过玩家侧雷达点、标签、锁框、目标线与精确 TGT 数据。
- 不复用 F-47 的完全相位隐形，也不覆盖 Snowblind 的区域传感器遮蔽；三种状态各自拥有生命周期。
- F-47/Wraith 同时拥有本系统的常态低可探测性与原有周期光学隐身；两层可重叠，但任何一层进入隐形都必须立即让玩家小队丢失 `combat_target`。

## 2. 数据定义

### 2.1 固定数值

| 项目 | 权威值 |
|---|---:|
| 雷达接触检查频率 | 5 Hz（复用现有雷达锁定 tick） |
| 失联宽限 | 5.0 s |
| 显形渐变 | 0.5 s |
| 隐形渐变 | 0.5 s |
| 近距强制揭露 | 任一存活玩家小队成员进入 1000 px（2000 m） |
| 首批启用机型 | F-22、F-35、Su-57、J-20、YF-23 常规敌版；F-47/Wraith BOSS 本体 |
| 玩家雷达来源 | 当前操控机与全部存活玩家僚机 |
| 有效照射条件 | 来源具备锁定武器、未受 JAM、目标位于来源真实雷达锥内 |

### 2.2 状态

每架启用隐形的敌机保存：

- `sensor_contact_hidden: bool`：是否已对玩家侧丢失传感器接触；这是逻辑门，渐变期间也立即生效。
- `sensor_contact_lost_s: float`：从最近一次有效照射起累计的失联时间。
- `sensor_contact_visual_alpha: float`：仅控制玩家侧飞机本体/残留效果的 0–1 渐变。

状态转移：

1. 生成时为可见接触，`lost_s = 0`。
2. 任一有效玩家雷达照射，或任一存活玩家小队成员进入 1000 px（2000 m）近距圈时，立即恢复逻辑接触、`lost_s = 0`，在 0.5s 内渐显。近距揭露不要求锁定武器，也不受 JAM 影响。
3. 本次 5Hz tick 没有任何有效照射时，`lost_s += 0.2s`。
4. 目标同时处于全部有效雷达锥外与近距圈外后才累计失联；`lost_s >= 5.0s` 时进入逻辑隐形，并在 0.5s 内渐隐。
5. 渐变可被反向照射打断，必须从当前 alpha 连续反向，不能跳变或叠加 tween。

## 3. 行为与规则

### 3.1 玩家侧接触

- 完全隐形的普通敌机不显示世界图标、尾迹、标签、锁框、目标线或精确状态数据，也不能被鼠标点选、玩家 AI 搜索、雷达锁定或武器制导选中；左下角雷达盘仍显示低亮度匿名位置提示点，作为玩家追索线索，但该提示不建立传感器接触或火控解算。
- 若隐形敌机是任务 TGT，任务目标不能丢失：保留当前位置的黄色 `TGT` 括号，但名称、距离、生命、速度、高度、威胁等精确信息统一显示为 `???`。
- TGT 标记跟随真实位置是任务可玩性豁免，不等价于恢复雷达接触；它不得帮助武器锁定或 AI 选敌。
- 进入传感器隐形时，玩家小队对该机的当前目标、指令目标、雷达主/副锁和作战追踪必须统一释放；其中 `combat_target` 必须在隐形逻辑沿当场变为 `null`，不能等待下一次 AI/武器 tick；其他阵营的目标与命令不受影响。
- 玩家小队的 `combat_target` 写入权威必须拒绝 `is_cloaked` 或传感器遮蔽目标；即使光学短窗保留 `commanded_target`，RTS 铁律、分火、防守与齐射等后续 tick 也不得把目标重新写回。显形后才允许沿保留的点名自动重接。

### 3.2 敌机与世界侧

- 隐形敌机仍可观察、锁定、追击并攻击玩家与其他敌对单位。
- 传感器隐形状态不得成为敌机 AI、物理、机动、武器或 LOD 的降级输入；隐形前后上述行为、更新频率与权限完全一致。相机离屏、拥挤度或战略层可以按各自通用规则降级，但必须对同条件显形敌机同样生效，不能因为“玩家看不见”额外停算。
- 它仍参与碰撞、边界、任务、生成上限、伤害、死亡与 XP 结算。
- 机炮弹、火箭、炸弹、爆炸 AOE 等已有实体/空间伤害允许盲打命中；传感器隐形不是无敌或命中免疫。
- F-47 `is_cloaked` 的完全相位隐形仍按“短窗挂起”契约运行：光学隐身沿清除全体玩家机的 `combat_target` 与主/副雷达锁，但保留 `commanded_target` 指针，显形后可自动重接。每次光学 cloak 结束后进入严格 60.0s CD，CD 结束才可再次使用；导弹来袭不得绕过 CD。开战后首次使用同样先等待 60.0s。
- 当前操控玩家机进入任一 Wraith 成员 1000 px（2000 m）内时，光学 cloak 不得启动；已在 cloak 中则提前结束并显形。光学淡入/淡出均为 1.0s，避免瞬间消失。
- F-47 另显式开启 `sensor_stealth_enabled`：光学隐身窗外仍按 5.0s 失联规则隐形；该传感器失联是硬失联，继续清除 `commanded_target`，不借用光学短窗的挂起语义。

### 3.3 在飞武器

- 目标进入逻辑隐形的同一时刻，已发射导弹失去制导并保持当前速度/航向继续惯性飞行；不能自动重捕获。
- 火箭、机炮弹、炸弹与已经生成的 AOE 不因目标隐形而删除、改道或取消命中。

### 3.4 状态重叠与生命周期

- Snowblind 区域遮蔽仍由 `sensor_hidden/sensor_shroud_id` 管理；被区域遮蔽的观察者不能刷新本系统接触。
- JAM 只使该雷达来源无效；若同队另一来源仍有效照射，目标继续显形。
- 来源死亡、换帅、切控、脱离树或目标排队释放时，下一次雷达 tick 自然重算；控制器不得永久缓存 Aircraft 引用。
- 已死亡或待释放单位不得被 tween、目标清理或尾迹切换重新访问。
- 战斗暂停/时间缩放沿现有游戏 delta 计时，5.0s 宽限随游戏时间而非墙钟推进。
- 被 `CinematicCast` 绑定为导演演员期间，该机属于虚拟演出环境：冻结失联计时，不触发隐形沿，
  也不让既存传感器隐形状态影响演员本体、尾迹或玩家侧演出观察。`release()` 后恢复真实战斗状态；
  演出纯视觉隐身仍只由导演自己的 `_cloak_alpha` 控制。

## 4. 结构与组成

- `AircraftParams` 只增加一个数据开关；首批六份敌机资源显式开启。
- 单个生存模式控制器复用现有 5Hz 雷达双层循环记录“本 tick 被照射”的实例 ID；tick 尾仅做一次 O(N) 状态收束，不新增第二次 O(N²) 扫描。
- 同一 tick 同时丢失接触的目标先汇总为一批，再只扫描一次玩家观察者并批量清理锁定/目标；
  Wraith 四机同时进入光学隐形也复用同一批量边。禁止按每个隐形目标重复扫描全场单位。
- 状态保存在 Aircraft，本体绘制、RadarDisplay、HUD、AI、导弹快照和 TrailRibbon 各消费同一逻辑查询。
- 不新增逐机 Node、`_process`、`_physics_process` 或独立传感器扫描。
- 同方向重复状态写入必须幂等：既有 0.5s 渐变不得被 5Hz 雷达 tick 或多观察者重复 kill/restart；渐变透明度走 CanvasItem 调制，绘制命令只在逻辑沿与完全隐形终点重建。完全隐形的非任务目标停止常规 redraw，但其 AI、物理与武器仍照常运行。
