# 高完成度纯矢量地图研究与制作规则（冻结）

> 2026-08-08 最终裁决：东京湾纯矢量候选未达到用户期望，正式主地图与 Tab 地图继续使用 8704×8704 PNG + shader。本文件保留为 UGC/新图与未来研究的方法档案，不再授权当前东京湾 PNG 退役；重启替换必须另立 approved spec。

本文件是 AGL 后续官方地图和 UGC 地图的可执行制作规则。视觉质量与帧率都属于毕业门；不能用“以后再补”绕过任一项。权威数值与产品行为仍写入对应 `docs/specs/`，本文只规定生产、审计和回归方法。

## 1. 先锁定共同输入

- 编辑器、主地图、Tab 地图必须消费同一份 `MapDocument` 或由其一次性派生的 renderer 描述；禁止维护三套手工样式。
- 世界边界、坐标变换、陆海判定、LOD 阈值和 style profile 必须带版本并写入构建清单。
- 大型地图内容只能是矢量/量化几何。极小且跨地图复用的 LUT、噪声纹理可以用于材质，但不能承载海岸、道路、城区或建筑内容。
- 所有原始 PBF、GeoJSON、逐格 JSON、截图和 diff 只放 `tmp/`；`resources/` 只接收运行时压缩包、manifest 和共享小材质。

## 2. 金样切片优先

先选一个同时包含海岸、密集城区、主辅道路、港口、机场或高楼的 4×4 km 金样。先在固定机位和固定 zoom 上完成并锁定：

1. 海面、浅海、陆地、城区、工业/港区的色阶；
2. 海岸窄边、浅海边、陆地内描边；
3. 主路 casing/core、次路单层概括、铁路和机场；
4. 城市质量块、普通建筑屋顶、大型建筑侧墙、真实高楼高度；
5. 世界空间颗粒、暗角和最终合成亮度。

金样未通过前不得铺整图。整图只能继承同一 style profile，禁止逐格调色。

## 3. 三档信息预算

| 档位 | 目的 | 应保留 | 必须省略 |
|---|---|---|---|
| Strategic / Tab | 识别海湾轮廓、城市关系、任务位置 | 陆海拓扑、主城区质量块、主交通轴、机场 | 逐栋楼、住宅小路、局部纹理 |
| Operational | 战斗常用中景 | 连续城区、真实街区骨架、双层主路、港区、大型概括楼，以及所有有玩法意义或真实高度证据的重要假 3D 大楼 | 中小逐栋楼、像素级道路密度 |
| Detail | 近景完成度 | OSM 建筑/地表/道路/铁路/港口图元、真实高度高楼、局部海岸精修 | 对帧率无贡献的重复微线和不可见小面 |

LOD 变化只调整 feature 层透明度或启用已预热的完整 Detail 层。禁止两个不透明根图互相 cross-fade；那会在滚轮缩放时造成整屏忽明忽暗。禁止规则格子、随机噪声或等值线冒充城市信息。

### 3.1 大色块精修顺序

当地图“信息够但不好看”时，先做视觉减法，不得把更多图元当作默认答案：

1. 先锁定同机位 PNG / vector 基线，分别测 Strategic、Operational、Detail 的低频明暗起伏和边缘密度；
2. 优先调整各 LOD 的海、陆、城区 palette 与现有 density/landuse alpha，缩小相邻大面的综合色差；
3. 再收窄既有海岸、建筑 casing/侧墙的宽度、透明度和统一光向偏移，保留边缘层次但避免冷黑阴影连成大块；
4. 除非固定机位证明缺的是结构而非色阶，否则禁止新增道路、建筑、噪声、terrain wash、逐格 tint 或独立 draw packet；
5. 调色轮必须证明 draw call、三角数和内容计数不增加，并重新通过 zoom 稳定性、全图 atlas 与成对压力测试。

三档允许使用不同 palette / alpha / 既有描边宽度，但必须共享同一拓扑和 style profile。Strategic/Tab 最柔和，Operational 保持海陆与主路可读，Detail 才保留屋顶和低浮雕；任何一档都不得靠大片不透明城市填充制造“完成度”。

## 4. 建筑层级

- 远景只用城市质量块。
- Operational 只提交面积足够大的真实概括体块；屋顶、casing 和统一光向侧墙各合并为静态 packet。
- Detail 恢复普通楼屋顶和大型楼低浮雕；只有存在 OSM `height` / `building:levels` 的楼才按真实高度拉高。
- 有玩法意义的建筑是游戏层，不是可随底图替换删除的装饰。东京湾 189 组横滨 `BuildingRenderer` 必须在 PNG/矢量两侧共享，视觉与阻挡状态一致；不得再写“候选开启时隐藏旧楼”。
- 全图真实 `>=80m` 高层须进入独立常驻 Operational `landmark` packet，任何战斗 zoom、Detail 未驻留和普通 LOD 降级都保持可辨的侧墙、窄深边与屋顶。普通城市才允许静态合批和省略。
- 不得把旧地图局部街区数据复制成全图逐建筑动态 renderer；共享玩法楼与全图常驻高层可以叠加，因为两者职责不同。
- 建筑对拍必须比较真实运行时完整 PNG 堆栈，包括 PNG 上方的独立建筑层、天气和最终调色，不能只比较底图文件。

普通城区的性能降级顺序固定为：小建筑 → 普通街巷 → 城市场景块数量/层数 → 普通 large 屋顶透明度。重要玩法大楼与有真实高度证据的常驻高层不得作为第一轮性能止损项；若连它们都必须删除才能过帧率门，应判定当前 renderer 路线未毕业。

纸模/总平面色块只能使用不规则 6–8 边、非同心内缩面和单一弱外描边；禁止规则格、六边蜂窝、同心靶纹。每一条边都必须在离线阶段与视觉水面边界做相交审计，不能只检查三角质心或靠海色遮盖越界。

参考纸板总平面风格时，城区、植被、工业分类默认共用一个材质色相，只通过明度、透明度和中性阴影表达差别。综合色锚点应保持 `R >= G > B` 的暖灰顺序，禁止用蓝灰、绿色、橙褐三种大面直接可视化数据通道；分类色只有在玩法确实要求玩家瞬时识别时才能突破该规则，并须单独写入 spec。色块总量以“有呼吸区”为门，不得均匀铺满每个视口。

## 5. 全图覆盖审计

固定网格必须逐格分类，不得只遍历 manifest：

- `registered_nonempty`：有运行时细节包；
- `registered_empty`：源数据确认无支持图元；
- `omitted_ocean`：严格陆地采样为零；
- `explicit_coast_edge`：主体为水、只有极小陆地/桥梁擦边，且固定同 zoom PNG/vector 对拍证明不构成视觉漏图；
- `failure`：任何未解释的陆地空格、丢包、解码失败或跨格硬边。

东京湾当前基线是 16×16 共 256 格：203 格注册、199 格非空、4 格空、53 格省略；`detail_10_06` 与 `detail_14_04` 是有截图和 PBF 分配记录支持的海岸边缘空格。新增或改动数据后，例外集合必须精确匹配，多一个或少一个都失败。

整图 atlas 必须使用同一 Operational 底层和同一 Detail renderer/cache 合成，统计每格亮度、RGB 偏色、三角数和全部水平/垂直边界跳变。代表机位另以相同分辨率、相同 zoom 覆盖东京、横滨、川崎、千叶、横须贺、机场、港区、接缝和全部显式空格。

## 6. 静态渲染与预热

- 地图 packet 只在 loading、编辑保存或安全暂停中一次性构建；战斗中禁止地图 SubViewport bake、GPU readback、全图三角化或持续 `queue_redraw`。
- `RenderingServer.canvas_item_add_triangle_array` 合并同材质三角；不要为每条路、每栋楼建立 Node。
- Detail 缓存按真实视口求所需非空格并集。完整集合装不进预算时整层回退 Operational，绝不截断后显示半屏。
- 相机移动时只做低频覆盖检查和整层平滑显隐；不得按格突然出现。zoom 语义 alpha 必须直接由连续曲线计算，资源覆盖完整度另用短时 alpha 平滑，两者相乘；禁止把 zoom 本身也放进时间滞后造成滚轮忽明忽暗。
- loading 必须预热出生区；跨战区与 Tab 任意航点只能在真暂停中预热，失败不阻塞游戏，回退 Operational。

## 7. 自主迭代循环

除非遇到需要用户选择的美术方向，地图作者或 agent 应自行完成至少三轮：

1. 固定基线：PNG 与候选使用同机位、同 zoom、同分辨率、完整运行时堆栈；
2. 分层诊断：拓扑 → 色阶 → 城市质量 → 海岸 → 道路 → 建筑 → grain/vignette；
3. 一轮只验证一个可证伪假设，保留指标和截图；
4. 每轮运行金样单测、全图 atlas、真实 GL 截图和成对性能 bench；
5. 最多八轮；连续两轮无可测改善就停止盲调，记录缺数据、renderer 能力或预算这一真实阻塞。

用户只审核方向里程碑和最终毕业候选，不负责逐轮发现黑点、断路、色偏或漏格。

## 8. 性能门

- 使用同一台机器、同一场景、同一时长，先 PNG 后 vector 或交替运行，记录平均 FPS、最差 FPS、低于 60 FPS 帧数、启动/预热耗时和 stderr。
- Sentinel + Lv5+ 是正式毕业压力场；地图造成持续掉帧或相对基线下降超过 15 FPS，立即按“小楼→普通街巷→纸模场景块→普通屋顶”的顺序削弱，不能先删重要玩法大楼或常驻真实高层，也不能放宽门槛。
- 记录每个 LOD 的主画布 draw call、三角数、压缩资源体积、CPU 缓存和 GPU Detail LRU 峰值。
- exit code 0 不等于通过；必须检查断言、原生错误、缓存失败和战斗中 bake/readback 证据。

## 9. 已踩过的坑

| 症状 | 根因 | 永久规则 |
|---|---|---|
| 整图忽明忽暗 | 两个根图随 zoom 叠加淡入淡出 | 固定一个不透明根层，只淡 feature |
| 远景出现蜂窝/格子 | 用规则图案伪造城区 | 只用真实 density mass 和概括骨架 |
| 蓝线飘在海上 | 道路缺陆地承托或坐标/裁剪错误 | 先闭合陆海面，再派生道路与海岸 |
| 黑色噪点 | 高频颗粒在缩放后混叠 | 世界空间低频 grain；不得逐像素随机点 |
| Detail 半屏断裂 | LRU 截断预热集合仍显示 | 视口并集全有或全退 |
| 缩放时细节突然跳出 | 每格或每 LOD 硬开关 | 完整层连续淡入，格子不独立显隐 |
| 假 3D 楼消失 | 把玩法楼误判成 PNG 内容，或让重要高层跟普通 Detail/LOD 一起退掉 | 玩法楼两侧共享；真实高层独立常驻 Operational；对照包含完整旧楼 |
| “整图已完成”却有漏格 | QA 只遍历 manifest，未审计 16×16 全网格 | 所有 256 格分类，空格例外精确锁定 |
| PNG 对照显得候选虚假领先 | 对照只画 PNG，漏掉独立旧建筑层 | 对拍完整生产堆栈 |
| 战斗卡顿 | 首次切换时现场三角化/截图 | loading/安全暂停预热，战斗只绑定缓存 |
| 为修接缝逐格调亮度 | tile tint 掩盖数据/采样错误 | 全图共用一个 tint，先修 padding、过滤和几何 |
| 城市像大片灰块 | density/landuse 与建筑阴影综合色差过大 | 先降 LOD palette/alpha 和既有阴影面积；结构已足够时禁止继续堆图元 |
| 城市像花绿拼布 | 把 urban/vegetation/industrial 数据通道直接映射成蓝、绿、橙大面 | 保留分类数据，显示统一暖灰纸板色；用明度与中性阴影分层，并减少台地数量 |

## 10. 毕业与回滚

本轮东京湾候选已由用户最终视觉验收否决，因此当前结论是**保留 PNG，停止生产化替换**。下列条目仅作为未来新 spec 的重新立项门，不能从本轮历史结果继承“已毕业”：

- 四条路径都消费同一 renderer 描述：编辑器预览、主地图、UGC 试飞、Tab 图；
- PNG/vector 完整堆栈并排通过，海面、海岸、陆地、城区、道路、机场、建筑、grain、暗角和全部 zoom 档不低于 PNG；
- 256 格覆盖审计、同 zoom atlas、代表机位、LOD 稳定性和显式空格全部通过；
- Sentinel + Lv5+ 成对压测通过，启动和内存预算通过，战斗期无地图 bake/readback/redraw；
- debug A/B 与原子回滚保持可用，至少经过一个稳定版本验证。

任一门失败时保留 PNG；是否继续修 renderer、数据或预算由新的用户授权决定。不得先删资源再逼迫候选上线，也不得以 debug A/B 存在为由把冻结候选接入正式默认。
