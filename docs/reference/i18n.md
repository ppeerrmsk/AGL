# 本地化 / i18n 系统

## 概览

AGL 使用 Godot 4 原生的 CSV 翻译系统。玩家可见文本按领域拆在 `i18n/` 的五份 CSV 中，
由 `LocaleManager` autoload 控制 locale 切换；运行时 key 与拆分前完全兼容。

| 文件 / 组件 | 作用 |
|---|---|
| [i18n/README.md](../../i18n/README.md) | 五份分表的领域边界与新增文本路由规则 |
| `i18n/interface.csv` | 菜单、HUD、战术控件、暂停、编辑器与通用界面文本 |
| `i18n/gameplay.csv` | 地图、战区、机体、进化、BOSS、奖励与事件文本 |
| `i18n/skills.csv` | 技能、属性轴、装备、状态、稀有度与配装文本 |
| `i18n/meta.csv` | 资料库、图鉴、信息手册、成就与局外商店文本 |
| `i18n/radio.csv` | 全部 `RADIO_*` 说话人与台词文本；无线电专属 |
| [scripts/i18n_catalog.gd](../../scripts/i18n_catalog.gd) | 构建/测试共用的五表清单与跨表审计；运行时不参与翻译查询 |
| [scripts/locale_manager.gd](../../scripts/locale_manager.gd) | AutoLoad：启动时从 `user://locale.cfg` 读取；主菜单按钮调 `set_locale_persistent(code)` 切换 zh / en / ja |
| `project.godot` `[internationalization]` 段 | 注册 `.translation` 资源路径 + 默认 fallback |

构建流水线：`bench\run.cmd i18n_build 5 120 Shadow` 逐表生成 `<分表>.zh/en/ja.translation`
到 `bench/results/`，共 15 份；复制回 `i18n/` 后由 `project.godot` 全部注册。Godot 编辑器也可
对单份 CSV 重新导入，但提交前仍应跑统一构建与审计。

## 命名约定

所有 key 用 SCREAMING_SNAKE_CASE，前缀表领域：

| 前缀 | 用途 | 例 |
|---|---|---|
| `MENU_*` | 主菜单 | `MENU_TITLE`, `MENU_MODE_SANDBOX_NAME` |
| `HUD_*` | 战斗 HUD | `HUD_HEADING_FMT`, `HUD_STALL`, `HUD_GAMEOVER_*` |
| `TACTIC_*` | 战术按钮标签 | `TACTIC_MISSILE_PRIORITY`, `TACTIC_EVADE_FMT` |
| `TOOLTIP_*` | 战术按钮 hover 提示 | `TOOLTIP_WEAPON_MISSILE_TITLE/BODY/HINT` |
| `SQUAD_*` | 小队指挥面板 | `SQUAD_HEADER`, `SQUAD_FORMATION_FMT` |
| `FORMATION_*` | 阵型名 | `FORMATION_FINGER_FOUR` |
| `ACTION_*` / `TACTIC_*`（动作） | 僚机动作/战术显示名 | `ACTION_EVADING`, `TACTIC_TEAM_ATTACK` |
| `WEAPON_PREF_*` | 武器偏好 | `WEAPON_PREF_MISSILE` |
| `STATE_ON` / `STATE_OFF` | 开/关状态 | 格式串里的填充 |
| `UPGRADE_<ID>_NAME` / `_DESC` | 升级表（与 UPGRADES `"id"` 对应） | `UPGRADE_HP_UP_NAME` |
| `UPGRADE_CATEGORY_*` | 升级分类前缀 | `UPGRADE_CATEGORY_COMBAT_PREFIX` |
| `MAP_SELECT_*` / `MAP_<ID>_*` | 选图界面 / 地图数据 | `MAP_DEFAULT_NAME` |
| `AIRCRAFT_SELECT_*` / `AIRCRAFT_<ID>_*` | 选机界面 / 机型卡片 | `AIRCRAFT_F16_CARDDESC` |
| `SLOT_*` | 通用槽位文本（PILOT/MAP 编号、未解锁、选择按钮等） | `SLOT_LOCKED_BUTTON` |
| `TAG_*` | 可复用的短标签（热诱弹/均衡/海岸等） | `TAG_HEAT_FLARE` |
| `POPUP_*` | 游戏内提示弹窗 | `POPUP_EVOLUTION_FMT`, `POPUP_COBRA` |
| `ACHIEVEMENT_<ID>_TOAST` | 生涯档案成就解锁 toast（spec career-archive，每条成就一 key） | `ACHIEVEMENT_UAV_HUNTER_TOAST` |
| `CODEX_*` | 敌人图鉴（spec career-archive §2.6）：页面壳 / 分组标题 / **每条敌人 `CODEX_<ID>_NAME` + `_DESC`** | `CODEX_MIG31_NAME`、`CODEX_SECTION_BOSS` |
| `INFO_*` / `ARCHIVE_*` | 游戏信息手册与资料库外壳（spec career-archive §2.7）：**每条机制 `INFO_<ID>_TITLE` + `_BODY`**；复用 Tab 小技巧的条目只需 TITLE | `INFO_KEY_E_TITLE`、`ARCHIVE_TAB_INFO` |
| `ACE_SQUAD_<ID>_NAME` / `_LORE` | 王牌中队名与队史（spec ace-squadron-tier §2.7；图鉴王牌组复用） | `ACE_SQUAD_VULTURE_LORE` |
| `RADIO_*` | 无线电说话人与台词；**只能放 `radio.csv`** | `RADIO_SPLASH_1` |

**带 `_FMT` 后缀** 表示字符串含 `%` 占位符，消费端用 `%` 运算符填充。

## 使用方式

### CSV 列结构

`keys,zh,en,ja` — 首列 key，后续三列分别是中、英、日翻译。新增 locale 需同步：
1. CSV 新增一列
2. `LocaleManager.SUPPORTED_LOCALES` 追加
3. `main_menu.gd._build_language_switcher` 的 `options` 数组追加新按钮

### 代码里

```gdscript
# 简单字符串
label.text = tr("MENU_TITLE")

# 带占位符的格式串
label.text = tr("HUD_KILLS_FMT") % kill_count

# 多个占位符
label.text = tr("HUD_LEVEL_FMT") % [level, xp, xp_to_next]

# 布尔态切换填充
button.text = tr("TACTIC_EVADE_FMT") % (tr("STATE_ON") if enabled else tr("STATE_OFF"))

# 多行 BBCode 文本（CSV 里写 \n 转义）
label.text = LocaleManager.trm("TOOLTIP_WEAPON_MISSILE_BODY")
```

### 数据驱动资源里

`.tres` 的 `display_name` / `card_desc` / `card_tags` 以及 GDScript 里硬编码的 `UPGRADES` / `MAP_LIST` / `PLAYABLE_LIST` 字典，**存 KEY 字符串**，消费端再 `tr()`：

```gdscript
# resources/playable_f16.tres
display_name = "AIRCRAFT_F16_DISPLAY"
card_tags = PackedStringArray("TAG_HEAT_FLARE", "TAG_BALANCED_MANEUVER", "TAG_SARH_MISSILE")
card_desc = "AIRCRAFT_F16_CARDDESC"

# survivor_select.gd 消费时 tr()
name_label.text = tr(profile.display_name)
desc_label.text = tr(profile.card_desc)
```

### 什么不走 tr()

- `AircraftParams.display_name`（如 `f16.tres` 里的 `"F-16"`）—— 战斗 HUD / AI 日志大量拼接使用，**保留原值**。只有 `PlayableAircraft.display_name`（选择卡片专用，如 `"F-16C Block 50"`）走 tr。
- `PlayableAircraft.codename`（如 `"SmartFalcon"`）—— 英文代号，中英一致。
- EventLogger 事件字符串 —— 开发者日志，不面向玩家。
- debug 面板（`debug_panel.gd` / `survivor_debug_*.gd`）—— 开发工具，玩家版不可见。但因为源数据（UPGRADES）现在是 KEY，debug 面板消费点仍需 `tr()` 包装以显示可读名。

## 新增文本的流程

1. 按 [i18n/README.md](../../i18n/README.md) 的领域规则选择分表，加一行 `KEY,中文,English,日本語`
   - 普通字符串直接写
   - 多行文本用 `\n` 转义（消费端调 `LocaleManager.trm()`）
   - 字段含半角逗号时用 `"..."` 包裹；含英文引号时用 `""` 转义
     ⚠ **忘了加引号不会报错**：该行会被切成 5+ 列 → 中文仍对、英文被截断、日文错位到列外，
     而 `tr()` 照样命中（"有译文"的检查抓不到）。`--bench=career_archive` 有全表**列数一致**
     断言守这条；2026-07-28 曾据此揪出 36 行（含两行长期截断的历史遗留）
2. 代码里用 `tr("KEY")` 或 `tr("KEY_FMT") % [...]`
3. 跑 `bench\run.cmd i18n_build 5 120 Shadow`，把 `bench/results/` 中对应的 `.translation` 复制回 `i18n/`
4. F5 运行 → 在主菜单底部的语言按钮切换验证

## 语言切换

- 支持三种 locale：`zh` / `en` / `ja`
- 启动时优先读 `user://locale.cfg` 里保存的选择；没有则回退到 `zh`
- **主菜单底部**三个语言按钮（中 / EN / 日），当前语言高亮
- 点击按钮调 `LocaleManager.set_locale_persistent(code)` → 设置 locale + 写入配置 + `get_tree().reload_current_scene()` 刷新当前场景
- **不使用功能键切换**：F8 在 Godot 编辑器里是"停止运行项目"的快捷键，会让游戏退出；其它 F 键也容易与游戏热键冲突，故统一走 UI 按钮

## 已知风险

1. **`UPGRADES["name"]` 作为字符串比较用的话会崩** —— 技能判断一律按 `"id"` 比较，**绝不**按 `"name"`（那是 i18n key，会随语言变）。
   ⚠ 旧文提到的 `"evolves_to"` 进化链**已废弃**（新技能不做"满级自动进化"），这里只保留"按 id 不按 name"这条铁律。
2. **格式串占位符一致性** —— 新增 en 翻译时必须保留 `%d` `%s` 占位符的数量和顺序，否则 `%` 运算会崩。
3. **`.tres` 改 KEY 后需重新导入** —— 手改 `.tres` 后在 Godot 编辑器里 Reimport 一次，避免缓存。
4. **字体** —— 目前使用 Godot 默认字体；切到 en 时无问题，中文若 fallback 缺失会回退到方块字（当前未观察到）。
5. **跨表重复 key** —— Godot 会按注册顺序覆盖，可能静默显示错误译文；`I18nCatalog.audit()` 与
   `career_archive` bench 会检查五表集合、四列结构和跨表唯一性。
